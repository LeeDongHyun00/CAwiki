# 카드 제목 개선 보고서 — "누르고 싶고, 쉬워 보이게"

작성일 2026-08-27 · 방법: 4각도 병렬 리서치(학습 플랫폼·기술 문서·UX 논문·한국어 작명) +
각 조사 출처 실재성 적대적 검증 + 종합. 핵심 인용은 작성자가 1차 출처로 재확인.

> **범위 주의** — 이 문서는 *제안*이다. 실제 제목 교체는 별도 결정 사항. 대상 파일은
> `lib/wiki.js`(카드 title/tag)와 `lib/home.js`(ARCH_META), 두 곳을 함께 맞춰야 한다.

## 진단 — 왜 지금 제목은 안 끌리는가

세 층위가 겹친다.

1. **전부 명사 종결** ('부팅 / 화면 녹화 / 멀티태스킹'). 어미도 물음표도 없어 '부르는
   목소리'가 없고 사전 표제어·목차 항목처럼 읽힌다.
2. **제목이 곧 전문용어**라 이미 답을 아는 사람의 언어다. 비전공 학습자에겐 '내가 아는
   그것'이 아니라 '배워야 할 그것'으로 다가와 진입장벽이 된다. 읽기 어려우면 과제도 어려워
   보이고(처리유창성) 자기효능감이 떨어져 시도 대신 회피를 부른다.
3. **제목이 개념을 다 말해버려** 아는 것과 모르는 것 사이 '정보 격차'가 안 열린다. 특히
   '절전과 복귀'는 너무 건조해 격차 자체가 생기지 않고, 컴퓨터가 주어라 '내 일'이 아닌
   '남의 기능'으로 읽힌다.

**결정적 낭비**: 이 프로젝트의 부제(tag)는 이미 '전원에서 로그인까지'·'클릭에서 픽셀까지'
같은 최적의 여정형 어감을 쓰고 있다. 그런데 그 살아있는 목소리가 작은 부제에만 있고,
먼저 눈에 들어오는 큰 제목은 건조한 명사다 — **위계가 뒤집혀 있다.**

## 원칙 7 — 근거와 함께

| # | 원칙 | 왜 통하는가 | 근거 |
|---|---|---|---|
| 1 | **제목=클릭 욕구, 부제=접근성 (역할 분업)** | 두 결핍(누르고 싶음+쉬워 보임)을 한 문장에 욱여넣지 말고 제목·부제로 나눠 담는다. 제목은 일상 행동+궁금증, 부제는 여정·소득을 평이하게. | cpu.land, wizardzines(훅 제목 + 평이한 약속) |
| 2 | **건조한 명사를 '순간·손동작' 앵커로 — 독자를 주어로** | 기능 명사는 기계가 주어지만, 독자가 실제로 하는 행동('전원 버튼을 누르면')을 앞세우면 남의 기능이 내 경험이 된다. 자기참조로 부호화된 정보가 더 잘 기억된다. | 자기참조 효과 (Rogers, Kuiper & Kirker 1977, JPSP); cpu.land 'Putting the **You** in CPU' |
| 3 | **의문형·유보로 '적당한' 호기심 격차만 열기** | 질문/'무슨 일이 벌어질까'는 격차를 부각해 메우고 싶게 만든다. 단 격차는 곡선형 — 너무 모호(건조)해도, 너무 구체(답을 다 말함)해도 클릭이 준다. 주제는 명확, 메커니즘은 궁금하게. | 정보격차 이론 (Loewenstein 1994, Psychological Bulletin 116:75–98); [Aubin Le Quéré & Matias 2025, *Sci. Reports*](https://www.nature.com/articles/s41598-024-81575-9) — Upworthy A/B 8,977건, 구체성↔클릭률 역U자 |
| 4 | **추상 개념 대신 구체·심상 장면으로** | '멀티태스킹'보다 즉시 그림이 그려지는 장면이 이해·기억(이중부호화)에 유리하고 '나와 상관있다'는 느낌을 준다. '게임'·'파일 열기'는 이미 좋은 장면명. | Duolingo 'Order in a Cafe', Brilliant 레슨명 'Storing Passwords'/'Video Compression'; 구체성 효과 (Paivio 이중부호화) |
| 5 | **여정형 'A에서 B까지'로 완주 가능성·범위 못박기** | 시작·도착점을 한 문장에 담으면 배울 범위가 생생해지고 '따라가면 끝까지 간다'는 완주 약속이 생겨 클릭 부담이 준다. 순서·인과가 핵심인 이 프로젝트에 딱 맞고, 부제가 이미 이 형태. | Nand2Tetris 'From NAND to Tetris', Ben Eater 'from scratch'; 프로젝트 자체 tag |
| 6 | **쉬운 말·짧게·핵심어 전방 배치로 '쉬워 보이게'** | 읽기 쉬우면 과제도 쉬워 보이고(처리유창성) 자기효능감이 올라 시도를 부른다. 전문어('멀티태스킹'·'스트리밍')를 일상어로, 첫 1~2단어가 내용을 암시하게. | Song & Schwarz 2008 (*Psych. Science* 19:10 "읽기 어려우면 하기도 어렵다"); NNG 헤딩 가이드(핵심어 전방·맥락 밖 자립·말장난 회피) |
| 7 | **차분한 호기심 레지스터 유지 + 여러 안 테스트** | '충격!·소름!·진짜 정체!!' 류 자극은 '아키텍처 도감'의 격을 떨어뜨리고, 질문 뒤 내용이 기대를 못 채우면 신뢰가 하락한다. 점잖은 호기심에 강도를 맞추고 한 번에 확정하지 말 것. | 클릭베이트 반작용·신뢰 하락 연구; Kurzgesagt·Brilliant의 제목 A/B 관행 |

## 제목 대안 15 — 현재 카드 전부

각 안은 **제목(클릭 욕구) + 부제(완주 약속)** 조합이다. 사용자가 직접 지목한
**부팅·절전·화면 녹화**에 특히 공들였다.

| 현재 | → 제안 제목 | 제안 부제 | 적용 원칙 |
|---|---|---|---|
| 부팅 | **전원 버튼을 누르면, 안에서 무슨 일이?** | 전원에서 로그인 화면까지, 컴퓨터가 깨어나는 순서 | 손동작 앵커 + 유보형 질문. 최고의 여정 문구는 부제로 유지 |
| 프로그램 실행 | **더블클릭 한 번에 프로그램이 뜨기까지** | 잠자던 코드가 SSD에서 CPU로 올라오는 길 | 손동작+여정, '한 번에'로 만만함 |
| 멀티태스킹 | **코어 몇 개로 어떻게 수백 개를 동시에?** | 한 CPU가 여러 일을 번갈아 처리하는 법 | 추상어 제거, 반전 감각을 제목으로 승격 |
| 게임 | **마우스를 클릭하면 화면 픽셀이 되기까지** | CPU와 GPU가 한 프레임을 그려내는 순서 | 좋은 장면명 유지 + 손동작 앵커 |
| 화면 녹화 | **지금 이 화면은 어떻게 영상 파일이 될까?** | 프레임버퍼의 픽셀이 저장 파일로 굳기까지 | '지금 이 화면'으로 독자의 현재를 앵커 |
| 파일 열기 | **내가 연 파일은 어디서 오는 걸까?** | SSD 셀에 잠든 데이터가 화면에 뜨기까지 | 암묵적 2인칭('내가 연') |
| 저장하기 | **Ctrl+S를 누르는 순간 무슨 일이?** | 메모리 버퍼의 데이터가 플래시에 새겨지기까지 | 가장 익숙한 손동작 + 유보, '새겨지기'로 물리성 |
| 게임 로딩 | **게임은 왜 로딩이 오래 걸릴까?** | 거대한 에셋이 SSD에서 화면까지 밀려오는 길 | 누구나 겪는 불만을 '왜 ~할까'로 |
| 인터넷 검색 | **엔터를 치면 신호는 어디까지 갔다 올까?** | 우리 집에서 데이터센터까지, 왕복 여정 | 손동작(엔터) + 공간 격차 |
| 동영상 스트리밍 | **버퍼링 막대 뒤에서는 무슨 일이?** | 쪼개진 패킷이 매끄러운 영상으로 이어지기까지 | 관측 가능한 대상('버퍼링 막대')에 묶기 |
| 화상통화 | **내 얼굴은 어떻게 지구 반대편에 닿을까?** | 카메라에서 상대방 화면까지 건너가는 길 | 2인칭 + 공간 격차 |
| 음악 재생 | **재생 버튼을 누르면 소리가 나기까지** | 파일 속 숫자가 스피커 진동이 되는 길 | 손동작 + '숫자가 진동으로' 반전 심상 |
| 키보드 입력 | **키를 누르면 왜 그 글자가 뜰까?** | 키 하나가 화면 글자가 되기까지 | 당연한 일을 '왜 ~할까'로 낯설게 |
| 절전과 복귀 | **노트북은 어떻게 1초 만에 깨어날까?** | 잠들 때 기억을 지키고 순식간에 되살아나는 법 | 가장 건조했던 카드. '1초 만에' 구체적 의외성으로 격차를 확 연다 |
| AI에게 질문 | **내 질문은 어떻게 답이 되어 돌아올까?** | 문장 한 줄이 GPU를 지나 답으로 돌아오기까지 | 2인칭 + 여정 의문형 |

## 하지 말 것

- **폭로형 '진짜 이유 / ~의 정체 / 사실은'** 남발 — 패턴 자체는 실증되나(과학드림 등) 차분한
  도감의 격을 떨어뜨린다. 절전·멀티태스킹에 붙이지 말 것.
- **15개 전부 질문형 도배** — 답이 기대를 못 채우면 신뢰가 하락한다(클릭베이트 반작용).
  여정형·장면형과 섞어 일부만 질문형으로.
- **답을 다 말해버리는 과도하게 구체적인 제목** — 격차가 닫혀 클릭이 오히려 준다(역U자).
- **영어권 감탄사·이모지 앵커**(부팅⚡ 게임🎮 절전😴) 이식 — 한국어에선 유치해지기 쉽다.
  문턱 낮추기 방향만 취하고 표현은 절제.
- **'5분 만에 / 3단계로'를 검증된 성과 공식처럼 확정 제시** — 이번 조사에서 특정 강좌 제목으로
  확인되지 않았다. 쓰더라도 개별 제목이 아니라 시리즈 배지 층에서 실험적으로만.
- **'충격·소름' 류 과장** — 애니메이션이 실제로 그 질문의 답을 단계별로 보여준다는 전제에서만
  질문을 던질 것(정직).

## 남은 확인거리

- 제안 제목이 각 시나리오의 **실제 애니메이션 내용과 일치**하는지(질문을 던졌으면 답을 실제로
  보여주는지) 카드별 대조 필요.
- 카드 UI가 2줄 이내라, 제안 제목의 **실제 글자 수·줄바꿈**을 렌더링해 확인하고 15개 톤을 통일.
- **질문형 / 여정형 / 장면형 비율** — 전부 질문형은 피하되 최적 배합은 실제 반응으로 검증 권장.
- '전공 지식 없어도, 한 카드씩 따라가며' 같은 **접근성 약속을 히어로/카테고리 층**에 배치할지 —
  개별 제목이 아니라 이 층이 '쉬워 보임'을 책임지는 게 안전(인프런 '만들면서 배우는' 계열).
- `home.js`의 ARCH_META 제목도 `wiki.js`와 **함께 일관되게** 갱신할지.
