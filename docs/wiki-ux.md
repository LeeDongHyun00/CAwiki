# 위키(아키텍처 도감) UX 개선 보고서

작성일 2026-08-27 · 방법: 3각도 병렬 리서치(학습 서비스 둘러보기 UX · 정보구조/카드·필터 UX ·
학습 동기·진행 연구) + 각 조사 출처 실재성 적대적 검증 + 종합. 핵심 출처는 작성자가 재확인.

> **범위 주의** — *제안* 문서다. 실제 구현은 별도 결정. 대상은 `wiki.html` · `lib/wiki.js` ·
> `assets/wiki.css`. 이 문서는 앞서의 [제목 개선 보고서](title-naming.md)와 같은 방식으로 작성됐다.

## 진단 — 현재 위키 UX의 약점 (코드 기준)

1. **진입점이 없다.** 15편이 카테고리별로 평면 나열될 뿐 '어디서 시작할지' 안내가 없다.
   비전공 학습자에게 평면 나열은 선택 과부하다 — Duolingo는 2022년 자유 스킬트리를 단일
   '패스'로 바꾸며 그 이유로 '선택 마비(choice paralysis)'를 명시했다.
2. **준비 중 11편이 라벨·어포던스 없이 디밍만 되어 있다.** 클릭 가능 여부를 예측할 수 없다.
   약한 시각 신호는 사용자를 불확실하게 만든다 — NNG 아이트래킹(Moran 2017, 71명): 약한
   신호 버전에서 작업시간 **+22%**, 시선 고정 **+25%**, "클릭·호버를 확신 없이" 하게 된다.
   게다가 준비 중 카드는 라벨 없는 `<div>`라 **스크린리더·키보드가 '비활성'임을 알 수 없다**(접근성 결함).
3. **라이브 4편의 클릭 어포던스도 약하다.** 화살표가 평소엔 흐려서(`ink-faint`) 호버 전엔
   '이게 눌리는구나'가 약하게 읽힌다. 위 NNG 근거가 그대로 적용된다.
4. **진행·완주 개념이 전무하다.** 공개된 4편은 '완주 가능한 작은 목표'인데, 어디까지 봤는지
   표시가 없어 그 동기를 못 살린다 — 목표 구배(goal-gradient), 인정된 진행(endowed progress).
5. **판단 단서(소요시간·수준)가 없다.** 다만 새 질문형 제목이 이미 강한 '정보 냄새
   (information scent)'를 주므로 이 약점은 상대적으로 가볍다.

## 개선안 (우선순위 · 구현비용)

### 🔴 높음 · 작음 — 지금 하면 좋은 것

**A. 준비 중 카드에 '상태 신호'를 (접근성 필수).**
지금은 디밍만 있어 왜 안 눌리는지 알 수 없고, 스크린리더엔 아예 안 알려진다.
- 최소: 준비 중 카드에 `aria-disabled="true"` + **시각적으로 숨긴 "준비 중" 텍스트**(화면엔 안
  보이나 스크린리더는 읽음), 그리고 키보드 포커스 대상에서 제외. → **화면 미관은 그대로 두고**
  접근성·어포던스만 고친다.
- 선택: 아주 절제된 시각 신호(예: 카드 모서리에 흐린 "곧" 한 글자, 또는 자물쇠 없는 점선 테두리).
  *단 사용자가 배지·라벨을 싫어했으므로, 시각 신호는 넣을지 말지 선택.* 접근성 텍스트는 미관과
  무관하니 넣기를 권장.
- 근거: NNG weak-signifier(Moran 2017); empty/coming-soon는 '왜 비었나 + 다음에 뭘'을 밝히라는
  empty-state 모범.

> **미학 ↔ UX 긴장 명시.** 앞서 요청대로 배지·카운트를 걷어내 미관은 좋아졌지만, 그 대가로
> '이건 못 누른다'는 신호까지 사라졌다. 절충은 **눈에는 안 보이되 스크린리더·키보드에는
> 존재하는 라벨** — 미관을 지키면서 '클릭되는 줄 알고 눌렀다 안 됨'을 막는다.

**B. 라이브 카드의 클릭 신호를 평소에도 조금 더 또렷이.**
화살표를 평소 `ink-faint` → 한 단계 진하게(예: `ink-soft`), 또는 라이브 카드에만 아주 옅은
상시 테두리 강조. 호버 전에도 '여긴 눌린다'가 읽히게. 비용 CSS 2~3줄. 근거: NNG 위 연구.

### 🟠 중간 · 작음

**C. "처음이라면 여기서" 가벼운 시작 앵커.**
히어로 밑이나 첫 공개 편(부팅)에 '처음이라면 여기서 시작' 한 줄. 15편 앞에서 '어디서 시작하지?'
마찰을 없앤다(Duolingo 선택 마비, freeCodeCamp의 '권장 순서+자유 탐색' 하이브리드).
- **주의(검증 지적):** 이 페이지는 이미 메인의 지도→투어를 거쳐 오므로 '시작' 강조가 중복일 수
  있다. 강한 별도 섹션 말고 **한 줄짜리 가벼운 힌트**로. '난이도 순서'라는 명분은 쓰지 말 것 —
  공개 4편은 서로 다른 4개 카테고리라 난이도 사다리가 아니다.

### 🟡 중간 · 중간 — 원하면

**D. '읽음' 표시(인정된 진행).**
공개 4편 중 연 편에 조용한 체크를 남긴다(localStorage). '0에서 시작'이 아니라 '이미 진행 중'으로
보이게 해 완주 동기를 높인다 — Nunes & Drèze(2006): 도장 2개 미리 찍은 쿠폰 상환율 **34% vs 19%**.
- **절제 필수(검증 지적):** 점수·배지·진행 바·완주 축하(confetti)는 넣지 말 것. SDT 연구상 외적
  보상은 내적 동기를 오히려 해치고 도감 톤을 깬다. '읽은 편에 옅은 체크' 정도의 **유능감 피드백**만.

### ⚪ 낮음 · 보류

- **카테고리별 '공개 n편' 카운트** — 어디에 실제 콘텐츠가 있는지 알려주지만, 사용자가 카운트를
  이미 제거했다. 넣는다면 아주 절제된 형태로, 낮은 우선순위.
- **소요시간·난이도 배지** — 질문형 제목이 이미 강한 scent라 이득이 작고, 배지는 미학상 회피 대상.
- **필터를 다중선택으로** — 15편(공개 4)엔 현재 단일선택으로 충분. 편수가 크게 늘면 재검토.

## 하지 말 것 (검증에서 걸러진 것)

- **진행 바·완주 축하·점수·배지·스트릭** — SDT상 내적 동기를 해치고 절제된 도감 톤을 깬다.
  (검증이 '진행 미터 + 완주 축하'를 tone-break 최고 위험으로 지목해 제외. 그 근거로 인용된
  'NNG 11~15%' 수치도 오귀속으로 확인돼 폐기.)
- **클라이언트 검색창** — 15편 규모엔 과하고 톤과 충돌.
- **'난이도 사다리' 순서 강제** — 공개 4편은 4개 다른 카테고리의 독립 시나리오다.
- **별도 '코스 스트립' 히어로 섹션** — 구조적 장식이 과하다. 필요하면 기존 카드에 옅은 ①–④ 번호
  정도의 가벼운 순서 힌트로.

## 남은 확인거리

- A의 '시각 신호를 넣을지'(접근성 텍스트는 권장, 시각 배지는 선택) — 미학 우선 vs 명료성 우선을
  사용자가 정해야 함.
- D의 '읽음 체크'가 이 페이지에 과한지 — 4편뿐이라 효과가 작을 수 있음. 편수가 늘 때 재평가.
- C의 시작 앵커가 메인 투어와 중복되지 않는 최소 형태 확정.
- 우선순위 A·B(접근성·어포던스)는 미학을 안 건드리고 이득이 확실하니, 원하면 바로 구현 가능.

## 출처 (검증 통과분)

- **NNG — Flat UI Elements Attract Less Attention and Cause Uncertainty** (Moran, 2017; 아이트래킹
  71명·9쌍, 약한 신호 → 작업시간 +22%·시선 +25%) — [nngroup.com](https://www.nngroup.com/articles/flat-ui-less-attention-cause-uncertainty/)
- **NNG — 3 Common IA Mistakes (Low Information Scent)** (Laubheimer, 2023) — 모호한 CTA·약한 정보 냄새
- **Nunes & Drèze (2006), *Journal of Consumer Research* 32(4):504–512** — 인정된 진행 효과(endowed
  progress), 세차 쿠폰 상환율 34% vs 19%
- **Duolingo (2022)** — 자유 스킬트리 → 단일 패스 전환, 사유 '선택 마비'
- **Huang et al. (2024), *ETR&D*** (DOI 10.1007/s11423-023-10337-7) — 게이미피케이션과 내적 동기(절제 근거)
- 실무 사례: Coursera·Codecademy 카탈로그 카드(난이도·소요시간 노출), freeCodeCamp(권장 순서+자유 탐색)

> 검증에서 **폐기**: 진행 미터의 'NNG 11~15%' 수치(오귀속), 클라이언트 검색창·난이도 사다리·
> 코스 스트립 섹션(과잉·톤 파괴). 종합 에이전트가 스키마 오류로 실패해, 이 보고서는 작성자가
> 6개 완료 에이전트(리서치 3+검증 3)의 저널을 직접 읽어 종합했다.
