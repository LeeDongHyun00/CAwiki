# 데이터센터
*Data Center*

> 수많은 서버·스토리지·네트워크 장비를 랙에 집적하고, 전력·냉각·네트워크를 이중화로 받쳐서 인터넷 서비스를 24시간 무중단으로 돌리는 거대한 '컴퓨터 건물'.

**분류**: 네트워크

---

## 🧭 한마디로, 무슨 일을 하나
데이터센터는 우리가 검색·스트리밍·게임 매칭·AI 질문을 할 때 그 계산과 저장을 실제로 떠맡는 곳이다. 개인용 PC 한 대가 아니라 수천~수십만 대의 평범한 서버를 한 건물에 모아 초고속 네트워크로 엮고, 가상화·오케스트레이션 소프트웨어로 하나의 거대한 자원 풀처럼 빌려 쓴다. 핵심 임무는 '연산(서버)·저장(스토리지)·전달(네트워크)'을 제공하면서 동시에 전력·냉각·물리 보안을 무중단으로 유지하는 것이다. 즉 데이터센터의 진짜 제품은 IT 성능이 아니라 '가용성(멈추지 않음)'이며, 진정한 무중단은 한 건물 안의 이중화뿐 아니라 여러 데이터센터(지역·가용영역)로 분산해야 완성된다.

## ⚙️ 작동 방식

**1. 요청이 건물 입구(경계 네트워크)에 도착한다**

사용자의 패킷은 GeoDNS와 Anycast/BGP 라우팅을 거쳐 가장 가깝고 여유 있는 데이터센터로 유도된다. 건물 가장자리의 경계 라우터(border/edge router)가 인터넷 백본으로부터 트래픽을 받아 내부망으로 넘기고, 이 경계에서 DDoS 방어·필터링도 이뤄진다. 왜 이렇게 하냐면, 한 곳에 몰리면 지연이 커지고 장애 시 전체가 멈추기 때문에 입구부터 트래픽을 분산·선별한다.

**2. 로드밸런서가 '어느 서버가 받을지'를 고른다**

요청은 하나의 대표 주소(VIP, 가상 IP)로 들어오지만 뒤에는 똑같은 일을 하는 서버가 수십~수천 대 있다. 로드밸런서는 헬스체크로 살아있는 서버만 골라 그중 한 대에 요청을 넘긴다(라운드로빈·최소연결 등). L4(IP·포트 기준)는 빠르게 흘려보내고, L7(HTTP 내용 기준)은 URL·쿠키를 보고 더 똑똑하게 배분한다. 이렇게 해야 한 서버가 죽어도 사용자는 눈치채지 못한다.

**3. 리프-스파인 네트워크를 타고 목적지 랙까지 간다**

선택된 서버가 다른 랙에 있으면 트래픽은 리프 스위치(각 랙 위의 ToR) → 스파인 스위치(중앙 백본) → 다른 랙의 리프로 흐른다(같은 랙 안이면 스파인을 거치지 않고 리프에서 1홉으로 끝난다). 이 Clos 구조에서는 '다른 랙 간'이면 항상 같은 홉 수라 지연이 균일하고, 링크 여러 개로 부하를 나눠(ECMP) 대량의 '서버 ↔ 서버(east-west)' 트래픽을 막힘없이 처리한다. 초대형 데이터센터는 여기에 3단째(super-spine)를 얹어 여러 파드(pod)를 잇는다.

**4. ToR 스위치가 랙 안 서버의 NIC로 전달한다**

랙 맨 위의 ToR(Top of Rack) 스위치는 그 랙 안 서버 수십 대를 짧은 구리/DAC 케이블(고속 구간은 광 트랜시버)로 묶는다. 목적지 서버의 NIC(네트워크 카드)가 패킷을 받아 PCIe 버스를 통해 CPU·RAM으로 올린다. NIC가 체크섬·세그먼트 분할 같은 잡일을 대신 처리(offload)하고, DPU/스마트NIC를 쓰면 가상 스위칭·암호화·스토리지 접속까지 떠맡아 CPU가 진짜 연산에만 집중하게 한다.

**5. 서버의 CPU·RAM이 실제 계산을 하고 필요하면 스토리지를 읽는다**

듀얼 소켓 CPU와 수백 GB~수 TB RAM이 요청을 처리한다. 데이터가 메모리에 없으면 계층화된 스토리지에서 가져온다: 가장 빠른 로컬 NVMe SSD → 네트워크로 붙은 올플래시/분산 스토리지 → 느리지만 싼 HDD·아카이브. '자주 쓰는 뜨거운 데이터는 빠른 층, 가끔 쓰는 차가운 데이터는 싼 층'으로 두는 이유는 속도와 비용을 동시에 맞추기 위해서다.

**6. 상태를 바꾸는 '쓰기'라면 여러 복제본에 안전히 기록한 뒤에야 완료로 답한다**

검색처럼 읽기만 하는 요청과 달리, 결제·문서 저장 같은 쓰기는 데이터를 잃으면 안 된다. 그래서 분산 스토리지·데이터베이스는 같은 데이터를 여러 노드(때로는 여러 가용영역)에 복제하거나 이레이저 코딩으로 조각내 저장하고, 정족수(quorum)가 기록을 확인한 뒤에야 '완료'로 응답한다. 이 지속성(durability) 절차 덕분에 서버 한 대나 디스크가 죽어도 데이터는 살아남는다.

**7. AI 질문이면 가속기 클러스터가 병렬로 달라붙는다**

일반 CPU로는 벅찬 대형 모델 추론·학습은 GPU/TPU 클러스터로 넘어간다. 한 노드(HGX 보드) 안 8개 GPU는 NVLink/NVSwitch로 직결되고, GB200 NVL72 같은 신형은 랙 전체 72개 GPU를 하나의 NVLink 도메인으로 묶는다. 노드와 노드는 InfiniBand(또는 이더넷 위 RoCE)로 낮은 지연·RDMA로 이어진다. 모델이 GPU 한 장에 안 들어가므로 여러 GPU가 각자 조각을 맡아 HBM(초고대역폭 메모리)에서 데이터를 쏟아내며 동시에 계산하고, all-reduce 같은 집합 통신으로 결과를 맞춘다.

**8. 결과가 역방향으로 조립되어 사용자에게 돌아간다**

서버가 만든 응답(HTML·JSON·영상 청크 등)은 왔던 길을 거꾸로 타고 NIC → ToR → 스파인 → 로드밸런서 → 경계 라우터 → 인터넷으로 나간다. 사용자 화면에는 수십 ms 만에 결과가 뜨지만, 그 안에서는 방금의 여러 단계를 모두 왕복한 것이다.

**9. 이 모든 시간 동안 전력·냉각이 끊기지 않게 받친다**

서버가 일하는 내내 전기가 필요하다. 평소엔 전력회사 전기를 쓰다가 정전이 나면 UPS(무정전 전원장치) 배터리(또는 플라이휠)가 순간의 공백을 즉시 메우고, 그 사이 디젤 발전기가 기동한다(비상전원 규격 NFPA 110은 약 10초 이내 정격 도달·부하 수용을 요구). 동시에 서버가 뿜는 열은 콜드 아일(찬 공기 흡입) → 서버 → 핫 아일(더운 공기 배출) → 냉수 코일/칠러로 빠져나간다. A/B 두 계통으로 전원·냉각을 이중화해 어느 한쪽이 고장 나도 계산은 멈추지 않는다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **랙(Rack)과 랙유닛(U)** | 장비를 세로로 꽂는 19인치 표준 골격. 높이를 1U(약 44.45 mm) 단위로 세며 보통 42U 한 개당 서버·스위치 수십 개를 담는다. 케이블·전원·냉각을 랙 단위로 표준화해 관리한다. |
| **서버(다소켓 CPU · 대용량 RAM · NIC)** | 실제 연산을 하는 알맹이. 보통 듀얼 소켓 CPU(합쳐 수십~수백 코어), 수백 GB~수 TB DDR5 RAM, 하나 이상의 고속 NIC를 얇은 1U~2U 섀시에 담는다. 여러 대가 모여 하나의 자원 풀처럼 쓰인다. |
| **NIC(Network Interface Card)** | 서버를 네트워크에 연결하는 카드. 25/100/200/400 GbE 같은 고속 링크로 ToR 스위치와 이어지며, 패킷 처리 일부를 CPU 대신 떠맡는다(오프로드). AI용은 RDMA를 지원한다. |
| **DPU / 스마트NIC(SmartNIC)** | NIC를 넘어 자체 CPU·가속 엔진을 얹은 '네트워크 위의 작은 컴퓨터'. 가상 스위칭·방화벽·암호화·스토리지 접속 같은 인프라 일을 호스트 CPU 대신 처리해 성능·보안·격리를 끌어올린다(NVIDIA BlueField, AWS Nitro 등). |
| **ToR 스위치(Top of Rack)** | 랙 맨 위에 놓여 그 랙 안 서버 전부를 묶는 액세스 스위치. 짧은 케이블로 서버를 모으고, 위쪽 스파인으로 올려보내는 첫 관문이다. 리프-스파인 구조에서 '리프' 역할을 겸한다. |
| **스파인 스위치 / 리프-스파인 패브릭** | 모든 리프(ToR)를 서로 이어주는 중앙 백본. 리프↔스파인이 촘촘히 연결돼 다른 랙 간에는 같은 홉 수로 도달하며, 대규모 서버 간 트래픽을 막힘없이 흘린다. 초대형은 super-spine을 얹어 3단으로 확장한다. |
| **로드밸런서(Load Balancer)** | 들어오는 요청을 살아있는 서버들에 고르게 분배하는 교통정리 장치. 대표 주소(VIP) 하나로 받아 뒤의 서버 풀로 나누고, 헬스체크로 죽은 서버는 자동 제외해 무중단을 만든다. L4/L7 두 층위로 동작한다. |
| **스토리지 계층(Storage Tier)** | 데이터를 속도·비용에 따라 층으로 나눠 보관. 로컬 NVMe SSD(핫) → 올플래시/분산 스토리지(웜) → HDD·테이프 아카이브(콜드) 순으로, 블록·파일·오브젝트 형태로 서버에 제공한다. 내구성을 위해 복제·이레이저 코딩으로 여러 벌을 둔다. |
| **AI 가속기 클러스터(GPU/TPU)** | 대규모 병렬 연산 전담. 한 노드에 GPU/TPU 여러 개와 HBM을 얹고, 노드 안은 NVLink, 노드 간은 InfiniBand/RoCE로 엮어 하나의 거대한 계산기처럼 학습·추론을 나눠 처리한다. |
| **NVLink · InfiniBand 인터커넥트** | 가속기끼리 데이터를 초고속·저지연으로 주고받는 전용 배선/망. NVLink(NVSwitch 포함)는 GPU 직결(신형은 랙 전체를 한 도메인으로), InfiniBand(또는 RoCE)는 서버를 넘는 RDMA 통신을 담당한다. |
| **UPS(무정전 전원장치)** | 정전 순간 배터리(또는 플라이휠)로 전력을 즉시 이어받아 수 초~수 분을 버틴다. 발전기가 기동해 안정될 때까지의 '공백'을 메워 서버가 꺼지지 않게 한다. |
| **비상 발전기(디젤 제너레이터)** | 장시간 정전에 대비한 자체 발전소. 정전 감지 후 대략 10초 안팎(NFPA 110 기준)에 부하를 받아 연료가 있는 한 건물 전체 전력을 공급한다. UPS와 짝을 이뤄 전력 이중화를 완성한다. |
| **배전 계통(스위치기어 · PDU · 서버 PSU)** | 전기를 서버까지 나눠주는 사슬. 고압을 받아 스위치기어가 분배하고, 랙 PDU(전원분배장치)가 A/B 두 계통으로 각 서버에 꽂아준다. 서버 PSU가 최종적으로 12V DC로 바꾸며, 고밀도 AI 랙은 48V DC 랙버스나 고압 직류(HVDC)를 쓰는 추세다. |
| **냉각 시스템(핫/콜드 아일 · CRAC/CRAH · 칠러 · 냉수)** | 서버 열을 밖으로 내보내는 순환계. 콜드 아일로 찬 공기를 넣고 핫 아일로 더운 공기를 모아, 냉수(chilled water) 코일과 칠러·냉각탑으로 열을 버린다. 고밀도 랙은 칩에 직접 붙는 직수랭(cold plate)·액침(immersion)을 쓴다. |
| **상면(Raised Floor)과 케이블·배관** | 장비를 놓는 바닥 공간. 전통적 이중 바닥(raised floor) 아래로 냉기·전원·케이블을 흘려보내며(고밀도 신설은 슬래브 바닥+오버헤드 배선도 많다), 상면 임대·설계가 데이터센터 용량의 기본 단위가 된다. |
| **관리·모니터링(DCIM · BMS · OOB)** | 건물의 신경계. DCIM/BMS가 전력·온도·습도를, 서버의 BMC(대역외 관리, OOB)가 개별 하드웨어 상태를 상시 감시해 고장을 조기에 잡고 원격으로 대응한다. |
| **경계 라우터(Border/Edge Router)** | 데이터센터와 인터넷 백본이 만나는 건물 가장자리의 라우터. BGP/Anycast로 트래픽을 받아 내부망(로드밸런서·리프-스파인)으로 넘기고 응답을 다시 인터넷으로 내보내며, 이 경계에서 DDoS 방어·필터링을 수행하는 North-South 트래픽의 첫·마지막 관문이다. 문서의 작동 방식 1·8단계에서 핵심 역할로 등장하지만 주요 부품 표에는 빠져 있다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **U (Rack Unit, 랙유닛)** | 랙 높이의 표준 단위. 1U = 약 44.45 mm(1.75인치). '1U 서버', '42U 랙'처럼 장비와 랙 용량을 세는 기준이다. |
| **ToR (Top of Rack)** | 랙 맨 위에 두는 스위치. 그 랙 안 모든 서버를 짧은 케이블로 묶어 상위 네트워크로 올려보내는 첫 스위치다. |
| **리프-스파인 (Leaf-Spine / Clos)** | 리프(액세스)들이 모든 스파인(백본)에 연결된 그물형 구조. 다른 랙 간에는 동일한 홉 수·균일한 지연으로 통신한다. 규모가 커지면 super-spine을 더한 3단(fat-tree)으로 확장한다. |
| **East-West / North-South 트래픽** | North-South는 사용자↔데이터센터(밖↔안) 트래픽, East-West는 데이터센터 안 서버↔서버 트래픽. 현대 데이터센터는 East-West가 압도적으로 많아 리프-스파인이 필요해졌다. |
| **로드밸런서 (Load Balancer, L4/L7)** | 요청을 여러 서버에 나눠주는 장치. L4는 IP·포트만 보고 빠르게, L7은 HTTP 내용(URL·쿠키)까지 보고 배분한다. VIP(가상 IP) 하나 뒤에 서버 풀을 숨긴다. |
| **가상화 · 오케스트레이션 (VM · 컨테이너 · Kubernetes)** | 물리 서버 무리를 하나의 자원 풀로 만드는 소프트웨어 계층. 하이퍼바이저가 서버를 여러 가상머신(VM)으로 쪼개고, 컨테이너·쿠버네티스가 워크로드를 어느 서버에 올릴지(스케줄링) 자동으로 배치·회복시킨다. '클라우드'로 빌려 쓸 수 있는 근본 이유. |
| **지역 · 가용영역 (Region / Availability Zone)** | 지리적 이중화 단위. 리전은 도시권 규모의 데이터센터 묶음, AZ는 전원·냉각·네트워크가 독립된 개별(또는 소수) 데이터센터. 한 AZ가 통째로 죽어도(화재·홍수·정전) 다른 AZ가 떠맡도록 서비스를 여러 AZ에 분산한다. |
| **이중화 (Redundancy: N+1 · 2N)** | 여분을 두어 하나가 죽어도 계속 도는 설계. N+1은 필요한 만큼(N)에 예비 1개 추가, 2N은 완전히 두 벌을 두는 방식(전원 A/B 계통이 대표적). |
| **가용성 / 나인(Nines) · Tier** | 얼마나 안 멈추는가의 지표. 99.99%(포 나인)는 연 약 52.6분, 99.999%(파이브 나인)는 연 약 5.26분 다운타임. Uptime Institute의 Tier I~IV는 설비의 '토폴로지·동시 유지보수·내결함' 등급이며, 특정 가동률(%)을 보장하는 규격은 아니다(흔히 인용되는 99.982%/99.995%는 참고치). |
| **데이터 내구성 (Durability: 복제 · 이레이저 코딩)** | 저장한 데이터를 잃지 않을 확률. 같은 데이터를 여러 노드·AZ에 복제하거나 이레이저 코딩(예: 데이터 조각 + 패리티 조각)으로 나눠 둔다. 대형 클라우드 오브젝트 스토리지는 대략 99.999999999%(11 나인)급 내구성을 목표로 한다. |
| **UPS (Uninterruptible Power Supply, 무정전 전원장치)** | 정전 순간 배터리(또는 플라이휠)로 전력을 끊김 없이 이어받는 장치. 발전기가 기동할 때까지의 짧은 공백을 메운다. |
| **핫 아일 / 콜드 아일 (Hot/Cold Aisle)** | 서버 앞줄(찬 공기 흡입)과 뒷줄(더운 공기 배출)을 통로 단위로 분리·격리하는 냉각 배치. 찬 공기와 더운 공기가 섞이지 않게 해 효율을 높인다. |
| **PUE (Power Usage Effectiveness)** | 데이터센터 총 전력 ÷ IT 장비 전력. 냉각·배전 손실 같은 '오버헤드'만 재는 지표로, 1.0에 가까울수록 낭비가 적다(IT 자체 효율은 측정하지 않으며, 1.0 미만은 원칙적으로 불가). 우수 설비 1.1~1.2, 업계 평균은 대략 1.5 안팎. |
| **NVLink / NVSwitch** | GPU끼리를 초고대역폭으로 직결하는 전용 인터커넥트. NVSwitch로 한 노드 내 8개(신형 NVL72는 랙 전체 72개) GPU를 마치 큰 하나처럼 묶어 메모리·데이터를 빠르게 공유한다. |
| **InfiniBand · RDMA · RoCE** | InfiniBand는 서버를 넘는 저지연 초고속 망. RDMA(원격 직접 메모리 접근)로 CPU를 거의 거치지 않고 메모리끼리 데이터를 옮긴다. RoCE는 이 RDMA를 이더넷 위에서 하는 방식. |
| **HBM (High Bandwidth Memory, 초고대역폭 메모리)** | GPU/가속기 바로 옆에 쌓아 붙인 메모리. 초당 수 TB의 데이터를 공급해 대규모 병렬 연산이 굶지 않게 한다. 현재 HBM3e가 주력이며 HBM4가 도입되는 단계(2026~). |
| **스토리지 계층화 (Hot/Warm/Cold Tiering)** | 데이터를 접근 빈도에 따라 빠른 층(NVMe)~싼 층(HDD·테이프)으로 나눠 두는 전략. 속도와 비용을 동시에 만족시킨다. |
| **냉수 (Chilled Water) / CRAC·CRAH / 직수랭·액침** | 칠러가 차게 만든 물을 코일로 순환시켜 서버 열을 흡수하는 냉각 방식. CRAC/CRAH는 전산실 공조기로 냉기를 콜드 아일에 뿜는다. 고밀도 AI 랙은 칩에 물을 직접 대는 직수랭(cold plate)이나 액체에 담그는 액침 냉각을 쓴다. |

## ⚠️ 흔한 오해

- **오해** — 데이터센터는 그냥 '엄청 좋은 컴퓨터 한 대'다.
  <br>**교정** — 한 대의 슈퍼컴이 아니라 평범한 서버 수천~수십만 대를 네트워크로 엮은 집합이다. 힘의 원천은 개별 성능이 아니라 '수평 확장(대수를 늘리는 것)'과 이중화다.
- **오해** — 서버가 한 대 죽으면 서비스가 멈춘다.
  <br>**교정** — 로드밸런서와 이중화 설계 덕분에 한 대(심지어 랙·전원 한 계통)가 죽어도 다른 자원이 즉시 떠맡아 사용자는 보통 알아채지 못한다. '멈추지 않음'이 데이터센터의 핵심 설계 목표다.
- **오해** — 데이터센터 한 곳만 튼튼하면 무중단이다.
  <br>**교정** — 한 건물은 화재·홍수·정전·광케이블 절단으로 통째로 죽을 수 있다. 진짜 무중단은 여러 데이터센터(가용영역·리전)에 데이터와 트래픽을 분산해야 완성되며, 그래서 클라우드는 서비스를 여러 AZ에 걸쳐 배치한다.
- **오해** — 냉방(에어컨)만 잘 틀면 냉각은 끝이다.
  <br>**교정** — 핵심은 온도 자체보다 '찬 공기와 더운 공기를 안 섞는 것'이다. 핫/콜드 아일 격리, 냉수 순환, 고밀도에선 칩 직결 액랭까지 동원한다. 냉각은 IT 전력에 맞먹을 수 있는 큰 에너지 항목(PUE로 측정)이다.
- **오해** — 정전이 나면 배터리(UPS)로 계속 버틴다.
  <br>**교정** — UPS는 몇 초~몇 분짜리 '다리'일 뿐이다. 장시간 정전은 디젤 발전기가 기동해 떠맡는다. UPS는 발전기가 올라오는 그 짧은 공백을 메우는 역할이다.
- **오해** — PUE가 낮으면 그 데이터센터가 IT적으로도 효율적이다.
  <br>**교정** — PUE는 냉각·배전 같은 '설비 오버헤드'만 재는 지표로, 서버가 그 전력으로 실제로 얼마나 유용한 일을 하는지는 말해주지 않는다. 1.0 미만도 원칙적으로 불가능하다(폐열 재활용을 회계적으로 반영한 경우 제외).
- **오해** — AI GPU들은 일반 이더넷으로 이어져 있다.
  <br>**교정** — AI 클러스터는 지연이 성능을 좌우하므로 노드 안은 NVLink, 노드 간은 InfiniBand(또는 RoCE)로 RDMA 저지연 전용망을 쓴다. 수백~수천 GPU가 한 문제를 나눠 풀 때 이 인터커넥트와 HBM 대역폭이 병목을 좌우한다.
- **오해** — 클라우드는 물리 서버가 없는 '가상' 공간이다.
  <br>**교정** — 클라우드도 결국 어딘가의 데이터센터에 있는 진짜 서버·랙·전원·냉각 위에서 돈다. '클라우드'는 그 물리 자원을 가상화·오케스트레이션으로 추상화해 빌려 쓰게 만든 서비스 계층일 뿐이다.
- **오해** — 리프-스파인은 그냥 스위치를 층층이 쌓은 것이다.
  <br>**교정** — 단순 계층이 아니라 모든 리프가 모든 스파인에 연결된 촘촘한 그물(Clos)이다. 그래서 다른 랙 간이면 어느 경로로 가도 홉 수가 같고, 여러 경로로 부하를 분산해 서버 간 대량 통신을 막힘없이 처리한다.

## 💡 비유

거대한 '아파트 단지형 사무실'로 보면 쉽다. 랙은 캐비닛, 서버는 그 안 책상에 앉은 직원, ToR 스위치는 각 층의 내선 교환기, 리프-스파인은 모든 층을 잇는 중앙 복도, 로드밸런서는 민원인을 빈 창구로 안내하는 안내데스크다. 그리고 정전에도 불이 안 꺼지도록 UPS(비상 배터리)와 자가 발전기를 갖추고, 사람이 많은 사무실이 더우면 냉방을 돌리듯 핫/콜드 아일로 열을 뺀다. 게다가 이 '사무실 건물'은 한 채가 아니라 도시마다 여러 채(리전·가용영역)를 두어, 한 건물이 정전·화재로 닫혀도 다른 건물이 업무를 이어받는다. 또 다른 비유로, 데이터센터는 '주방이 수천 개인 초대형 프랜차이즈 본사'다. 손님(요청)이 오면 배차 담당(로드밸런서)이 한가한 주방(서버)에 주문을 넘기고, 재료 창고는 자주 쓰는 건 손 닿는 냉장고(NVMe), 안 쓰는 건 지하 창고(HDD·테이프)에 계층별로 둔다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 인터넷 검색 왕복: 엔터를 치면 패킷이 DNS를 거쳐 데이터센터의 경계 라우터 → 로드밸런서 → 리프-스파인 → 서버 → 스토리지를 왕복해 검색 결과를 만들어 돌려보낸다(CAwiki search 시나리오의 '데이터센터' 존이 바로 이 장면).
- AI 질문: 챗봇에 질문을 던지면 데이터센터의 GPU/TPU 클러스터가 NVLink·InfiniBand로 협력해 대형 모델을 병렬로 돌려 답을 생성한다.
- 영상 스트리밍: 재생 버튼을 누르면 데이터센터(또는 CDN 엣지)의 스토리지에서 영상 청크를 꺼내 로드밸런서·네트워크를 통해 끊김 없이 흘려보낸다.
- 게임 렌더링/매칭: 온라인 게임의 매칭·서버 로직·리더보드는 데이터센터 서버에서 돌아가고, 클라우드 게이밍이면 렌더링까지 데이터센터 GPU가 대신한다.
- 파일 열기 · Ctrl+S 저장(클라우드): 클라우드 드라이브의 문서를 열거나 저장하면, 실제 읽고 쓰는 대상은 데이터센터의 분산 스토리지 계층이며 여러 복제본(또는 여러 가용영역)에 안전히 기록된 뒤에야 저장이 완료된다.
- 부팅 후 로그인·동기화: 기기를 켜고 계정에 로그인하면 인증·설정 동기화 요청이 데이터센터의 서버로 가서 처리되고 응답이 돌아온다.
