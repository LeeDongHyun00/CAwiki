# SSD (솔리드 스테이트 드라이브)
*Solid State Drive (SSD)*

> 회전 원판·헤드 같은 움직이는 부품 없이, NAND 플래시 셀에 전하를 가둬 데이터를 기록·유지하는 비휘발성 반도체 저장장치.

**분류**: 저장장치

---

## 🧭 한마디로, 무슨 일을 하나
SSD는 전원이 꺼져도 데이터를 유지하는 컴퓨터의 영구 저장 계층(보조기억장치)이다. OS·프로그램·파일이 평소 잠들어 있는 곳으로, CPU가 다룬 데이터는 결국 RAM을 거쳐 SSD로 내려가고 필요할 때 다시 RAM으로 끌어올려진다. HDD와 달리 기계적 탐색(seek)이 없어 접근 지연이 수백 배 짧고, 이 속도가 부팅·앱 실행·파일 열기·게임 로딩의 체감 속도를 좌우한다. 다만 플래시는 '덮어쓰기 불가·블록 단위 소거'라는 독특한 제약이 있고 전하가 시간이 지나면 새어 나가므로, 컨트롤러 펌웨어(FTL)가 이 제약과 마모·오류를 감춰 일반 디스크처럼 보이게 만드는 것이 SSD의 본질이다.

## ⚙️ 작동 방식

**1. 호스트 명령 접수 — NVMe 큐와 도어벨**

OS가 파일시스템을 통해 'LBA(논리 블록 주소) 몇 번을 읽어라/써라'를 정하면, NVMe 드라이버는 이 명령을 시스템 RAM의 제출 큐(Submission Queue)에 넣고 SSD의 도어벨 레지스터를 울려 알린다. 컨트롤러는 PCIe로 명령을 DMA로 가져온다. 큐의 개수와 큐 깊이가 모두 커 여러 요청이 동시에 몰릴 수 있는데, 이 병렬성이 SSD 고성능의 출발점이다.

**2. FTL 주소 변환 — 논리를 물리로**

컨트롤러는 호스트가 준 LBA를 실제 NAND의 물리 위치(다이·블록·페이지)로 바꿔야 한다. 플래시는 같은 자리에 덮어쓸 수 없어 논리 주소와 물리 위치가 고정 대응하지 않기 때문에, FTL(Flash Translation Layer) 펌웨어가 매핑 테이블(주로 DRAM 캐시에 상주)을 조회·갱신해 둘을 연결한다. 이 추상화 덕분에 OS는 SSD를 평범한 블록 디스크로 취급할 수 있다.

**3. 읽기 — pass 전압·문턱전압 판독·read retry·오류정정**

읽기라면 대상 페이지의 워드라인에 기준 읽기 전압을, 같은 NAND 스트링의 나머지 셀에는 무조건 켜지는 높은 pass 전압(Vpass)을 걸어 스트링 전체의 도통 여부로 대상 셀만 판독한다. 셀이 전류를 흘리면(=가둔 전하가 적어 문턱전압이 기준보다 낮으면) 한쪽 비트, 아니면 다른 쪽으로 읽힌다. TLC/QLC는 여러 전압 구간을 촘촘히 구분해야 해 미세한 전하 이동·간섭도 오류가 되는데, 어긋나면 기준 전압을 조금씩 옮겨 다시 읽는 read-retry와 ECC 엔진(LDPC)이 정정해 원래 데이터를 복원한 뒤 채널로 올려보낸다.

**4. 쓰기 — 버퍼를 거쳐 빈 페이지에 프로그램(덮어쓰기 불가, ISPP)**

쓰기라면 데이터를 먼저 빠른 버퍼(SLC 캐시/DRAM)에 받고, NAND에서는 이미 지워진(모두 1인) 빈 페이지를 골라 전자를 선택적으로 주입해 0을 새긴다(프로그램). 목표 문턱전압에 정확히 맞추려 전압을 조금씩 올리며 확인-재시도하는 ISPP(Incremental Step Pulse Programming)를 쓴다. 기존 위치를 고칠 수 없으므로 항상 새 페이지에 기록하고(out-of-place), 옛 페이지는 '무효(invalid)'로 표시한 뒤 FTL 매핑을 새 위치로 갱신한다. 이 out-of-place 방식이 뒤이은 가비지 컬렉션을 필요하게 만든다.

**5. 다채널·다이·플레인 병렬 인터리빙**

NAND 한 다이의 프로그램은 느리지만(수백 µs~수 ms), 컨트롤러는 8~16개 채널에 여러 다이·플레인을 붙여 동시에 굴린다. 한 다이가 프로그램하는 동안 다른 다이로 다음 데이터를 보내는 식으로 작업을 겹쳐(인터리빙) 개별 소자의 느림을 수~십수 GB/s의 대역폭으로 메운다. SSD 속도가 용량·구성(채널·다이 수)에 비례해 커지는 이유다.

**6. 가비지 컬렉션 — 블록 단위 소거를 위한 청소**

무효 페이지가 블록마다 쌓이면 쓸 공간이 마른다. 소거는 오직 블록 단위로만 가능하므로, GC는 유효 페이지가 적게 남은 '희생 블록'을 골라 그 안의 살아있는 페이지만 다른 블록으로 옮긴 뒤 통째로 소거해 빈 블록으로 되돌린다. 이때 호스트가 요청하지 않은 추가 쓰기가 생겨 쓰기 증폭(Write Amplification)이 발생한다.

**7. 웨어 레벨링 — 마모 균등화**

셀은 프로그램/소거(P/E)를 반복하면 절연막이 손상돼 수명이 유한하다. 컨트롤러는 특정 블록만 닳지 않도록 쓰기를 골고루 분산하고(동적 웨어 레벨링), 거의 바뀌지 않는 '차가운 데이터'가 어린 블록을 차지하면 일부러 옮겨(정적 웨어 레벨링) 전체 마모를 평준화한다. 그래서 전체 셀 수명을 최대한 길게 쓴다.

**8. TRIM — 호스트가 알려주는 '이건 쓰레기'**

파일을 지워도 SSD는 그 데이터가 유효한지 스스로 알 수 없어, GC 때 쓸데없이 복사할 수 있다. OS가 TRIM(NVMe Deallocate/DSM, ATA TRIM) 명령으로 '이 LBA들은 이제 안 쓴다'고 알려주면 SSD는 해당 페이지를 즉시 무효로 처리해, GC 복사량과 쓰기 증폭을 줄이고 성능·수명을 지킨다.

**9. 완료 보고 — 완료 큐와 인터럽트**

작업이 끝나면 컨트롤러는 완료 큐(Completion Queue)에 결과를 쓰고 인터럽트(MSI-X)로 호스트에 알린다. 드라이버가 이를 회수하면 하나의 읽기/쓰기 왕복이 마무리된다. 랜덤 읽기 지연은 대략 수십 µs 수준으로, 회전 디스크(수 ms)보다 수백 배 빠르다.

**10. 백그라운드 미디어 관리 — 보존·읽기 방해 대응**

요청 처리와 별개로, 컨트롤러는 유휴 시간에 셀 건강을 관리한다. 전하 누설(retention loss)·읽기 방해(read disturb)로 오류율이 오른 블록의 데이터를 새 블록으로 옮겨 다시 쓰고(refresh/scrubbing), 배드 블록을 격리하며, 미리 빈 블록을 확보하고(백그라운드 GC), 과열 시 속도를 낮춘다(스로틀링). 이 보이지 않는 관리가 장기 신뢰성과 꾸준한 성능을 유지한다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **NAND 플래시 셀 (플로팅 게이트/CTF 트랜지스터)** | 데이터를 저장하는 최소 단위. 절연된 도체 게이트(플로팅 게이트)나 절연체 전하 포집층(CTF)에 전자를 가둬 트랜지스터의 문턱전압을 바꿔 비트를 기억한다. 전원이 없어도 전하가 남아 비휘발성이지만, 전하는 시간이 지나면 서서히 새어 나간다. |
| **NAND 플래시 다이·패키지** | 셀이 페이지·블록·플레인 계층으로 조직된 실제 메모리 칩. 다이 안에는 셀을 읽고 쓰는 동안 데이터를 담는 페이지 버퍼(센스앰프/페이지 레지스터)가 있다. 여러 다이를 한 패키지에 쌓고, 보드에 여러 패키지를 얹어 용량을 만든다. 최신은 셀을 수직으로 쌓은 3D NAND(200단 이상). |
| **SSD 컨트롤러 (SoC)** | SSD의 두뇌. 대개 멀티코어 ARM 프로세서로, FTL 매핑·ECC·웨어 레벨링·가비지 컬렉션·큐 관리·암호화를 모두 실행한다. 채널 병렬성을 조율해 성능을 뽑아낸다. |
| **다채널 플래시 인터페이스** | 컨트롤러와 NAND를 잇는 8~16개의 병렬 채널(ONFI/Toggle DDR 규격). 여러 다이를 동시에 굴려 개별 소자의 느림을 대역폭으로 만회한다. |
| **DRAM 캐시** | FTL 매핑 테이블과 쓰기 버퍼를 담는 고속 임시 메모리. 페이지 단위 매핑 기준 대략 용량 1TB당 1GB DRAM 비율. DRAM-less 제품은 이를 생략하고 HMB(호스트 RAM 일부)로 대체한다. |
| **FTL (펌웨어 계층)** | 논리 주소(LBA)를 물리 위치로 바꾸는 소프트웨어 계층. 매핑·GC·웨어 레벨링·배드블록 관리 정책을 담당한다. 물리 칩이 아니라 컨트롤러가 실행하는 논리 구성요소. |
| **ECC 엔진 (LDPC 디코더)** | 셀에서 읽은, 미세하게 어긋난 신호의 비트 오류를 정정하는 하드웨어. 실패하면 기준 전압을 옮겨 다시 읽는 read-retry, 연판정(soft-decision) 디코딩과 함께 TLC/QLC처럼 전압 구간이 촘촘한 고밀도 셀의 신뢰성을 떠받치는 핵심. |
| **호스트 인터페이스 (PCIe PHY + NVMe 프론트엔드)** | 메인보드와 연결되는 관문. PCIe 레인으로 데이터를 실어 나르고, NVMe 프로토콜로 제출/완료 큐와 도어벨을 처리한다. (SATA SSD는 SATA PHY + AHCI를 사용.) |
| **전원관리(PMIC)와 전력손실 보호 커패시터** | 여러 내부 전압을 안정적으로 공급한다. 엔터프라이즈·일부 제품은 커패시터(PLP)로 정전 순간 버퍼에 남은 데이터를 마저 기록해 손실을 막는다. |
| **온다이 차지 펌프** | NAND 다이 내부 회로. 프로그램/소거에 필요한 고전압(대략 15~25V)을 낮은 공급전압에서 만들어낸다. Fowler-Nordheim 터널링으로 전자를 절연막 너머로 밀어 넣거나 빼내는 데 쓰인다. |
| **PCB 기판과 폼팩터 커넥터 (M.2 등)** | 부품을 얹고 신호를 배선하는 보드. M.2 2280 같은 폼팩터의 키/노치로 메인보드 슬롯에 꽂혀 물리·전기적으로 연결된다. |
| **펌웨어·메타데이터 영역** | 컨트롤러 동작 규칙과 매핑 테이블 스냅샷, 배드블록 목록, 마모 통계 등을 NAND 예약 영역에 보관해 재부팅 후에도 상태를 복원한다. |
| **온도 센서·서멀 스로틀링 로직 (+선택 방열판)** | 컨트롤러·NAND 온도를 감시해 임계 온도를 넘으면 성능을 낮춰(throttle) 소자를 보호한다. 고속 PCIe 4.0/5.0 NVMe는 발열이 커 방열판(히트싱크)이 흔히 필요하고, 방열 여부가 대용량 연속 쓰기의 지속 성능을 좌우한다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **NAND 플래시 (NAND Flash)** | 셀을 직렬로 엮은 NAND(부정 논리곱) 구조의 비휘발성 메모리. 고밀도·저비용이라 SSD의 저장 매체로 쓰인다. 반대인 NOR 플래시는 랜덤 읽기가 빠르지만 밀도가 낮아 코드 저장용에 주로 쓰인다. |
| **플로팅 게이트 / CTF (Charge Trap Flash, 전하 포집 플래시)** | 전하를 가두는 방식. 플로팅 게이트는 절연된 '도체' 게이트에, CTF는 '절연체(질화막)' 포집층에 전자를 저장한다. 3D NAND는 셀 간섭에 강하고 적층 공정에 유리한 CTF를 주로 쓴다. |
| **SLC/MLC/TLC/QLC** | 한 셀에 저장하는 비트 수. Single(1)·Multi(2)·Triple(3)·Quad(4) Level Cell. 각각 2·4·8·16개 전압 구간을 구분한다. 비트가 많을수록 용량·저가이지만 속도·수명·신뢰성은 떨어진다. |
| **페이지 / 블록 / 플레인 / 다이** | 저장 계층. 페이지=읽기·쓰기의 최소 단위(대략 4~16KB), 블록=소거의 최소 단위(수백~수천 페이지 묶음), 플레인=다이 안에서 병렬로 동작하는 구획, 다이=실리콘 칩 한 장. |
| **읽기/프로그램/소거 비대칭** | 읽기·쓰기(프로그램)는 페이지 단위지만 소거는 블록 단위로만 가능하고, 속도는 읽기≪프로그램≪소거 순으로 느려진다. 같은 자리 덮어쓰기가 불가능해 out-of-place 쓰기와 가비지 컬렉션이 필수가 된다. |
| **FTL (Flash Translation Layer, 플래시 변환 계층)** | 논리 주소(LBA)를 물리 위치로 매핑하는 계층. 플래시의 괴상한 제약을 감추고 SSD를 평범한 블록 디스크처럼 보이게 하는 핵심 추상화. 페이지 단위 매핑이 유연하지만 큰 매핑 테이블이 필요하다. |
| **웨어 레벨링 (Wear Leveling, 마모 균등화)** | P/E 사이클을 특정 블록에 몰지 않고 전체에 고르게 분산해 수명을 늘리는 기법. 자주 바뀌는 데이터를 흩뿌리는 '동적', 안 바뀌는 데이터를 옮겨 어린 블록을 풀어주는 '정적'이 있다. |
| **가비지 컬렉션 (Garbage Collection, GC)** | 무효 페이지가 섞인 블록에서 유효 페이지만 옮겨 담고 블록을 통째로 소거해 빈 블록을 확보하는 청소 작업. 백그라운드로 미리 해두면 쓰기 성능이 유지된다. |
| **쓰기 증폭 (Write Amplification Factor, WAF)** | 호스트가 요청한 양보다 실제 NAND에 더 많이 쓰이는 비율(= 실제 NAND 쓰기 / 호스트 쓰기). GC의 유효 페이지 복사 때문에 1보다 커진다. 오버프로비저닝·TRIM·순차 쓰기가 이를 낮춘다. |
| **TRIM** | OS 파일시스템이 삭제된 LBA를 SSD에 알려주는 명령(ATA TRIM / NVMe Deallocate·Dataset Management). SSD가 해당 데이터를 유효한 줄 알고 GC 때 헛되이 복사하는 것을 막아 성능·수명을 지킨다. |
| **오버프로비저닝 (Over-Provisioning, OP)** | 사용자에게 보이지 않는 여분 용량(예: 표기 용량의 7~28%). GC·웨어 레벨링이 숨 쉴 공간으로 쓰여, 여유가 클수록 쓰기 증폭이 줄고 성능·수명이 좋아진다. |
| **SLC 캐싱 (pSLC)** | TLC/QLC NAND의 일부를 1비트 SLC 모드로 운용해 빠른 쓰기 버퍼로 쓰는 기법. 들어온 쓰기를 우선 빠르게 받고 뒤에서 TLC/QLC로 접어 넣는다(folding). 캐시가 다 차면 네이티브 속도로 뚝 떨어진다. |
| **DRAM 캐시 / HMB (Host Memory Buffer)** | 매핑 테이블을 담는 온보드 DRAM. DRAM-less SSD는 그 대신 NVMe HMB 기능으로 호스트 시스템 RAM의 작은 영역(전통적으로 대략 32~64MB, 최신 PCIe 4.0/5.0 제품은 더 큰 영역을 요청하기도)을 빌려 매핑 일부를 둔다. |
| **NVMe (Non-Volatile Memory Express)** | 플래시를 위해 PCIe 위에서 설계된 저지연·다중 큐 프로토콜. 큐가 얕고(1개×32명령) 오버헤드가 큰 옛 AHCI/SATA를 대체해, SSD 내부 병렬성을 그대로 끌어낸다. |
| **M.2 / PCIe** | M.2는 크기·커넥터를 규정하는 '폼팩터'(예: 2280=22×80mm), PCIe는 실제 데이터 '버스'다. M.2 슬롯은 SATA 신호 또는 PCIe/NVMe 신호를 실을 수 있어, 폼팩터만으로 속도가 정해지지 않는다. |
| **ECC / LDPC (Low-Density Parity-Check)** | 읽기 시 발생하는 비트 오류를 검출·정정하는 오류정정부호. 촘촘한 전압 구간을 쓰는 고밀도 셀(TLC/QLC)에서 데이터 신뢰성을 보장하는 필수 요소로, read-retry·연판정 디코딩과 함께 쓰인다. |
| **Read Retry / 적응형 읽기 전압** | 셀 전압 분포가 마모·전하 누설·온도로 이동하면 고정 기준으로는 오독이 난다. 컨트롤러는 기준 읽기 전압을 조금씩 옮겨 다시 읽고(read retry), 분포 변화를 추적해 최적 기준을 잡아 오류율을 낮춘다. |
| **데이터 보존 / 읽기 방해 / 프로그램 방해 (Retention·Read/Program Disturb)** | 셀에 가둔 전하는 시간이 지나며 새어 나가(retention loss) 문턱전압이 이동하고, 특정 페이지를 반복해 읽거나(read disturb) 이웃을 프로그램하면(program disturb) 인접 셀의 전하가 교란된다. 마모(P/E)가 클수록·전원을 오래 끊을수록·QLC일수록 심해지며, 컨트롤러는 임계에 이르면 데이터를 새 블록으로 옮겨 다시 써(refresh) 대응한다. |
| **P/E 사이클 (Program/Erase Cycle)** | 셀이 견디는 프로그램-소거 반복 횟수, 곧 셀의 수명 단위. 반복될수록 절연막이 손상돼 오류율이 오르고 데이터 보존 시간이 짧아진다. |
| **문턱전압 (Threshold Voltage, Vt)** | 트랜지스터가 켜지기 시작하는 전압. 셀에 가둔 전하량에 따라 이 값이 옮겨가며, 읽기 회로는 여러 기준 전압과 비교해 저장된 비트를 판독한다. |
| **서멀 스로틀링 (Thermal Throttling)** | 고속 NVMe는 컨트롤러·NAND 발열이 커, 임계 온도를 넘으면 스스로 속도를 낮춰(throttle) 소자를 보호한다. 그래서 대용량 연속 쓰기의 지속 성능은 방열판(히트싱크) 유무에 크게 좌우된다. |
| **자기암호화 드라이브 (SED, Self-Encrypting Drive)** | 컨트롤러가 저장 데이터를 하드웨어 AES로 실시간 암·복호화한다. TCG Opal·eDrive 등으로 관리하며, '보안 소거(crypto-erase)'는 암호화 키만 폐기해 전체 데이터를 즉시 복구 불가능하게 만든다. |

## ⚠️ 흔한 오해

- **오해** — SSD도 HDD처럼 파일을 지운 자리에 바로 덮어쓴다.
  <br>**교정** — 플래시는 같은 페이지에 덮어쓸 수 없다. 재기록하려면 블록을 통째로 지워야 하므로, 실제로는 새 페이지에 쓰고 옛 데이터는 무효 표시했다가 나중에 가비지 컬렉션으로 정리한다.
- **오해** — 저장 셀은 0과 1을 '전하 있음/없음'으로 딱 나눠 저장한다.
  <br>**교정** — 셀은 가둔 전하량이 만든 아날로그 문턱전압을 여러 구간으로 나눠 판독한다. TLC는 8구간, QLC는 16구간을 구분하므로 미세한 전압 이동도 오류가 되어 ECC(LDPC)·read-retry가 필수다.
- **오해** — M.2에 꽂히면 곧 NVMe이고 무조건 빠르다.
  <br>**교정** — M.2는 크기·커넥터(폼팩터)일 뿐이다. 같은 M.2 슬롯에 느린 SATA SSD가 꽂힐 수도 있고, 속도는 실제로 PCIe/NVMe 사용 여부와 세대(4.0·5.0 등)가 결정한다.
- **오해** — SSD는 쓰면 쓸수록 금방 수명이 다한다.
  <br>**교정** — 셀 수명은 유한하지만 웨어 레벨링·오버프로비저닝·큰 TBW 덕분에 일반 사용자는 보통 수년~수십 년을 써도 쓰기 한계에 도달하기 어렵다.
- **오해** — 용량을 거의 꽉 채워 써도 속도는 그대로다.
  <br>**교정** — 빈 블록이 부족하면 가비지 컬렉션이 바빠지고 SLC 캐시가 줄어 쓰기 속도가 크게 떨어진다. 여유 공간과 TRIM이 성능을 지킨다.
- **오해** — DRAM 없는 SSD는 매핑 정보를 둘 곳이 없어 제대로 못 쓴다.
  <br>**교정** — HMB로 호스트 RAM 일부를 빌려 매핑 테이블 일부를 두므로 정상 동작한다. 다만 대용량·고부하 랜덤 작업에서는 온보드 DRAM 탑재 제품이 유리하다.
- **오해** — TRIM은 있으면 좋은 옵션이라 없어도 상관없다.
  <br>**교정** — TRIM이 없으면 SSD가 삭제된 데이터를 유효한 줄 알고 GC 때 계속 복사해, 쓰기 증폭이 커지고 시간이 지날수록 성능·수명이 나빠진다.
- **오해** — 광고에 적힌 순차 속도가 실사용 속도다.
  <br>**교정** — 표기 속도는 대개 SLC 캐시가 살아있는 순차 작업의 최고치다. 캐시가 소진되거나 잘게 흩어진 랜덤 작업에서는 훨씬 낮아지며, 실제 체감은 랜덤 IOPS·지연이 더 크게 좌우한다.
- **오해** — SSD는 비휘발성이라 전원을 안 꽂아도 데이터가 영원히 남는다.
  <br>**교정** — 셀의 전하는 시간이 지나면 서서히 새어 나간다. 규격(JEDEC)상 소비자용은 수명 말기 기준 전원 없이 약 1년 보존을 보장할 뿐이며, 많이 마모됐거나 QLC일수록·고온일수록 보존 기간이 짧아진다. 장기 콜드 보관용으로 전원 없이 방치하는 것은 위험하다.

## 💡 비유

비유 1 — '연필로만 쓰는 노트': NAND 블록은 한 줄만 고치고 싶어도 지우개가 페이지(블록) 전체만 지울 수 있는 노트와 같다. 그래서 한 줄을 바꾸려면 새 줄에 옮겨 적고 옛 줄엔 빗금(무효)을 친 뒤, 빗금이 가득 차면 그 페이지를 통째로 지워 재활용한다(가비지 컬렉션·블록 소거). 게다가 연필 자국은 오래 두면 흐려지므로(전하 누설), 관리인이 이따금 다시 진하게 옮겨 적는다(refresh). 비유 2 — '주차 대행 관리자': 컨트롤러는 거대한 발레파킹 관리자다. 손님(호스트)은 'LBA'라는 번호표만 건네고, 실제 차(데이터)를 어느 자리(물리 블록)에 댔는지는 관리자(FTL)의 장부(매핑 테이블)만 안다. 관리자는 자리를 골고루 돌려 쓰고(웨어 레벨링) 빈 자리를 미리 치워두며(GC), 손님이 '이 차 이제 안 쓴다'고 말해주면(TRIM) 즉시 그 자리를 비운다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 부팅(boot 시나리오): 전원을 켜면 SSD에 잠들어 있던 부트로더·커널·드라이버가 NVMe 명령으로 대량 읽혀 RAM으로 올라온다. SSD의 낮은 지연과 높은 순차 대역폭이 '몇 초 만의 부팅'을 만든다.
- 파일 열기(storage 시나리오 '내가 연 파일은 어디서 오는 걸까?'): 더블클릭하면 파일시스템이 이름을 LBA로 바꾸고 → NVMe로 SSD에 읽기 요청 → FTL이 물리 페이지를 찾아 셀을 판독·ECC 정정 → DMA로 RAM 페이지 캐시에 올려 CPU·화면까지 도달. SSD가 이 읽기 경로의 출발점이다.
- 게임 렌더링(game 시나리오): 레벨 로딩 때 텍스처·에셋 수 GB를 SSD에서 순차·랜덤으로 읽어 RAM/VRAM에 채운다. 높은 IOPS와 대역폭이 로딩 시간과 오픈월드 스트리밍의 끊김을 줄인다(DirectStorage류 기술이 이 경로를 더 짧게 만든다).
- 인터넷 검색 왕복(search 시나리오): 브라우저 캐시·쿠키·방문 기록이 SSD에 저장·조회되고, 받아온 페이지 자원이 디스크 캐시로 남아 다음 방문을 빠르게 한다.
- Ctrl+S 저장: 편집 중이던 데이터가 RAM에서 파일시스템을 거쳐 SSD로 내려간다. SLC 캐시/버퍼에 먼저 받고 빈 페이지에 프로그램한 뒤 FTL 매핑을 갱신한다. 전력손실 보호(PLP)가 있으면 정전 순간에도 버퍼 잔여분까지 안전하게 기록한다.
- 영상 스트리밍·소리 재생: 시청 중 버퍼링된 조각과 앱·브라우저 캐시가 SSD에 쓰였다 읽힌다. 영상을 통째로 저장·다운로드하면 대량 순차 쓰기가 몰려 SLC 캐시 용량과 쓰기 증폭을 시험한다.
- AI 질문: 로컬에서 큰 모델 가중치(수 GB~수십 GB)를 SSD에서 RAM/VRAM으로 로드할 때 순차 읽기 대역폭이 모델 로딩 시간을 좌우한다. 클라우드 서비스라면 서버 측 NVMe SSD가 같은 역할을 맡는다.
