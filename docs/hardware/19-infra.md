# 홈·인터넷 인프라
*Home & Internet Infrastructure*

> 집 안의 공유기부터 대륙을 잇는 해저 광케이블까지, 내 데이터를 지구 반대편 서버로 실어 나르는 계층적 네트워크 장비들의 총체.

**분류**: 네트워크

---

## 🧭 한마디로, 무슨 일을 하나
내 컴퓨터의 NIC에서 나온 패킷이 목적지 서버까지 갔다 오도록 실어 나르는 "바깥 세계의 배관"이다. 집 안 공유기가 출입구를 지키고, 모뎀·ONT가 신호를 광으로 바꾸며, ISP·백본·해저케이블·IXP가 대륙을 잇고, DNS가 길 안내를, CDN이 지름길을 제공한다. CPU·RAM·SSD가 한 컴퓨터 안의 속도 계층이라면, 이 인프라는 전 세계 컴퓨터를 하나로 잇는 계층이며, 컴퓨터 아키텍처의 관점에서는 "가장 느리고 가장 먼 메모리 계층"에 해당한다. 인터넷 왕복(RTT)은 대략 수십~수백 ms로, 약 0.3~1 ns인 레지스터·L1 캐시 접근에 견주면 어림잡아 수천만 배(대략 3천만~1억 배) 느린 셈이다. 중앙 관제탑 없이 수많은 자율적 장비가 협력해 데이터를 릴레이하는, 인류가 만든 가장 큰 분산 기계다.

## ⚙️ 작동 방식

**1. 기기에서 집 안 공유기까지 (LAN 진입)**

노트북·폰이 만든 IP 패킷은 먼저 집 안 공유기로 향한다. 무선이면 Wi-Fi 전파(2.4/5/6 GHz)로, 유선이면 이더넷 구리선으로 전달된다. 기기는 부팅 때 공유기의 DHCP 서버에서 사설 IP(예: 192.168.0.x)와 '바깥으로 나가는 문(기본 게이트웨이)' 주소를 이미 받아 뒀기에 어디로 보낼지 안다. 공유기 안의 스위치 부가 목적지 MAC 주소를 보고 알맞은 포트나 라디오로 프레임을 넘긴다. 왜: 집 안 모든 트래픽은 인터넷으로 나가기 전에 반드시 이 한 대의 게이트웨이를 통과하도록 설계돼 있다.

**2. NAT·방화벽 통과 (공유기의 문지기 역할)**

집에는 보통 ISP가 준 공인 IPv4가 하나뿐이라, 공유기가 NAT(네트워크 주소 변환)로 여러 기기의 사설 IP를 대표 공인 IP 하나로 바꿔 내보낸다. 나갈 때 출발지 주소·포트를 변환표에 적어 두었다가, 응답이 돌아오면 그 표를 보고 올바른 기기로 되돌린다. 동시에 상태 기반 방화벽(SPI)이 '내가 먼저 시작한 연결의 응답'만 통과시키고 밖에서 먼저 두드리는 패킷은 차단한다. 다만 IPv4 고갈이 심해져, 요즘은 ISP가 공인 IP마저 여러 가입자와 공유하는 CGNAT(캐리어급 NAT)를 쓰기도 하고, 주소가 사실상 무한한 IPv6에서는 NAT 없이 기기마다 공인 주소를 갖기도 한다. 왜: 부족한 IPv4 공인 주소를 아끼고, 안에서 시작한 연결만 허용해 기본 보안을 제공한다.

**3. DNS 이름 풀이 + 연결 수립 (전화번호부 조회와 악수)**

URL의 도메인 이름(www.example.com)은 사람용 이름일 뿐, 실제 라우팅은 숫자 IP로 한다. 기기는 공유기나 ISP·공개 DNS의 재귀 리졸버에 이름을 물어보고, 리졸버는 캐시에 없으면 루트 서버 → TLD 서버(.com) → 권한 서버 순으로 계층적으로 찾아 IP를 돌려준다. 캐시에 있으면 0에 가깝고, 없으면 대략 수십 ms 걸린다. 그런데 IP를 알아낸 뒤에도 곧바로 데이터가 흐르는 게 아니라, TCP 3-way 핸드셰이크와(HTTPS면) TLS 핸드셰이크로 연결을 세우는 데 다시 1~3번의 왕복(RTT)이 더 든다(QUIC/HTTP3는 이를 1 RTT로 줄임). 왜: 이 '이름 → 주소' 조회와 연결 수립이 끝나야 비로소 실제 데이터를 주고받는다. DNS 자체는 데이터를 나르지 않고 길만 알려준다.

**4. 모뎀·ONT에서 광 신호로 변환, 가입자망 진입**

공유기에서 나온 전기 신호 패킷은 광랜(FTTH) 환경에서 ONT(광 네트워크 종단장치)의 레이저 다이오드가 빛의 깜빡임으로 바꿔 광섬유에 실어 보낸다(구형 동축 케이블은 DOCSIS 케이블 모뎀, 전화선은 DSL 모뎀이 다른 방식으로 변조). 이 신호는 동네 광 분배함을 거쳐 ISP 국사의 OLT까지 간다. GPON 방식에서는 여러 가정이 한 가닥 광섬유를 시간 분할로 공유한다. 왜: 구리선보다 광섬유가 훨씬 멀리, 빠르게, 손실 적게 신호를 나르기 때문에 마지막 구간(가입자망)까지 광이 들어온다.

**5. ISP 교환국 라우터에서 경로 결정**

ISP 국사의 에지 라우터가 수많은 가입자 트래픽을 집선한 뒤, 목적지 IP를 라우팅 테이블과 대조해 '다음 홉(next hop)'을 정한다. 인터넷에는 중앙 관제탑이 없어서, 라우터들이 BGP로 서로 '이 IP 대역은 이쪽으로 가면 된다'고 광고해 만든 지도를 따라 홉에서 홉으로 패킷을 릴레이한다(패킷 스위칭). 왜: 목적지까지 통째로 예약된 전용선이 아니라, 매 라우터가 그때그때 최선의 다음 구간만 골라 전달하기에 한 링크가 끊겨도 우회가 가능하다.

**6. 백본·IXP·해저케이블로 장거리 이동**

지역망을 벗어나면 대용량 광 백본으로 올라탄다. 서로 다른 사업자망은 IXP(인터넷 교환지점)에서 만나 트래픽을 무정산으로 맞교환(피어링)하거나, 상위 사업자에게 돈을 내고 통과(트랜짓)한다. 대륙을 건널 땐 해저 광케이블을 타고, 수십~백 km마다 놓인 광증폭기(중계기, EDFA)가 감쇠한 빛을 되살린다. DWDM 기술로 한 가닥 섬유에 수십 개의 색(파장)을 겹쳐 보내 용량을 끌어올린다. 왜: 전 세계 국제 트래픽의 대부분(흔히 99% 이상으로 인용)은 위성이 아니라 이 물리적 해저 유선망을 지난다.

**7. CDN 엣지 캐시 또는 원 서버 도달, 그리고 역방향 왕복**

동영상·이미지·웹 같은 자주 요청되는 콘텐츠는 굳이 원본이 있는 먼 데이터센터(원 서버)까지 가지 않고, 내 지역 가까운 CDN 엣지 서버가 캐시본으로 바로 응답한다. 엣지에 없으면 원 서버까지 가서 받아온다. 응답 데이터는 왔던 길을 거의 거슬러(때로는 다른 경로로) 집까지 돌아오고, 공유기의 NAT 표가 올바른 기기로 되돌린다. 왕복 한 번이 국내 대략 수~수십 ms, 대륙 간 100 ms대. 왜: 물리 거리를 줄여 지연을 낮추고 백본 혼잡을 던다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **공유기 라우팅 엔진(SoC)** | 공유기의 두뇌. 패킷의 목적지 IP를 보고 어디로 보낼지 결정하고, NAT 주소 변환·DHCP 주소 배정·방화벽 규칙을 실행한다. 저가형은 범용 CPU가, 고급형은 전용 하드웨어 가속기(네트워크 오프로드 엔진)가 처리한다. |
| **내장 이더넷 스위치** | 공유기의 유선 LAN 포트 여러 개를 묶어, 집 안 유선 기기끼리 또는 유선↔무선 사이에서 MAC 주소를 기준으로 프레임을 전달하는 2계층(데이터 링크) 부품. |
| **무선 AP (라디오 + 베이스밴드 + 안테나)** | Wi-Fi 신호를 만들고 받는 부분. 디지털 데이터를 전파로 변조·복조하고, 여러 안테나(MIMO)와 빔포밍으로 속도와 도달 거리를 높인다. |
| **모뎀 / ONT의 광 트랜시버** | 레이저 다이오드(전기→빛)와 포토다이오드(빛→전기)로 신호 형태를 바꾸는 광↔전기 변환기. FTTH에서 가정 쪽 광 종단 역할을 한다. |
| **OLT (국사 쪽 광 종단)** | ISP 국사에서 한 가닥 광을 나눠 쓰는 수십~수백 가정의 ONT를 상대하는 집선 장비. ONT의 반대편 짝으로, 가입자 광선을 모아 코어망으로 넘긴다(PON 분기비는 보통 1:32~1:128). |
| **ISP 에지/코어 라우터** | 대형 캐리어급 라우터. 여러 라인카드(고속 광 포트 다발)와 대용량 스위칭 패브릭, 초당 수억~수십억 개 패킷을 조회·전달하는 포워딩 ASIC을 갖추고 라우팅 테이블을 유지한다. |
| **광섬유 백본 링크 + DWDM 장비** | 도시·국가를 잇는 장거리 유리섬유 간선. DWDM 다중화 장비가 여러 파장(색)을 한 섬유에 겹쳐 실어 한 가닥의 대역폭을 수십 배로 배가한다. |
| **해저 광케이블 + 중계기(EDFA)** | 대륙을 잇는 해저 유리섬유 다발. 수십~백 km마다 든 어븀 첨가 광증폭기(EDFA)가 감쇠한 빛을 전기 변환 없이 그대로 증폭한다. 바깥은 강철선·구리(전력 공급용 도체)·폴리에틸렌으로 수압과 어선·닻으로부터 보호한다. |
| **IXP 스위칭 패브릭** | 여러 네트워크 사업자·콘텐츠 사업자가 한 건물에 모여 서로 케이블을 꽂아 트래픽을 직접 교환하는 중립적 대형 스위치. 먼 우회 없이 짧고 싸게 데이터를 주고받게 한다. |
| **CDN 엣지 서버 (캐시 스토리지)** | 사용자 가까이 전 세계에 분산 배치된 서버. RAM·SSD에 인기 콘텐츠(영상·이미지·정적 파일)를 미리 담아 두고, 원 서버 대신 낮은 지연으로 빠르게 응답한다. |
| **DNS 서버 계층** | 이름→IP 사전. 재귀 리졸버(사용자 대신 찾아 주는 창구)와 루트·TLD·권한 서버(주소 원본을 계층으로 나눠 관리)로 구성된다. |
| **라우팅 테이블 & 프로토콜(BGP·OSPF)** | 논리적 부품. 어느 IP 대역이 어느 방향에 있는지 적힌 지도(라우팅 테이블)와, 그 지도를 서로 자동으로 갱신·공유하는 규약(BGP는 사업자 간, OSPF는 사업자 내부). |
| **공유기 전원부·플래시·RAM** | 어댑터로 받은 전기를 회로용 전압으로 바꾸는 전원부, 펌웨어(운영 코드)를 담은 플래시, 지나가는 패킷과 NAT 표를 잠시 담는 RAM. 공유기 자체가 작은 전용 컴퓨터임을 보여준다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **공유기 (라우터+스위치+AP 통합기)** | 가정용 한 대에 라우터(경로 결정·NAT), 스위치(유선 포트 분배), 무선 AP(Wi-Fi)가 합쳐진 장비. 흔히 '공유기'라 부르는 것은 이 통합 박스다. |
| **NAT (Network Address Translation, 네트워크 주소 변환)** | 집 안 여러 기기의 사설 IP를 ISP가 준 공인 IP 하나로 바꿔 인터넷에 내보내고, 응답을 원래 기기로 되돌리는 기법. 공인 주소 절약과 기본 보안을 동시에 준다. |
| **DHCP (Dynamic Host Configuration Protocol, 동적 호스트 구성 프로토콜)** | 기기가 네트워크에 접속할 때 사설 IP·게이트웨이·DNS 주소를 자동으로 배정받게 해 주는 프로토콜. 공유기가 이 서버 역할을 한다. |
| **AP (Access Point, 접속점)** | 유선 네트워크와 무선 기기를 이어 주는 Wi-Fi 신호 송수신 장치. 가정 공유기 안에 내장돼 있다. |
| **ONT / OLT (Optical Network Terminal / Line Terminal, 광망 종단/회선 종단)** | ONT는 가정 쪽에서 광↔전기 신호를 바꾸는 종단, OLT는 국사 쪽에서 여러 ONT를 집선하는 대응 장비. |
| **PON / GPON (Passive Optical Network / Gigabit PON, 수동형 광가입자망)** | 국사에서 나온 한 가닥 광을 전원 없는 광 분배기로 갈라 여러 가정이 시간 분할로 공유하는 FTTH 방식. GPON(2.5G급), 그 상위인 XGS-PON(10G 대칭), 25G/50G PON 등이 있다. |
| **FTTH (Fiber To The Home, 댁내 광가입자망)** | 광섬유를 가정 안(공유기/ONT)까지 직접 끌어오는 방식. 구리선 구간이 없어 속도·안정성이 높다. |
| **DNS (Domain Name System, 도메인 이름 체계)** | 사람이 읽는 도메인 이름을 컴퓨터가 쓰는 숫자 IP 주소로 바꿔 주는 분산 전화번호부. 루트·TLD·권한 서버가 계층으로 나눠 관리한다. |
| **ISP (Internet Service Provider, 인터넷 서비스 사업자)** | 가정·기업에 인터넷 접속을 파는 통신 사업자. 가입자망·국사 라우터·백본을 운영하며 다른 ISP와 상호 연결한다. |
| **IXP (Internet Exchange Point, 인터넷 교환지점)** | 여러 네트워크 사업자가 한곳에 모여 트래픽을 직접 맞교환하는 중립적 물리 시설. 먼 우회를 줄여 지연과 비용을 낮춘다. |
| **피어링 / 트랜짓 (Peering / Transit)** | 피어링은 두 네트워크가 서로의 트래픽을 대개 무정산으로 직접 교환하는 것, 트랜짓은 상위 사업자에게 돈을 내고 인터넷 전체로 나가는 통로를 빌리는 것. |
| **BGP (Border Gateway Protocol, 경계 경로 프로토콜)** | 서로 다른 사업자망(자율 시스템, AS)들이 '어느 IP 대역이 우리 쪽으로 오면 된다'고 광고해 인터넷 전체의 경로 지도를 만드는 프로토콜. |
| **CDN (Content Delivery Network, 콘텐츠 전송망)** | 콘텐츠를 사용자 가까운 곳에 미리 복제해 두는 분산 서버망. 엣지 캐시가 원 서버 대신 응답해 지연을 줄이고 원본 부하를 던다. |
| **홉 (Hop)** | 패킷이 지나는 라우터 하나하나를 세는 단위. 출발지에서 목적지까지 대략 10~30 홉을 거친다. 각 홉에서 처리·전송 지연이 조금씩 쌓인다. |
| **RTT / 지연 (Round Trip Time / Latency)** | 요청이 목적지에 갔다 응답이 돌아오기까지 걸리는 왕복 시간. 물리 거리, 홉 수, 라우터 처리·큐잉이 더해져 결정된다. 게임의 '핑'이 이 값이다. |
| **대역폭 vs 지연 (Bandwidth vs Latency)** | 대역폭은 단위 시간당 나르는 데이터 양(굵기), 지연은 한 비트가 도달하기까지의 시간(길이). 둘은 독립적 지표라서 굵은 회선이라도 멀면 핑이 높다. |
| **패킷 스위칭 (Packet Switching)** | 데이터를 작은 패킷으로 쪼개 각자 독립적으로 최선의 경로를 따라 보내는 방식. 전용 회선을 통째로 예약하는 회선 교환과 대비된다. |
| **TCP / UDP (전송 계층 프로토콜)** | IP가 패킷을 목적지까지 보내는 것을 전제로, TCP는 순서·재전송·혼잡제어로 손실 없는 신뢰 전송을 보장(웹·파일 전송)하고, UDP는 이런 보장 없이 빠르게 보내는 방식(음성·영상·게임). 실제 앱 데이터는 이 4계층 위에서 오간다. |
| **TLS 핸드셰이크 / QUIC·HTTP3** | HTTPS는 데이터를 주고받기 전에 TLS 핸드셰이크로 암호 열쇠를 교환한다(TLS 1.3은 1 RTT). QUIC/HTTP3는 UDP 위에서 전송+암호 수립을 합쳐 지연을 줄이고 재접속 시 0-RTT까지 지원한다. DNS·TCP·TLS를 합치면 첫 바이트 전에 여러 왕복이 쌓인다. |
| **IPv4 주소 고갈 / IPv6** | 32비트 IPv4(약 43억 개)는 이미 고갈돼 새 배정이 어렵다. 128비트 IPv6는 사실상 무한한 주소를 제공해 NAT 없이도 기기마다 공인 주소를 줄 수 있고, 현재 IPv4와 병행 운용(듀얼 스택)된다. |
| **CGNAT (Carrier-Grade NAT, 캐리어급 NAT)** | ISP가 부족한 공인 IPv4를 아끼려고 여러 가입자를 하나의 공인 IP 뒤에 몰아넣는 대규모 NAT. 이 경우 가정은 진짜 공인 IP를 받지 못해 외부 접속·포트 개방이 제한될 수 있다. |
| **DWDM (Dense Wavelength Division Multiplexing, 고밀도 파장분할다중화)** | 한 가닥 광섬유에 서로 다른 파장(색)의 빛 수십~수백 개를 겹쳐 동시에 보내, 물리 섬유를 늘리지 않고 용량을 수십 배로 키우는 기술. |
| **EDFA / 중계기 (Erbium-Doped Fiber Amplifier, 어븀 첨가 광섬유 증폭기)** | 해저·장거리 케이블에서 거리가 멀어 약해진 빛을 전기로 바꾸지 않고 광 상태 그대로 증폭하는 중계기. 수십~백 km 간격으로 놓인다. |
| **방화벽 / SPI (Firewall / Stateful Packet Inspection, 상태 기반 패킷 검사)** | 안에서 먼저 시작한 연결의 응답만 통과시키고, 밖에서 무단으로 들어오는 패킷을 차단하는 공유기의 기본 보안 기능. |
| **사설 IP / 공인 IP (Private / Public IP)** | 사설 IP(예: 192.168.x.x, 10.x.x.x)는 집 안에서만 쓰는 주소, 공인 IP는 인터넷 전체에서 유일하게 통하는 주소. NAT가 둘을 이어 준다. |

## ⚠️ 흔한 오해

- **오해** — 공유기와 모뎀은 같은 것이다.
  <br>**교정** — 역할이 다르다. 공유기는 경로 결정·NAT·DHCP·방화벽을 담당하는 라우터이고, 모뎀·ONT는 신호를 광↔전기로 변환해 ISP 회선에 실어 주는 장치다. 요즘은 한 박스에 합쳐진 경우가 많아 헷갈릴 뿐이다.
- **오해** — Wi-Fi 속도가 곧 인터넷 속도다.
  <br>**교정** — Wi-Fi 속도는 집 안 무선 구간의 속도일 뿐이다. 실제 체감 속도는 ISP 계약 회선 속도와 상대 서버 상태가 좌우한다. Wi-Fi가 아무리 빨라도 회선이 100 Mbps면 그 이상 나오지 않는다.
- **오해** — 인터넷은 무선이나 '클라우드'에 떠 있다.
  <br>**교정** — 국제 트래픽의 대부분(흔히 99% 이상)은 바다 밑에 깔린 물리적 해저 광케이블(유선)을 지난다. 위성은 소수의 특수 용도이며, '클라우드'도 결국 유선으로 연결된 실제 데이터센터 건물이다.
- **오해** — 데이터는 빛의 속도로 가니 거리는 지연에 영향이 없다.
  <br>**교정** — 광섬유 속 빛은 진공 광속의 약 2/3로 느려지고, 거쳐 가는 라우터마다 처리·큐잉 지연이 쌓인다. 물리적 거리가 지연의 하한을 정하므로, 서버가 멀수록 왕복이 확실히 길어진다.
- **오해** — 더 비싼 공유기를 사면 인터넷이 빨라진다.
  <br>**교정** — 공유기는 집 안 분배(Wi-Fi 커버리지·동시 접속 처리)를 개선할 뿐, 인터넷 회선 속도의 상한은 ISP 계약이 정한다. 회선이 병목이면 공유기 교체 효과는 제한적이다.
- **오해** — DNS 서버가 웹페이지 데이터를 전달해 준다.
  <br>**교정** — DNS는 '이름 → IP 주소'만 알려 주는 안내소(전화번호부)다. 실제 데이터 전송은 그렇게 알아낸 IP의 서버와 직접 주고받는 별개 과정이다.
- **오해** — IXP나 피어링은 한 ISP 내부의 일이다.
  <br>**교정** — IXP는 서로 다른 여러 사업자망이 만나 트래픽을 교환하는 중립적 공용 시설이다. 피어링은 두 네트워크가 서로 직접 연결해 먼 우회와 트랜짓 비용을 줄이는 협정이다.
- **오해** — 기기마다 공인 IP가 하나씩 있다.
  <br>**교정** — 일반 가정은 보통 공인 IP를 하나만 받고(때로는 CGNAT로 그마저 여러 집이 공유), 집 안 여러 기기가 NAT를 통해 그 하나를 나눠 쓴다. 각 기기의 192.168.x.x 같은 사설 IP는 집 밖에서는 통하지 않는다.
- **오해** — 속도(대역폭)가 높으면 지연(핑)도 낮다.
  <br>**교정** — 대역폭(한 번에 나르는 양)과 지연(도달까지 걸리는 시간)은 별개 지표다. 굵은 회선이라도 물리 거리가 멀면 핑은 높다. 게임 반응성은 대역폭보다 지연이 좌우한다.
- **오해** — IPv4 주소는 아직 넉넉하다.
  <br>**교정** — 약 43억 개인 IPv4 공인 주소는 이미 고갈돼 새 배정이 어렵다. 그래서 NAT·CGNAT로 주소를 쥐어짜고, 사실상 무한한 IPv6로 이전 중이며 현재는 둘을 함께 쓰는 듀얼 스택이 흔하다.
- **오해** — 공유기 NAT·방화벽이 있으니 완벽하게 안전하다.
  <br>**교정** — NAT와 SPI는 밖에서 먼저 두드리는 연결을 막아 주는 기본 방어일 뿐이다. 사용자가 먼저 접속한 악성 사이트, 애플리케이션 취약점, 이미 감염된 내부 기기, 잘못 열린 포트(UPnP 등)는 막지 못하므로 별도의 보안 조치가 필요하다.

## 💡 비유

우편·물류 시스템에 빗대면 이해가 쉽다. 공유기는 우리 집 대표 주소를 관리하는 문지기(NAT=대표 주소 하나로 온 식구가 편지를 주고받음), DNS는 이름으로 주소를 찾아 주는 전화번호부, ISP는 우리 동네 우체국, 백본·해저케이블은 국가 간 항공·해운 간선 노선, IXP는 여러 택배사가 소포를 맞교환하는 대형 물류 허브, CDN 엣지는 자주 찾는 물건을 미리 갖다 둔 동네 물류창고, 라우터는 매 교차로에서 방향을 정해 주는 교통 표지판, 홉은 거쳐 가는 교차로 수다. TCP·TLS 핸드셰이크는 소포를 보내기 전 상대와 '받을 준비 됐냐'고 몇 차례 확인 전화를 주고받는 절차에 해당한다. 또는 도로망 비유로, 집 앞 골목(Wi-Fi·LAN) → 지방도(ISP 가입자망) → 고속도로(백본) → 대륙을 잇는 해저 터널(해저케이블)로 이어지고, 나들목이 IXP, 각 교차로가 홉에 해당한다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 인터넷 검색 왕복 — 이 인프라의 대표 무대. 브라우저 요청이 DNS 조회→TCP·TLS 연결 수립→공유기 NAT→ONT→ISP→백본→데이터센터를 지나 갔다 돌아오는 전 과정이 곧 홈·인터넷 인프라의 작동이다.
- 영상 스트리밍(유튜브·넷플릭스) — CDN 엣지 캐시가 주역. 원 서버 대신 지역 캐시가 응답해 버퍼링을 줄이고, 적응형 스트리밍이 회선 상태에 맞춰 화질을 조절한다.
- AI에게 질문할 때 — 질문이 집 밖으로 나가 먼 데이터센터의 GPU·NPU 클러스터까지 왕복한다. 인프라의 지연이 응답이 오기까지의 체감 시간에 그대로 더해진다.
- 화상통화 — 낮은 지연과 실시간성이 생명이라 UDP·라우팅·홉 지연이 통화 품질을 좌우한다. 지연이 크면 말이 겹치고 끊긴다.
- 온라인 게임 — '핑'이 바로 이 인프라의 왕복 지연(RTT). 서버까지의 물리 거리와 홉 수가 반응성을 결정한다.
- 부팅 직후 — OS가 DHCP로 IP를 받고, NTP로 시간을 맞추고, 클라우드 계정에 로그인하며 인프라를 처음 깨운다.
- 파일 열기·Ctrl+S 저장(클라우드) — 문서를 클라우드 드라이브에 저장하거나 열 때, 이 인프라를 통해 원격 데이터센터와 동기화된다.
- 프로그램·게임 업데이트 다운로드 — 대용량 파일을 CDN 엣지에서 내려받으며, 회선 대역폭과 엣지 위치가 다운로드 속도를 결정한다.
