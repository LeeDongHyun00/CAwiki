# 램 (주기억장치, DRAM)
*DRAM (Dynamic Random Access Memory) — Main Memory*

> 아주 작은 커패시터에 담긴 전하(있음/없음)로 0과 1을 저장해, CPU가 '지금' 실행 중인 프로그램과 데이터를 넓게 펼쳐 두는, 빠르지만 전원이 꺼지면 내용이 사라지는 휘발성 주기억장치.

**분류**: 메모리

---

## 🧭 한마디로, 무슨 일을 하나
DRAM은 CPU와 저장장치(SSD/HDD) 사이에서 '지금 실행 중인' 코드와 데이터를 담아 두는 작업 공간이다. CPU 캐시(SRAM)보다는 느리지만 용량이 훨씬 크고 값이 싸며, SSD보다는 압도적으로 빨라서 수 GB~수십 GB 규모의 주기억장치로 쓰인다. 프로그램을 실행하려면 먼저 저장장치의 내용을 DRAM으로 올려야 하고, CPU는 캐시에 없는 데이터를 이 DRAM에서 읽어 온다. 전원이 끊기면 내용이 즉시 사라지는 휘발성이라, 영구 보관은 SSD/HDD의 몫이고 DRAM은 어디까지나 '실행 중 임시 작업대'다.

## ⚙️ 작동 방식

**1. 주소 도착과 명령 디코드**

CPU에 내장된 메모리 컨트롤러(IMC)가 접근할 물리 주소를 채널·랭크·뱅크그룹·뱅크·행(row)·열(column)로 쪼갠 뒤, 명령/주소(CA) 버스로 내보낸다. 칩 선택(CS) 신호로 대상 랭크를 고르고 뱅크 주소로 어느 뱅크를 열지 정한다. 왜: DRAM은 하나의 평면이 아니라 잘게 나뉜 격자여서, 먼저 '어디'를 지목해야 한다.

**2. 행 활성화(ACTIVATE, RAS)**

행 디코더가 지정된 워드라인 한 줄에 전압을 걸어 그 행에 속한 모든 셀의 접근 트랜지스터를 동시에 켠다. 그러면 각 셀의 커패시터가 자기 비트라인으로 극히 작은 전하를 나눠(전하 공유) 비트라인 전압을 미세하게 흔든다. ACTIVATE부터 열 접근(READ)까지의 최소 대기가 tRCD다. 왜: 커패시터 하나가 가진 전하는 너무 작아 그대로는 0/1로 읽을 수 없기 때문.

**3. 센스앰프 감지·증폭·복원**

비트라인은 미리 VDD/2 부근으로 프리차지돼 있고, 각 비트라인의 센스앰프가 셀 전하가 만든 미세한 차이를 감지해 완전한 0 또는 1로 증폭한 뒤 그 행 전체를 '행 버퍼(활성 행)'에 래치한다. 이때 커패시터 전하는 읽으면서 소모되므로 센스앰프가 동시에 원래 값을 셀에 다시 채워 넣는다. 왜: DRAM 읽기는 파괴적이라 매번 복원하지 않으면 데이터가 지워진다.

**4. 열 선택과 CAS Latency**

열 주소(CAS)가 도착하면 열 디코더가 행 버퍼에서 원하는 열의 데이터를 골라 낸다. READ 명령을 준 시점부터 첫 데이터가 나오기까지 CAS Latency(CL)만큼의 클럭 주기가 흐른다. 왜: 넓은 행 버퍼에서 필요한 조각만 정확히 뽑아 데이터 핀으로 보내기 위한 내부 파이프라인 지연이다.

**5. 버스트 전송(Double Data Rate)**

내부 배열은 I/O 핀보다 느려서 한 번 접근에 여러 비트를 넓게 미리 읽어(프리페치) 두었다가, DDR는 클럭의 상승·하강 양쪽 엣지 모두에서(그래서 'Double Data Rate') I/O 버퍼를 거쳐 DQ 핀으로 연속해서 몰아 보낸다(버스트). DDR5는 16n 프리페치라 최소 버스트가 16비트(BL16)다. 왜: 매번 주소를 새로 주는 대신 이미 열려 있는 행 버퍼에서 인접 데이터를 빠르게 긁어와 대역폭을 끌어올린다.

**6. 행 버퍼 히트 vs 프리차지**

다음 요청이 같은 행이면(행 버퍼 히트) 활성화를 건너뛰고 열 선택만으로 훨씬 빠르게 응답한다. 다른 행이면 PRECHARGE(소요 시간 tRP)로 비트라인을 기준 전압으로 되돌려 현재 행을 닫은 뒤 새 행을 활성화해야 한다. 왜: 이 '열려 있으면 빠르고, 바꾸면 느린' 특성이 실제 체감 지연을 크게 좌우한다.

**7. 뱅크·뱅크그룹 병렬 처리(인터리빙)**

한 뱅크가 활성화나 프리차지로 바쁜 동안, 컨트롤러는 다른 뱅크·뱅크그룹으로 명령을 보내 지연을 서로 겹쳐 감춘다. 왜: 개별 접근은 느려도 여러 뱅크를 번갈아 돌리면 전체 처리량(대역폭)이 크게 올라간다. DDR5가 뱅크와 뱅크그룹 수를 늘린 이유다.

**8. 주기적 리프레시(Refresh)**

커패시터는 가만히 둬도 전하가 서서히 새 나가므로, 컨트롤러가 일정 간격(tREFI)마다 REFRESH 명령을 보낸다. 이 명령 하나가 칩 내부 카운터가 가리키는 '여러 행'을 한꺼번에 되살리며(활성화-복원), 보존시간(약 64ms, 고온 시 절반) 안에 전 행을 빠짐없이 한 바퀴 돈다. tREFI는 DDR4가 약 7.8µs, DDR5는 행 수가 늘어 절반인 약 3.9µs다. 왜: 리프레시를 멈추면 수십 ms 안에 전하가 뭉개져 0/1이 사라진다. 'Dynamic(동적)'이라는 이름이 바로 이 끝없는 되살리기를 뜻한다.

**9. 전원 차단과 휘발**

전원이 끊기면 컨트롤러의 리프레시도 멈추고, 남아 있던 커패시터 전하가 방전되며 모든 내용이 순식간에 사라진다. 왜: 저장 매체가 '전하'라는 유지 비용이 드는 상태이기 때문 — 이것이 DRAM이 휘발성인 근본 이유이고, 그래서 저장은 SSD가 맡는다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **저장 커패시터 (storage capacitor)** | 전하가 차 있으면 1, 비어 있으면 0 — 딱 1비트를 담는 초소형(펨토패럿급) 전하 저장소. DRAM 셀의 실제 '기억' 부분. |
| **접근 트랜지스터 (access transistor)** | 워드라인 신호로 켜지고 꺼지는 스위치. 커패시터를 비트라인에 연결(읽기/쓰기)하거나 끊어(보관) 준다. 커패시터와 함께 '1T1C' 셀을 이룬다. |
| **워드라인 (wordline, 행 선)** | 한 행에 속한 모든 셀의 접근 트랜지스터 게이트를 동시에 켜는 가로 배선. 활성화할 '행'을 고르는 선. |
| **비트라인 (bitline, 열 선)** | 켜진 셀의 전하를 센스앰프까지 실어 나르는 세로 배선. 읽기 전 VDD/2로 프리차지돼 있다가 미세 전압 변화가 여기서 나타난다. |
| **센스앰프 (sense amplifier)** | 비트라인의 극히 작은 전압 차이를 감지해 완전한 0/1로 증폭·래치하고 셀에 값을 복원한다. 사실상 '활성 행 버퍼' 역할을 겸한다. |
| **행 디코더 / 열 디코더** | 컨트롤러가 보낸 주소를 해독해 정확히 하나의 워드라인(행)과 원하는 열을 선택한다. |
| **뱅크 (bank)** | 독립적으로 행을 열고 닫을 수 있는 셀 배열 단위. 각자 자신의 행 버퍼를 가져, 여러 뱅크가 동시에 다른 행을 다룰 수 있게 한다. |
| **뱅크 그룹 (bank group)** | 뱅크들을 묶은 상위 단위. 연속 접근을 그룹끼리 나눠 처리해 병렬성을 높인다(DDR4/DDR5의 핵심 구조). |
| **리프레시 카운터/로직** | 다음에 되살릴 행 주소를 추적해, REFRESH 명령이 올 때마다 해당 행 묶음을 순회시켜 전 행이 보존시간 안에 빠짐없이 리프레시되도록 한다. |
| **모드 레지스터 (Mode Register)** | CAS Latency, 버스트 길이, 구동 옵션 등 칩의 동작 설정을 담아 두는 설정 레지스터. 부팅 초기화(트레이닝) 때 값이 쓰인다. |
| **I/O 버퍼 / 프리페치 버퍼와 DQ 데이터 핀** | 내부에서 넓게 프리페치한 비트를 모아 두었다가 칩 안팎으로 실제 데이터를 주고받는 관문. DDR의 양 엣지 전송이 여기서 일어난다. |
| **명령/주소(CA)·제어 버스 인터페이스** | CS·클럭·명령/주소 등 제어·주소 신호를 받아들이는 입력부. 데이터 버스(DQ)와 분리돼 있다. |
| **(DDR5 칩) 온다이 ECC(ODECC) 엔진** | DDR5부터 모든 칩에 의무 탑재. 대략 128비트 데이터당 8비트 패리티로 칩 내부의 단일 비트 오류를 스스로 정정해 미세공정 결함을 감춘다. 모듈 밖 사이드밴드 ECC와는 별개·상호보완. |
| **(모듈) PCB와 금도금 엣지 커넥터 핀** | 여러 DRAM 칩을 얹어 슬롯에 꽂는 기판과 접점. DDR5 DIMM은 288핀, SO-DIMM은 262핀. |
| **(모듈) SPD EEPROM** | 모듈의 용량·표준 타이밍·제조사 정보와 XMP/EXPO 오버클록 프로필을 담은 작은 칩. 부팅 시 BIOS/펌웨어가 읽어 메모리 설정을 자동으로 잡는다. |
| **(DDR5 모듈) PMIC 전력관리 IC** | DDR5부터 모듈 위에 올라온 전원 관리 칩. 메인보드가 아니라 모듈 자체에서 필요한 전압을 만들고 다스린다. |
| **(서버 모듈) RCD 레지스터 클록 드라이버 / 데이터 버퍼** | RDIMM은 주소·명령을 RCD가 한 번 받아 재구동(버퍼링)해 전기 부하를 줄여 랭크를 많이 꽂게 한다. LRDIMM은 데이터 라인까지 버퍼링해 초대용량을 지원한다. |
| **(모듈) 노치(키)·히트 스프레더·선택적 ECC 칩** | 노치는 세대·방향 오삽입을 막는 홈, 히트 스프레더는 방열, ECC 칩은 오류 검출·정정용 여분 폭을 제공한다(비ECC 64비트 → DDR4 ECC 72비트 / DDR5 ECC 80비트). |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **1T1C 셀 (1-Transistor 1-Capacitor cell)** | 트랜지스터 1개 + 커패시터 1개로 1비트를 저장하는 DRAM의 기본 구조. 구조가 단순해 매우 촘촘하게(고밀도) 집적되어 값이 싸다 — 그 대가가 리프레시 필요와 파괴적 읽기. |
| **DRAM (Dynamic Random Access Memory)** | 'Dynamic(동적)'은 주기적으로 리프레시해 값을 되살려야 한다는 뜻. 리프레시가 필요 없는 SRAM(정적)과 대비된다. 'Random Access'는 자기테이프 같은 순차매체와 달리 어느 주소든 직접 접근한다는 의미(실제 지연은 행 버퍼 히트/미스로 변동). |
| **리프레시 (Refresh)** | 새 나가는 커패시터 전하를 주기적으로 다시 채워 데이터를 유지하는 동작. 보통 보존시간(약 64ms, 고온 32ms) 안에 모든 행을 한 바퀴 돈다. 평균 간격 tREFI는 DDR4 약 7.8µs, DDR5는 약 3.9µs(행 수가 늘어 절반). |
| **RAS / CAS (Row / Column Address Strobe)** | 먼저 행 주소로 한 행을 통째로 열고(RAS/ACTIVATE), 그다음 열 주소로 그 안에서 원하는 조각을 고르는(CAS) 2단계 어드레싱. DRAM 접근이 '행 먼저, 열 나중'인 이유. (옛 비동기 DRAM은 /RAS·/CAS 전용 핀이었고, 지금 SDRAM은 명령으로 인코딩된다.) |
| **센스앰프 (Sense Amplifier) / 행 버퍼** | 비트라인의 미세 전압차를 0/1로 증폭·복원하고 열려 있는 한 행을 담아 두는 부분. 같은 행 재접근(행 버퍼 히트)이 빠른 근본 이유. |
| **n-비트 프리페치 (prefetch)** | 셀 배열의 내부 동작 속도는 I/O 핀 속도보다 훨씬 느리다. 그래서 한 번 접근에 내부에서 넓게(여러 비트를) 한꺼번에 읽어 I/O로 몰아 낸다 — DDR4는 8n, DDR5는 16n. 이 값이 곧 최소 버스트 길이(BL8/BL16)를 정한다. |
| **1차 타이밍 (CL-tRCD-tRP-tRAS)** | 램 스티커의 '30-38-38-96' 같은 숫자열. CL=READ→첫 데이터, tRCD=ACTIVATE→READ(행 열기), tRP=PRECHARGE(행 닫기), tRAS=행 최소 활성 유지. 모두 클럭 '주기 수'라 절대 지연(ns)은 클럭으로 나눠 봐야 한다. |
| **뱅크 / 랭크 / 채널** | 뱅크=독립적으로 행을 여닫는 배열 단위(칩 내부 병렬성). 랭크=하나의 CS 신호로 함께 응답하는 칩 묶음으로 한 번에 64비트 데이터폭을 낸다(ECC면 DDR4 72비트, DDR5는 서브채널당 40비트씩 총 80비트). 채널=컨트롤러와 메모리를 잇는 독립된 버스. |
| **듀얼채널 (Dual Channel)** | 독립 채널 2개를 함께 써 컨트롤러-메모리 사이 '차선'을 2배로 넓히는 구성. 용량이 아니라 대역폭이 늘어난다. (DDR5는 한 DIMM이 32비트 서브채널 2개로 나뉘어 그 자체로 채널 2개처럼 동작.) |
| **DIMM / SO-DIMM / UDIMM·RDIMM·LRDIMM** | DIMM=데스크톱용 긴 모듈, SO-DIMM=노트북용 짧은 모듈. 버퍼 유무로는 UDIMM(버퍼 없음), RDIMM(주소·명령을 RCD가 재구동해 서버가 랭크를 많이 꽂게 함), LRDIMM(데이터까지 버퍼링해 초대용량)으로 나뉜다. 양면 핀이 독립 신호라 'Dual In-line'. |
| **DDR (Double Data Rate)** | 클럭의 상승 엣지와 하강 엣지 양쪽에서 데이터를 전송하는 방식. 그래서 데이터율(MT/s)이 I/O 클럭(MHz)의 2배다. |
| **CAS Latency (CL)** | READ 명령을 준 뒤 첫 데이터가 나오기까지 걸리는 클럭 주기 수. 절대 지연(ns) = CL ÷ I/O 클럭. 숫자만으로 빠름/느림을 비교할 수 없고 클럭과 함께 봐야 한다. |
| **MT/s vs MHz** | MT/s(Mega Transfers per second)=초당 전송 횟수, MHz=클럭 주파수. DDR는 클럭당 2번 전송하므로 MT/s = MHz × 2. 'DDR5-6400'은 6400 MT/s이고 실제 I/O 클럭은 3200MHz. |
| **대역폭 vs 지연 (Bandwidth vs Latency)** | 대역폭=초당 옮기는 데이터 양(넓이), 지연=한 요청의 응답까지 걸리는 시간(빠름). 세대가 지나며 대역폭은 크게 늘었지만 절대 지연은 거의 정체(메모리 월). |
| **온다이 ECC(ODECC) vs 사이드밴드 ECC** | DDR5는 모든 칩이 내부에 ODECC(약 128비트당 8비트)를 의무 탑재해 칩 내부 결함을 스스로 정정한다(미세공정 수율용). 반면 서버용 ECC 모듈의 '사이드밴드 ECC'는 랭크당 여분 폭(+16비트)으로 버스 전송·모듈 전체 오류까지 잡는 별개 계층이다. 둘은 상호보완이라 ODECC가 있어도 무오류 환경은 여전히 ECC 모듈이 필요. |
| **로우해머 (Rowhammer)** | 특정 행을 매우 빠르게 반복 활성화하면 인접 행 커패시터가 전기적으로 교란돼 비트가 뒤집히는 물리적 취약점(보안 이슈). 대응책으로 TRR(Target Row Refresh), DDR5 JESD79-5C의 PRAC(행별 활성화 카운팅) 등이 도입됐다. |
| **휘발성 (Volatile)** | 전원이 끊기면 저장 내용이 사라지는 성질. 저장 매체가 유지 비용이 드는 '전하'이기 때문. SSD/플래시의 비휘발성과 대비된다. |
| **SPD / PMIC / ECC** | SPD(Serial Presence Detect)=모듈 사양·XMP/EXPO 프로필을 담아 부팅 시 자동 설정하게 하는 정보 칩. PMIC=모듈 전원관리 IC(DDR5부터). ECC(Error-Correcting Code)=비트 오류를 검출·정정하는 여분 폭. |

| CAS Latency (절대 지연) | DDR5-6000 CL30 ≈ 10 ns, DDR4-3200 CL16 ≈ 10 ns | 계산: CL ÷ I/O 클럭. 세대가 지나도 CAS 절대 지연은 대략 10~15ns 수준으로 정체 |
| 전체 랜덤 접근 지연 | 대략 50~90 ns | 행 활성화(tRCD)+CAS+데이터 등 합산. 다른 행을 열어야 하면 더 늘고, 행 버퍼 히트면 짧아짐 |
| 리프레시 간격 / 보존시간 | DDR4 tREFI ≈ 7.8µs, DDR5 tREFI ≈ 3.9µs / 보존 약 64ms | DDR5는 행 수가 늘어 all-bank 리프레시 간격이 절반. 약 85°C 초과 고온에서는 보존이 절반(≈32ms)으로 줄어 리프레시가 더 잦아짐 |
| ECC 데이터폭 | 비ECC 64비트 / DDR4 ECC 72비트 / DDR5 ECC 80비트(랭크당) | DDR5 사이드밴드 ECC는 32비트 서브채널마다 +8비트(=40비트)씩 2개. 여기에 더해 DDR5 전 칩은 약 128비트당 8비트 온다이 ECC를 의무 내장(별개 계층) |
| 뱅크 수 | DDR5 32뱅크 (8 뱅크그룹 × 4), DDR4 16뱅크 (4 × 4) | x4/x8 칩 기준. x16 칩은 뱅크그룹이 절반(DDR5 16뱅크, DDR4 8뱅크). 뱅크·뱅크그룹이 많을수록 병렬성과 실효 대역폭이 오름 |
| 버스트 길이 / 프리페치 | DDR5 BL16 (16n prefetch), DDR4 BL8 (8n prefetch) | DDR5는 32비트 서브채널 × 16비트 버스트 = 512비트 = 64바이트(캐시 라인 1개)를 한 번에 취득 |
| 모듈 핀 수 | DDR5 DIMM 288핀 / SO-DIMM 262핀, DDR4 DIMM 288핀 / SO-DIMM 260핀 | 핀 수가 같아도 노치(키) 위치와 핀 배치가 달라 DDR4/DDR5는 서로 꽂히지 않음 |
| 셀 커패시터 규모 | 펨토패럿(fF) 급, 셀 크기 약 6F² | F는 공정 최소 선폭. 커패시터 전하가 극히 작아 센스앰프 증폭이 필수 |
| 흔한 모듈 용량 | 모듈당 8~48 GB, 데스크톱 시스템 총 16~64 GB급 흔함 | DDR5는 24/48GB 같은 비2의거듭제곱 용량도 등장. 서버는 128GB+ 대용량 RDIMM/LRDIMM 사용 |

## ⚠️ 흔한 오해

- **오해** — RAM이 많을수록 컴퓨터가 무조건 빨라진다.
  <br>**교정** — 용량이 부족해 저장장치로 스와핑(swap)이 일어날 때만 큰 효과가 난다. 이미 충분하면 용량을 더 늘려도 속도는 거의 그대로 — 용량과 속도(대역폭·지연)는 별개의 축이다.
- **오해** — CAS Latency(CL) 숫자가 크면 그 램은 더 느리다.
  <br>**교정** — CL은 클럭 '주기 수'라 클럭이 빨라지면 자연히 커진다. 절대 지연(ns)=CL÷클럭으로 봐야 한다. DDR5-6000 CL30과 DDR4-3200 CL16은 둘 다 약 10ns로 실제 지연이 비슷하다.
- **오해** — DDR5-6400은 6400MHz로 동작한다.
  <br>**교정** — 실제 I/O 클럭은 절반인 3200MHz다. DDR는 클럭의 상승·하강 두 엣지에서 전송하므로 데이터율이 6400 MT/s가 된다. 'MT/s'와 'MHz'는 다른 단위다.
- **오해** — RAM은 파일을 저장하는 곳이다.
  <br>**교정** — DRAM은 휘발성이라 전원이 꺼지면 내용이 사라진다. 영구 저장은 SSD/HDD의 몫이고, RAM은 실행 중에만 쓰는 임시 작업대다. Ctrl+S가 필요한 이유가 여기 있다.
- **오해** — 듀얼채널은 메모리 용량이 2배가 된다.
  <br>**교정** — 늘어나는 건 용량이 아니라 대역폭(버스 폭)이다. 컨트롤러와 메모리 사이 통로를 2차선으로 만드는 것이라, 초당 옮길 수 있는 데이터 양이 커질 뿐 총 저장 용량은 합산 그대로다.
- **오해** — 한 번 써 놓은 DRAM 데이터는 그대로 유지된다.
  <br>**교정** — 커패시터 전하가 계속 새 나가 두면 수십 ms 안에 사라진다. 그래서 컨트롤러가 끊임없이 리프레시로 되살린다 — 이것이 'Dynamic'의 의미다.
- **오해** — 메모리를 읽어도 데이터는 그 자리에 그대로 남는다.
  <br>**교정** — DRAM 읽기는 파괴적이다. 읽는 순간 커패시터 전하가 소모되므로, 센스앰프가 매번 곧바로 같은 값을 다시 써 넣어(복원) 데이터를 지킨다.
- **오해** — RAM은 하나의 큰 평평한 배열이다.
  <br>**교정** — 실제로는 채널→랭크→뱅크그룹→뱅크→행/열로 잘게 나뉘어 여러 부분이 동시에 병렬로 일한다. 이 계층 구조 덕분에 개별 셀은 느려도 전체 대역폭이 높다.
- **오해** — DDR5는 칩마다 온다이 ECC가 있으니 서버에서도 따로 ECC 램이 필요 없다.
  <br>**교정** — 온다이 ECC(ODECC)는 칩 내부 미세결함을 감추는 수율용일 뿐, 버스 전송 오류나 모듈 전체를 지키지 못한다. 무오류가 필요한 서버는 여전히 별도 '사이드밴드 ECC' 모듈(랭크당 +16비트)을 써야 한다.

## 💡 비유

회의실 화이트보드 비유: SSD가 문서를 영구 보관하는 서류 캐비닛이라면, DRAM은 지금 진행 중인 회의에서 쓰는 넓은 화이트보드다. 여러 내용을 한눈에 펼쳐 두고 즉석에서 읽고 고칠 수 있지만(빠름·넓음), 회의가 끝나 지우면(전원 차단) 내용이 사라진다(휘발성). 캐비닛에 옮겨 적어 두는 행위가 바로 저장(Ctrl+S)이다. 커패시터 셀은 '물이 조금씩 새는 종이컵'에 비유할 수 있다 — 물이 차 있으면 1, 비면 0. 그냥 두면 새서 값이 지워지므로 주기적으로 다시 채워 주는데(리프레시), 컵의 물 높이가 너무 미세해 마이크로 증폭기(센스앰프)로 크게 키워야 읽을 수 있다.

- 부팅: 전원이 들어오면 BIOS/펌웨어가 각 모듈의 SPD를 읽어 용량·타이밍을 파악하고 메모리를 초기화(트레이닝)한 뒤, 커널과 드라이버를 SSD에서 DRAM으로 올려 실행 가능한 상태를 만든다. DRAM이 준비되지 않으면 아무 프로그램도 돌 수 없다.
- 게임 렌더링: 게임 실행 코드와 물리·AI 상태, 스트리밍할 에셋 원본이 시스템 DRAM에 상주하며 CPU가 프레임마다 읽어 처리한다. (대량 텍스처는 GPU의 별도 VRAM에 올라가지만, 그 원본을 쥐고 GPU로 넘기는 무대가 시스템 RAM이다. 프레임 드랍/로딩 끊김은 RAM 대역폭·용량과 직결.)
- 인터넷 검색 왕복: NIC가 받은 패킷과 브라우저가 조립한 웹페이지의 DOM·자바스크립트·이미지가 모두 DRAM에 담긴 채로 파싱·렌더링된다. 탭을 많이 열수록 이 작업 공간(RAM)을 많이 잡아먹는다.
- 파일 열기: SSD에서 읽어 온 파일 데이터가 DRAM의 페이지 캐시로 복사되어 앱이 접근한다. 한 번 열어 둔 파일을 다시 열면 SSD까지 가지 않고 RAM 캐시에서 바로 꺼내 빠르다.
- Ctrl+S 저장: 편집 중인 문서의 '진짜 원본'은 줄곧 휘발성 DRAM에 있다. 저장은 그 내용을 비휘발성 SSD로 내려쓰는 행위 — 저장 전에 정전되면 RAM의 내용이 사라진다는 점이 DRAM의 휘발성을 가장 체감시키는 장면이다.
- 소리 재생 / 영상 스트리밍: 디코딩된 오디오 샘플과 비디오 프레임이 DRAM의 버퍼에 놓여, CPU/GPU와 사운드·디스플레이 장치로 흐른다. 버퍼가 RAM에 충분히 쌓여 있어야 끊김 없이 재생된다.
- AI 질문: 로컬에서 모델을 돌리면 모델 가중치와 대화 문맥이 메모리에 로드되는데, 여기서는 지연보다 '대역폭'이 병목이 되어 DRAM의 대역폭 vs 지연 개념을 가장 극적으로 보여준다. (그래서 AI 가속기는 HBM 같은 초고대역폭 메모리를 쓴다.)
