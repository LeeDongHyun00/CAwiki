# SRAM (정적 램) — 레지스터·캐시
*SRAM (Static RAM) — Registers & Cache*

> 트랜지스터 래치로 1비트를 리프레시 없이 붙잡아 두는, CPU 코앞의 가장 빠른 메모리 — 레지스터 파일과 L1·L2·L3 캐시를 이룬다.

**분류**: 메모리

---

## 🧭 한마디로, 무슨 일을 하나
SRAM은 CPU가 매 클럭 손을 뻗는 극소량·초고속 저장소를 담당한다. 연산 유닛(ALU) 바로 옆의 레지스터 파일, 그리고 그 뒤를 받치는 L1/L2/L3 캐시가 모두 SRAM 계열로 만들어진다(단, 레지스터 파일은 동시 다중 읽기/쓰기를 위해 표준 단일포트 6T가 아니라 다중포트 셀 — 흔히 8T 이상 — 로 구성된다). 코어는 빠른데 주기억장치(DRAM)는 수백 사이클씩 느리다는 '메모리 벽' 문제를, 자주 쓰는 데이터를 코어 근처에 붙잡아 두어 메운다. 덕분에 대부분의 접근이 몇 사이클 안에 끝나고, 프로그램이 이론이 아니라 체감 속도로 돌아간다.

## ⚙️ 작동 방식

**1. CPU가 주소를 내고 계층의 맨 위부터 훑는다**

명령어가 어떤 데이터를 요구하면, 먼저 레지스터에 이미 있는지 확인한다(레지스터는 명령어가 이름으로 직접 지정하므로 태그·인덱스 탐색이 아니다). 없으면 그 값의 메모리 주소를 들고 L1 캐시부터 아래로 내려가며 찾는다. 위로 갈수록 빠르고 작으므로, 가장 빠른 곳부터 물어보는 것이 평균 대기 시간을 줄이기 때문이다.

**2. 주소를 오프셋·인덱스·태그로 쪼갠다**

캐시는 주소를 세 토막으로 해석한다. 하위 비트인 오프셋(offset)은 64바이트 라인 안에서 몇 번째 바이트인지(64바이트면 6비트), 그 위 인덱스(index)는 어느 세트(set)를 볼지, 나머지 상위 비트인 태그(tag)는 그 세트 안에서 이 라인이 진짜 내가 찾는 그 주소인지 판별하는 신분증이다. 실제 L1은 프로그램이 쓰는 주소가 가상 주소이므로, TLB로 물리 주소를 변환하는 동안 가상 주소 하위 비트로 세트를 먼저 인덱싱하는 VIPT(가상 인덱스·물리 태그) 방식으로 변환과 조회를 겹쳐 지연을 숨기는 경우가 많다.

**3. 인덱스로 세트를 골라 워드라인을 켠다**

행 디코더(row decoder)가 인덱스를 받아 해당 세트에 대응하는 워드라인(word line) 한 줄만 HIGH로 올린다. 그러면 그 줄에 매달린 SRAM 셀들의 접근 트랜지스터가 일제히 열려, 저장된 비트들이 세로 방향 비트라인(bit line)에 연결된다. 원하는 한 줄만 정확히 여는 것이 임의 접근(random access)의 핵심이다.

**4. 6T 셀이 비트라인을 살짝 기울이고 감지증폭기가 읽어낸다**

읽기 전 두 비트라인(BL과 반전선 BL̄)을 함께 HIGH로 프리차지(precharge)해 둔다. 워드라인이 열리면 셀의 교차결합 인버터 중 '0'을 붙든 쪽이 자기 비트라인을 아주 조금 끌어내려 두 선 사이에 미세한 전압 차가 생긴다. 감지증폭기(sense amplifier)가 이 작은 차이를 즉시 완전한 0/1로 증폭한다. DRAM 읽기는 커패시터 전하를 방전시켜 값을 파괴하므로 읽은 뒤 되써야 하지만, SRAM은 래치가 스스로 값을 계속 유지하므로 읽어도 값이 파괴되지 않아 되쓰기가 필요 없고 그래서 빠르다.

**5. 태그를 비교해 적중/부적중을 판정한다**

세트에서 꺼낸 각 라인의 저장된 태그를, 주소의 태그와 비교기(comparator)로 동시에 맞춰 본다. 유효비트(valid bit)가 1이고 태그가 일치하는 라인이 있으면 캐시 적중(hit), 하나도 없으면 캐시 부적중(miss)이다. 집합연관(N-way)에서는 한 세트의 N개 후보를 병렬로 비교하므로, 직접사상보다 자리싸움(충돌 부적중)이 줄어든다. 태그 어레이는 데이터 어레이와 병렬로 읽혀 지연을 숨긴다.

**6. 적중이면 오프셋으로 바이트를 골라 즉시 돌려준다**

일치한 라인(=원하는 64바이트 블록)에서, 오프셋이 필요한 바이트(들)를 열 멀티플렉서로 선택해 CPU로 보낸다. L1 적중이면 대략 4~5사이클(약 1ns 안팎) 만에 값이 도착해, 코어는 거의 멈추지 않는다.

**7. 부적중이면 아래 계층으로 내려가 라인 전체를 인출한다**

L1이 없으면 L2, 그래도 없으면 L3, 최후엔 DRAM으로 요청이 내려간다. 이때 요청한 1바이트만이 아니라 그 바이트가 속한 캐시 라인(보통 64바이트) 전체를 통째로 끌어올린다(공간 지역성 가정). 논블로킹 캐시는 이 대기 중에도 코어를 멈추지 않는다 — 미해결 부적중을 MSHR(Miss Status Handling Register)에 기록해 두고, 독립적인 다른 명령을 계속 실행하며(hit-under-miss/miss-under-miss), 여러 부적중을 동시에 처리한다.

**8. 교체 정책이 희생 라인을 고르고, 필요하면 6T 셀에 새 값을 강제로 쓴다**

세트가 이미 꽉 찼으면 어떤 라인을 내보낼지 교체 정책(예: LRU 근사)이 정한다. 내보낼 라인이 수정됨(dirty) 상태면 하위 계층에 먼저 되쓴다(라이트백). 쓰기 자체는 쓰기 드라이버(write driver)가 비트라인을 강하게 반대 값으로 몰아붙여 셀의 되먹임을 이겨내고 래치를 뒤집는 방식이다. 새 라인을 설치하고 태그·유효·LRU 상태를 갱신하면 다음 접근부터는 적중이 된다. 멀티코어에서는 다른 코어의 사본과 어긋나지 않도록 캐시 일관성 프로토콜(MESI 등)이 이 상태 변화를 함께 조율한다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **교차결합 인버터 쌍 (cross-coupled inverters, 래치)** | 인버터 두 개의 출력을 서로의 입력에 물려 만든 쌍안정 회로(트랜지스터 4개). 1비트를 두 가지 안정 상태(Q=1/Q̄=0 또는 그 반대)로 붙들며, 전원이 켜져 있는 한 되먹임으로 값을 스스로 지탱한다. 셀의 심장이다. |
| **접근(패스) 트랜지스터 2개** | 래치의 두 내부 노드(Q, Q̄)를 각각 비트라인에 연결하는 문지기. 워드라인이 열릴 때만 통해서, 평소엔 셀을 외부와 격리해 값을 보호하고 접근 시에만 읽기·쓰기를 허용한다. 인버터 2개(트랜지스터 4개) + 접근 트랜지스터 2개 = 6T 셀. |
| **워드라인 (word line, 행 선택선)** | 한 행(같은 인덱스의 셀들)의 접근 트랜지스터를 동시에 여닫는 가로선. 디코더와 워드라인 드라이버가 딱 한 줄만 활성화해 접근할 행을 지정한다. |
| **비트라인 쌍 (bit line, BL / BL̄)** | 셀에서 데이터를 실어 나르는 세로선 두 가닥(참·반전). 읽을 땐 셀이 만든 미세 전압차를 감지증폭기로, 쓸 땐 드라이버가 몬 값을 셀로 전달하는 통로다. |
| **행 디코더 (row decoder)** | 주소의 인덱스 비트를 받아 수많은 워드라인 중 정확히 하나만 HIGH로 만든다. n비트 인덱스를 2ⁿ개의 행 선택으로 변환한다. |
| **열 디코더 / 멀티플렉서 (column decoder/mux)** | 활성화된 행에서 나온 여러 열 중 실제로 읽거나 쓸 열(오프셋에 해당하는 바이트/워드)을 골라 입출력 경로에 연결한다. |
| **프리차지 회로 (precharge)** | 읽기 직전 두 비트라인을 같은 HIGH 전압으로 미리 충전해 균형을 맞춘다. 이 균형이 있어야 셀이 만드는 작은 불균형을 감지증폭기가 빠르고 정확히 읽는다. |
| **감지 증폭기 (sense amplifier)** | 비트라인 사이의 수십 mV 수준 미세 차이를 완전한 0/1 로직 레벨로 순식간에 증폭한다. SRAM이 빠른 큰 이유 중 하나 — 셀이 비트라인을 끝까지 흔들 때까지 기다리지 않는다. |
| **쓰기 드라이버 (write driver)** | 쓸 값을 비트라인에 강하게 실어, 셀의 자기유지 되먹임을 힘으로 눌러 래치를 원하는 상태로 뒤집는다. 셀 트랜지스터 크기(쓰기 용이성)와 균형을 이뤄야 한다. |
| **데이터 어레이 (data array)** | 실제 캐시 라인(예: 64바이트) 데이터를 담는 SRAM 셀들의 본체. 캐시 용량의 대부분을 차지한다. |
| **태그 어레이 (tag array)** | 각 라인의 상위 주소(태그)를 저장하는 별도의 작은 SRAM. 부적중/적중 판정에 쓰이며, 데이터 어레이와 병렬로 읽혀 지연을 줄인다. |
| **유효비트·수정비트·일관성 상태 비트 (valid / dirty / coherence state)** | 유효비트는 라인에 진짜 데이터가 들었는지, 수정비트는 값이 바뀌어 하위 계층과 달라졌는지(라이트백 필요 여부)를 표시한다. 멀티코어 캐시는 여기에 MESI 등 일관성 상태(Modified/Exclusive/Shared/Invalid)도 함께 둔다. |
| **태그 비교기 (comparator)** | 세트 안 각 후보 라인의 저장 태그와 요청 주소 태그를 동시에 비교해 일치 여부를 내보낸다. 완전연관·고연관일수록 비교기가 많이 필요해 비싸진다. |
| **교체 상태 비트 (LRU / pseudo-LRU state)** | 집합연관 캐시에서 한 세트 안 라인들의 최근 사용 순서를 근사해 기록한다. 부적중 시 어느 라인을 내보낼지 교체 정책이 이 비트로 결정한다. |
| **MSHR (미해결 부적중 처리 레지스터)** | 논블로킹 캐시가 진행 중인 부적중 요청들을 추적하는 작은 표. 부적중이 나도 코어를 멈추지 않고 다른 명령을 계속 실행하며, 여러 부적중을 동시에 처리하고 도착한 데이터를 대기 중인 명령에 되돌려 준다. |
| **쓰기(스토어) 버퍼 (store/write buffer)** | 쓰기 요청을 잠시 담아 두어, 코어가 하위 계층 쓰기 지연을 기다리지 않고 진행하게 한다. 라이트백·라이트스루 트래픽을 흡수·병합한다. |
| **ECC·패리티 로직 (error correction / parity)** | 미세 공정에서 늘어나는 소프트 에러(비트 뒤집힘)를 검출·정정한다. 큰 캐시(특히 L2/L3)는 SECDED 같은 ECC로, 일부 L1은 패리티로 보호한다. |
| **출력 드라이버·래치** | 감지·선택된 데이터를 안정된 신호로 정형해 코어(또는 상위 캐시)로 내보낸다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **6T SRAM 셀 (6-Transistor cell)** | SRAM 1비트의 표준 구조. 교차결합 인버터 2개(각 인버터 = PMOS 1 + NMOS 1, 합쳐 트랜지스터 4개) + 접근 트랜지스터 2개 = 총 6개. 커패시터가 없어 전원만 있으면 값을 유지한다. 밀도를 위한 4T, 안정성·다중포트를 위한 8T·10T 변형도 있다(레지스터 파일은 다중포트가 필요해 흔히 8T 이상). |
| **교차결합 인버터 / 쌍안정 (cross-coupled inverters, bistable)** | 두 인버터의 출력을 서로의 입력에 연결한 정귀환(positive feedback) 고리. 상태가 두 개(0/1)뿐이고 어느 쪽이든 스스로를 강화해 안정적으로 굳는다. SRAM이 리프레시 없이 값을 붙드는 원리다. |
| **리프레시 불필요 (refresh-free) / 정적(static)** | DRAM은 커패시터의 전하가 새어 나가므로 각 행을 주기적으로(대개 셀 보존시간 약 64ms 이내, 고온에선 32ms; 리프레시 명령은 tREFI 약 7.8µs 간격) 다시 읽고 써 주는 리프레시가 필요하다. SRAM의 'static'은 그 주기적 재기록이 필요 없다는 뜻이다. 접근이 빠르고 대기 전력 관리가 단순해지는 이유. |
| **휘발성 (volatile)** | SRAM도 DRAM과 마찬가지로 전원이 끊기면 값이 사라진다. '정적'은 비휘발성이 아니다. 전원이 없어도 남는 것은 플래시·ROM 같은 비휘발성 메모리다. |
| **캐시 라인 (cache line / block)** | 캐시와 하위 메모리 사이에서 오가는 최소 전송 단위. 보통 64바이트(애플 실리콘 등 일부는 128바이트). 1바이트가 필요해도 라인 전체를 가져오는데, 근처 데이터도 곧 쓸 것이라는 지역성 때문이다. |
| **연관도 (associativity)** | 한 메모리 블록이 캐시의 어디에 들어갈 수 있는가. 직접사상(direct-mapped, 자리 1곳), 집합연관(N-way set-associative, 세트 안 N곳 중 아무 데나), 완전연관(fully associative, 아무 데나). 연관도가 높을수록 충돌 부적중이 줄지만 비교기·전력·지연 비용이 커진다. |
| **태그·인덱스·오프셋 (tag / index / offset)** | 주소를 캐시가 해석하는 세 토막. 오프셋=라인 내 바이트 위치, 인덱스=어느 세트를 볼지, 태그=그 자리에 든 게 정말 이 주소인지 확인하는 상위 주소. 캐시 검색의 좌표계다. |
| **VIPT / 가상·물리 주소지정과 TLB** | 프로그램이 쓰는 가상 주소를 물리 주소로 바꾸는 것이 TLB(Translation Lookaside Buffer). L1 캐시는 흔히 VIPT(가상 인덱스·물리 태그)로, 가상 주소 하위 비트로 세트를 인덱싱하는 동안 TLB 변환을 병렬 수행해 태그 비교 직전에 물리 태그를 얻는다 — 변환 지연을 조회에 겹쳐 숨긴다. |
| **적중 / 부적중 (hit / miss)** | 적중은 찾는 데이터가 캐시에 있는 경우, 부적중은 없어 하위 계층에서 가져와야 하는 경우. 부적중은 최초(compulsory)·용량(capacity)·충돌(conflict), 그리고 멀티코어에서 다른 코어가 무효화해 생기는 일관성(coherence)까지 4C로 나뉜다. 적중률이 성능을 좌우한다. |
| **논블로킹 캐시 / MSHR** | 부적중이 나도 코어를 멈추지 않는 캐시. 진행 중 부적중을 MSHR에 기록하고 독립 명령을 계속 실행하며(hit-under-miss, miss-under-miss), 여러 부적중을 동시에 처리한다. 비순차(out-of-order) 실행의 메모리 병렬성을 살리는 핵심. |
| **교체 정책 (replacement policy)** | 세트가 꽉 찼을 때 어느 라인을 내보낼지 정하는 규칙. LRU(가장 오래 안 쓴 것 축출)가 대표적이고, 하드웨어 비용 때문에 실제로는 근사한 pseudo-LRU나 FIFO·랜덤도 쓴다. |
| **라이트백 / 라이트스루 / 쓰기할당** | 쓰기 반영 방식. 라이트백은 일단 캐시에만 쓰고 수정비트를 세운 뒤 축출 시 하위로 내려보내 대역폭을 아낀다. 라이트스루는 매번 하위까지 즉시 쓴다. 부적중 쓰기 시 라인을 먼저 올릴지(write-allocate)/안 올릴지(no-write-allocate)도 함께 정한다. 현대 대용량 캐시는 대개 라이트백+쓰기할당. |
| **캐시 일관성 (cache coherence, MESI)** | 여러 코어가 같은 주소를 각자 캐시에 두면 사본이 어긋날 수 있다. MESI(Modified/Exclusive/Shared/Invalid) 같은 프로토콜이 스누핑(버스 감시)이나 디렉터리로 각 사본의 상태를 조율해, 한 코어가 쓰면 다른 코어의 사본을 무효화·갱신한다. 공유 L3와 멀티코어 정합성의 토대. |
| **캐시 계층 포함성 (inclusive / exclusive / NINE)** | 상위 캐시 내용이 하위에도 반드시 들어있는지의 정책. 포함(inclusive)은 일관성 검사·무효화가 단순하지만 용량 중복이 있고, 배제(exclusive)는 유효 용량을 늘리며, 둘 다 강제하지 않는 NINE도 있다. |
| **감지 증폭기 (sense amplifier)** | 비트라인의 미세 전압차를 완전한 로직 레벨로 빠르게 증폭하는 회로. 셀이 비트라인을 끝까지 흔들기를 기다리지 않고 읽을 수 있게 해 접근 지연을 줄인다. |
| **지역성 (locality)** | 프로그램의 접근 패턴이 한곳에 몰리는 경향. 방금 쓴 주소를 곧 또 쓰는 시간 지역성(temporal), 근처 주소를 잇따라 쓰는 공간 지역성(spatial). 캐시 라인·계층 구조가 성립하는 근본 이유다. |
| **아키텍처 레지스터 vs 물리 레지스터 (레지스터 리네이밍)** | 명령어가 이름으로 지정하는 x86-64 16개·ARM64 31개는 '아키텍처' 레지스터다. 비순차 실행 CPU는 거짓 의존을 없애려 이를 훨씬 많은 '물리' 레지스터(정수·벡터 각각 수백 개)에 리네이밍해 매핑한다. 레지스터 파일 자체가 다중포트 SRAM 배열이다. |
| **정적 잡음 여유 (SNM, Static Noise Margin)** | 6T 셀이 읽는 중에도 저장값이 뒤집히지 않고 버티는 안정성 척도. 공정이 미세해지고 전압이 낮아질수록 확보가 어려워, 셀 트랜지스터 크기 비율과 8T 같은 구조로 대응한다. |

## 📊 대표 사양·수치 감각

| 항목 | 값 | 비고 |
|---|---|---|
| 셀당 트랜지스터 수 | 6개 (6T) | DRAM은 1트랜지스터+1커패시터(1T1C). 이 차이가 SRAM이 빠르고(래치·리프레시 불필요) 비싼(면적·저밀도) 근본 원인이다. 다중포트 레지스터 파일은 8T 이상. |
| 고밀도 셀 면적 (선단 공정) | 대략 0.02 μm² 안팎 | TSMC 5nm급 고밀도 SRAM 셀이 약 0.021 μm², 3nm급도 약 0.0199 μm²로 최근 SRAM 미세화가 로직보다 뚜렷이 더뎌졌다. 공정별 편차가 크므로 '대략'. |
| 레지스터 (범용) | 아키텍처: x86-64 64비트 16개 / ARM64(AArch64) 64비트 31개(X0–X30) | 이는 명령어가 이름으로 지정하는 아키텍처 수. 실제 물리 레지스터 파일은 리네이밍으로 수백 개(정수·벡터 각 ~180~300+). 벡터는 별도: x86 AVX-512 512비트 32개, ARM AArch64 SIMD 128비트 32개(SVE는 가변 폭). Intel APX는 범용 레지스터를 32개로 확장. |
| L1 캐시 용량 (코어당) | 대략 32~64 KB (명령 L1i·데이터 L1d 분리) | x86은 대개 명령/데이터 각 32~48 KB. 애플 실리콘 성능 코어는 L1d 128 KB·L1i 192 KB, 라인 128바이트로 크다. 세대·설계마다 다름. |
| L1 접근 지연 | 대략 4~5 사이클 (약 1 ns 안팎) | 코어 클럭과 동급 속도. 적중 시 파이프라인이 거의 멈추지 않는다. |
| L2 캐시 용량 / 지연 | 코어당 약 256 KB ~ 2 MB(전용) / 대략 10~20 사이클 | 코어 전용이 일반적이나, 애플은 성능 클러스터가 큰 L2를 공유. 최근 x86 설계는 L2를 1.25~2 MB로 키우는 추세. |
| L3 캐시 용량 / 지연 | 공유 약 4 MB ~ 수십 MB(3D 적층은 100 MB 안팎) / 대략 30~60+ 사이클(약 10~20 ns) | 여러 코어가 공유(설계에 따라 CCX/클러스터 단위). AMD 3D V-Cache처럼 실리콘을 쌓아 코어 콤플렉스 L3를 90~130 MB급으로 키운 예도 있다. 값은 세대별 편차 큼. |
| 주기억장치(DRAM) 지연 — 대조용 | 약 60~100 ns (수백 사이클) | L1보다 두 자릿수 느리다. 이 격차를 메우려고 SRAM 캐시 계층이 존재한다. |
| 캐시 라인 크기 | 일반적으로 64바이트 (일부 128바이트) | 캐시↔메모리 전송·정렬의 기본 단위. 애플 실리콘 등 일부는 128바이트. |
| 동작 전압 | 대략 0.6~1.1 V | 코어 전압대에서 동작하며, SNM 확보를 위해 SRAM 어레이에 별도(대개 약간 높은) 전압 레일을 두기도 한다. 전압을 낮추면 전력은 주나 셀 안정성(SNM)이 나빠져 하한이 있다. |
| 동작 클럭 | 코어와 동일 (최대 약 5~6 GHz) | L1은 코어 클럭에 맞춰 동작. 하위 캐시(L2/L3)로 갈수록 상대적으로 여유 있게 동작하기도 한다. |

## ⚠️ 흔한 오해

- **오해** — 'Static(정적)'이니까 전원을 꺼도 값이 남는 비휘발성 메모리다.
  <br>**교정** — 아니다. SRAM도 전원이 끊기면 값이 사라지는 휘발성 메모리다. 'static'은 '리프레시가 필요 없다'는 뜻일 뿐이다. 전원 없이 남는 건 플래시·ROM이다.
- **오해** — SRAM은 아주 작은 커패시터에 전하로 비트를 저장한다.
  <br>**교정** — 그건 DRAM이다. SRAM은 커패시터 없이 교차결합 트랜지스터 래치의 안정 상태로 비트를 저장한다. 그래서 전하가 새지 않아 리프레시가 필요 없다.
- **오해** — SRAM 1비트는 트랜지스터 1개면 된다.
  <br>**교정** — 표준은 6개(6T)다. 교차결합 인버터 2개(=트랜지스터 4개) + 접근 트랜지스터 2개. 이 많은 트랜지스터가 SRAM을 빠르지만 비싸고 밀도가 낮게 만든다. (밀도용 4T, 안정성·다중포트용 8T·10T 변형도 존재)
- **오해** — 캐시는 크면 클수록 무조건 빠르다.
  <br>**교정** — 용량과 지연은 상충한다. 배열이 커지면 배선·디코딩·용량성 부하가 늘어 접근이 느려진다. 그래서 작고 빠른 L1 위에 크고 느린 L2·L3를 쌓는 계층 구조를 쓴다.
- **오해** — 캐시는 CPU와 별개인 외부 부품/칩이다.
  <br>**교정** — 현대 CPU에서 L1·L2·L3 캐시는 모두 같은 다이(칩) 안에 통합돼 있다. 과거(예: 초기 펜티엄 시절)엔 L2가 외부에 있기도 했지만, 지금은 온다이가 표준이다(단 AMD 3D V-Cache처럼 별도 SRAM 다이를 코어 다이 위에 3D 적층하는 형태도 있다).
- **오해** — 무엇을 캐시에 둘지는 프로그래머나 OS가 직접 정한다.
  <br>**교정** — 일반적인 CPU 캐시는 하드웨어가 자동·투명하게 관리한다. 소프트웨어는 프리페치 힌트나 접근 패턴(캐시 친화적 코드)으로 간접 영향만 준다. 명시적으로 관리하는 온칩 SRAM은 스크래치패드/GPU 공유메모리 같은 별도 개념이다.
- **오해** — 레지스터는 그냥 캐시 계층의 맨 위 캐시일 뿐이다.
  <br>**교정** — 기능상 저장 계층의 최상위인 건 맞지만 관리 방식이 다르다. 레지스터는 명령어가 이름(예: RAX)으로 직접 지정하는 명시적 저장소이고, 캐시처럼 태그·인덱스로 주소를 대조해 찾지 않는다. 또 리네이밍으로 아키텍처 이름이 훨씬 많은 물리 레지스터에 매핑된다.
- **오해** — SRAM은 정적이라 읽어도 다시 쓸 필요가 없듯, DRAM도 읽기만 하면 값이 그대로다.
  <br>**교정** — DRAM 읽기는 파괴적이다. 커패시터 전하를 감지선으로 흘려 읽으므로 읽은 직후 같은 값을 되써야 한다. 비파괴 읽기는 래치로 값을 유지하는 SRAM의 특성이다.

## 💡 비유

계층 구조는 작업 공간에 비유할 수 있다. 손에 쥔 펜(레지스터) — 책상 위(L1) — 책상 서랍(L2) — 사무실 공용 캐비닛(L3) — 시 외곽 물류창고(DRAM). 가까울수록 순식간에 꺼내지만 담을 수 있는 양이 적고, 멀수록 많이 담지만 다녀오는 데 오래 걸린다. 6T 셀은 서로를 붙잡아 세우는 두 사람에 비유된다 — 한 사람이 '참'이라 서면 상대가 '거짓'으로 굳어 서로를 지탱하는 안정된 자세(래치)다. DRAM은 계속 물을 부어야 하는 새는 양동이라면, SRAM은 한 번 딸깍 고정되면 그대로 있는 걸쇠(latch)에 가깝다. 여러 사람이 같은 서류의 사본을 나눠 들 때 누가 고치면 서로 알려 맞추는 규칙이 캐시 일관성(MESI)이다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 부팅(boot): CPU가 부트 코드를 실행하는 첫 순간부터 모든 명령어·데이터가 레지스터와 L1~L3 캐시를 거친다. 처음엔 캐시가 비어 부적중(콜드 미스)이 잦다가, 반복 코드가 채워지며 캐시가 '데워져' 점점 빨라진다.
- 게임 렌더링(game): 프레임마다 도는 물리·변환 계산의 뜨거운 루프와 자료 구조가 L1·L2에 얼마나 잘 얹히느냐가 프레임레이트를 좌우한다. 캐시 부적중이 잦으면 코어가 DRAM을 기다리며 놀아 프레임이 떨어진다(논블로킹 캐시가 일부 지연을 겹쳐 숨긴다).
- 인터넷 검색 왕복(search): 브라우저·자바스크립트 엔진이 HTML 파싱과 TLS 암호 연산을 레지스터에서 돌리고, 작업 집합(working set)을 캐시에 유지한다. 캐시 적중률이 페이지 응답의 체감 속도를 크게 바꾼다.
- 파일 열기·저장(storage, Ctrl+S): 파일 메타데이터와 버퍼가 캐시에 올라오고, 직렬화·체크섬 루프가 레지스터에서 데이터를 훑어 처리한다. 디스크로 나가기 전 대부분의 가공이 SRAM 계층 위에서 일어난다.
- AI 질문: 거대한 행렬 곱을 캐시 라인 크기와 캐시 용량에 맞춰 잘게 쪼개(타일링/블로킹) 돌린다. 레지스터가 누산기(accumulator)를 붙들고, 타일이 L1·L2에 머무는 동안 재사용을 최대화하는 것이 연산 처리량의 핵심이다.
- 영상 스트리밍: 디코딩 루프가 참조 프레임 블록을 캐시에 유지하며 픽셀을 처리한다. 접근 패턴이 캐시 친화적일수록 같은 코어로 더 높은 해상도·프레임레이트를 재생할 수 있다.
