# 보조 프로세서·마이크로컨트롤러
*Co-processors & Microcontrollers*

> 메인 CPU를 도와 특정 작업 한 가지를 저전력·실시간으로 전담하는, 시스템 곳곳에 숨은 '작은 완결형 컴퓨터'들(SSD 컨트롤러·웹캠 ISP·오디오 DSP·임베디드 컨트롤러·키보드 MCU·NPU 등).

**분류**: 연산

---

## 🧭 한마디로, 무슨 일을 하나
컴퓨터는 사실 '컴퓨터 한 대'가 아니라, 메인 CPU를 중심으로 수십 개의 작은 컴퓨터가 협업하는 연합체다. 보조 프로세서와 마이크로컨트롤러(MCU)는 SSD·웹캠·키보드·전원부·팬 같은 곳에 숨어, 특정한 일 한 가지를 저전력·실시간·저비용으로 전담한다. 이들이 반복적이고 전용적인 잔일을 떠맡아 주기 때문에 메인 CPU는 범용 계산에 집중할 수 있고, 물리적으로 가까운 곳에서 처리되어 버스 왕복이 줄며, 심지어 메인 CPU가 꺼진 상태에서도 일부 기능(전원 버튼 감시·배터리 충전·시계(RTC) 유지)이 계속 살아 있게 된다.

## ⚙️ 작동 방식

**1. 전원 인가와 리셋 벡터에서 펌웨어 시작**

MCU도 작은 컴퓨터라 자기만의 부팅을 한다. 공급 전압이 안정되면(브라운아웃 리셋 회로가 확인) 내부 리셋이 풀리고, CPU 코어가 정해진 '리셋 벡터'(내장 플래시/ROM의 고정 주소)에서 첫 명령을 가져온다. 예컨대 ARM Cortex-M은 벡터 테이블의 첫 워드에서 초기 스택 포인터, 둘째 워드에서 리셋 핸들러 주소를 읽어 시작한다. 이 코드가 바로 펌웨어다. 외장 저장장치도 DRAM도 없이, 칩 안에 구운 프로그램으로 곧장 실행이 시작되는 것이 범용 CPU와의 큰 차이다.

**2. 클럭 생성과 주변장치 초기화**

내장 오실레이터(RC 또는 크리스털)가 기준 박자를 만들고 필요하면 PLL로 체배해 코어 클럭을 얻는다. 이어 펌웨어가 GPIO 핀 방향, 타이머, ADC/DAC, 통신 인터페이스(UART·SPI·I2C·I2S·USB) 레지스터를 설정한다. 인터럽트 벡터 테이블을 등록해 '어떤 사건이 오면 어느 함수로 점프할지'를 미리 정해 둔다. 이 준비가 끝나야 실제 일을 받을 수 있다.

**3. 메인 루프에서 이벤트를 기다림(대부분은 잠들어 있음)**

임베디드 펌웨어의 전형은 '무한 루프 + 인터럽트'(베어메탈 슈퍼루프)이며, 복잡한 경우 RTOS가 여러 태스크를 스케줄링한다. 할 일이 없으면 코어는 저전력 슬립(예: ARM의 WFI 명령)으로 들어가 전력을 거의 안 쓰며 기다린다. 키 눌림, 타이머 만료, ADC 변환 완료, 패킷 도착 같은 사건이 인터럽트를 발생시키면 즉시 깨어난다. '평소엔 자다가 사건이 오면 번쩍 깬다'는 이 구조가 저전력·실시간의 핵심이다.

**4. 신호·데이터 획득**

주변장치가 바깥 세계의 아날로그/디지털 입력을 디지털 샘플로 바꿔 들여온다. 오디오 DSP는 코덱의 ADC가 초당 약 48,000회(48kHz) 샘플링한 값을 I2S로 받고, 웹캠 ISP는 이미지 센서의 원시 픽셀(Bayer 패턴)을 보통 MIPI CSI-2로 받고, 키보드 MCU는 키 매트릭스의 행·열을 주기적으로 스캔하며, SSD 컨트롤러는 메인 CPU로부터 'LBA 블록을 읽/써라'는 NVMe 명령을 받는다. 종종 DMA가 CPU 코어를 거치지 않고 이 데이터를 내부 SRAM 버퍼로 직접 나른다.

**5. 전용 연산 — 각 칩의 특성이 드러나는 단계**

여기서 '전용 처리'의 정체가 보인다. DSP는 MAC(곱셈-누산) 하드웨어로 acc += b×c를 한 클럭에 처리해 FIR 필터·FFT·에코 제거를 실시간으로 돌리고, 고정소수점 연산으로 지연을 일정하게 유지한다. ISP는 디모자이킹·화이트밸런스·노이즈 제거·감마 보정을 고정기능 파이프라인으로 흘려보낸다. SSD 컨트롤러는 FTL 주소 매핑, ECC 오류정정(현대엔 LDPC), 웨어 레벨링, 가비지 컬렉션을 수행한다. 공통점은 '정해진 마감시간 안에 반드시 끝낸다'는 실시간 제약이다.

**6. 결과 출력과 상위 시스템에 통지**

처리 결과를 다음 단계로 내보낸다. 오디오 DSP는 DAC로 아날로그 파형을 만들어 앰프·스피커로, ISP는 정돈된 프레임을 메모리/USB로, 키보드 MCU는 키코드(HID Usage ID)를 USB HID 리포트로 호스트에(레거시 PS/2 스캔코드가 아니며, 실제 문자 매핑은 호스트 OS가 담당), SSD 컨트롤러는 NAND 셀의 플로팅 게이트/차지 트랩에 전하를 저장하고 완료를 알린다. 메인 CPU와는 인터럽트를 걸거나 공유 메모리/레지스터에 플래그를 세워 '끝났다'고 알린다.

**7. 저전력 대기로 복귀(그리고 상시 감시)**

일이 끝나면 다시 슬립으로 돌아가 다음 사건을 기다린다. 특히 노트북의 임베디드 컨트롤러(EC)는 시스템이 완전히 꺼진 상태(ACPI S5)에서도 대기 전원(standby rail)으로 계속 깨어, 전원 버튼·뚜껑 센서·충전 회로·팬·온도를 감시한다. 이때 소비 전류는 구현과 대기 레일 구성에 따라 대략 수 µA~수 mA 수준으로 매우 낮다. 그래서 전원 버튼을 누르는 순간 시스템을 다시 깨울 수 있고, 꺼진 노트북도 배터리 충전이 관리된다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **CPU 코어(연산 코어)** | 명령을 실행하는 두뇌. 임베디드에선 ARM Cortex-M, RISC-V, 옛 8051, AVR, MSP430 같은 작고 단순한 코어를 쓴다. 참고로 8051·AVR·다수 DSP는 명령/데이터 버스를 분리한 하버드 계열이며, 하버드는 DSP만의 특징이 아니다. |
| **프로그램 메모리(ROM / 내장 플래시)** | 펌웨어를 저장하는 비휘발성 메모리. 전원이 꺼져도 지워지지 않아, 켜자마자 여기서 곧바로 코드를 실행한다. 플래시는 재기록 가능해 펌웨어 업데이트가 된다(진짜 고정된 마스크 ROM은 일부에 불과). |
| **데이터 메모리(내장 SRAM)** | 실행 중 변수·스택·입출력 버퍼를 담는 휘발성 작업 공간. 외장 DRAM 없이 칩 안의 이 SRAM만으로 동작하는 경우가 많다. |
| **클럭 시스템(오실레이터 + PLL)** | 칩 전체의 동작 박자를 만든다. 저속 오실레이터를 PLL로 체배해 코어 클럭을 얻고, 필요 없을 땐 클럭을 늦추거나 꺼서(클럭 게이팅) 전력을 아낀다. |
| **실시간 시계(RTC)** | 저전력 별도 도메인에서 초·분·시를 계속 세는 시계. 시스템이 꺼진 상태에서도 코인셀/대기 전원으로 동작해 날짜·시각을 유지하고, 예약 알람으로 시스템을 깨우는 웨이크업 소스가 된다. |
| **타이머/카운터 · 워치독 타이머** | 시간을 재고 주기적 인터럽트를 발생시키며 PWM(모터·백라이트·팬 제어) 신호를 만든다. 워치독은 펌웨어가 제때 '살아있다' 신호(kick)를 안 주면 칩을 강제 리셋해 멈춤에서 복구한다. |
| **인터럽트 컨트롤러(예: ARM NVIC)** | 여러 사건에 우선순위를 매겨, 급한 일이 오면 진행 중이던 코드를 멈추고 해당 처리 루틴으로 즉시 점프시킨다. 실시간 반응성의 관제탑. |
| **GPIO(범용 입출력 핀)** | 칩과 바깥 회로를 잇는 디지털 신호선. 버튼·LED·릴레이·다른 칩의 제어선을 읽고 쓴다. |
| **통신 주변장치(UART·SPI·I2C·I2S·USB·CAN)** | 다른 칩·센서·호스트와 표준 규약으로 데이터를 주고받는 하드웨어 블록. 코어가 비트/바이트 단위로 씨름하지 않도록 직렬 통신을 자동 처리한다. |
| **ADC / DAC(아날로그-디지털 변환기)** | 센서의 아날로그 전압을 디지털 숫자로(ADC), 디지털 값을 아날로그 파형으로(DAC) 변환. 마이크·온도센서·오디오 출력의 관문이다(저가 MCU는 ADC만 있고 DAC는 없는 경우도 많다). |
| **MAC 유닛(하드웨어 곱셈-누산기)** | DSP의 심장. 곱셈과 덧셈을 한 연산으로 묶어 필터·FFT·행렬곱을 한 클럭에 한 단계씩 진행시킨다. 신호처리가 실시간으로 가능한 이유. |
| **DMA 컨트롤러** | CPU 코어를 거치지 않고 주변장치↔메모리 사이로 데이터 뭉치를 직접 나른다. 코어는 그동안 다른 일을 하거나 잠들 수 있어 효율이 오른다. |
| **하드웨어 가속 블록(암호 엔진·ECC 엔진·ISP 파이프라인·보안 부팅 등)** | 특정 작업만 처리하는 전용 고정기능 회로. 소프트웨어로 하면 느릴 일을 회로로 굳혀 압도적으로 빠르고 저전력으로 처리하며, 서명 검증(보안 부팅)·키 저장 같은 보안 기능도 담당한다. |
| **내장 전원 관리·리셋/브라운아웃 회로** | 코어 전압을 만들고(내장 LDO/레귤레이터) 슬립/웨이크를 제어하며, 전압이 불안정할 때 안전하게 리셋해 오동작을 막는다. 초저전력 상시 동작을 뒷받침한다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **MCU (Microcontroller Unit, 마이크로컨트롤러)** | CPU 코어 + 프로그램 메모리(플래시) + 데이터 메모리(SRAM) + 주변장치를 한 칩에 통합한 완결형 소형 컴퓨터. PC의 CPU가 메모리·저장장치 등 외부 칩이 있어야 동작하는 것과 달리, MCU는 칩 하나로 홀로 돌아간다. |
| **DSP (Digital Signal Processor, 디지털 신호 처리기)** | 소리·영상·통신 신호처럼 연속적인 데이터 스트림에 대한 곱셈-누산 계산에 특화된 프로세서. FIR/IIR 필터, FFT, 에코·노이즈 제거를 실시간으로 돌리도록 설계됐다. |
| **MAC (Multiply-Accumulate, 곱셈-누산)** | '누산값 = 누산값 + (a × b)'를 한 번의 연산으로 처리하는 것. FIR 필터·FFT·행렬곱·신경망의 기본 단위여서, DSP·NPU는 이 MAC을 잔뜩 병렬로 두어 성능을 낸다. |
| **고정소수점 (Fixed-point)** | 소수점 위치를 미리 고정해 두고 정수 연산으로 소수를 다루는 방식. 부동소수점보다 회로가 단순하고 전력이 적으며 연산 지연이 일정해, 실시간·저전력 신호처리에서 표준적으로 쓰인다. |
| **펌웨어 (Firmware)** | 비휘발성 메모리(플래시/ROM)에 저장돼 하드웨어를 직접 제어하는 소프트웨어. 하드웨어와 일반 소프트웨어의 중간에 있으며, 대부분 업데이트가 가능하다(SSD·키보드·무선 이어폰 펌웨어 업데이트). |
| **실시간 (Real-time)** | 정해진 마감시간(deadline) 안에 반드시 반응해야 하는 성질. 평균 속도보다 '최악의 경우 지연(worst-case latency)'을 보장하는 것이 중요해서, 예측이 어려운 최적화는 일부러 피하기도 한다. |
| **RTOS (Real-Time OS, 실시간 운영체제)** | 우선순위 기반으로 여러 태스크를 예측 가능한 시간 안에 스케줄링하는 작은 운영체제(FreeRTOS·Zephyr 등). 단순 펌웨어의 '무한루프+인터럽트'(베어메탈 슈퍼루프)와 대비되며, 마감시간 보장이 필요한 복잡한 임베디드에서 쓴다. |
| **ISP (Image Signal Processor, 이미지 신호 처리기)** | 이미지 센서의 원시 데이터(Bayer 패턴)를 디모자이킹·노출·화이트밸런스·노이즈 제거로 가공해 사람이 볼 만한 사진/영상으로 만드는 전용 프로세서. 웹캠·스마트폰 카메라에 들어 있다. |
| **EC (Embedded Controller, 임베디드 컨트롤러)** | 노트북 메인보드의 관리 전용 MCU. 전원 버튼·키보드·터치패드·팬·배터리·온도·뚜껑 센서를 담당하며, 메인 CPU가 꺼져 있어도 대기 전원으로 상시 대기한다. |
| **FTL (Flash Translation Layer, 플래시 변환 계층)** | SSD 컨트롤러의 펌웨어가 OS가 쓰는 논리 주소(LBA)를 실제 NAND 물리 위치로 매핑하는 계층. 웨어 레벨링·가비지 컬렉션과 함께 NAND의 약점(덮어쓰기 불가·수명 제한)을 감춰 준다. |
| **하버드 구조 (Harvard architecture)** | 명령용 메모리와 데이터용 메모리의 버스를 분리한 구조. 명령과 데이터를 같은 클럭에 동시에 읽을 수 있어 DSP·MCU(8051·AVR 등)가 처리량을 높이는 데 쓴다. (PC의 CPU는 통합 메모리 관점에선 폰노이만이지만 L1 캐시 단에서 명령/데이터를 분리한 '수정 하버드') |
| **인터럽트 (Interrupt)** | 외부/내부 사건이 실행 중인 코드를 즉시 가로채, 미리 정한 처리 루틴(ISR)으로 점프하게 만드는 메커니즘. 평소엔 잠자다가 사건에 반응하는 임베디드 동작의 뼈대. |
| **워치독 타이머 (Watchdog Timer)** | 펌웨어가 주기적으로 리셋해 주지 않으면 칩을 강제 재시작시키는 타이머. 프로그램이 멈추거나 무한루프에 빠졌을 때 스스로 복구하게 하는 안전장치. |
| **오프로딩 (Offloading)** | 메인 CPU가 할 반복적·전용적 작업을 보조 프로세서에 떠넘기는 것. 오프로딩으로 CPU는 자유로워지고, 전용 칩은 더 싸고 적은 전력으로 그 일을 처리한다. |
| **NPU (Neural Processing Unit, 신경망 처리장치)** | 대량의 MAC(곱셈-누산)을 병렬로 두어 행렬 곱·합성곱을 저전력으로 가속하는 전용 프로세서. 온디바이스 AI 추론(음성 인식·이미지 분류·생성 모델)을 메인 CPU 대신 담당한다. |
| **ARM Cortex-M / RISC-V** | 임베디드 32비트 MCU에서 널리 쓰이는 CPU 코어 아키텍처. Cortex-M0/M4/M7 계열이 사실상 표준이고, 보안 확장(TrustZone)을 담은 M23/M33도 늘고 있으며, 개방형 명령집합인 RISC-V가 빠르게 확산 중이다. |

## 📊 대표 사양·수치 감각

| 항목 | 값 | 비고 |
|---|---|---|
| MCU 코어 클럭 | 대략 8MHz ~ 수백 MHz (고성능 Cortex-M7은 480MHz+) | PC CPU의 GHz급보다 낮지만 담당 작업엔 충분. 예: Arduino의 ATmega328은 16MHz, STM32H7은 480MHz 안팎. |
| 코어 비트 폭 | 8 / 16 / 32비트 | 8비트(AVR·8051), 16비트(MSP430 등), 32비트(ARM Cortex-M·RISC-V)가 주류. MCU에서 64비트는 드물다(64비트는 주로 Cortex-A급 응용 프로세서). |
| 내장 플래시(펌웨어) 용량 | 대략 수 KB ~ 수 MB | 예: 16KB~2MB. 프로그램 저장용 규모로, PC의 저장장치(SSD 수백 GB~수 TB)와 비교하면 대략 5~8자릿수(십만~억 배) 작다. |
| 내장 SRAM 용량 | 대략 수 KB ~ 수백 KB (고성능은 ~수 MB) | 변수·스택·버퍼용. 외장 DRAM 없이 이것만으로 동작하는 경우가 많다. |
| 동작 전압 | 대략 1.8V ~ 5V (흔히 3.3V) | 코어 내부 전압은 더 낮음(대개 1.0~1.2V, 내장 레귤레이터로 생성). 전압이 낮을수록 소비전력이 준다. |
| 슬립 소비 전류 | 대략 수십 nA ~ 수 µA (활성 시 수 mA) | 저전력 MCU 딥슬립 기준. 상시 감시하는 노트북 EC의 S5 대기 전류는 구현에 따라 수 µA~수 mA로, 꺼진 배터리를 거의 안 먹는다. |
| DSP MAC 처리량 | 클럭당 1~수 개 MAC (수백 MMAC/s ~ GMAC/s급) | MAC=곱셈-누산. FIR/FFT의 기본 연산을 한 클럭에 한 스텝씩 흘린다. NPU는 이보다 훨씬 많은 MAC을 병렬화한다. |
| 오디오 샘플링 | 44.1kHz / 48kHz / 96kHz (고해상은 192kHz), 16~24비트 | 오디오 DSP가 이 속도로 끊김 없이 실시간 처리해야 소리가 튀지 않는다. |
| ISP 픽셀 처리량 | 웹캠급 대략 1억 ~ 5억 픽셀/초, 최신 스마트폰 ISP는 1~3 Gpx/s급 | 예: 1080p60 ≈ 약 1.24억 px/s, 4K60 ≈ 약 5억 px/s. 100MP+ 고해상 센서·고프레임을 다루는 플래그십 ISP는 기가픽셀/초대에 이른다. |
| SSD 컨트롤러 규모 | 멀티코어(예: ARM Cortex-R/-M 또는 RISC-V 3~5개) + 자체 DRAM, NVMe/PCIe 4.0·5.0 | '보조 프로세서'라지만 그 자체가 완전한 소형 컴퓨터다. 현대 ECC는 LDPC가 표준이며, 저가·소형 제품은 자체 DRAM 없이 HMB(호스트 메모리 버퍼)를 쓰는 DRAM-less 구성도 흔하다. |
| 대표 코어 아키텍처·세대 | ARM Cortex-M0/M4/M7/M23/M33, RISC-V, 8051, AVR, MSP430 | Cortex-M이 임베디드 32비트의 사실상 표준. 보안 확장(TrustZone) M23/M33 확대, RISC-V가 빠르게 확산 중. |

## ⚠️ 흔한 오해

- **오해** — 보조 프로세서·MCU는 그냥 CPU의 축소판이고 성능만 낮은 것이다.
  <br>**교정** — 규모가 아니라 목적과 구조가 다르다. 범용 CPU는 무엇이든 빠르게 하도록, MCU·DSP는 특정 작업 하나를 저전력·실시간·저비용으로 하도록 만들어졌다. DSP의 MAC·고정소수점 회로처럼 범용 CPU엔 없거나 약한 전용 하드웨어를 갖는다.
- **오해** — 전원을 끄면 시스템 안의 작은 컴퓨터들도 전부 함께 꺼진다.
  <br>**교정** — EC(임베디드 컨트롤러)·PMIC 같은 관리용 MCU는 시스템이 꺼진 상태(S5)에서도 대기 전원으로 상시 대기하며 전원 버튼·충전·시계(RTC)를 감시한다. 소비 전류는 매우 낮아, 꺼진 노트북도 배터리 충전이 관리되고 버튼 한 번에 다시 켜진다.
- **오해** — 펌웨어는 하드웨어의 일부라 절대 바뀌지 않는다.
  <br>**교정** — 펌웨어는 플래시에 저장된 소프트웨어다. SSD 펌웨어 업데이트, 무선 이어폰·키보드(QMK 등) 펌웨어 갱신처럼 대부분 다시 쓸 수 있다. 진짜 고정된 마스크 ROM은 일부에 불과하다.
- **오해** — 무조건 빠른 것이 좋은 프로세서다.
  <br>**교정** — 실시간 시스템에선 평균 속도보다 '마감 준수(예측 가능한 최악 지연)'가 더 중요하다. 그래서 캐시·분기예측처럼 평균은 빠르지만 지연이 들쭉날쭉해지는 기법을 일부러 안 쓰거나 제한하기도 한다. 오디오가 한 번 늦으면 소리가 튀기 때문이다.
- **오해** — 고정소수점은 부동소수점의 열등한 버전일 뿐이다.
  <br>**교정** — 용도가 다르다. 고정소수점은 회로가 단순하고 지연이 일정해 실시간·저전력에 유리하다. 오디오·통신 DSP에서는 오히려 표준적인 선택이며, 정밀도·넓은 동적범위가 필요한 곳에만 부동소수점을 쓴다.
- **오해** — SSD·웹캠·키보드 안에 '컴퓨터'가 들어 있다는 건 과장이다.
  <br>**교정** — 실제로 SSD 컨트롤러는 멀티코어 프로세서 + 자체 DRAM(또는 HMB) + 펌웨어를 갖춘 완전한 컴퓨터다. 웹캠 ISP, 오디오 DSP, 키보드 MCU도 각자 코어·메모리·프로그램을 가진 작은 컴퓨터다. 현대 PC 한 대엔 이런 프로세서가 수십 개 들어 있다.

## 💡 비유

회사 비유: 메인 CPU는 무엇이든 처리하는 만능 사장(CEO), 보조 프로세서·MCU는 전담 부서의 전문가다. 사장이 경리·사진 보정·음향·경비까지 다 하면 병목이 생기니, 경리(SSD 컨트롤러)·사진 보정 전문가(웹캠 ISP)·음향 엔지니어(오디오 DSP)·경비원(EC)에게 위임한다. 전문가는 자기 일만 빠르고 싸게 처리하고, 심지어 사장이 퇴근(전원 오프)해도 경비원은 계속 근무한다. / DSP의 MAC 비유: 계산기로 '×' 누르고 '+' 눌러 두 번에 하던 일을, 한 번에 끝내는 전용 버튼과 같다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 컴퓨터가 켜지는 과정(부팅): EC가 전원 버튼 신호를 가장 먼저 받아 PSU/전원 레일을 깨우고, 그때부터 SSD 컨트롤러가 NAND에서 부트로더·커널을 꺼내 넘겨준다. UEFI 펌웨어가 도는 SPI 플래시 자체도 이 '작은 컴퓨터' 생태계의 일부다.
- Ctrl+S 저장 / 파일 열기: SSD 컨트롤러(보조 프로세서)가 FTL 주소 매핑·ECC(LDPC) 오류정정·웨어 레벨링·가비지 컬렉션을 전담한다. 메인 CPU는 'LBA 블록 써줘'라고만 말하고 나머지는 컨트롤러가 알아서 한다.
- 음악이 스피커에서 나오기까지: 오디오 코덱/DSP가 디코딩·믹싱·이퀄라이저·노이즈 제거를 초당 4.8만 샘플(48kHz)로 실시간 처리하고 DAC로 아날로그 파형을 만든다. 블루투스 이어폰 안의 SoC도 작은 DSP를 품고 있다.
- 화상통화 / 영상: 웹캠 ISP가 이미지 센서의 원시 픽셀(Bayer)을 디모자이킹·노출·화이트밸런스·노이즈 제거로 다듬어 깨끗한 영상으로 만든 뒤에야 인코더로 넘긴다.
- 키보드 입력이 글자가 되기까지: 키보드 MCU가 키 매트릭스를 스캔하고 채터링을 디바운스한 뒤 키코드(HID Usage ID)를 USB HID 리포트로 호스트에 보낸다. 실제 문자 매핑은 호스트 OS가 한다. 마우스 광센서 안의 DSP도 표면 이미지를 실시간 분석해 이동량을 낸다.
- 절전 모드와 복귀: EC가 슬립/웨이크를 관장하고 RTC와 함께 상시 대기하며, RAM 셀프 리프레시와 전원 레일을 제어한다. 뚜껑을 덮으면 EC가 감지해 절전으로 들어간다.
- USB를 꽂는 순간: USB 장치 안의 MCU가 스스로 깨어나 자기 장치 ID·디스크립터를 호스트에 보고(열거, enumeration)한다. 이 대화 자체가 장치 속 작은 컴퓨터가 하는 일이다.
- AI에게 질문할 때: 온디바이스 추론을 맡는 NPU/DSP가 MAC 연산을 대량 병렬로 돌려, 메인 CPU를 대신해 행렬 곱을 저전력으로 가속한다.
