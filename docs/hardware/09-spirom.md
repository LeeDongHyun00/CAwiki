# SPI 플래시 롬 (부트 롬)
*SPI Flash ROM (Boot ROM)*

> 메인보드에 붙어 UEFI/BIOS 펌웨어를 담고, 전원이 켜지자마자 CPU가 (칩셋 매핑을 통해) 가장 먼저 첫 명령을 읽어 가는 비휘발성 NOR 플래시 칩 — 컴퓨터 부팅의 물리적 출발점.

**분류**: 저장장치

---

## 🧭 한마디로, 무슨 일을 하나
전원을 넣은 직후, 아직 DRAM도 초기화되지 않고 OS도 없는 무(無)의 상태에서 CPU가 실행할 '맨 처음 코드(펌웨어)'를 보관하는 칩이다. CPU는 리셋되면 하드웨어로 고정된 주소(리셋 벡터)에서 명령을 가져오는데, 칩셋(PCH)/SoC가 이 주소를 SPI 플래시로 디코드해 매핑해 둔다. 즉 이 칩은 저장 용량으로 승부하는 장치가 아니라 '언제나 같은 자리에서, 전원만 들어오면, 별도 초기화 없이 즉시 읽히는' 신뢰할 수 있는 시작점을 제공하는 것이 본질적 역할이다. 이 플래시는 CPU뿐 아니라 관리 엔진(ME/PSP)·EC 등도 각자의 리전을 읽어 가는 공용 저장소이기도 하다. 부팅이 끝나 OS가 SSD에서 올라온 뒤에는 대부분 조용히 쉬며, UEFI 설정·부트 순서·Secure Boot 키 같은 비휘발성 값을 계속 보관한다.

## ⚙️ 작동 방식

**1. 전원 인가와 CPU 리셋 해제**

전원 버튼을 누르면 전원 시퀀싱이 진행되고 리셋 신호가 풀린다. CPU는 리셋에서 나오며 레지스터가 하드웨어 초기값을 갖는데, x86에서는 CS 베이스가 0xFFFF0000, IP가 0xFFF0으로 세팅되어 실효 물리주소가 리셋 벡터 0xFFFFFFF0(4GB 주소공간 최상단−16바이트)이 된다. 아직 DRAM은 훈련(트레이닝)되지 않아 쓸 수 없으므로, CPU가 코드를 읽을 수 있는 곳은 비휘발성이며 즉시 접근 가능한 SPI 플래시밖에 없다.

**2. (보안) 부트 가드가 첫 코드 블록을 먼저 검증**

최신 플랫폼에서는 명령을 실행하기 전에 하드웨어 신뢰 루트가 개입한다. CPU 마이크로코드가 인텔이 서명한 인증 코드 모듈(ACM, 이 역시 플래시에서 로드)을 불러오고, ACM이 SPI 플래시 안의 최초 부트 블록(IBB)을 칩셋(PCH)의 필드 프로그래머블 퓨즈(FPF)에 각인된 OEM 공개키 해시로 검증(Verified Boot) 또는 TPM에 측정(Measured Boot)한다. 서명이 맞지 않으면 실행을 막고 정지시켜, 변조된 플래시가 악성 초기 코드를 실행하지 못하게 한다. AMD는 PSP 기반 PSB(Platform Secure Boot)로 대응한다.

**3. 리셋 벡터 읽기 요청이 SPI 트랜잭션으로 변환**

CPU가 리셋 벡터 주소로 메모리 읽기를 내면, PCH/SoC 로직이 그 주소를 'BIOS/펌웨어 디코드 윈도우'(대개 4GB 바로 아래의 상위 영역)로 인식한다. PCH의 SPI 컨트롤러가 이 읽기를 SPI 직렬 트랜잭션으로 바꾼다 — 칩 선택(CS#)을 활성화하고, 클럭(SCLK)에 맞춰 Fast Read 같은 명령 코드와 24비트(≤16MB) 또는 32비트(4바이트, >16MB) 주소를 데이터 선으로 내보낸다. 주소를 병렬로 뿌리는 게 아니라 직렬로 '주문서'를 보내는 구조다.

**4. NOR 셀에서 바이트를 직렬로 스트리밍(XIP)**

플래시 내부에서 주소 디코더가 해당 NOR 셀을 고르고 감지 증폭기가 셀의 미세 전류를 기준값과 비교해 0/1로 판별한다. 그 바이트들이 클럭에 맞춰 데이터 선(1·2·4비트: Single/Dual/Quad)으로 흘러나오고 PCH가 이를 모아 CPU에 전달한다. NOR는 바이트 단위 랜덤 접근이 가능해 XIP(제자리 실행)에 알맞다 — 현대 x86에서는 엄밀히는 PCH 메모리맵 윈도우를 통해 캐시를 경유해 읽고 실행한다. 첫 명령은 보통 실제 펌웨어 진입점으로 가는 점프이며 여기서 UEFI SEC 단계가 시작된다.

**5. 캐시를 임시 RAM처럼 써서 메모리를 살림**

초기 코드는 아직 사용할 DRAM이 없으므로 CPU 캐시를 임시 RAM처럼 쓰는 'Cache-as-RAM(CAR)' 기법으로 동작한다. PEI 단계에서 메모리 컨트롤러를 초기화·훈련(트레이닝)해 DRAM을 사용 가능하게 만든 뒤, 플래시에 압축되어 있던 DXE 단계 코드를 RAM으로 풀어 옮겨 실행한다(플래시보다 RAM이 훨씬 빠르기 때문). 이 과정에서 플래시 BIOS 리전 안의 NVRAM 변수 저장소도 읽어 온다.

**6. 부트 순서 읽고 OS로 제어를 넘김**

BDS 단계에서 펌웨어는 플래시 NVRAM에 저장된 BootOrder·Boot#### 변수를 읽어 부팅 장치를 정하고, Secure Boot 정책(db/dbx 키)으로 부트로더 서명을 확인한 뒤 NVMe SSD 등에서 OS 부트로더를 불러온다. 여기서 제어가 펌웨어를 떠나 OS로 넘어간다.

**7. OS로 넘기기 전 플래시 쓰기 보호 잠금**

제어를 OS에 넘기기 직전(또는 그 전 단계에서) 펌웨어는 플래시 BIOS 리전을 런타임 변조로부터 보호하도록 잠근다 — PCH의 쓰기 보호 레지스터(BIOS_CNTL의 BLE/BIOSWE, SMM_BWP)와 Protected Range(PRx) 레지스터를 설정하고 FLOCKDN으로 구성을 고정한다. 이후 정상 실행 중 플래시는 대체로 유휴 상태가 되고, 런타임 UEFI 서비스·SMM 핸들러·설정 변경/펌웨어 업데이트(허용된 경로) 때만 다시 접근된다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **NOR 플래시 셀 어레이 (플로팅 게이트/차지 트랩 트랜지스터)** | 실제 비트를 담는 심장부. 각 셀이 전하의 유무로 문턱전압을 바꿔 0/1을 비휘발성으로 기억한다. NOR 배선 구조 덕분에 셀 하나(바이트)를 개별적으로 빠르게 랜덤 읽기 할 수 있어 코드 저장·XIP에 적합하다. |
| **행·열 디코더 + 감지 증폭기 (sense amplifier)** | 요청된 주소의 셀을 골라내고, 셀에 흐르는 극히 작은 전류를 기준 전류와 비교해 논리 레벨(0/1)로 판독한다. 랜덤 접근 읽기의 속도와 정확도를 좌우한다. |
| **SPI 직렬 인터페이스 로직 (명령 디코더·주소 래치·시프트 레지스터) + SFDP 테이블** | SCLK에 맞춰 들어오는 명령 코드와 주소를 해석하고, 읽은 데이터를 직렬 출력한다. Single/Dual/Quad(1·2·4비트) 전송 폭과 Fast Read 등 명령을 처리한다. JEDEC 표준 SFDP(직렬 플래시 파라미터 발견) 테이블을 내장해, 컨트롤러가 이 칩의 용량·지원 명령·더미 사이클 등을 자동 인식하게 한다. |
| **상태·설정 레지스터 (Status/Configuration Register) + OTP/보안 레지스터** | 쓰기 활성 래치(WEL), 블록 보호 비트(BP/TB), Quad Enable, 소거/프로그램 진행 상태(Busy/WIP) 등을 담아 쓰기 보호와 동작 모드를 결정한다. 별도의 OTP(1회 프로그램) 보안 레지스터 영역을 두어 고유 ID·서명 등 불변 데이터를 보관하기도 한다. |
| **차지 펌프 (charge pump)** | 3.3V(또는 1.8V) 공급 전압에서 셀을 프로그램·소거하는 데 필요한 더 높은 내부 전압을 만들어 낸다. 재기록을 물리적으로 가능하게 하는 부품. |
| **프로그램/소거 상태 머신 (내부 컨트롤러)** | 페이지 프로그램(쓰기)과 섹터/블록 소거의 순서·타이밍·검증을 자동으로 관리한다. NOR는 비트를 1→0으로만 프로그램할 수 있어(소거가 1로 되돌림), 되돌리려면 섹터/블록 전체를 소거해야 하는데 이 로직이 그 절차를 담당한다. |
| **쓰기 보호 로직 + WP#/HOLD#(또는 RESET#) 핀** | 하드웨어 핀(WP#)과 상태 레지스터의 보호 비트로 특정 영역의 무단 쓰기를 막는다. 펌웨어 변조를 막는 1차 방어선이며, 메인보드/PCH의 플래시 쓰기 보호 정책과 맞물린다. |
| **8핀 패키지와 핀 배열 (CS#, SCLK, SI/IO0, SO/IO1, WP#/IO2, HOLD#(RESET#)/IO3, VCC, GND)** | SOIC/WSON 8핀 몸체로 메인보드에 실장된다. 병렬 ROM 대비 핀 수가 매우 적어 작은 칩으로 만들 수 있고, Quad 모드에서는 IO0~IO3 4개 핀을 동시에 데이터 선으로 쓴다. |
| **(보드측) PCH/CPU의 SPI 컨트롤러 + BIOS 디코드 윈도우 + 쓰기 보호 레지스터** | 칩 자체는 아니지만 논리적으로 한 쌍. CPU의 메모리 읽기(리셋 벡터 포함)를 SPI 트랜잭션으로 번역하고, 주소공간 상위를 플래시에 매핑한다. BIOS_CNTL(BLE/BIOSWE·SMM_BWP)·Protected Range(PRx)·FLOCKDN 같은 레지스터로 플래시 쓰기 보호를 실제로 강제하는 것도 이 컨트롤러다. |
| **논리적 저장 구조: Flash Descriptor · BIOS(내부에 NVRAM 변수 저장소) · ME/CSME · GbE · EC 등 리전** | 인텔 플랫폼에서는 플래시 첫머리의 Flash Descriptor가 전체 레이아웃과 리전별 접근 권한을 정의한다. 그 아래로 BIOS(UEFI 펌웨어 — UEFI 변수/부트 순서/Secure Boot 키를 담는 NVRAM 저장소는 이 BIOS 리전 내부의 펌웨어 볼륨이다), ME/CSME(관리 엔진 펌웨어), 필요시 GbE(네트워크)·EC·Platform Data 리전이 한 칩 안에 공존한다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **NOR 플래시 (NOR Flash)** | 셀을 NOR 논리 구조로 배선한 플래시. 바이트 단위 랜덤 읽기가 빠르고 신뢰성이 높아 코드 저장·XIP에 쓴다. 대용량·저가 저장(SSD)에 쓰는 NAND 플래시와 대비된다 — NAND는 페이지 단위로만 읽고 밀도가 높아 코드 즉시 실행(XIP)에는 부적합하다. |
| **XIP (eXecute In Place, 제자리 실행)** | 코드를 RAM으로 복사하지 않고 저장 매체(NOR 플래시)에서 CPU가 직접 실행하는 방식. NOR의 랜덤 접근 읽기 덕분에 가능하며, RAM이 아직 없는 부팅 초기에 필수다. 현대 x86에서는 PCH 메모리맵 윈도우를 통해 캐시를 경유해 실행하는 형태다. |
| **SPI (Serial Peripheral Interface, 직렬 주변장치 인터페이스)** | 칩셋(마스터)과 플래시(슬레이브)를 잇는 동기식 직렬 버스. 기본 4선(SCLK 클럭, MOSI/SI, MISO/SO, CS# 칩선택). 과거의 병렬 NOR와 그 뒤의 FWH(LPC 위에서 동작)를 대체해 핀 수를 크게 줄였다. |
| **QSPI (Quad SPI)** | 데이터 선 4개(IO0~IO3)를 동시에 써 (주로 데이터 페이즈 기준) 읽기 속도를 약 4배로 높인 SPI 모드. Dual(2선)·Octal(8선)·DTR/DDR(양엣지 전송) 같은 더 빠른 변형도 있다. |
| **리셋 벡터 (Reset Vector)** | CPU가 리셋 직후 무조건 첫 명령을 가져오는 고정 주소. x86에서는 0xFFFFFFF0(리셋 시 CS 베이스 0xFFFF0000 + IP 0xFFF0)이며, 칩셋이 이 주소를 SPI 플래시 상단에 디코드해 매핑한다. 부팅의 '0번지'. |
| **UEFI / BIOS (Unified Extensible Firmware Interface / Basic Input-Output System)** | 이 칩에 저장되는 플랫폼 펌웨어. 하드웨어를 초기화하고 OS를 불러오는 첫 소프트웨어. UEFI가 현대 표준이며 BIOS는 그 전신. 부팅 단계: SEC→PEI→DXE→BDS→런타임. |
| **NVRAM (UEFI 변수 저장소)** | UEFI 변수(부트 순서 BootOrder/Boot####, Secure Boot 키, 각종 설정)를 담는 저장 영역. 별도의 배터리 백업 RAM 칩이 아니라 SPI 플래시 BIOS 리전 내부의 비휘발성 변수 저장소(펌웨어 볼륨)로 구현되어, 전원을 꺼도 유지된다. |
| **부트 가드 (Intel Boot Guard) / IBB / ACM** | 펌웨어 자체의 무결성을 하드웨어로 보증하는 신뢰 루트. 최초 부트 블록(IBB, Initial Boot Block)을 인증 코드 모듈(ACM, Authenticated Code Module)이 칩셋(PCH)의 필드 프로그래머블 퓨즈(FPF)에 각인된 OEM 키 해시로 검증/측정한다. AMD의 대응 기술은 PSB(Platform Secure Boot). |
| **Secure Boot (보안 부팅)** | 펌웨어가 불러오는 OS 부트로더의 서명을 검증하는 UEFI 기능(PK/KEK/db/dbx 키 사용). 부트 가드가 '펌웨어 자신'을 지킨다면, Secure Boot는 '펌웨어가 부팅하는 대상'을 지키는 별개의 상위 층이다. |
| **Cache-as-RAM (CAR)** | DRAM이 초기화되기 전, CPU 내부 캐시를 임시 RAM처럼 활용해 초기 펌웨어 코드를 돌리는 기법. 메모리 컨트롤러를 훈련하기 전 단계를 넘기는 다리 역할. |
| **플래시 쓰기 보호/잠금 (Flash Write Protection & Lockdown)** | 칩의 WP# 핀·보호 비트에 더해, 플랫폼(PCH) 측에서 BIOS_CNTL(BIOSWE/BLE), SMM 기반 쓰기 보호(SMM_BWP), Protected Range(PRx) 레지스터, FLOCKDN으로 부팅 마무리 시 BIOS 리전을 잠가 런타임 변조를 막는다. 펌웨어 루트킷 방어의 핵심. |
| **SFDP (Serial Flash Discoverable Parameters)** | JEDEC 표준으로 플래시 내부에 담기는 파라미터 테이블. 컨트롤러가 이 칩의 용량·지원 명령·주소 바이트 수·더미 사이클 등을 자동으로 읽어(발견) 부품별 하드코딩 없이 구성할 수 있게 한다. |
| **P/E cycle (Program/Erase, 프로그램/소거 주기)** | 플래시 셀을 한 번 소거하고 다시 쓰는 것을 한 주기로 센다(내구성은 섹터/블록 단위). SPI NOR는 대략 10만(10^5) 주기 등급이 흔해, 잦은 쓰기용이 아니라 가끔 갱신하는 펌웨어 저장에 알맞다. |

## ⚠️ 흔한 오해

- **오해** — 부팅 설정(부트 순서)은 CMOS 코인 배터리(CR2032)가 유지한다.
  <br>**교정** — 최신 UEFI에서는 부트 순서·Secure Boot 키 등 대부분의 설정이 비휘발성 SPI 플래시의 NVRAM 변수 저장소에 저장된다. 코인 배터리는 주로 실시간 시계(RTC)와 소량의 CMOS만 유지하며, 배터리를 빼도 대부분의 UEFI 설정은 플래시에 그대로 남는다.
- **오해** — 이름이 ROM(읽기 전용 메모리)이니 내용을 바꿀 수 없다.
  <br>**교정** — 이름은 ROM이지만 실제로는 재기록 가능한 플래시다. BIOS/UEFI 업데이트는 섹터를 소거하고 새 이미지를 프로그램하는 것. '전원이 꺼져도 안 지워진다'는 뜻에서 ROM처럼 부를 뿐, 물리적으로는 쓰기 가능하다.
- **오해** — CPU는 켜지자마자 RAM에서 첫 명령을 읽는다.
  <br>**교정** — 리셋 시점엔 DRAM 컨트롤러가 아직 훈련되지 않아 RAM을 쓸 수 없다. CPU는 리셋 벡터에 매핑된 SPI 플래시에서 XIP로 첫 명령을 읽는다. RAM은 그 펌웨어가 나중에 초기화해 준다.
- **오해** — SPI는 병렬 버스라서 빠르다.
  <br>**교정** — SPI는 1~4(~8)비트짜리 직렬 버스다. 과거의 병렬 NOR와 그 뒤의 FWH/LPC(이미 저핀수) 인터페이스를 대체하며 핀 수를 크게 줄였고, 대신 절대 속도는 낮다. 그래서 초기 코드만 플래시에서 돌리고 나머지는 RAM으로 옮겨 실행한다.
- **오해** — LPC는 병렬 버스다.
  <br>**교정** — LPC(Low Pin Count)는 이름 그대로 '저핀수' 버스로, 4비트 다중화 직렬형에 가깝다. 진짜 병렬 BIOS 플래시는 그 이전의 PLCC/DIP 병렬 NOR(다수의 주소·데이터 핀)였다. 세대 흐름은 병렬 NOR → FWH(LPC 위) → SPI다.
- **오해** — UEFI Secure Boot가 펌웨어 자체의 무결성을 지켜 준다.
  <br>**교정** — Secure Boot는 펌웨어가 불러오는 OS 부트로더의 서명을 검증하는 상위 층이다. 펌웨어(플래시) 자체의 변조를 막는 것은 Intel Boot Guard/AMD PSB 같은 하드웨어 신뢰 루트와, PCH의 플래시 쓰기 보호(BIOS_CNTL/PRx/FLOCKDN)로, 서로 다른 계층이다.
- **오해** — '부트 롬'은 항상 CPU 칩 안에 들어 있는 마스크 ROM이다.
  <br>**교정** — 임베디드 SoC 맥락에서는 온다이(on-die) 부트롬이 맞지만, PC 플랫폼에서 말하는 SPI 플래시 롬은 메인보드에 별도로 실장된 외장 칩으로 UEFI/BIOS 펌웨어를 담는다. 문맥에 따라 가리키는 대상이 다르다.

## 💡 비유

① 건물의 붙박이 비상구 표지판: 정전으로 모든 시스템이 꺼져도(RAM도 없어도) 늘 같은 자리에서 '이 문으로 나가시오'라는 첫 지시를 준다. 벽에 새겨져 지워지지 않는다는 점(비휘발성)까지 닮았다. ② 오케스트라의 '첫 소절 악보': 컴퓨터라는 오케스트라가 완전히 조용한 상태에서 지휘자(CPU)가 가장 먼저 펼쳐 보는 악보. 이 한 장이 없으면 어떤 연주(부팅)도 시작될 수 없고, 리셋 벡터는 '몇 페이지부터 펴시오'라고 박아 둔 화살표다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 부팅(전원 버튼): 이 칩의 주 무대. 전원 인가 → CPU 리셋 → 리셋 벡터(0xFFFFFFF0) → 부트 가드가 IBB 검증 → SPI 플래시에서 UEFI 펌웨어를 XIP로 읽어 실행 → DRAM 훈련 → NVRAM의 부트 순서를 읽어 SSD의 OS 부트로더로 제어를 넘긴다.
- 모든 시나리오의 공통 출발점: 게임 렌더링·인터넷 검색 왕복·파일 열기·Ctrl+S 저장·소리 재생·영상 스트리밍·AI 질문 — 이 모든 세션은 결국 이 칩이 건넨 '첫 명령'에서 비롯된 부팅 위에서 돌아간다. 정작 그 동작들 자체가 실행될 때 SPI 플래시는 대개 조용히 쉰다.
- UEFI 설정 변경/부트 순서 조정: 사용자가 펌웨어 화면에서 부팅 장치 순서나 Secure Boot를 바꾸면, 그 값이 이 칩의 NVRAM 변수 저장소에 재기록되어 다음 부팅부터 반영된다.
- BIOS/UEFI 펌웨어 업데이트: 새 펌웨어 이미지를 받아 섹터를 소거하고 다시 프로그램한다. 이 칩이 '재기록 가능한 플래시'임이 드러나는 순간이며, 실패 대비로 이중 BIOS 칩을 둔 보드도 있다. 이때 PCH의 쓰기 보호를 (허용된 경로로) 풀었다가 다시 잠근다.
- 재부팅/절전 복귀: 다시 켜질 때마다 같은 리셋 벡터에서 같은 칩을 읽어 항상 결정적으로 부팅이 시작된다 — '물리적 출발점'이 반복 확인되는 장면.
