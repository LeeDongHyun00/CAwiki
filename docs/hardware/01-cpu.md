# CPU (중앙처리장치)
*Central Processing Unit (CPU)*

> 메모리에 담긴 프로그램 명령어를 하나씩 가져와 해석하고 실행해, 컴퓨터의 거의 모든 범용 계산과 제어·조율을 담당하는 핵심 연산 장치.

**분류**: 연산

---

## 🧭 한마디로, 무슨 일을 하나
CPU는 컴퓨터 전체의 '지휘 본부'다. RAM에 올라온 프로그램의 기계어 명령을 클럭 박자에 맞춰 가져와(페치) 해석하고(디코드) 실제 계산과 데이터 이동을 수행한다. 산술·논리·비교·분기·메모리 접근 같은 범용 연산을 모두 처리하며, GPU·SSD·네트워크 카드 같은 주변 장치에게 언제 무엇을 할지 지시하고 그 결과를 받아 조율하는 총괄 역할도 맡는다. 다만 겉보기에는 '순서대로 하나씩' 실행하는 것처럼 보여도, 내부에서는 여러 명령을 동시에·순서를 바꿔가며 병렬로 처리한다. 즉 다른 하드웨어가 특정 일에 특화된 전문가라면, CPU는 무엇이든 시키는 대로 하는 만능 일꾼이자 오케스트라의 지휘자다.

## ⚙️ 작동 방식

**1. 페치 — 다음 명령어를 가져온다**

제어부가 프로그램 카운터(PC/IP, 다음에 실행할 명령의 주소)를 보고 그 주소의 명령어를 L1 명령어 캐시에서 읽어온다. 캐시에 없으면(캐시 미스) L2→L3→RAM 순으로 내려가 가져온다. 이때 MMU와 명령어 TLB(iTLB)가 프로그램이 쓰는 가상 주소를 실제 물리 주소로 번역한다. 실제로는 분기 예측기가 '다음에 어느 주소를 페치할지'를 앞서 결정해 페치를 이끈다. 왜: CPU는 스스로 코드를 만들지 않고 메모리에 저장된 명령을 순서대로 읽어 실행하는 기계이므로, 매 사이클 '다음에 뭘 할지'를 먼저 읽어와야 한다.

**2. 디코드 — 명령어의 뜻을 푼다**

가져온 이진 비트열을 디코더가 해석해 '무슨 연산(더해라/비교해라/메모리에서 읽어라)인지, 어떤 레지스터·값을 쓰는지'를 알아낸다. x86 같은 복잡한 명령은 여기서 여러 개의 내부 마이크로옵(micro-op)으로 쪼개진다. 자주 도는 코드는 이미 디코드해 둔 마이크로옵을 마이크로옵 캐시(uop cache)에서 바로 꺼내 디코드 단계를 건너뛴다. 왜: 실행 유닛은 잘게 정규화된 내부 연산만 이해하므로, 사람이 짠 다양한 형태의 명령을 하드웨어가 처리 가능한 단위로 번역해야 한다.

**3. 분기 예측과 추측 실행 — 갈림길에서 미리 달린다**

if/반복문 같은 조건 분기를 만나면 조건 결과가 확정되기 전에 분기 예측기가 '아마 이 길로 갈 것'이라 추측하고 그 방향의 명령을 미리 페치·실행(추측 실행)한다. 예측은 실제로 페치 단계와 맞물려 다음 페치 주소를 정한다. 왜: 조건 계산이 끝날 때까지 파이프라인을 비워 두면 십수~수십 사이클을 낭비하므로, 과거 패턴 통계로 미리 달려 성능을 끌어올린다. 틀리면(예측 실패) 잘못 실행한 것을 버리고(파이프라인 비우기) 되돌린다.

**4. 발행·스케줄 — 여러 개를 동시에, 순서를 바꿔 던진다**

슈퍼스칼라 구조라 한 사이클에 여러 마이크로옵을 발행한다. 레지스터 리네이밍으로 이름이 겹쳐 생기는 가짜 의존 관계(WAR·WAW)를 제거하고, 스케줄러(예약 스테이션)가 '입력값이 준비된 것부터' 순서를 바꿔(비순차 실행) 놀고 있는 실행 포트로 보낸다. 왜: 앞 명령이 느린 메모리를 기다리는 동안 뒤의 독립적인 명령을 먼저 처리하면 실행 유닛이 쉬지 않아 사이클당 처리량(IPC)이 오른다.

**5. 실행 — 실제 계산을 한다**

각 실행 유닛이 일을 나눠 맡는다. ALU는 정수 덧셈·논리·비교·시프트, FPU는 부동소수점 계산, SIMD/벡터 유닛은 여러 데이터를 한 명령으로 한꺼번에, 로드/스토어 유닛(AGU 포함)은 메모리 주소를 계산해 캐시에 읽기/쓰기를 낸다. 현대 코어에서는 스칼라 부동소수점과 SIMD가 같은 벡터 실행 유닛을 공유하는 경우가 많다. 왜: 연산 종류마다 전용 회로가 여러 벌 병렬로 있어야 여러 명령을 동시에 처리할 수 있다.

**6. 메모리 접근 — 데이터를 읽고 쓴다**

load/store 명령은 L1 데이터 캐시를 먼저 두드린다. 있으면 대략 1 나노초 안팎(4~5 사이클)에, 없으면 L2·L3·RAM으로 내려가며 점점 느려진다(캐시 계층). 쓰기는 스토어 버퍼에 모았다가 순서에 맞춰 캐시에 반영하고, 로드는 로드 버퍼로 순서·의존을 관리한다. 하드웨어 프리페처가 접근 패턴을 예측해 필요할 데이터를 미리 캐시로 끌어오기도 한다. 왜: RAM 접근은 캐시보다 수십 배 느리므로, 자주 쓰는 데이터를 코어 옆 캐시에 두어 대기 시간을 숨긴다.

**7. 라이트백·리타이어 — 결과를 확정하고 순서를 되맞춘다**

계산 결과를 물리 레지스터 파일에 기록하고, 재정렬 버퍼(ROB)가 비순차로 끝난 명령들을 '원래 프로그램 순서대로' 은퇴(retire/commit)시켜 아키텍처 상태를 확정한다. 분기 예측이 맞았는지도 이때 판정해, 틀렸으면 추측으로 실행한 결과를 폐기하고 올바른 경로부터 다시 페치한다. 왜: 안에서는 순서를 바꿔 빨리 처리했지만, 밖에서 볼 때는 프로그램이 쓴 순서대로 결과가 나온 것처럼 보여야 정확성이 지켜진다.

**8. 다음 사이클로 — 클럭이 박자를 몰아간다**

PC가 다음 명령 주소로 넘어가고 클럭 신호의 다음 에지(보통 상승 에지)에 맞춰 파이프라인 각 단계가 한 칸씩 전진한다. 부하가 높고 전력·온도에 여유가 있으면 부스트로 클럭을 순간적으로 끌어올리고(DVFS), 한가하면 클럭·전압을 낮춰 전력을 아낀다. 온도가 한계에 닿으면 스로틀링으로 클럭을 낮춰 자신을 보호한다. 왜: 파이프라인은 여러 명령이 각 단계를 컨베이어벨트처럼 겹쳐 흐르는 구조라, 일정한 박자(클럭)가 있어야 단계 간 데이터가 어긋나지 않는다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **코어 (Core)** | 명령을 페치→디코드→실행→라이트백까지 처리하는 완결된 연산 엔진 하나. 현대 CPU는 이 코어를 여러 개 담아(멀티코어) 서로 다른 작업을 물리적으로 동시에 처리한다. 각 코어는 SMT(하이퍼스레딩)로 논리 스레드 2개(일부 아키텍처는 4·8개)를 굴려 실행 유닛의 빈틈을 메우기도 한다. 최근엔 성능 코어(P)와 효율 코어(E)를 섞은 이종(빅·리틀) 구성도 흔하다. |
| **ALU (Arithmetic Logic Unit, 산술논리장치)** | 정수 덧셈·뺄셈, AND/OR/XOR 같은 논리 연산, 크기 비교, 시프트를 담당하는 핵심 계산 회로. 한 코어에 여러 개가 있어 정수 연산을 병렬 처리한다. 프로그램 대부분의 기본 연산이 여기서 처리된다. |
| **FPU (Floating-Point Unit, 부동소수점장치)** | 소수점이 있는 실수 계산(3.14 × 2.71 등)을 전담한다. 물리 시뮬레이션, 3D 그래픽 좌표 변환, 과학 계산에 필수. 정수만 다루는 ALU로는 비효율적인 실수 연산을 전용 회로로 빠르게 처리한다. 현대 코어에선 이 부동소수점 연산이 SIMD/벡터 유닛과 회로를 공유하는 경우가 많다. |
| **SIMD/벡터 실행유닛 (Single Instruction, Multiple Data)** | '하나의 명령으로 여러 데이터를 한꺼번에' 계산하는 넓은 연산 유닛(x86의 SSE/AVX/AVX-512, ARM의 NEON/SVE). 예컨대 256비트 폭이면 32비트 실수 8개를 한 명령으로 동시에 더한다. 영상·이미지 처리, 오디오 디코딩, AI 추론처럼 같은 연산을 대량 반복하는 일에서 처리량을 몇 배로 올린다. |
| **레지스터 파일 (Register File)** | CPU 안에서 가장 빠른 초소형 저장소. 지금 계산 중인 값·주소를 담는다. x86-64는 프로그램이 보는 범용 레지스터가 16개, ARM64(AArch64)는 31개지만, 실제로는 리네이밍용 물리 레지스터가 수백 개 있어 여러 명령이 서로 안 부딪히게 한다. 접근 지연은 대략 1 사이클로 사실상 즉시에 가깝다. |
| **제어부 (Control Unit) / 마이크로코드** | 명령어를 해석해 각 부품에 '언제 무엇을 하라'는 제어 신호를 뿌리는 지휘자. 프로그램 카운터를 관리하고 파이프라인의 흐름을 통제한다. 아주 복잡하거나 드문 명령은 마이크로코드(칩 안에 저장된 내부 소형 프로그램)로 여러 단계로 풀어 실행한다. |
| **명령어 페치 유닛 + 디코더 + 마이크로옵 캐시** | 페치 유닛이 L1 명령어 캐시에서 명령 비트열을 끌어오고, 디코더가 그것을 실행 유닛이 이해하는 마이크로옵으로 번역한다. 마이크로옵 캐시(uop cache)는 이미 디코드해 둔 결과를 담아, 반복되는 코드에서 비싼 디코딩을 건너뛰게 해 준다. x86은 명령 길이가 1~15바이트로 제각각이라 디코딩이 까다롭고, ARM(AArch64)은 4바이트로 고정돼 디코딩이 단순하다. |
| **분기 예측기 (Branch Predictor)** | 조건 분기(if/반복문)에서 어느 방향으로 갈지 과거 이력 패턴으로 예측하고, 분기 목표 버퍼(BTB)·리턴 스택 버퍼로 목적지 주소까지 미리 짚어 페치를 이끈다. 현대 예측기의 적중률은 대략 95~99%로 매우 높아, 파이프라인이 갈림길에서 멈추지 않고 계속 달리게 하는 성능의 숨은 주역이다. |
| **스케줄러(예약 스테이션) + 재정렬 버퍼(ROB, Reorder Buffer)** | 비순차 실행의 심장. 스케줄러는 입력이 준비된 마이크로옵부터 실행 포트로 내보내 순서를 재배치하고, ROB는 그렇게 뒤죽박죽 끝난 결과를 원래 프로그램 순서대로 은퇴시켜 정확성을 보장한다. ROB는 수백 개의 미완료 명령을 담아 긴 대기를 감춘다. |
| **로드/스토어 유닛 (LSU) + 주소 생성 유닛(AGU)** | 메모리 읽기(load)·쓰기(store) 명령을 처리한다. AGU가 접근할 주소를 계산하고, 로드/스토어 큐와 버퍼로 메모리 접근 순서·의존을 관리한다. 캐시와 코어 사이의 데이터 창구다. |
| **하드웨어 프리페처 (Hardware Prefetcher)** | 메모리 접근 패턴(연속·일정 간격 등)을 관찰해, 아직 요청되지 않은 데이터를 미리 캐시로 끌어와 둔다. 실제 접근 때 캐시 히트가 되도록 대기 시간을 숨겨, 순차·규칙적 데이터 처리에서 체감 성능을 크게 올린다. |
| **L1 / L2 캐시 (코어 전용)** | 코어 바로 옆에 붙은 초고속 소형 메모리. L1은 명령용·데이터용으로 나뉘어 가장 빠르고(대략 1 ns, 4~5 사이클), L2는 조금 크고 조금 느리다(약 3~4 ns). 자주 쓰는 코드·데이터를 여기 담아 느린 RAM 왕복을 줄인다. |
| **L3 캐시 (공유) + 코어 간 인터커넥트(링/메시)** | 여러 코어가 함께 쓰는 큰 캐시로, 코어들 사이의 데이터 공유·일관성(캐시 코히런스, 예: MESI)의 중심이다. 링 버스나 메시 네트워크가 코어·캐시·메모리 컨트롤러를 그물처럼 이어 데이터를 실어 나른다. AMD의 3D V-캐시나 서버 칩은 이 L3를 수십~수백 MB까지 키운다. |
| **MMU (Memory Management Unit) + TLB (Translation Lookaside Buffer)** | 프로그램이 쓰는 가상 주소를 실제 물리 주소로 번역하는 장치. TLB는 최근 번역 결과를 담은 캐시로, 매번 페이지 테이블을 뒤지지(page walk) 않고 빠르게 주소를 변환한다. 프로세스 간 메모리 보호와 가상 메모리를 가능케 한다. |
| **통합 메모리 컨트롤러 (IMC, Integrated Memory Controller)** | 예전엔 메인보드 칩셋(노스브리지)에 있던 것이 이제 CPU 안으로 들어온 부품. DRAM(DDR5 등)과 직접 대화하며 읽기/쓰기 타이밍과 채널을 관리한다. CPU 옆에 붙어 있어 메모리 지연이 크게 줄었다. |
| **PCIe 컨트롤러 (Peripheral Component Interconnect Express)** | GPU·NVMe SSD·네트워크 카드 같은 고속 주변장치와 CPU를 직접 잇는 초고속 통로. 여러 개의 '레인'으로 데이터를 병렬 전송하며, IMC와 함께 CPU를 시스템의 데이터 허브로 만든다. |
| **클럭 생성기(PLL) + 전압조정·전력관리** | PLL(Phase-Locked Loop)이 기준 클럭을 곱해 코어가 쓰는 수 GHz 클럭을 만든다. 전력·온도 여유를 보고 클럭·전압을 실시간으로 올리거나(부스트) 낮춰(절전) 성능과 발열·전력의 균형을 맞춘다(DVFS). 온도 한계에서는 스로틀링으로 클럭을 낮춘다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **명령어 파이프라인 (Instruction Pipeline)** | 명령 처리를 페치·디코드·실행·메모리·라이트백 등 여러 단계로 쪼개, 세탁기·건조기·개기를 겹쳐 돌리듯 여러 명령을 각 단계에서 동시에 흐르게 하는 구조. 한 명령을 끝까지 기다리지 않아 처리량이 크게 오른다. |
| **슈퍼스칼라 (Superscalar)** | 한 클럭 사이클에 명령을 한 개가 아니라 여러 개 동시에 발행·실행하는 구조. 실행 유닛(ALU·FPU 등)을 여러 벌 두어 병렬로 처리한다. 현대 고성능 코어는 대략 4~10개 폭이다. |
| **비순차 실행 (Out-of-Order Execution, OoO)** | 프로그램에 적힌 순서 그대로가 아니라, 입력값이 먼저 준비된 명령부터 실행하는 방식. 앞 명령이 느린 메모리를 기다릴 때 뒤의 독립 명령을 먼저 처리해 유닛이 쉬지 않게 한다. 결과는 ROB가 원래 순서로 되맞춘다. |
| **분기 예측 + 추측 실행 (Branch Prediction, Speculative Execution)** | 조건이 확정되기 전에 분기 방향을 예측해 미리 실행하는 것. 맞으면 시간을 벌고, 틀리면 되돌린다. 파이프라인이 갈림길에서 멈추지 않게 하는 핵심 기술. |
| **레지스터 리네이밍 (Register Renaming)** | 이름이 같은 레지스터를 여럿이 다른 용도로 쓸 때 생기는 '가짜 의존성(WAR·WAW)'을, 물리 레지스터를 넉넉히 두어 서로 다른 실물에 매핑해 없애는 기법. 비순차 실행을 가능케 한다. |
| **IPC (Instructions Per Cycle, 사이클당 명령 수)** | 클럭 한 번에 평균 몇 개의 명령을 끝내는가. 클럭 속도(GHz)와 함께 성능을 결정한다(성능 ≈ 클럭 × IPC). '클럭이 같아도 IPC가 높으면 더 빠르다' — 세대 개선의 핵심 지표. |
| **클럭 · 부스트 (Clock, Turbo Boost)** | 클럭은 CPU가 일하는 박자로 초당 진동수(GHz, 1 GHz = 초당 10억 사이클). 부스트는 전력·온도 여유가 있을 때 일부 코어의 클럭을 기본값보다 순간적으로 끌어올리는 기능. |
| **ISA (Instruction Set Architecture, 명령어 집합 구조)** | CPU가 이해하는 기계어 명령의 규격·약속. x86-64(인텔·AMD)와 ARM(AArch64, 애플 M시리즈·스마트폰), 그리고 개방형 RISC-V가 대표. 같은 프로그램도 ISA가 다르면 다시 컴파일해야 한다. |
| **CISC vs RISC (x86 vs ARM)** | CISC(x86)는 명령이 복잡하고 길이가 가변(1~15바이트), RISC(ARM)는 명령이 단순하고 대체로 4바이트 고정. 요즘 x86도 내부에선 명령을 잘게 쪼개(마이크로옵) RISC처럼 비순차·슈퍼스칼라로 실행해 경계가 흐려졌다. |
| **SIMD (Single Instruction, Multiple Data)** | 하나의 명령으로 여러 데이터를 동시에 계산하는 병렬 방식. x86의 SSE/AVX/AVX2/AVX-512, ARM의 NEON/SVE가 이에 해당. 영상·오디오·AI처럼 같은 연산을 대량 반복할 때 위력적. |
| **캐시 계층 · 지역성 · 캐시 라인** | L1<L2<L3 순으로 크고 느린 다층 캐시. 최근·근처의 데이터가 또 쓰일 가능성이 높다는 '지역성(시간·공간)'을 이용한다. 데이터는 보통 64바이트 단위(캐시 라인)로 통째 옮겨진다(애플 실리콘은 128바이트). |
| **캐시 일관성 (Cache Coherence)** | 여러 코어가 각자 캐시에 같은 데이터의 사본을 둘 때, 한 곳에서 값을 바꾸면 다른 사본을 무효화·갱신해 모두가 같은 값을 보게 하는 규약(예: MESI). 멀티코어에서 데이터 정합성을 지키는 바탕이다. |
| **MMU · TLB · 가상 메모리** | 프로그램은 실제 물리 주소가 아닌 가상 주소를 쓰고, MMU가 이를 물리 주소로 번역한다. TLB는 그 번역 결과를 캐시해 빠르게 처리하고, 놓치면 페이지 테이블을 뒤진다(page walk). 프로세스마다 독립된 메모리 공간과 보호를 제공한다. |
| **IMC (Integrated Memory Controller, 통합 메모리 컨트롤러)** | CPU 안에 내장돼 DRAM과 직접 통신하는 컨트롤러. 과거 별도 칩(노스브리지)에 있던 것을 CPU로 흡수해 메모리 지연을 줄였다. |
| **PCIe (Peripheral Component Interconnect Express)** | GPU·NVMe SSD·네트워크 카드를 CPU에 잇는 고속 직렬 통로. '레인' 단위로 병렬 전송하며 세대(4.0/5.0/6.0)가 오를수록 레인당 대역폭이 대략 두 배씩 는다. |
| **마이크로옵 (micro-op, μop) · 마이크로옵 캐시** | 복잡한 기계어 명령을 CPU 내부에서 실행하기 쉽게 쪼갠 최소 단위 연산. 실제 실행 유닛은 이 마이크로옵을 처리한다. 이미 디코드한 마이크로옵을 마이크로옵 캐시에 담아두면 반복 코드에서 디코딩을 건너뛴다. |
| **SMT / 하이퍼스레딩 (Simultaneous Multi-Threading)** | 물리 코어 하나를 논리 코어 2개(일부 아키텍처는 4·8개)처럼 보이게 해, 한 스레드가 노는 사이 다른 스레드가 실행 유닛을 쓰게 하는 기술. 코어 자원 활용률을 높인다(성능이 두 배가 되는 것은 아님). 애플 M계열 등 SMT를 아예 안 쓰는 설계도 많다. |
| **투기적 실행의 보안 취약점 (Spectre / Meltdown)** | 성능을 위한 추측 실행이, 접근하면 안 될 데이터를 잠깐 미뤄 처리하는 과정에서 캐시 등에 흔적을 남겨 비밀을 유추당할 수 있다는 부작용(부채널 공격). 2018년 공개된 이 문제로 소프트·하드웨어 완화책이 도입됐다. |

## 📊 대표 사양·수치 감각

| 항목 | 값 | 비고 |
|---|---|---|
| 코어 수 / 스레드 수 | 소비자용 대략 4~24 코어(P·E 혼합 포함, 최대 32스레드 안팎), 서버용 최대 128~192 코어(일부 288 E코어) | SMT를 쓰면 스레드 수는 보통 코어 수의 2배. SMT 없는 설계(애플 M 등)는 코어=스레드. 세대·등급별 편차 큼 |
| 베이스 / 부스트 클럭 | 베이스 대략 2~4 GHz, 부스트 대략 5~6 GHz(최상위 6 GHz 초과) | 1 GHz = 초당 10억 사이클. 부스트는 일부 코어·짧은 시간 한정 |
| 파이프라인 깊이 | 일반적으로 대략 14~20 단계 | 깊을수록 고클럭에 유리하나 분기 예측 실패 시 손해(수십 사이클)가 커짐 |
| 슈퍼스칼라 폭 | 고성능 코어 대략 4~10 wide(애플 M·Zen5 등 8~10) | 한 사이클에 디코드·발행할 수 있는 명령(마이크로옵) 수 |
| 재정렬 버퍼(ROB) 크기 | 대략 200~600+ 엔트리 | 동시에 처리 중일 수 있는 미완료 명령의 규모. 신형일수록 커지는 추세(애플 M계열 ~600+) |
| L1 캐시 | 명령·데이터 각각 대략 32~64 KB(합 64~128 KB), 지연 약 1 ns(4~5 사이클) | 가장 빠르고 가장 작음. 애플 실리콘은 L1D가 128~192 KB로 예외적으로 큼 |
| L2 캐시 | 코어당 대략 512 KB ~ 3 MB(구형은 256 KB), 지연 대략 3~4 ns(약 12~16 사이클) | 코어 전용, L1보다 크고 느림. 일부 설계는 코어 클러스터가 공유 |
| L3 캐시 | 소비자용 공유 대략 8~64 MB(3D 캐시 96 MB 이상), 서버는 수백 MB(예: EPYC 384 MB+), 지연 대략 10~15 ns(약 30~50 사이클) | 여러 코어가 공유하는 마지막 레벨 캐시(LLC) |
| DRAM(주메모리) 접근 지연 | 대략 60~100 ns | L1보다 수십 배 느려 캐시로 감추는 이유 |
| 캐시 라인 크기 | 대부분 64 바이트(x86·대다수 ARM), 애플 실리콘은 128 바이트 | 캐시가 데이터를 옮기는 최소 단위 |
| TLB 엔트리 / 페이지 크기 | L1 TLB 수십~약 100개, L2(공유) TLB 약 1500~3000+개 / 기본 페이지 4 KB(대형 페이지 2 MB·1 GB, ARM은 16 KB·64 KB도) | 주소 번역 캐시 규모. 미스 시 페이지 테이블 워크로 느려짐 |
| 메모리(IMC) — DDR5 | DDR5-6000 기준 채널당 약 48 GB/s, 듀얼 채널 약 90~96 GB/s | 6000 MT/s × 8바이트 ≈ 48 GB/s. DDR5 한 채널은 32비트 서브채널 2개로 나뉨. 세대: DDR4→DDR5 |
| PCIe 컨트롤러 | PCIe 5.0 레인당 약 3.9 GB/s(방향당), x16이면 방향당 약 63 GB/s | 세대마다 레인당 대역폭 약 2배(4.0 x16은 방향당 약 32 GB/s). 값은 단방향 기준 |
| 코어 전압 (VCore) | 대략 0.7~1.4 V | 부하·클럭에 따라 실시간 변동, 절전 시 더 낮음, 순간 부스트 시 더 높을 수 있음 |
| 공정 노드 / 트랜지스터 | 3~5 nm급 공정, 수십억~수백억 개 트랜지스터 | 'nm'은 세대를 가리키는 상업적 이름일 뿐 실제 트랜지스터 물리 치수가 아님. 미세화할수록 더 많은 트랜지스터를 낮은 전력으로 집적 |
| TDP (열설계전력) | 모바일 약 9~55 W, 데스크톱 약 35~250 W | 지속 발열·냉각 설계의 기준값이지 순간 최대 소비전력이 아님. 부스트 시 실제 전력(PL2/PPT)은 TDP를 크게 웃돌 수 있음(데스크톱 최상위 300 W 이상) |
| SIMD 벡터 폭 | SSE 128비트, AVX/AVX2 256비트, AVX-512 512비트 / ARM NEON 128비트, SVE 가변(128~2048비트) | 한 명령이 다루는 데이터 폭. AVX-512는 제품별 지원 편차가 큼 |

## ⚠️ 흔한 오해

- **오해** — 클럭(GHz)이 높은 CPU가 무조건 더 빠르다.
  <br>**교정** — 실제 성능은 대략 클럭 × IPC(사이클당 처리하는 명령 수)로 결정된다. 세대가 새로운 CPU는 클럭이 같거나 낮아도 IPC가 높아 더 빠를 수 있다. 클럭만으로, 특히 ISA·세대가 다른 CPU끼리 우열을 가릴 수 없다.
- **오해** — 코어가 2배면 프로그램이 2배 빨라진다.
  <br>**교정** — 여러 코어를 쓰려면 작업이 병렬로 쪼개져야 한다. 순차적 의존이 많은 작업은 코어를 늘려도 거의 빨라지지 않는다(암달의 법칙). 게임·일반 앱은 소수 코어의 단일 성능이 더 중요할 때가 많다.
- **오해** — CPU는 명령을 항상 프로그램에 적힌 순서 그대로 하나씩 실행한다.
  <br>**교정** — 현대 고성능 CPU는 비순차 실행으로 순서를 바꿔 여러 명령을 동시에 처리하고, 분기 예측으로 미래 명령을 미리 추측 실행한다. 겉으로 보이는 결과만 원래 순서를 지킬 뿐, 내부는 병렬·재배치·추측으로 돌아간다(단, 저전력·임베디드용 순차 실행 코어도 여전히 있다).
- **오해** — 하이퍼스레딩(SMT)은 코어를 두 배로 늘려 성능을 두 배로 만든다.
  <br>**교정** — 물리 코어는 그대로이고, 한 코어의 놀고 있는 실행 유닛을 두 스레드가 나눠 쓰게 하는 것이다. 활용률을 높여 흔히 20~30% 정도 이득을 주지만 두 배가 되지는 않으며, 작업에 따라 이득이 없거나 손해일 수도 있다.
- **오해** — 캐시는 RAM과 같은 종류의 메모리라 별로 중요하지 않다.
  <br>**교정** — 캐시는 코어에 붙은 SRAM으로, RAM(DRAM)과 종류가 다르다. RAM 접근은 대략 60~100 ns, L1 캐시는 약 1 ns로 수십 배 차이다. 캐시가 없으면 CPU는 대부분의 시간을 데이터를 기다리며 놀게 된다. 캐시 적중률이 체감 성능을 좌우한다.
- **오해** — 메모리 컨트롤러와 PCIe는 메인보드(칩셋)에 있는 별개 부품이다.
  <br>**교정** — 요즘 CPU는 메모리 컨트롤러(IMC)와 PCIe 컨트롤러를 칩 안에 통합했다. 그래서 CPU가 RAM·GPU·SSD와 훨씬 짧은 거리로 직접 대화해 지연이 줄었다. 메인보드 칩셋은 상대적으로 느린 나머지 I/O를 담당한다.
- **오해** — x86과 ARM은 성능·전력 특성이 태생적으로 완전히 다른 별개의 세계다.
  <br>**교정** — 둘의 차이는 명령어 집합(ISA) 규격이며, 내부적으로 x86도 명령을 마이크로옵으로 쪼개 비순차·슈퍼스칼라로 실행해 RISC와 비슷하게 동작한다. 전력·성능 차이는 ISA 자체보다 마이크로아키텍처 설계·공정·목표 시장에서 더 크게 갈린다.
- **오해** — TDP가 CPU가 소비하는 최대 전력이다.
  <br>**교정** — TDP는 지속적으로 감당해야 할 발열을 냉각 설계에 알려주는 기준값이지, 순간 최대 소비전력이 아니다. 부스트가 걸리면 실제 전력(인텔 PL2, AMD PPT)은 TDP를 크게 웃돌 수 있어, 65 W TDP 칩이 순간 100 W 이상을 끌기도 한다.

## 💡 비유

CPU는 거대한 주방의 총괄 셰프에 가깝다. 레시피(프로그램)를 한 줄씩 읽어(페치) 뜻을 파악하고(디코드), 여러 조리대(ALU·FPU·SIMD)에 일을 나눠 던지며, 자주 쓰는 재료는 손 닿는 곳(캐시)에 두고 창고(RAM)까지 가는 걸음을 아낀다. 파이프라인은 컨베이어벨트 공장 라인이다 — 한 제품이 완성될 때까지 기다리지 않고, 자르기·조립·포장 단계에 서로 다른 제품이 동시에 흐른다. 분기 예측은 갈림길에서 신호가 바뀌기 전에 '초록불이겠지' 하고 미리 출발하는 노련한 운전자와 같아서, 맞으면 시간을 벌고 틀리면 왔던 길을 되짚어 돌아온다. 비순차 실행은, 손이 빈 조리대가 있으면 순번을 기다리지 않고 재료가 준비된 주문부터 먼저 만들되, 손님에게 내갈 때는 원래 주문 순서대로 내가는 셈이다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 부팅: 전원이 들어오면 CPU가 리셋 벡터부터 깨어나 펌웨어(UEFI/BIOS) 코드를 페치·실행하며 하드웨어를 점검하고, 부트로더를 거쳐 운영체제 커널을 RAM에 올려 실행한다. (엄밀히는 인텔 ME·AMD PSP 같은 보안 프로세서가 먼저 초기화를 돕는다.) 이후 모든 초기화 명령이 CPU를 통과한다.
- 게임 렌더링: 게임 로직·물리·AI·입력 처리를 CPU가 담당하고, 매 프레임 GPU에 그릴 명령(드로우콜)을 만들어 PCIe로 넘긴다. 분기 예측과 높은 단일코어 성능이 프레임 시간에 직접 영향을 준다.
- 인터넷 검색 왕복: 브라우저가 검색어를 보내고 응답을 받는 동안, CPU가 네트워크 카드에서 온 패킷을 처리하고(인터럽트) TLS 암호 해독, HTML/JS 파싱, 페이지 레이아웃 계산을 모두 수행한다.
- 파일 열기: CPU가 파일 시스템 자료구조를 뒤져 파일 위치를 찾고, NVMe SSD에 읽기 명령을 내린 뒤(PCIe 경유) 도착한 데이터를 애플리케이션이 쓸 형태로 디코딩·배치한다.
- Ctrl+S 저장: 키 입력 인터럽트를 CPU가 받아 저장 루틴을 실행하고, 메모리의 문서 데이터를 정리해 SSD에 쓰기 명령을 발행하며 파일 시스템 메타데이터를 갱신한다.
- 소리 재생: 압축된 오디오(MP3 등)를 CPU가 디코딩하는데, 이때 SIMD 유닛이 반복 연산을 병렬 처리하고, 풀린 파형을 사운드 장치로 흘려보낸다.
- 영상 스트리밍: 네트워크 수신·버퍼 관리·자막·재생 제어를 CPU가 맡고, 코덱에 따라 SIMD로 소프트웨어 디코딩을 돕거나 전용 하드웨어 디코더/GPU에 작업을 넘기도록 조율한다.
- AI 질문: 입력 텍스트의 토큰화·전처리와 결과 후처리를 CPU가 하고, 무거운 행렬 연산은 GPU/NPU로 보내되 그 데이터 이동과 스케줄링 전체를 CPU가 지휘한다.
