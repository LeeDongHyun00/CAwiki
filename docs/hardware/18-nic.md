# 네트워크 인터페이스 (NIC · Wi-Fi 모듈)
*Network Interface Controller & Wi-Fi Module*

> 컴퓨터 내부의 디지털 비트(0과 1)를 케이블 속 전기신호나 공기 중 전파로 바꿔 다른 기기와 주고받게 하는, 바깥 네트워크로 향하는 관문이다.

**분류**: 네트워크

## 🧭 한마디로, 무슨 일을 하나
CPU와 메모리가 다루는 디지털 데이터를, 바깥 네트워크 매체가 이해하는 형태(구리선의 전압 변화, 광섬유의 빛, 안테나의 전자기파)로 변환하고 그 역변환도 담당하는 하드웨어다. OSI 모델의 2계층(데이터링크)과 1계층(물리)을 실물 회로로 구현해, 데이터를 '프레임'이라는 규격 봉투에 담고 주소(MAC)를 붙이며 오류검출 도장(CRC)을 찍고 매체 접근을 통제한다. 이때 유선(이더넷)은 스위치 기반 전이중으로 충돌 없이 주고받지만, 무선(Wi-Fi)은 공기를 공유하는 반이중이라 CSMA/CA로 충돌을 피하며 802.11 MAC/PHY를 구현한다. 나아가 체크섬 계산이나 큰 데이터 쪼개기 같은 반복 작업을 하드웨어가 대신 처리(오프로드)해 CPU의 부담을 덜어준다. 유선 이더넷 NIC와 무선 Wi-Fi 모듈은 매체가 다를 뿐 "디지털 ↔ 물리신호 변환 관문"이라는 본질은 같다.

## ⚙️ 작동 방식

**1. 운영체제가 보낼 데이터를 메모리에 놓고, NIC가 DMA로 가져간다**

애플리케이션이 보낸 데이터는 커널의 소켓 버퍼에 쌓이고, 드라이버는 '데이터가 메모리 어디에 있는지'를 적은 디스크립터(descriptor)를 링 버퍼에 등록한다. NIC는 이 디스크립터를 읽어 CPU 개입 없이 DMA(Direct Memory Access)로 데이터를 직접 읽어온다. 왜: CPU가 바이트 하나하나를 밀어넣으면 낭비가 크므로, '위치만 알려주면 알아서 가져가는' 구조로 CPU를 자유롭게 한다.

**2. 오프로드 엔진이 데이터를 잘게 나누고 오류검사 값을 미리 계산한다**

수십 KB(최대 약 64KB의 슈퍼패킷)짜리 큰 데이터를 OS 대신 NIC가 하드웨어로 처리한다. TSO(TCP Segmentation Offload)는 데이터를 링크가 실을 수 있는 크기(MSS)로 자동 분할하고 각 조각마다 TCP/IP 헤더를 복제·조정(시퀀스 번호·체크섬)해 붙인다. CSO(Checksum Offload)는 IP·TCP·UDP 체크섬을 회로에서 계산해 채운다. 왜: 이 반복 연산을 CPU가 하면 수만 번의 사이클을 소모하므로, 전용 하드웨어가 맡아 처리량을 끌어올린다.

**3. MAC 계층이 '프레임'을 조립하고 CRC 도장을 찍는다**

MAC(Media Access Control) 컨트롤러가 목적지·출발지 MAC 주소(각 6바이트), 타입/길이 필드(EtherType), 페이로드, 그리고 끝에 CRC-32로 계산한 FCS(Frame Check Sequence, 4바이트)를 붙여 하나의 이더넷 프레임(64~1518바이트, VLAN 태그 시 1522)을 만든다. 다만 그 앞에 붙는 프리앰블(7바이트)·SFD(1바이트)와 프레임 사이 최소 간격(IFG, 12바이트=96비트타임)은 수신측이 클럭을 맞추고 경계를 잡도록 물리계층이 덧대는 '프레이밍'으로, 64~1518바이트 프레임 크기나 FCS 계산 범위에는 포함되지 않는다. 과거 반이중(공유 매체) 시절엔 CSMA/CD로 충돌을 감지했지만, 오늘날 스위치 기반 전이중 링크는 각 방향 전용 회선이라 충돌 자체가 없다. 왜: 링크에서는 연속 비트가 아니라 '경계·주소·검사값이 있는 덩어리' 단위로 주고받아야 수신측이 시작·끝·오류를 판별한다.

**4. PHY가 비트를 선로 코드로 바꿔 물리 신호 심볼로 만든다**

PHY(물리계층 트랜시버)의 PCS(Physical Coding Sublayer)가 스크램블링(전자기 간섭·DC 쏠림 억제)과 라인 코딩을 하는데, 방식은 매체에 따라 다르다. 광/SerDes 기반 10GBASE-R(SFP+ 등)은 64B/66B 블록 코딩을 쓰지만, RJ45 구리선 기반은 1000BASE-T가 4D-PAM5(트렐리스), 10GBASE-T가 128-DSQ/PAM-16을 쓴다. 고속 구리 등급(10GBASE-T 등)은 LDPC 같은 FEC(전방오류정정)를 덧붙인다. 이어 PMA/PMD가 이를 여러 전압 준위를 가진 PAM 심볼(구리) 또는 직렬 심볼(광/SerDes)로 만들어 선로에 실을 준비를 한다. 왜: 긴 구리선을 안정적으로 통과하려면 신호의 균형을 잡고, 잡음에 대비한 정정 여유를 심어두어야 한다.

**5. 5-A. (유선) 자기소자를 거쳐 RJ45로 나가 트위스트 페어에 실린다**

신호는 자기소자(격리 트랜스포머 + 공통모드 초크, 흔히 RJ45에 통합된 MagJack)를 통과한다. 트랜스포머는 두 기기의 접지 전위차를 끊어 갈바닉 절연·감전 보호를 하고, 공통모드 초크는 두 선에 함께 실린 잡음을 상쇄한다. 신호는 RJ45(8P8C) 커넥터의 여러 트위스트 페어에 차동 신호(두 선의 전압 차)로 실려 나가며, 1000BASE-T 이상은 각 쌍을 에코 제거로 양방향 동시에 쓴다. 왜: 차동 전송과 꼬임은 외부 잡음을 양쪽 선이 똑같이 받아 상쇄시키므로 먼 거리에서도 신호가 살아남는다.

**6. 5-B. (무선) 매체를 확보한 뒤 베이스밴드→변조→RF 프런트엔드→안테나로 전파가 된다**

Wi-Fi는 공기라는 공유 매체를 여러 기기가 함께 쓰고 한 무전기가 같은 채널에서 송·수신을 동시에 못 하는 반이중이라, 보내기 전에 먼저 CSMA/CA(반송파 감지→비어 있으면 임의 백오프 뒤 송신, 필요 시 RTS/CTS로 예약)로 충돌을 '회피'한다(유선 CSMA/CD가 충돌을 '감지'하는 것과 다르다). 매체를 확보하면 베이스밴드 프로세서가 비트를 QAM 성좌점(예: 1024-QAM은 심볼당 10비트)에 대응시키고, OFDM(직교주파수분할다중)으로 수백 개 부반송파에 나눠 실은 뒤 IFFT로 시간 파형을 만든다. DAC가 이를 아날로그로 바꾸고, 믹서가 국부발진기(PLL/신디사이저)로 2.4/5/6 GHz 반송파 위로 주파수를 올리며, PA(전력증폭기)가 세기를 키워 안테나로 방사한다. OFDMA는 채널을 자원단위(RU)로 쪼개 여러 기기가 동시에, MU-MIMO는 여러 안테나로 공간 스트림을 겹쳐 보낸다. 왜: 디지털 데이터를 매질(공기)이 나를 수 있는 전자기파의 진폭·위상 패턴으로 바꿔야 무선으로 전달된다.

**7. 반대편 NIC가 물리 신호를 받아 다시 비트로 복원한다**

수신측 PHY(또는 Wi-Fi RX)는 안테나·LNA(저잡음증폭기)로 약한 신호를 키우고, 다운컨버전·ADC·FFT를 거쳐 복조하며(유선은 클럭 복원·등화·디코딩), FEC로 오류를 정정한다. MAC은 프레임 끝의 FCS를 다시 계산해 일치하면 통과, 어긋나면 폐기한다. 왜: 매질을 지나며 감쇠·왜곡된 신호에서 원래 심볼을 추정하고, 손상 프레임을 걸러내 잘못된 데이터가 위로 올라가지 않게 한다.

**8. 수신 오프로드로 묶어 host 메모리에 올리고 CPU에 알린다**

검증된 프레임은 헤더가 벗겨지고, LRO/GRO(수신측 병합)가 여러 조각을 하나의 큰 버퍼로 합쳐 처리 횟수를 줄인다(LRO는 NIC 하드웨어가, GRO는 커널 소프트웨어가 수행하는 일반화 버전이다). NIC는 DMA로 데이터를 host 메모리에 쓰고 인터럽트로 CPU에 도착을 알린다. 이때 인터럽트 병합(coalescing)으로 알림을 몰아서 보내고(리눅스는 NAPI로 인터럽트→폴링 전환), RSS(Receive Side Scaling)로 트래픽을 해시해 여러 CPU 코어에 분산한다. 왜: 패킷마다 인터럽트를 걸면 고속에서 CPU가 마비되므로, 묶어서 알리고 코어별로 나눠 병목을 없앤다.

**9. 블루투스·전력관리 등 부가 기능이 같은 무선 자원을 조율한다**

노트북의 콤보 칩은 Wi-Fi와 블루투스가 같은 2.4 GHz 대역과 때로는 안테나를 공유하므로, 공존(coexistence) 로직이 시간을 나눠 서로 간섭을 피한다. Wi-Fi 6 이후엔 TWT(Target Wake Time)로 기기가 정해진 시각에만 깨어나 배터리를 아끼고, Wi-Fi 7의 MLO는 여러 대역 링크를 동시에 묶어 지연을 낮추고 안정성을 높인다. 왜: 한정된 주파수를 여러 무선 규격이 나눠 써야 하고, 모바일 기기에선 전력 절약이 성능만큼 중요하다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **MAC 컨트롤러 (Media Access Control)** | 프레임을 조립·해체하고 MAC 주소를 붙이며 CRC(FCS)를 계산·검증하고, 매체 접근(유선 전이중/무선 CSMA/CA)과 송수신 큐를 관리하는 2계층의 두뇌. 오늘날 PC에서는 흔히 칩셋/SoC 안에 통합돼 있다. |
| **PHY 트랜시버 (물리계층: PCS/PMA/PMD)** | 비트를 선로 코드·심볼로 바꾸고(송신) 물리 신호에서 비트를 복원하며(수신), 스크램블링·등화·클럭 복원(SerDes)·오토니고시에이션을 담당하는 1계층 회로. |
| **자기소자 (격리 트랜스포머 + 공통모드 초크)** | 두 기기의 접지 전위차를 끊어 갈바닉 절연·감전 보호를 하고, 공통모드 잡음을 상쇄하며 임피던스를 정합한다. RJ45에 통합되면 MagJack이라 부른다. |
| **RJ45 (8P8C) 커넥터** | 랜케이블을 꽂는 8핀 물리 접점. 여러 트위스트 페어를 통해 차동 신호가 드나드는 유선 이더넷의 출입구. |
| **Wi-Fi 베이스밴드/MAC 프로세서** | 무선 프레임 조립, CSMA/CA 매체 접근, 암호화, QAM 매핑, OFDM/OFDMA 처리, MIMO 스트림 관리 등 무선 통신의 디지털 두뇌. 대개 전용 펌웨어로 동작한다. |
| **RF 트랜시버 (믹서·PLL 신디사이저·ADC/DAC)** | 베이스밴드 디지털 신호를 아날로그로 바꾸고(DAC), 국부발진기로 반송파 위로 주파수를 올리거나 내리는(믹서) 아날로그-디지털 경계. |
| **RF 프런트엔드 (PA·LNA·RF 스위치·SAW/BAW 필터)** | 송신 신호를 증폭하는 PA(전력증폭기), 수신 신호를 잡음 적게 키우는 LNA(저잡음증폭기), 송수신을 전환하는 스위치, 원치 않는 주파수를 걸러내는 필터의 묶음. |
| **안테나** | 전기 신호를 전자기파로 방사하고 되받는 변환기. Wi-Fi는 여러 개(다중 안테나)로 MIMO·빔포밍을 구현하며, 블루투스와 공유하기도 한다. |
| **블루투스 콤보 & 공존 로직** | 같은 2.4 GHz 대역과 안테나를 쓰는 Wi-Fi·블루투스가 서로 간섭하지 않도록 시간을 나눠 조율하는 부분. 노트북·폰의 콤보 칩에 함께 들어간다. |
| **host 버스 인터페이스 & DMA 엔진 (PCIe/USB/M.2)** | NIC를 컴퓨터 본체와 연결하고, 디스크립터 링을 읽어 CPU 개입 없이 메모리와 데이터를 직접 주고받는(DMA) 통로. |
| **온보드 버퍼·메모리 (FIFO/SRAM) 와 펌웨어 저장소(EEPROM/플래시)** | host와 링크의 속도 차를 흡수하는 송수신 버퍼, MAC 주소·설정을 담은 EEPROM, 동작 코드를 담은 펌웨어 플래시. |
| **클럭 소스 (크리스탈 오실레이터)** | 정확한 심볼 타이밍과 반송파 주파수의 기준이 되는 진동자. 무선에서는 주파수 정확도가 통신 품질을 좌우한다. |
| **상태 표시 LED / 오프로드·보안 가속 블록(서버급)** | 링크·활동을 알리는 LED. 서버용 NIC에는 TCP 오프로드, 암호화 가속, 대형 패킷 버퍼 등 추가 가속 회로가 들어가기도 한다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **MAC 주소 (Media Access Control address)** | NIC마다 부여된 48비트(6바이트) 하드웨어 식별자. 같은 링크(로컬 네트워크) 안에서 프레임을 어느 장치로 보낼지 가리킨다. IP 주소가 종단 간 '집 주소'라면 MAC은 '지금 이 구간의 옆집 이름'이며, 둘의 대응은 ARP가 링크 안에서 물어보아 맺어준다. |
| **MAC 계층 / PHY (물리계층)** | MAC은 프레임·주소·오류검출·접근제어를 다루는 2계층, PHY는 비트를 실제 전기·전파 신호로 바꾸는 1계층. NIC는 이 둘을 하드웨어로 구현한 장치다. |
| **프레임 / CRC / FCS (Frame Check Sequence)** | 데이터를 주소·검사값과 함께 감싼 전송 단위가 프레임. 끝에 붙는 FCS는 CRC-32로 계산한 오류검출 값으로, 수신측이 다시 계산해 비교하며 손상 여부를 판별한다(정정이 아닌 '검출'). 프레임 앞의 프리앰블·SFD와 프레임 사이 간격(IFG)은 물리계층 프레이밍이라 프레임 크기나 FCS 범위에 포함되지 않는다. |
| **CSMA/CD · CSMA/CA 와 전이중/반이중** | CSMA/CD는 공유 케이블 시절 유선에서 충돌을 감지하던 방식으로, 오늘날 스위치 기반 유선은 각 기기가 전용 링크로 동시에 송·수신하는 전이중이라 충돌이 없다. 반면 Wi-Fi는 공기를 공유하고 한 무전기가 같은 채널에서 송·수신을 동시에 못 하는 반이중이라, 충돌을 미리 피하는 CSMA/CA(반송파 감지 + 임의 백오프 + 필요 시 RTS/CTS 예약)를 쓴다. |
| **OFDM / OFDMA** | OFDM은 데이터를 서로 직교하는 수백 개 부반송파에 나눠 실어 잡음·간섭에 강하게 만드는 변조. OFDMA는 그 부반송파를 자원단위(RU)로 쪼개 여러 기기가 한 채널을 동시에 나눠 쓰게 한 Wi-Fi 6의 핵심 기술. |
| **QAM (Quadrature Amplitude Modulation, 직교진폭변조)** | 신호의 진폭과 위상을 조합해 한 심볼에 여러 비트를 싣는 방식. 1024-QAM은 심볼당 10비트, Wi-Fi 7의 4096-QAM은 12비트를 실어 속도를 높이지만, 그만큼 잡음에 민감해 근거리·강신호에서만 유리하다. |
| **MIMO / MU-MIMO / 빔포밍** | MIMO(Multiple Input Multiple Output)는 여러 안테나로 독립적인 공간 스트림을 동시에 보내 속도를 배가한다. MU-MIMO는 여러 사용자에게 동시에, 빔포밍은 신호를 특정 방향으로 모아 도달거리·품질을 높인다. |
| **대역(band) / 채널 / 채널폭** | Wi-Fi가 쓰는 주파수 묶음이 대역(2.4·5·6 GHz), 그 안을 나눈 통로가 채널, 한 통신이 차지하는 폭이 채널폭(20~320 MHz). 폭이 넓을수록 빠르지만 겹침·간섭 위험도 커진다. |
| **Wi-Fi 6 / 6E / 7 (IEEE 802.11ax / 802.11be)** | Wi-Fi 6은 802.11ax(2.4·5 GHz, OFDMA·1024-QAM), 6E는 여기에 6 GHz 대역을 더한 것, Wi-Fi 7은 802.11be로 320 MHz 채널·4096-QAM·MLO를 도입했다. (참고 세대: Wi-Fi 4=11n, Wi-Fi 5=11ac) |
| **오프로드 (TSO/LSO, CSO, LRO/GRO)** | CPU가 할 반복 작업을 NIC 하드웨어가 대신하는 것. TSO/LSO는 큰 데이터 자동 분할, CSO는 체크섬 계산을 담당한다. 수신 병합은 LRO(NIC 하드웨어)와 GRO(커널 소프트웨어 일반화 버전)로 나뉘어 처리 횟수를 줄인다. |
| **DMA / 디스크립터 링** | NIC가 CPU를 거치지 않고 메모리와 직접 데이터를 주고받는 것이 DMA. 그 위치·상태를 적어둔 원형 목록이 디스크립터 링으로, host와 NIC가 이 목록을 보며 협업한다. |
| **차동 신호 / 자기소자 / 갈바닉 절연** | 두 선의 전압 '차이'로 값을 전하는 차동 신호는 공통 잡음에 강하다. 자기소자(트랜스포머)는 두 기기의 전위차를 끊어(갈바닉 절연) 감전·잡음으로부터 보호한다. |
| **오토니고시에이션 (Auto-Negotiation)** | 링크 양쪽 PHY가 연결 순간 서로의 능력을 교환해 최대 공통 속도(10M~10G 등)와 듀플렉스(전이중/반이중)를 자동으로 맞추는 이더넷 절차. 랜선만 꽂으면 알아서 '1G 전이중' 같은 조합이 정해지는 원리다. |
| **속도 등급 & NBASE-T** | 1G(1000BASE-T)·2.5G·5G·10G(10GBASE-T) 등 링크 속도 등급. 2.5G·5G는 기존 Cat5e/Cat6 배선을 그대로 쓰면서 속도를 올리려 만든 NBASE-T(IEEE 802.3bz) 규격이다. |
| **MTU / 점보 프레임** | 한 프레임이 실을 수 있는 최대 페이로드 크기가 MTU(일반적으로 1500바이트). 이를 최대 9000바이트까지 늘린 것이 점보 프레임으로, 대량 전송 시 오버헤드를 줄인다. |
| **MLO / TWT (Wi-Fi 6/7 부가 기술)** | MLO(Multi-Link Operation)는 여러 대역 링크를 동시에 묶어 속도·안정성을 높이는 Wi-Fi 7 기능, TWT(Target Wake Time)는 기기가 정해진 시각에만 깨어나 배터리를 아끼는 절전 기능. |
| **PoE (Power over Ethernet)** | 데이터를 나르는 랜케이블로 전력까지 함께 공급하는 기술. IP카메라·AP처럼 콘센트가 없는 곳의 장치에 대략 48V 전력을 함께 보낸다(IEEE 802.3af/at/bt). |

## ⚠️ 흔한 오해

- **오해** — 인터넷 '1기가' 회선이면 초당 1000 MB(1 GB)를 받는다.
  <br>**교정** — 1 Gbps는 초당 1000 '메가비트'라 바이트로는 약 125 MB/s다. 헤더 오버헤드까지 빼면 실효는 더 낮다. 비트(b)와 바이트(B)는 8배 차이.
- **오해** — Wi-Fi가 빨라졌으니 유선 NIC(랜포트)는 이제 필요 없다.
  <br>**교정** — 무선은 편하지만 지연·안정성·간섭 회피·전이중 측면에서 유선이 여전히 우세하다. 온라인 게임, 대용량 백업, 저지연 작업에는 유선이 유리하다.
- **오해** — MAC 주소도 IP처럼 인터넷 전체에서 나를 찾아온다.
  <br>**교정** — MAC은 '같은 링크(로컬)' 안에서만 유효하다. 프레임은 라우터를 지날 때마다 출발지·목적지 MAC이 바뀌고, 끝까지 유지되는 것은 IP 주소다.
- **오해** — 5 GHz(또는 6 GHz)가 2.4 GHz보다 무조건 좋다.
  <br>**교정** — 고주파는 대역폭이 넓어 빠르지만 벽 투과·도달거리가 약하다. 멀거나 벽이 많은 곳에서는 2.4 GHz가 오히려 잘 잡힌다. 상황에 따라 다르다.
- **오해** — 안테나가 3개면 속도가 3배가 된다.
  <br>**교정** — MIMO 스트림 수는 송신·수신·경로 환경 중 가장 적은 값에 묶이고, 다중경로 반사가 있어야 이득이 난다. 상대 기기 안테나가 1개면 스트림도 1개로 제한된다.
- **오해** — 규격에 적힌 9.6 Gbps(Wi-Fi 6) 같은 숫자가 실제 속도다.
  <br>**교정** — 그것은 최대 안테나·최대 채널폭·최고 QAM을 모두 가정한 물리계층 이론치다. 실제 앱 처리량은 거리·간섭·프로토콜 오버헤드로 그 수분의 1 수준인 경우가 많다.
- **오해** — 프레임 끝의 CRC(FCS)는 오류를 발견하면 고쳐준다.
  <br>**교정** — CRC/FCS는 오류를 '검출'만 한다. 정정은 PHY의 FEC(예: LDPC)나 상위 계층의 재전송이 담당하며, 손상 프레임은 보통 폐기 후 다시 보낸다.
- **오해** — Wi-Fi도 유선처럼 동시에 양방향(전이중)으로 통신한다.
  <br>**교정** — Wi-Fi 무전기는 같은 채널에서 송신과 수신을 동시에 못 하는 '반이중'이다. 그래서 여러 기기가 공기를 나눠 쓰려고 CSMA/CA(감지·백오프)로 순서를 다투며, 이것이 유선보다 지연 변동이 큰 이유다. MLO나 별도 대역을 써야 사실상의 동시성이 생긴다.
- **오해** — NIC는 데이터를 그냥 통과시키는 케이블 어댑터일 뿐이다.
  <br>**교정** — NIC은 프레임 조립, MAC 주소·CRC 처리, 세그멘테이션·체크섬 오프로드, DMA·인터럽트 관리까지 하는 작은 통신 컴퓨터다. 특히 고속에서는 이 하드웨어 처리가 CPU를 살린다.
- **오해** — Wi-Fi 6와 Wi-Fi 6E는 이름만 다르고 같은 것이다.
  <br>**교정** — 6E는 Wi-Fi 6에 6 GHz 대역을 추가로 개방한 것이다. 혼잡이 적은 새 대역을 쓸 수 있어 근거리에서 더 넓은 채널·낮은 간섭의 이점이 있다.

## 💡 비유

첫째, NIC은 '통역사 겸 우체국 창구'다. 컴퓨터 안쪽 언어(디지털 비트)와 바깥세상 언어(전선의 전압 변화, 공기 중 전파)를 서로 통역하고, 편지(데이터)를 규격 봉투(프레임)에 넣어 주소(MAC)를 적고 봉인 검사 도장(CRC)을 찍어 부친다. 도착한 편지는 봉인이 멀쩡한지 확인한 뒤 뜯어 안으로 전한다. 둘째, Wi-Fi의 변조·OFDMA는 '넓은 도로에 차선 긋기'에 가깝다. 라디오 방송처럼 데이터를 반송파에 실어 보내되, 하나의 넓은 주파수 도로(채널)를 여러 차선(부반송파·자원단위)으로 나눠 여러 기기가 동시에 달리게 한다. 다만 이 무선 도로는 한 번에 한 방향만 갈 수 있는 왕복 1차선(반이중)이라, 끼어들기 전에 눈치껏 순서를 살피는 규칙(CSMA/CA)이 필요하다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 인터넷 검색 왕복 — '엔터'를 치면, NIC이 DNS 조회·TCP 연결·HTTP 요청을 프레임으로 만들어 공유기로 내보내고, 돌아온 응답 패킷을 받아 CRC 검사 후 브라우저로 올린다. CAwiki의 '엔터를 치면 신호는 어디까지 갔다 올까' 여정의 첫 관문이자 마지막 관문이다.
- 동영상 스트리밍 / 소리·영상 재생 — 초당 수만 개의 패킷이 쏟아져 들어올 때, 체크섬 오프로드와 LRO/GRO가 CPU 대신 검증·병합을 처리해 끊김 없는 재생을 돕는다. '버퍼링 막대 뒤'에서 실제로 데이터를 받아내는 장치.
- AI 질문 — 입력한 프롬프트를 패킷으로 데이터센터에 보내고, 스트리밍으로 돌아오는 토큰 응답을 실시간으로 받아 화면에 흘려보내는 통로.
- 온라인 게임 — 작은 조작 패킷을 최대한 낮은 지연으로 주고받아야 해서, 유선 NIC의 1 ms 미만 왕복이 무선보다 선호된다. 프레임을 빠르게 쏘아 보내는 순발력의 무대.
- 부팅 — 네트워크에서 IP를 받아오는 DHCP, 디스크 없이 서버에서 OS를 내려받는 PXE 네트워크 부팅, 꺼진 PC를 원격으로 깨우는 Wake-on-LAN이 모두 NIC에서 시작된다.
- 파일 열기(네트워크 드라이브·NAS) 와 클라우드 저장 — NAS의 파일을 열거나 Ctrl+S가 클라우드 동기화로 이어질 때, SMB 등의 프레임을 조립·전송하며 저장 매체와 원격 서버 사이를 잇는다.
