# 신경망처리장치 (NPU)
*Neural Processing Unit (NPU)*

> 신경망의 핵심인 행렬곱·합성곱(수많은 곱셈-누산)을 저정밀·저전력으로 대량 병렬 처리하도록 특화된, 주로 온디바이스 추론을 담당하는 도메인 특화 AI 가속기.

**분류**: 연산

---

## 🧭 한마디로, 무슨 일을 하나
NPU는 CPU·GPU와 함께 SoC(시스템 온 칩) 안에 들어가는 도메인 특화 연산 장치로, 딥러닝 모델의 추론(inference)을 주로 담당한다(데이터센터용 대형 NPU/TPU는 학습도 수행). CPU가 프로그램의 흐름을 지휘하고 GPU가 그래픽·범용 병렬 연산을 맡는 동안, NPU는 신경망에서 압도적 비중을 차지하는 곱셈-누산(MAC) 기반의 무거운 텐서 연산을 전담해(활성함수·정규화 등 나머지는 내부 벡터 유닛이 처리) 같은 일을 훨씬 적은 전력으로 처리한다. 핵심 가치는 절대 최고 속도가 아니라 '전력당 성능(TOPS/W)'이다. 그래서 배터리로 동작하는 노트북·스마트폰에서 음성 인식, 얼굴 인식, 실시간 영상 처리, 온디바이스 AI 같은 상시(always-on) AI 기능을 발열과 배터리 부담을 최소화하며 돌리는 것이 NPU의 존재 이유다.

## ⚙️ 작동 방식

**1. 모델 컴파일·양자화 (사전 준비, 오프라인)**

학습이 끝난 신경망 모델을 NPU가 이해하는 명령 그래프로 변환하고, 가중치(weight)를 FP32(또는 BF16/FP16)에서 INT8/INT4 같은 저정밀 형식으로 '양자화'한다. NPU는 CPU처럼 임의의 코드를 실행하는 게 아니라 미리 짜인 고정된 연산 스케줄을 돌리기 때문에, 어떤 레이어를 어떤 순서로·어느 버퍼에 올려 계산할지가 이 단계에서 결정된다. 정밀도를 낮추면 데이터 크기가 예컨대 FP32→INT8에서 4분의 1(→INT4는 8분의 1)로 줄어 메모리·에너지 부담이 급감한다.

**2. 작업 디스패치 (CPU가 지시)**

앱이 추론을 요청하면 CPU가 드라이버를 통해 '이 모델로 이 입력을 추론하라'는 명령과 메모리 주소를 NPU에 넘긴다. NPU는 스스로 일을 찾는 주체가 아니라 CPU가 지휘하는 보조 연산기(co-processor)이므로 시작·종료·결과 회수를 CPU가 조율한다. 이렇게 넘기면 CPU는 그동안 다른 일을 하고, 무거운 MAC은 NPU가 대신 떠맡는다.

**3. 온칩 SRAM으로 데이터 스테이징 (DMA)**

DMA(직접 메모리 접근) 엔진이 시스템 DRAM에 있던 가중치와 입력 데이터를 NPU 내부의 온칩 SRAM(스크래치패드/버퍼)으로 끌어온다. 오프칩 DRAM 한 번 접근은 저정밀 곱셈-누산 한 번보다 대략 수백~수천 배 많은 에너지를 쓰기 때문에, 계산에 쓸 데이터를 미리 칩 안 가까운 곳에 올려두고 최대한 재사용하는 것이 NPU 효율의 핵심이다.

**4. MAC 배열로 행렬곱·합성곱 실행**

온칩에 올라온 활성값(activation)과 가중치가 격자로 배열된 처리 요소(PE) 어레이로 흘러 들어간다. 각 PE는 매 클럭 곱셈 하나와 덧셈 하나(1 MAC)를 수행하고 부분합(partial sum)을 이웃 PE로 넘겨 누적한다. TPU식 시스톨릭 어레이는 데이터를 리듬 있게(systole) 관통시켜 여러 PE가 재사용하지만, 애플 뉴럴 엔진·퀄컴 헥사곤 등은 SIMD/벡터 기반 타일형 MAC 엔진을 쓰는 등 배열 구조는 제품마다 다르다. 공통점은 신경망의 무거운 연산(거대한 행렬곱 GEMM·합성곱)을 수천~수만 개 MAC으로 분해해 동시에 처리하고, 한 번 불러온 데이터를 최대한 재사용(dataflow, data reuse)한다는 원리다.

**5. 누적·재양자화·활성함수 적용**

어레이가 만든 부분합을 넓은 비트폭(보통 INT32) 누산기에 모아 최종값을 만들고, 편향(bias)을 더한 뒤 스케일(scale)·제로포인트(zero-point)로 다음 레이어의 정수 범위에 맞게 재양자화(requantize)하거나 필요 시 실수로 역양자화(dequantize)한다. 이어 벡터·특수함수 유닛이 ReLU·GELU·softmax·풀링·정규화 같은 비선형 연산을 적용한다. 곱셈-누산만으로는 신경망이 표현력을 갖지 못하므로, 이 비선형 단계를 거쳐야 한 레이어의 진짜 출력이 완성된다.

**6. 중간 결과 저장 후 다음 레이어로 반복**

완성된 레이어 출력(중간 활성값)을 온칩 SRAM에 되쓰고(너무 크면 DRAM으로 내보낸 뒤 다시 불러옴), 같은 하드웨어로 다음 레이어의 3~5단계를 반복한다. 딥러닝 모델은 레이어가 수십~수백 개 쌓여 있으므로, 같은 MAC 배열과 버퍼를 계속 재사용하며 층층이 계산을 흘려보낸다.

**7. 최종 출력 회수 (CPU·앱으로 반환)**

마지막 레이어까지 통과하면 결과(분류 확률, 생성된 토큰, 잡음 제거된 영상 프레임 등)가 만들어지고, DMA로 시스템 메모리에 기록된 뒤 CPU/앱이 가져가 화면·소리·응답으로 사용한다. 여기까지가 '한 번의 추론'이며, 음성 웨이크워드 감지처럼 상시 켜진 작업은 이 사이클을 초당 수십~수백 번 반복한다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **MAC 배열 / PE 어레이 (Systolic Array 등)** | NPU의 심장. 곱셈-누산(MAC)을 수행하는 수천~수만 개의 처리 요소(PE)가 2차원 격자로 배열되어 행렬곱·합성곱을 대량 병렬로 처리한다. 데이터가 격자를 규칙적으로 통과하는 시스톨릭 어레이(TPU식)가 대표적이지만, SIMD/벡터 기반 타일형 MAC 엔진, 도트-프로덕트 엔진 등 다른 조직을 쓰는 NPU도 많다. |
| **처리 요소 (PE, Processing Element)** | 어레이를 이루는 최소 연산 단위. 각 PE는 매 클럭 곱셈 1회 + 덧셈 1회(1 MAC)를 수행하고, 계산한 부분합을 이웃 PE로 넘겨 누적을 이어간다. 내부에 소형 레지스터(가중치·부분합 보관)를 가진다. |
| **온칩 SRAM (통합 버퍼 / 스크래치패드)** | 가중치·입력·중간 활성값을 담아두는 칩 내부 고속 메모리. DRAM보다 훨씬 빠르고 에너지가 저렴해, 데이터를 여기 올려두고 반복 재사용함으로써 값비싼 외부 메모리 접근을 줄인다. NPU 효율의 상당 부분이 이 SRAM 활용과 데이터 재사용에서 나온다. |
| **누산기 / 부분합 레지스터 (Accumulator)** | 행렬곱 과정에서 생기는 부분합을 쌓아 최종 합을 만드는 저장소. 저정밀 입력(예: INT8×INT8)을 곱한 결과가 넘치지 않도록 보통 더 넓은 비트폭(예: INT32)으로 누적한다. |
| **벡터 / 활성함수 유닛 (Special Function Unit)** | MAC 배열이 못 하는 비선형·요소별 연산을 담당. ReLU·GELU·softmax·풀링·정규화(LayerNorm 등)와 element-wise 연산을 처리해 레이어 출력을 완성한다. |
| **양자화 / 역양자화 유닛 (Quantization Unit)** | 부동소수점과 저정밀 정수 사이를 변환한다. 스케일(scale)과 제로포인트(zero-point)를 적용해 INT8/INT4로 낮추거나, 누적 결과를 다음 레이어 범위로 재양자화·정상 범위로 역양자화한다. 저전력 정수 연산과 정확도 사이를 잇는 다리. |
| **DMA 엔진 (Direct Memory Access)** | CPU 개입 없이 시스템 DRAM과 온칩 SRAM 사이로 가중치·활성값 블록을 옮긴다. 연산과 데이터 이동을 겹쳐(double-buffering) 어레이가 놀지 않게 데이터를 계속 공급한다. |
| **제어기 / 명령 시퀀서 (Control Sequencer)** | 컴파일된 모델 명령을 명령/가중치 프리페치 버퍼에서 해석해 '언제 어떤 데이터를 어느 버퍼에서 어레이로 흘릴지'를 지휘한다. NPU 전체의 타이밍과 데이터플로우를 조율하는 지휘자. |
| **온칩 인터커넥트 / SoC 버스 인터페이스 (NoC·AXI)** | NPU 내부 타일 간, 그리고 NPU와 SoC의 CPU·메모리 컨트롤러를 잇는 고속 배선. 이를 통해 시스템 통합 메모리를 CPU·GPU와 공유한다. |
| **클럭 · 전력 관리 유닛 (Power/Clock Management, DVFS·클럭 게이팅)** | 동작 클럭·전압을 부하에 맞춰 조절(DVFS)하고 쓰지 않는 블록의 클럭을 끈다(클럭 게이팅). 웨이크워드 감지 같은 상시(always-on) 작업을 극저전력으로 유지하는 데 핵심이라, 전력당 성능이 생명인 NPU에서 특히 중요하다. |
| **가중치 압축·희소성 처리 유닛 (Sparsity / Decompression)** | 많은 신경망 가중치가 0이거나 압축 가능하다는 점을 이용해, 0을 건너뛰거나 압축된 가중치를 풀어 실제 계산량·메모리 대역폭을 줄인다(모든 NPU에 있는 것은 아님). |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **MAC (Multiply-Accumulate, 곱셈-누산)** | a ← a + (b × c) 형태의 기본 연산. 신경망 계산의 대부분이 이 MAC의 반복이며, NPU는 이 연산을 대량 병렬로 처리하도록 설계된다. |
| **OPS와 MAC의 관계 (2 OPS = 1 MAC)** | TOPS 카운팅은 보통 곱셈과 덧셈을 각각 1 연산으로 세므로 1 MAC = 2 OPS다. 따라서 이론 성능 ≈ 2 × (MAC 개수) × (클럭). 예로 TPU v1은 65,536 MAC × 700MHz × 2 ≈ 92 TOPS다. MAC 수만 보고 TOPS를 반으로 오해하지 않도록 이 2배 계수를 기억해야 한다. |
| **시스톨릭 어레이 (Systolic Array)** | PE(처리 요소)를 격자로 배열하고 데이터가 심장 박동(systole)처럼 규칙적으로 격자를 통과하며 각 PE가 자기 몫의 MAC을 이어받는 구조. 한 번 읽은 데이터를 여러 PE가 재사용해 메모리 접근을 최소화한다. 구글 TPU식 대표 구조이지만 모든 NPU가 채택하는 것은 아니다(SIMD/벡터형·타일형 MAC 엔진 등 다양). |
| **GEMM (General Matrix Multiply, 일반 행렬 곱셈)** | 두 행렬을 곱하는 연산. 완전연결층·트랜스포머의 핵심이며 신경망 연산 부하의 대부분을 차지한다. 다수의 NPU는 사실상 GEMM 가속기로 볼 수 있다. |
| **합성곱 (Convolution)** | 작은 필터(커널)를 이미지 위로 미끄러뜨리며 곱하고 더하는 연산. CNN의 핵심으로, 내부적으로는 결국 대량의 MAC(또는 im2col을 통한 GEMM)으로 계산된다. |
| **양자화 (Quantization)** | FP32/BF16 실수 가중치·활성값을 INT8/INT4 같은 저정밀 정수로 근사하는 기법. 데이터 크기·연산 에너지를 크게 줄이는 대신 약간의 정확도를 감수한다. 온디바이스 추론의 전제. |
| **INT8 / INT4 (8비트 / 4비트 정수)** | 추론에서 널리 쓰는 저정밀 정수 형식. INT8은 온디바이스 추론의 주력이고, 대형 언어모델 가중치는 INT4까지 낮춰 메모리를 아끼기도 한다. |
| **BF16 / FP16 / FP8 (부동소수점 형식)** | BF16은 지수부를 FP32와 똑같이 8비트로 유지해(가수부만 축소) 표현 범위는 넓고 정밀도만 낮춘 16비트 형식으로, 정확도가 중요한 연산·학습에서 FP32를 대체한다. FP16은 지수 5비트로 범위가 좁다. 최신 NPU는 LLM용으로 FP8이나 블록 부동소수점(마이크로스케일링, MXFP 등)도 지원하는 추세다. |
| **TOPS / TOPS/W** | TOPS는 Tera Operations Per Second(초당 10¹² 회 연산)로 NPU의 이론적 최대 처리량(보통 INT8 기준, MAC=2 OPS로 계산). TOPS/W는 와트당 TOPS로 전력효율을 나타내며, 배터리 기기에서 NPU의 진짜 경쟁력을 보여주는 지표다. |
| **데이터플로우 / 데이터 재사용 (Dataflow / Data Reuse)** | 어떤 데이터를 어레이에 '고정'하고 무엇을 흘려보낼지 정하는 전략(weight-stationary·output-stationary·row-stationary 등). 한 번 불러온 데이터를 최대한 재사용해 비싼 메모리 접근을 줄이는 것이 목표다. |
| **메모리 병목 / 루프라인 (Memory-bound vs Compute-bound)** | 연산 대비 필요한 데이터 이동량(연산 강도, operational intensity)이 낮으면 성능이 MAC이 아니라 메모리 대역폭에 묶인다(memory-bound). LLM 토큰 생성처럼 가중치를 계속 읽어야 하는 작업이 대표적이라, 광고 TOPS가 높아도 대역폭이 실제 병목이 되기 쉽다. |
| **온칩 SRAM (On-chip Static RAM)** | 칩 내부에 둔 빠른 정적 메모리. DRAM보다 지연·에너지가 훨씬 작아, 계산에 쓸 데이터를 이곳에 올려두고 반복 사용하는 것이 NPU 설계의 핵심이다. |
| **SoC / NoC (System on Chip / Network on Chip)** | SoC는 CPU·GPU·NPU·메모리 컨트롤러·ISP를 한 칩에 통합한 것. NoC는 이 블록들을 잇는 온칩 네트워크로, NPU는 이를 통해 통합 메모리를 CPU·GPU와 공유한다. |
| **DMA (Direct Memory Access, 직접 메모리 접근)** | CPU를 거치지 않고 메모리와 NPU 버퍼 사이에서 데이터 블록을 옮기는 엔진. 연산과 데이터 이동을 겹쳐 어레이가 쉬지 않게 한다. |
| **도메인 특화 아키텍처 (DSA, Domain-Specific Architecture)** | 범용성을 포기하고 특정 연산(여기선 신경망 텐서 연산)에만 하드웨어를 맞춰 전력·면적 효율을 극대화하는 설계 철학. 무어의 법칙 둔화 이후 NPU·TPU·Tensor Core가 등장한 배경이며, NPU가 '범용 코드는 못 돌리지만 AI엔 압도적'인 이유다. |
| **추론 vs 학습 (Inference vs Training)** | 학습은 데이터로 모델의 가중치를 만드는 무거운 과정(주로 데이터센터 GPU/TPU), 추론은 완성된 모델로 결과를 뽑는 과정. 온디바이스 NPU는 대부분 추론 전용이다. |
| **이용률 (Utilization)** | MAC 배열이 실제로 얼마나 놀지 않고 채워져 돌아가는지의 비율. 데이터 공급이 부족하거나 레이어 모양이 배열 크기와 맞지 않으면 이용률이 떨어져, 광고된 TOPS보다 실제 성능이 낮아진다. |

## 📊 대표 사양·수치 감각

| 항목 | 값 | 비고 |
|---|---|---|
| 대표 연산 성능(INT8) | 약 수 TOPS ~ 80+ TOPS (2025~2026 온디바이스 노트북·스마트폰 기준) | TOPS = 초당 10¹² 회 연산(MAC=2 OPS). 마이크로소프트 Copilot+ PC는 NPU 40 TOPS 이상을 요구하며, 스냅드래곤 X/애플 M4/인텔 루나레이크/AMD XDNA2 등 40~50+ TOPS가 일반화. 데이터센터용 대형 가속기는 이보다 수십~수백 배 높음 |
| 전력효율 | 대략 수 ~ 수십 TOPS/W (INT8, 선단 공정) | 같은 추론 작업에서 범용 CPU/GPU보다 전력당 성능이 수 배~수십 배 높은 것이 목표. NPU의 존재 이유 |
| 연산 정밀도 | INT8 · INT4 · INT16 · FP16 · BF16 (최신은 FP8·블록 부동소수점 지원 확대) | 추론은 INT8이 주력, LLM 가중치는 INT4까지 낮추기도. BF16/FP16은 정확도가 중요한 연산에, FP8/MXFP 등은 최신 LLM 가속에 사용 |
| 온칩 SRAM 용량 | 대략 수백 KB ~ 수십 MB | 예: 구글 TPU v1은 24MB(MiB) 통합 버퍼를 둠. 모바일 NPU는 이보다 작은 편이며, 대형 데이터센터 가속기는 수십~수백 MB에 이르기도 |
| MAC 배열 규모 | 수천 ~ 수만 개 MAC (예: TPU v1은 256×256 = 65,536개) | PE 한 개가 대체로 클럭당 1 MAC 수행. 이론 성능 ≈ 2 × MAC 수 × 클럭 (예: 65,536 × 700MHz × 2 ≈ 92 TOPS). 병렬 규모가 곧 처리량 |
| 동작 클럭 | 대략 수백 MHz ~ 2 GHz 안팎 | CPU만큼 고클럭이 아니며(예: TPU v1 700MHz), 클럭보다 대규모 병렬성과 저정밀로 성능을 낸다 |
| 시스템 메모리 / 대역폭 | LPDDR5 / LPDDR5X 통합 메모리 공유 — 노트북·폰 대략 60~140 GB/s, 고급 통합 SoC는 수백 GB/s~800 GB/s+ | 전용 VRAM 없이 SoC 통합 메모리를 CPU·GPU와 나눠 쓰므로 대역폭이 병목이 되기 쉬움. 애플 Max/Ultra급은 광폭 버스로 수백 GB/s 이상, 데이터센터 가속기는 HBM으로 TB/s급 |
| 에너지 비대칭 (메모리 vs 연산) | 오프칩 DRAM 1회 접근이 저정밀 MAC 1회보다 대략 수백~수천 배 많은 에너지 소모 | 정밀도와 오프칩 여부에 따라 차이. 그래서 온칩 SRAM에 올려 재사용(dataflow)하는 것이 효율 설계의 핵심 |
| 대표 세대·제품 | Apple Neural Engine, Qualcomm Hexagon(NPU), Intel/AMD(XDNA) NPU, Samsung/화웨이 모바일 NPU, Google TPU 등 | 모바일·PC SoC에 내장되는 추론 NPU와, 데이터센터용 대형 변종(TPU 등, 학습도 수행)으로 나뉨 |

## ⚠️ 흔한 오해

- **오해** — NPU는 CPU·GPU보다 무조건 빠르고 강력하다.
  <br>**교정** — NPU는 행렬곱·합성곱 같은 특정 연산에만 특화된 장치라 범용 코드는 아예 못 돌린다. 절대 최고 성능(FLOPS)은 데이터센터 GPU가 훨씬 크다. NPU의 강점은 최고 속도가 아니라 '전력당 성능(효율)'이다.
- **오해** — NPU가 AI 모델을 학습(training)시킨다.
  <br>**교정** — 온디바이스 NPU는 거의 대부분 완성된 모델로 결과만 뽑는 추론(inference) 전용이다(일부는 제한적 파인튜닝 지원). 무거운 학습은 주로 데이터센터의 GPU나 TPU 같은 대형 가속기가 담당한다.
- **오해** — NPU는 정밀한 부동소수점 연산으로 계산한다.
  <br>**교정** — NPU는 주로 INT8/INT4 같은 저정밀 정수 연산을 쓴다(정확도가 필요하면 BF16/FP16/FP8도 지원). 정밀도를 일부러 낮춰(양자화) 메모리와 에너지를 줄이는 것이 핵심 설계라, 모델을 미리 양자화하는 과정이 필요하다.
- **오해** — TOPS 숫자가 높으면 실제로 그만큼 빠르다.
  <br>**교정** — TOPS는 이론적 최대치(peak)일 뿐이다. 실제 성능은 메모리 대역폭, 데이터 재사용, 모델 구조, MAC 배열 이용률에 좌우돼 광고 수치보다 훨씬 낮게 나올 수 있다(특히 LLM은 memory-bound).
- **오해** — NPU는 GPU의 한 부분이거나 사실상 같은 것이다.
  <br>**교정** — 둘은 별개 하드웨어다. GPU는 유연한 SIMT 범용 병렬 프로세서, NPU는 고정된 데이터플로우의 도메인 특화 가속기다. (NVIDIA GPU 안의 Tensor Core는 개념상 NPU와 비슷한 행렬 유닛이지만 GPU 내부 기능이다.)
- **오해** — NPU의 MAC 배열은 모두 시스톨릭 어레이다.
  <br>**교정** — 시스톨릭 어레이는 구글 TPU식 대표 구조일 뿐, 모든 NPU가 쓰는 것은 아니다. 애플 뉴럴 엔진·퀄컴 헥사곤 등 상당수 모바일 NPU는 SIMD/벡터 기반 타일형 MAC 엔진이나 도트-프로덕트 엔진 등 다른 배열을 쓴다. 공통 원리는 특정 배선 구조가 아니라 '대규모 MAC 병렬 + 온칩 데이터 재사용'이다.
- **오해** — NPU만 있으면 인터넷 없이 모든 AI를 돌릴 수 있다.
  <br>**교정** — 작고 중간 크기 모델은 온디바이스로 가능하지만, 초대형 언어모델은 메모리 용량·대역폭 한계 때문에 여전히 클라우드가 필요하다. NPU는 만능이 아니라 효율 특화 장치다.

## 💡 비유

시스톨릭 어레이는 '김밥 공장의 컨베이어 라인'과 같다. 재료(데이터)가 벨트를 따라 흐르고, 나란히 선 작업자(PE)들은 각자 자기 앞을 지나는 재료에 곱셈-덧셈 한 번씩만 하고 옆으로 넘긴다. 재료를 창고(DRAM)에서 매번 새로 꺼내지 않고 라인 위에서 여러 작업자가 이어서 쓰기 때문에 낭비가 없다(단, 모든 NPU가 이 컨베이어식은 아니고, 여러 작업대에 재료를 흩뿌리는 SIMD식도 있다). 또한 CPU·GPU·NPU를 요리사에 비유하면, CPU는 뭐든 만들지만 혼자라 느린 '만능 요리사', GPU는 대량으로 밀어붙이는 '대형 주방의 요리사 군단', NPU는 오직 김밥만 극도로 효율적으로 뽑아내는 '전용 자동화 라인'이다.
