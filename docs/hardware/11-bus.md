# 버스·인터커넥트
*Buses & Interconnects*

> CPU·메모리·저장장치·주변기기를 잇는 '도로망과 교통 규칙' — 직렬 차동 링크(PCIe)와 그 위를 흐르는 패킷, 전송을 CPU 대신 처리하는 DMA, 완료를 알리는 인터럽트(MSI), 그리고 그 위에 얹힌 캐시 일관성 확장(CXL)까지의 체계.

**분류**: 기판·버스·전원

---

## 🧭 한마디로, 무슨 일을 하나
버스와 인터커넥트는 컴퓨터 부품들 사이를 잇는 도로망이자 그 위의 교통 규칙이다. 대역폭이 생명인 장치(GPU·주 NVMe SSD)는 CPU에 직결하고, 느린 다수(USB·SATA·오디오·네트워크)는 칩셋에 모아 한 가닥(DMI)으로 공유시키는 '대역폭 계층'을 설계한다. 데이터는 패킷(TLP)으로 쪼개 직렬 차동 배선으로 신뢰성 있게(재전송 보장) 전달하고, CPU가 일일이 바이트를 옮기지 않도록 DMA에 전송을 위임한 뒤 완료를 인터럽트로 통보받는다. 부팅 때 버스를 열거(enumeration)해 장치마다 정체를 파악하고 주소를 배정하는 것부터가 이 계층의 일이며, 최근에는 같은 PCIe 전기 배선 위에 캐시 일관성 프로토콜(CXL)을 얹어 메모리 확장·가속기 연결까지 확장되고 있다. 사실상 CAwiki의 모든 시나리오에서 '데이터가 이동하는 구간'은 전부 여기서 벌어진다.

## ⚙️ 작동 방식

**1. 버스 열거 — 장치 지도를 그린다**

부팅 초기, 펌웨어(UEFI)와 이어받은 OS가 루트 컴플렉스(Root Complex)에서 출발해 버스를 재귀적으로 훑는다. 존재할 수 있는 모든 버스·장치·기능(Bus-Device-Function, BDF) 조합의 '설정 공간(Configuration Space)'을 읽어, 응답이 오면 Vendor ID·Device ID·Class Code로 그 장치가 무엇인지 파악하고 번호를 매긴다. 현대 PCIe에서는 이 설정 공간을 레거시 I/O 포트(0xCF8/0xCFC)가 아니라 ECAM이라는 MMIO 창(메모리 주소로 직접 읽기)으로 접근한다. 왜: 어디에 무엇이 붙어 있는지 지도가 있어야 그다음에 주소를 나눠 줄 수 있기 때문.

**2. 주소 공간 매핑 — 장치에 번지수를 준다**

각 장치는 BAR(Base Address Register)로 '나는 메모리 N바이트(또는 I/O 공간)가 필요하다'고 선언한다. BAR는 32비트/64비트, 프리페처블 여부 등을 표시하며, GPU의 대용량 VRAM처럼 큰 창은 64비트 BAR나 Resizable BAR로 노출한다. 펌웨어/OS는 물리 주소 공간에서 서로 겹치지 않는 구간을 골라 그 시작 주소를 BAR에 써 넣는다. 이후 CPU가 그 주소를 보통의 load/store로 읽고 쓰면 곧 장치의 레지스터에 접근하게 된다(MMIO, 메모리 사상 입출력). 왜: CPU가 장치를 '메모리처럼' 다루려면 겹치지 않는 번지수가 배정되어 있어야 한다.

**3. 링크 트레이닝과 직렬 차동 신호 — 물리적으로 말이 통하게 한다**

물리 계층이 링크를 깨워 양쪽이 지원하는 최고 속도(세대)와 레인 폭을 자동 협상하고 등화(equalization)까지 맞춘다(LTSSM, 링크 트레이닝). 이 순간 프로토콜도 결정되는데, 상대가 CXL 장치면 표준 PCIe 대신 CXL 모드로 붙는다. 데이터는 옛 병렬 버스처럼 여러 선으로 한꺼번에 보내지 않고, 레인마다 2쌍(송신 1쌍·수신 1쌍)의 차동 배선으로 흐른다. 한 쌍의 두 선에 서로 반대 부호의 전압을 실어 그 '차이'로 정보를 실으며, 클럭은 별도 선 없이 데이터 스트림에 인코딩되어 함께 가 수신부가 복원(CDR)한다. 왜: 초고속에서는 병렬 배선의 신호 어긋남(스큐)과 노이즈가 치명적이라, 직렬+차동이 오히려 훨씬 빠르고 안정적이다.

**4. CPU가 일을 지시한다 — 디스크립터와 도어벨**

CPU는 데이터를 직접 나르는 대신, 호스트 RAM에 마련된 명령 큐(링 버퍼)에 디스크립터('RAM의 X~Y 구간을 읽어 장치로', 또는 그 반대)를 써 넣고, 장치의 '도어벨(doorbell)' 레지스터에 MMIO 쓰기 한 번으로 '큐에 일감이 쌓였다(꼬리 포인터가 여기까지)'고 알린다(NVMe·NIC 등이 이 방식). 즉 디스크립터는 RAM에 있고, 장치로 건너가는 것은 도어벨 신호뿐이다. 왜: CPU는 지시만 내리고 실제 바이트 운반은 아래 단계로 위임해, 그 시간에 다른 계산을 하기 위함.

**5. DMA 전송 — CPU 없이 메모리를 직접 오간다**

장치 안의 DMA 엔진(버스 마스터)이 스스로 버스의 주인이 되어 도어벨이 가리키는 디스크립터를 읽고 RAM과 직접 데이터를 주고받는다. 전송은 TLP(Transaction Layer Packet)로 쪼개지는데, 각 패킷은 헤더(목적지 주소·길이·읽기/쓰기 종류)와 페이로드로 구성되고, 데이터 링크 계층이 순서 번호·LCRC·ACK/NAK 재전송으로 신뢰성을, 신용 기반 흐름 제어(credit-based flow control)로 수신 버퍼 넘침 방지를 보장한다. 이때 IOMMU가 장치가 대는 주소를 검사·번역해 허가된 영역만 건드리게 막는다. x86에서는 DMA 쓰기가 캐시를 스누프해 일관성이 유지되므로(캐시 일관성 DMA) 소프트웨어가 매번 캐시를 비울 필요가 없다. 왜: CPU를 바이트 복사 노동에서 해방시켜 대역폭을 최대로 끌어내고, 물리적으로 흩어진 메모리 페이지(scatter-gather)도 한 번에 처리하기 위함.

**6. 대역폭 계층을 타고 흐른다 — CPU 직결 vs 칩셋 경유**

흐름은 위치에 따라 두 경로로 갈린다. GPU(보통 x16)와 주 NVMe SSD(x4)처럼 급한 장치는 CPU의 PCIe 레인에 직결되어 최단 경로로 오간다. USB·SATA·오디오·유선 네트워크 등 느린 다수는 칩셋(PCH)이 일단 모은 뒤, CPU와 칩셋을 잇는 좁은 DMI 링크 한 가닥으로 함께 실어 보낸다. 왜: CPU의 핀과 레인 수는 유한하므로, 대역폭이 절실한 것만 직결하고 나머지는 허브에 몰아 공유(오버서브스크립션)하는 것이 경제적이다.

**7. 완료를 인터럽트로 알린다 — APIC와 MSI**

전송이 끝나면 장치가 CPU에 '다 됐다'를 알린다. 요즘은 전용 IRQ 전선 대신 MSI/MSI-X(Message Signaled Interrupts)를 쓴다 — 약속된 특정 메모리 주소(로컬 APIC의 인터럽트 영역, 통상 0xFEEx…)에 값을 쓰는 것(메모리 쓰기 TLP)만으로 인터럽트를 표현한다. 이 쓰기는 대상 코어의 로컬 APIC로 직접 배달되어 I/O APIC(주로 레거시 와이어 IRQ 담당)를 우회하며, IOMMU의 인터럽트 재매핑을 거쳐 어느 코어·어느 벡터로 갈지 정해진다. CPU는 IDT(인터럽트 서술자 테이블)에서 해당 핸들러를 찾아 실행한다. 코어가 많은 시스템은 x2APIC로 더 넓은 APIC ID를 다룬다. 왜: CPU가 계속 '끝났나?' 물어보는(폴링) 낭비 없이 즉시 통보받고, 큐마다 다른 코어로 부하를 분산하기 위함.

**8. 한 케이블로 여러 프로토콜을 함께 흘린다 — 터널링(USB4·Thunderbolt)**

USB4와 Thunderbolt는 단 하나의 USB-C 링크 위에 PCIe·DisplayPort·USB 트래픽을 각각 캡슐화(터널링)해 동시에 실어 나른다. 협상으로 각 프로토콜에 대역폭을 나눠 주며, PCIe를 터널로 뽑아내면 외장 GPU나 초고속 외장 저장장치도 가능해진다. 왜: 포트·케이블 하나로 디스플레이·데이터·전력을 통합해 확장성을 높이기 위함.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **루트 컴플렉스(Root Complex)** | CPU와 PCIe 세계를 잇는 관문. CPU의 메모리·I/O 요청을 PCIe 트랜잭션(TLP)으로 바꿔 아래 장치들로 내려보내고, 열거·주소 매핑의 출발점이 된다. 현대에는 CPU 다이 안에 통합되어 있으며, CXL 링크의 호스트 측 앵커(루트 포트) 역할도 겸한다. |
| **PCIe 레인과 차동 배선쌍(SerDes PHY)** | 실제 데이터가 흐르는 길. 레인 1개는 송신 1쌍·수신 1쌍의 차동 배선으로 이뤄지며, PHY의 직렬화기/역직렬화기(SerDes)가 CPU 내부의 병렬 비트를 직렬 신호로 바꿔 보내고 받는 쪽에서 되돌린다. x1·x4·x8·x16으로 묶어 폭을 키우며(bifurcation으로 x16을 x8+x8 등으로 쪼갤 수도 있다). |
| **PCIe 스위치·브리지(Switch/Bridge)** | 레인을 분기해 여러 장치를 붙인다. 상위 버스에서 온 패킷을, 목적지 주소가 속한 하위 버스로만 골라 전달한다(포워딩). 열거 때 각 브리지의 하위 버스 번호와 주소 범위가 프로그래밍된다. |
| **칩셋(PCH / 사우스브리지)** | USB·SATA·유선 네트워크·오디오·저속 PCIe 등 느린 다수의 I/O를 한데 모으는 허브. 여기 붙은 장치들은 CPU로 올라가는 상향 링크(DMI 등)의 대역폭을 나눠 쓴다. 과거 노스브리지의 메모리·그래픽 기능은 CPU로 흡수되었다. |
| **DMI 링크(Direct Media Interface)** | Intel에서 CPU와 칩셋을 잇는 전용 상향 링크. 사실상 PCIe와 같은 방식이며(고급 칩셋은 DMI 4.0 = PCIe 4.0 x8 상당, 보급형은 x4), 칩셋 아래 모든 장치의 트래픽이 이 좁은 병목을 통과해 CPU로 간다. (AMD는 별도 이름 대신 PCIe 4.0 x4 링크 자체로 칩셋을 연결한다.) |
| **메모리 컨트롤러(IMC)와 메모리 버스** | CPU 다이 안에 통합된 컨트롤러가 DDR/LPDDR RAM을 CPU에 직결한다. PCIe·DMI와 별개인 최고 대역폭 경로로, DMA 전송의 반대편 종착지가 대개 이 RAM이다. 최근에는 CXL로 붙는 메모리 확장 계층이 이 로컬 RAM 바깥의 추가 메모리로 쓰이기도 한다. |
| **DMA 엔진 / 버스 마스터** | CPU 개입 없이 메모리와 장치 사이 데이터를 실제로 나르는 일꾼. 현대 장치(NVMe·NIC·GPU)는 저마다 이 엔진을 내장한 '버스 마스터'로, 디스크립터를 읽어 스스로 전송을 수행하고 흩어진 페이지(scatter-gather)까지 처리한다. |
| **IOMMU (입출력 메모리 관리 장치)** | 장치가 DMA로 대는 주소를 검사·번역하는 관문(Intel VT-d, AMD-Vi). 각 장치를 허가된 메모리 영역에만 가두어 오작동·악성 장치의 임의 메모리 접근을 막고, 인터럽트 재매핑과 가상화(장치 통과, SR-IOV)를 돕는다. |
| **인터럽트 컨트롤러(로컬 APIC + I/O APIC)** | 장치가 보낸 '작업 완료' 신호를 어느 코어에 전달할지 라우팅한다. 레거시 와이어 인터럽트는 I/O APIC가 받아 각 코어의 로컬 APIC로 분배하고, 현대 MSI/MSI-X는 로컬 APIC로 직접 배달된다. 로컬 APIC는 코어의 타이머와 코어 간 신호(IPI)도 담당하며, 코어가 많으면 x2APIC 모드를 쓴다. |
| **MSI / MSI-X 메커니즘** | 전용 인터럽트 전선 없이, 약속된 메모리 주소에 값을 쓰는 것만으로 인터럽트를 표현하는 방식. MSI는 함수당 최대 32벡터, MSI-X는 최대 2048벡터를 지원해, 다중 큐 장치(NVMe·고속 NIC)가 큐마다 다른 코어를 깨울 수 있게 한다. |
| **설정 공간(Configuration Space)과 BAR** | 각 PCIe 기능이 가진 표준 레지스터 묶음. Vendor/Device ID·Class Code로 정체를 알리고, BAR(Base Address Register)로 필요한 주소 공간의 크기·종류를 선언한다. PCI 256바이트/PCIe 확장 4KB이며, 열거와 주소 매핑이 모두 이 공간을 (ECAM MMIO로) 읽고 쓰며 이뤄진다. |
| **호스트 컨트롤러(xHCI·AHCI 등)와 장치 인터페이스(NVMe)** | 특정 버스 표준을 관장하는 컨트롤러. xHCI는 USB 3.x/2.0 장치를, AHCI는 SATA 장치를 NCQ(명령 큐잉)로 다룬다. 반면 NVMe는 별도 호스트 컨트롤러를 경유하지 않고 PCIe에 직결된 SSD 자체의 레지스터·명령셋 인터페이스로, OS 드라이버가 이들을 통해 주변기기와 대화한다. |
| **온다이/패키지·소켓 간 인터커넥트(링·메시·Infinity Fabric·UPI)** | 칩 내부에서 코어·캐시·메모리 컨트롤러·PCIe 컨트롤러를 잇고 캐시 일관성을 유지하는 그물망. Intel의 링/메시, AMD의 Infinity Fabric이 대표적이며, 칩렛(여러 다이)을 한 패키지로 묶는 접착제이자, 소켓 간에는 Intel UPI·AMD xGMI로 확장돼 멀티소켓 서버의 NUMA 도메인을 잇는다. |
| **코히런트 확장 링크(CXL)** | PCIe 5.0/6.0과 같은 전기 PHY 위에서 링크 트레이닝 때 협상되는 캐시 일관성 프로토콜(CXL.io/.cache/.mem). CPU와 가속기·메모리 확장 장치가 서로의 메모리를 일관성 있게 공유하게 해, 메모리 풀링·용량 확장·가속기 결합을 가능케 한다(주로 서버/AI). PCIe와 배선을 공유하지만 프로토콜 계층이 다르다. |
| **레퍼런스 클럭 / 클럭 복원(CDR)** | 링크 양쪽이 대략 같은 박자를 맞추도록 기준 클럭(대개 100MHz)을 공급한다. 실제 비트 타이밍은 데이터에 실린 임베디드 클럭을 수신부가 복원(CDR)해 맞춘다. 양쪽이 같은 기준 클럭을 쓰면 공통 클럭, 각자 다른 클럭에 독립 스펙트럼 확산을 쓰면 SRIS 구성이며, 스펙트럼 확산(SSC)으로 전자파 간섭(EMI)을 줄인다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **PCIe (Peripheral Component Interconnect Express)** | 현대 PC 확장의 표준 인터커넥트. 이름에 'Bus'가 들어가지만 실제로는 '점대점 직렬 링크'라는 점이 핵심이다. 레인 단위로 확장하고, 계층화된 패킷 프로토콜(트랜잭션·데이터링크·물리)로 통신한다. |
| **레인(Lane)** | PCIe의 최소 전송 단위. 송신용 차동 1쌍 + 수신용 차동 1쌍으로, 양방향 동시 통신(전이중)한다. x1·x4·x8·x16처럼 레인을 묶을수록 대역폭이 비례해 커진다. |
| **GT/s (기가트랜스퍼/초, Gigatransfers per second)** | 레인 1개가 초당 보내는 심볼(전송 단위) 수. NRZ를 쓰는 1~5세대는 1심볼=1비트라 32 GT/s=32 Gbps이지만, PAM4를 쓰는 6.0은 1심볼=2비트라 32 GBaud로도 64 GT/s가 된다. 인코딩 오버헤드를 빼야 실제 바이트 대역폭이 나온다. 예: PCIe 5.0의 32GT/s는 128b/130b 인코딩을 거쳐 레인당 약 3.94GB/s. |
| **차동 신호(Differential Signaling)** | 두 선에 서로 반대 부호의 전압을 싣고, 수신부가 그 '차이'만 읽는 방식. 두 선에 똑같이 실린 배경 노이즈(공통 모드)가 상쇄되어, 낮은 전압으로도 초고속·장거리 전송이 가능하다. |
| **전이중(Full-duplex)** | 보내기와 받기를 동시에 하는 것. PCIe·USB 3.x는 송·수신 배선이 분리되어 전이중이다. 반면 USB 2.0은 한 쌍을 번갈아 쓰는 반이중이다. 그래서 대역폭을 말할 때 '편방향'인지 '양방향 합산'인지 구분해야 한다. |
| **TLP (Transaction Layer Packet)** | PCIe에서 오가는 데이터의 기본 단위. 헤더(목적지 주소·길이·읽기/쓰기 종류)와 페이로드로 구성된다. 메모리 읽기/쓰기, 설정 접근, 그리고 MSI 인터럽트까지 모두 이 패킷으로 표현된다. 데이터 링크 계층이 순서 번호·LCRC·ACK/NAK로 재전송을 관리한다. |
| **MMIO (Memory-Mapped I/O, 메모리 사상 입출력)** | 장치의 레지스터·메모리를 CPU의 물리 주소 공간에 매핑해, CPU가 보통의 메모리 load/store 명령으로 장치를 제어하는 방식. x86의 옛 방식인 별도 I/O 주소 공간(IN/OUT 명령, 포트 매핑)을 대체했다. |
| **BAR (Base Address Register)** | 장치가 '나는 이만큼의 주소 공간이 필요하다'고 선언하는 레지스터. 32/64비트·프리페처블 여부를 표시하며, 열거 단계에서 펌웨어/OS가 겹치지 않는 물리 주소를 골라 여기에 써 주면 그 주소가 그 장치의 MMIO 창구가 된다. |
| **버스 열거(Bus Enumeration)와 BDF** | 부팅 시 루트 컴플렉스부터 아래로 버스를 훑어 어떤 장치가 어디 붙었는지 파악하고 주소를 배정하는 과정. 각 기능은 버스·장치·기능 번호(Bus-Device-Function, BDF)로 식별되며, 설정 공간은 ECAM(MMIO)으로 접근한다. |
| **DMA (Direct Memory Access, 직접 메모리 접근)** | CPU를 거치지 않고 장치가 메모리를 직접 읽고 쓰는 전송. CPU는 '어디서 어디로, 얼마'만 지시하고 빠진다. 대량 데이터 전송에서 CPU 부담을 없애 대역폭을 극대화하는 핵심 기법이다. |
| **캐시 일관성 DMA와 스누핑(Cache-coherent DMA)** | DMA가 RAM을 고치면 CPU 캐시에 남은 옛 값과 어긋날 수 있다. x86 등 현대 시스템은 DMA 트랜잭션이 캐시를 스누프(엿봄)해 자동으로 일관성을 맞추므로, 소프트웨어가 매번 캐시를 비우지 않아도 된다(일부 임베디드/비일관 도메인은 예외). |
| **버스 마스터(Bus Master)** | 버스의 소유권을 스스로 쥐고 전송을 주도할 수 있는 장치. 중앙의 옛 DMA 컨트롤러에 의존하지 않고 자체 DMA 엔진을 내장해 직접 메모리를 오간다(퍼스트파티 DMA). NVMe·NIC·GPU가 대표적이다. |
| **IOMMU (Input-Output Memory Management Unit)** | 장치의 DMA 주소를 번역·검사하는 하드웨어(Intel VT-d, AMD-Vi). CPU의 MMU가 프로세스를 격리하듯, 각 장치를 허가된 메모리 영역에만 가둬 보호·인터럽트 재매핑·가상화를 제공한다. |
| **APIC (Advanced Programmable Interrupt Controller)** | 멀티코어 시대의 인터럽트 라우팅 장치. 코어마다 있는 '로컬 APIC'와 시스템 전역의 'I/O APIC'로 나뉜다. 옛 단일 PIC(8259)를 대체해 인터럽트를 여러 코어에 분배하고, 코어 간 신호(IPI)와 코어 타이머를 담당한다. 대규모 코어에는 x2APIC를 쓴다. |
| **MSI / MSI-X (Message Signaled Interrupts)** | 전용 인터럽트 전선 대신 약속된 메모리 주소(로컬 APIC 영역)에 값을 써서 인터럽트를 발생시키는 방식. 핀이 필요 없고, I/O APIC를 우회한다. MSI-X는 함수당 최대 2048벡터를 지원해 큐별로 다른 코어를 깨울 수 있다. |
| **DMI (Direct Media Interface)** | Intel에서 CPU와 칩셋(PCH)을 잇는 전용 링크. 내부적으로 PCIe와 같은 방식이며(고급 칩셋은 DMI 4.0 ≈ PCIe 4.0 x8, 보급형은 x4), 칩셋 아래 모든 저속 장치의 트래픽이 이 좁은 병목을 공유해 CPU로 올라간다. |
| **칩셋 / PCH (Platform Controller Hub)** | USB·SATA·네트워크·오디오 등 느린 I/O를 모아 CPU에 연결하는 허브 칩. '사우스브리지'의 후신이다. 과거 노스브리지가 맡던 메모리·그래픽 연결은 CPU 안으로 옮겨졌다. |
| **CXL (Compute Express Link)** | PCIe 5.0/6.0과 같은 전기 PHY 위에서 링크 트레이닝 때 협상되는 캐시 일관성 인터커넥트. CXL.io(=PCIe 호환)·CXL.cache·CXL.mem 세 프로토콜로, CPU와 가속기·메모리 확장 장치가 메모리를 일관성 있게 공유·풀링하게 한다. 주로 서버·AI 인프라에서 메모리 용량·대역폭 확장에 쓰인다. |
| **NVLink / 가속기 인터커넥트** | GPU·가속기끼리 PCIe보다 훨씬 넓은 대역폭으로 직접 잇는 전용 링크(NVIDIA NVLink 등). 다중 GPU가 모델·텐서를 나눠 학습할 때 GPU 간 인터커넥트 대역폭이 곧 성능 병목이 되므로, 이런 전용 패브릭으로 PCIe를 보완한다. |
| **프로토콜 터널링(USB4·Thunderbolt)** | 하나의 물리 링크 위에 PCIe·DisplayPort·USB 등 여러 프로토콜을 각각 캡슐화해 동시에 실어 나르는 기법. USB-C 케이블 한 가닥으로 디스플레이·데이터·외장 GPU를 함께 다룰 수 있게 한다. |
| **링크 트레이닝(Link Training / LTSSM)** | 링크가 켜질 때 양쪽이 지원 가능한 최고 속도(세대)와 레인 폭을 자동 협상하고 신호 타이밍·등화를 맞추는 과정. 그래서 x16 슬롯이라도 실제로는 더 낮은 폭·세대로 동작할 수 있다. |
| **신용 기반 흐름 제어(Credit-based Flow Control)** | 수신 측이 받아들일 수 있는 버퍼 용량을 '신용(credit)'으로 미리 알려 주면, 송신 측은 신용이 있는 만큼만 패킷을 보내는 방식. PCIe가 수신 버퍼 넘침 없이 무손실로 흐르게 하는 링크 계층의 규칙이다. |

## 📊 대표 사양·수치 감각

| 항목 | 값 | 비고 |
|---|---|---|
| PCIe 3.0 (레인당, 편방향) | 8 GT/s → 약 0.985 GB/s | 128b/130b 인코딩. x16이면 약 15.75GB/s, x4 NVMe면 약 3.94GB/s. |
| PCIe 4.0 (레인당, 편방향) | 16 GT/s → 약 1.97 GB/s | 세대마다 레인당 대역폭이 대략 2배로 증가. x16 약 31.5GB/s. |
| PCIe 5.0 (레인당, 편방향) | 32 GT/s → 약 3.94 GB/s | x16 약 63GB/s(양방향 합산 약 128GB/s). 현재 고성능 GPU(RTX 50 세대)·SSD의 주력. |
| PCIe 6.0 (레인당, 편방향) | 64 GT/s → 약 8 GB/s | PAM4(심볼당 2비트, 32 GBaud)+FLIT+FEC. x16 약 128GB/s 편방향(양방향 약 256GB/s). FLIT/FEC 프레이밍 감안 시 실효 페이로드는 약 7.5GB/s로 다소 낮다. 주로 서버·AI. |
| PCIe 7.0 (레인당, 편방향) | 128 GT/s → 약 16 GB/s | x16 약 256GB/s 편방향(양방향 약 512GB/s). 2025년 6월 1.0 규격 발표(확정). 데이터센터·AI부터 도입, 소비자 보급은 한참 이후. |
| DMI 4.0 (CPU↔칩셋, Intel) | 고급 칩셋 = PCIe 4.0 x8 상당, 약 16 GB/s | 보급형 칩셋은 x4(약 8GB/s). 칩셋 아래 USB·SATA·네트워크 등 모든 장치가 이 대역폭을 공유(오버서브스크립션). AMD는 별도 이름 없이 PCIe 4.0 x4로 칩셋 연결. |
| SATA III (Serial ATA 6Gbps) | 6 Gbps → 약 600 MB/s | 8b/10b 인코딩 탓 6Gbps가 600MB/s. 실효 약 550MB/s. SATA SSD가 이 벽에 갇혀 NVMe로 넘어간 이유. |
| USB 2.0 (High-Speed) | 480 Mbps (약 60 MB/s) | 반이중, 단일 차동 쌍(D+/D-). 실효는 대략 40MB/s 안팎. 지금도 키보드·마우스 등 저속 장치의 주력. |
| USB 3.2 Gen 1 (구 USB 3.0) | 5 Gbps (약 500 MB/s) | 8b/10b 인코딩. 전이중용 별도 SuperSpeed 배선쌍 추가. Gen 2는 10Gbps(128b/132b), Gen 2x2는 20Gbps(USB-C 전용). |
| USB4 / Thunderbolt 3·4 | 40 Gbps | USB-C 커넥터에서 PCIe·DisplayPort·USB를 터널링. USB4는 20 또는 40Gbps로 협상. 프로토콜 통합의 정점. |
| USB4 v2 / Thunderbolt 5 | 80 Gbps (비대칭 시 한쪽 최대 120) | PAM3 신호 채택. 고해상도 디스플레이처럼 한쪽 대역폭이 큰 경우 비대칭 배분(예: 120/40) 가능. |
| 차동 신호 전압 스윙(대략) | 약 0.8~1.2 V p-p (PCIe 초기 세대 기준) | 두 선 전압 차로 비트를 표현. 저전압이지만 노이즈 상쇄로 초고속 유지. 고속 세대일수록 스윙은 더 낮아지고 등화·FEC 의존도가 커진다. |
| USB 버스 전력(참고) | 기본 5V, USB PD 최대 240W(48V·5A) | 데이터와 별개로 전력도 함께 공급. USB Power Delivery(PD 3.1 EPR)는 노트북 충전까지 담당. |
| 인터럽트 벡터 / 설정 공간 | IDT 벡터 256개(0~31 예외 예약), MSI-X 최대 2048벡터 / 설정공간 PCI 256B·PCIe 4KB | CPU는 벡터 번호로 IDT에서 핸들러를 찾는다. PCIe는 확장 설정공간 4KB를 ECAM(MMIO)으로 접근. |

## ⚠️ 흔한 오해

- **오해** — PCIe는 여러 선으로 한꺼번에 보내는 병렬 버스다.
  <br>**교정** — 아니다. 이름의 'Bus'와 달리 PCIe는 장치와 장치를 1:1로 잇는 '직렬' 링크다. 옛 PCI는 여러 장치가 공유하는 병렬 버스였지만, 고속에서 병렬 선들의 신호 어긋남(스큐)이 한계에 부딪히자 레인마다 독립된 직렬 차동 링크로 전환했다.
- **오해** — x16 슬롯에 꽂으면 무조건 x16 최고 속도로 동작한다.
  <br>**교정** — 실제 동작 폭·세대는 링크 트레이닝으로 협상된다. 슬롯이 물리적으로 x16이어도 전기적으로는 x4·x8만 연결되어 있거나, 장치·메인보드 세대가 낮으면 그만큼만 쓴다. 반대로 GPU가 x16 대신 x8로 떨어져도 게임 성능 차이는 미미한 경우가 많다.
- **오해** — USB의 Gbps와 저장장치의 GB/s는 같은 단위라 숫자를 그대로 비교하면 된다.
  <br>**교정** — Gbps(기가비트)와 GB/s(기가바이트)는 8배 차이다. 게다가 인코딩 오버헤드가 있어(8b/10b는 20%) SATA 6Gbps가 약 600MB/s밖에 안 된다. 대역폭을 비교할 땐 비트/바이트 단위와 인코딩·편방향/양방향을 먼저 맞춰야 한다.
- **오해** — DMA는 CPU가 데이터를 더 빨리 복사하는 특별한 명령이다.
  <br>**교정** — 정반대다. DMA는 CPU가 데이터 복사에서 '빠지는' 것이다. 장치의 DMA 엔진이 스스로 RAM을 직접 읽고 쓰며, CPU는 시작 지시(디스크립터·도어벨)와 완료 인터럽트만 처리하고 그동안 다른 계산을 한다.
- **오해** — 메모리(RAM)도 칩셋을 거쳐 CPU에 연결된다.
  <br>**교정** — 지금은 메모리 컨트롤러가 CPU 다이 안으로 들어와 RAM이 CPU에 직결된다. 칩셋(과거 노스브리지)이 메모리를 중계하던 시대는 지났다. DMI는 CPU와 '저속 주변기기 허브'인 칩셋을 잇는 별개의 좁은 링크일 뿐, 메모리 경로가 아니다(단, CXL 메모리 확장은 PCIe 배선을 통해 별도 계층으로 붙는 예외가 생겼다).
- **오해** — 인터럽트는 반드시 장치에서 CPU로 이어진 물리적 전선이 있어야 발생한다.
  <br>**교정** — 현대 PCIe 장치는 MSI/MSI-X를 써서 전용 핀 없이, 약속된 메모리 주소(로컬 APIC 영역)에 값을 쓰는 것(메모리 쓰기 패킷)만으로 인터럽트를 표현한다. 이 방식이 I/O APIC를 우회하고 다중 큐·멀티코어 분산에 유리해 표준이 되었다.
- **오해** — USB-C와 Thunderbolt는 같은 것이다.
  <br>**교정** — USB-C는 커넥터(포트의 물리적 모양)이고, Thunderbolt·USB4는 그 위를 흐르는 프로토콜이다. 겉모습이 같은 USB-C 포트라도 어떤 것은 USB 2.0만, 어떤 것은 Thunderbolt 40Gbps를 지원하는 등 실제 능력은 제각각이다.
- **오해** — CXL은 PCIe와 전혀 다른 별개의 배선·슬롯을 쓴다.
  <br>**교정** — CXL은 PCIe 5.0/6.0과 동일한 전기 PHY와 커넥터를 그대로 쓰고, 링크 트레이닝(협상) 단계에서 표준 PCIe 대신 CXL 프로토콜로 붙을지를 정한다. 물리 배선은 같고 프로토콜 계층이 다른 것이며, CXL이 더하는 핵심은 CPU-장치 간 '캐시 일관성'과 메모리 공유다.

## 💡 비유

첫째, 도로망 비유: CPU 직결 PCIe 레인은 도심으로 곧장 이어지는 급행 고속도로(GPU·NVMe 전용선)이고, 칩셋+DMI는 여러 국도(USB·SATA·오디오·네트워크)를 하나의 인터체인지에 모은 뒤 좁은 다리 한 가닥으로 시내에 밀어 넣는 구조다. 레인 수는 차선 수, 세대(3.0/4.0/5.0)는 제한 속도에 해당한다. CXL은 같은 고속도로 노면 위에 '차량이 서로의 화물칸을 공유하는' 새 운행 규칙을 얹은 셈이다. 둘째, 택배 비유: DMA는 택배 서비스와 같다. 나(CPU)는 '이 물건을 저 창고(RAM)로'라고 주소와 물량을 송장(디스크립터, RAM에 비치)에 적고 초인종만 한 번 누르면(도어벨), 택배 기사(DMA 엔진)가 알아서 오가고 배달이 끝나면 초인종(인터럽트)을 눌러 알린다. 그동안 나는 다른 일을 한다. 셋째, 차동 신호는 시끄러운 공장에서 두 사람이 같은 말을 서로 반대로 외치고, 듣는 쪽이 '둘의 차이'만 들어 배경 소음을 지워 버리는 것과 같다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 컴퓨터가 켜지는 과정(부팅): UEFI가 PCIe 버스를 열거해 장치마다 정체를 파악하고 BAR로 주소를 배정하며, DMI 링크와 SATA·NVMe가 인식되는 '버스 계층이 깨어나는' 순간.
- 게임 조작이 화면이 되기까지: CPU가 만든 드로우콜과 텍스처가 PCIe x16을 타고 GPU와 VRAM으로 밀려 들어가는 구간.
- 게임 로딩 화면의 정체(DirectStorage)와 드라이브 파일 열기: NVMe SSD가 PCIe x4로 붙어 DMA로 RAM에 직접 에셋을 쏟아붓고, 끝나면 MSI 인터럽트로 완료를 통보.
- Ctrl+S 한 번의 여정: 저장할 데이터가 DMA로 NVMe 컨트롤러에 넘어가 PCIe 위의 TLP 패킷으로 흐르는 쓰기 경로.
- USB를 꽂는 순간: xHCI 호스트 컨트롤러가 새 장치를 열거해 장치 ID를 읽고 주소를 배정하며, 칩셋을 경유해 DMI로 CPU에 이르는 과정.
- 인터넷 검색 한 번의 왕복: NIC가 받은 패킷을 DMA로 RAM에 써 넣고 MSI 인터럽트로 특정 코어를 깨우는 수신 경로.
- 유튜브·영상 스트리밍: NIC가 받은 영상 데이터가 DMA로 RAM에 쌓이고, 다시 PCIe를 건너 GPU의 하드웨어 디코더로 전달되는 흐름.
- 음악이 스피커에서 나오기까지: 오디오 코덱이 칩셋 버스에 붙어 DMA로 오디오 샘플 스트림을 끊김 없이 받아 가는 장면.
- AI에게 질문할 때: 대량의 텐서 데이터가 PCIe/NVLink로 GPU·NPU와 오가며, 이때 '인터커넥트 대역폭'이 곧 성능 병목이 되는 지점.
- 여러 프로그램이 동시에 도는 법: 타이머와 장치 인터럽트가 APIC를 통해 각 코어로 분배되어 스케줄러를 깨우는 순간.
