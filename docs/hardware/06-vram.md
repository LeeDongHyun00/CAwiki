# 그래픽 메모리 (VRAM)
*Video RAM (VRAM)*

> GPU 바로 옆에 붙어, 화면·텍스처·AI 가중치 같은 대용량 데이터를 초당 수백 GB~수 TB로 퍼올리는, 지연(latency)보다 '처리량(대역폭)'을 위해 설계된 전용 DRAM.

**분류**: 메모리

---

## 🧭 한마디로, 무슨 일을 하나
VRAM은 GPU가 매 순간 소비하는 방대한 데이터(렌더링할 텍스처·기하 정보, 화면 픽셀을 담는 프레임버퍼와 깊이 버퍼, 신경망의 가중치와 중간 활성값·KV 캐시)를 담아두는 GPU 전용 작업 기억장치다. GPU는 수천~수만 개의 연산 유닛이 동시에 데이터를 요구하기 때문에, 한 번에 조금씩 빠르게 왕복하는 시스템 RAM과 달리 '한 번에 아주 넓게' 데이터를 실어나르는 능력이 필요하다. 그래서 VRAM은 넓은 메모리 버스와 초고속 신호 기술로 시스템 RAM보다 대략 10~20배(데이터센터급 HBM에선 그 이상) 큰 대역폭을 제공하도록 설계된다. 개별 접근의 지연시간(레이턴시)을 줄이기보다 총 처리량을 극대화하고, 그 대기 시간은 GPU가 수많은 스레드를 번갈아 실행해 숨기는 것이 설계 철학이다.

## ⚙️ 작동 방식

**1. GPU 연산 유닛이 데이터를 요청한다**

셰이더 코어나 텐서/AI 연산 유닛이 텍스처 한 조각, 정점 좌표, 또는 신경망 가중치가 필요해지면 메모리 주소가 담긴 로드/스토어 요청을 만든다. 필요한 값이 GPU 칩 안의 L1/L2 캐시에 없을 때(캐시 미스) 비로소 칩 밖 VRAM까지 나가야 하기 때문이다. GPU에서는 이런 요청이 초당 수십억 건 단위로 쏟아진다.

**2. 메모리 컨트롤러가 요청을 모으고 재정렬한다**

GPU 다이 위에 있는 여러 개의 메모리 컨트롤러가 수천 개의 요청을 큐에 모아, 같은 DRAM 뱅크·행(row)을 건드리는 요청끼리 묶고 인접 주소 접근을 하나로 합친다(코얼레싱). DRAM은 한 번 연 행 안에서 연속 접근할 때 훨씬 효율적이라, 접근 순서를 재배열해 헛된 행 열기/닫기를 줄이고 처리량을 끌어올린다.

**3. 명령/주소를 보내 DRAM 행을 연다(Activate)**

컨트롤러가 명령·주소(CA) 버스로 ACTIVATE 명령을 보내 목표 뱅크의 한 행을 선택하면, 그 행에 속한 수천~수만 개 셀의 미세한 전하가 감지증폭기(로우 버퍼)로 끌어올려져 래치된다. DRAM 셀은 커패시터에 담긴 전하라 신호가 약해서, 읽기 전에 먼저 행 전체를 증폭해 안정된 값으로 만들어 두어야 하기 때문이다.

**4. 열을 읽고 내부에서 넓게 미리 가져온다(Prefetch)**

READ 명령으로 열(column)을 지정하면, DRAM은 느린 셀 속도를 감추기 위해 한 번에 여러 비트를 미리 끌어내는 프리페치(예: GDDR6는 채널당 16n)를 수행한다. 코어 셀 어레이의 클럭은 상대적으로 느리므로, 한 번의 내부 동작으로 넓은 데이터 묶음을 확보해 두어야 바깥의 초고속 인터페이스 속도를 굶기지 않고 채울 수 있다.

**5. PHY가 데이터를 직렬화해 초고속 신호로 핀에 실어보낸다**

물리계층(PHY)이 데이터를 DQ 핀으로 내보낸다. 데이터 클럭(WCK)의 양쪽 에지 모두에서 보내는 DDR 방식에 더해, GDDR6X는 PAM4(4레벨, 심볼당 2비트), GDDR7은 PAM3(3레벨, 심볼당 약 1.5비트) 신호로 한 심볼에 1비트보다 많은 정보를 실어 핀당 20~32 Gbps 이상을 달성한다. 심볼 전송 속도(baud)를 무작정 올리지 않고도 핀당 비트 수를 늘릴 수 있기 때문이며, GDDR7이 PAM4 대신 PAM3를 택한 것은 레벨 간 간격이 넓어 고속에서 잡음 여유(SNR)가 더 좋기 때문이다.

**6. 넓은 버스로 수많은 핀이 동시에 데이터를 쏟아낸다**

예컨대 32비트(x32)짜리 GDDR 칩 12개를 붙이면 384비트 버스가 되어, '핀당 속도 × 버스폭 ÷ 8'으로 초당 수백 GB에서 약 1.8 TB에 이르는 데이터가 한꺼번에 흐른다. HBM은 한 스택에서 1024비트(HBM4는 2048비트)라는 훨씬 넓은 길을 열어 핀당 속도는 낮아도 스택 하나로 약 1 TB/s 이상을 낸다. 이것이 '지연을 줄이는 대신 폭으로 밀어붙이는' 처리량 우선 설계의 핵심이다.

**7. GPU가 다른 스레드를 돌리며 대기 시간을 숨긴다**

데이터가 도착하는 동안 GPU는 놀지 않고, 메모리를 기다리는 스레드 묶음(워프/웨이브)을 잠시 재우고 준비된 다른 스레드를 실행한다. 수만 개의 스레드를 번갈아 돌려 메모리 접근의 긴 지연시간을 연산으로 덮기 때문에, VRAM의 절대 지연이 시스템 RAM보다 길어도 전체 처리량은 유지된다.

**8. 결과를 되쓰고 DRAM을 주기적으로 리프레시한다**

렌더링 결과인 색상 프레임버퍼와 깊이(Z) 버퍼, AI 연산의 중간 활성값은 같은 경로를 거꾸로 타고 VRAM에 기록된다. 이때 GPU는 델타 색상 압축(DCC) 같은 무손실 압축을 걸어 실제로 오가는 데이터량 자체를 줄이기도 한다. 한편 DRAM 셀의 커패시터 전하는 시간이 지나면 새어나가 데이터가 사라지므로, 컨트롤러가 일정 주기마다 모든 행을 읽어 다시 채우는 리프레시를 수행해 내용을 보존한다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **DRAM 셀 어레이 (뱅크·뱅크 그룹)** | '커패시터 1개 + 트랜지스터 1개'로 된 셀이 행과 열의 격자로 배열된 저장 본체. 여러 뱅크·뱅크 그룹으로 나뉘어 서로 다른 뱅크를 겹쳐 접근함으로써 사실상 병렬로 동작해 처리량을 높인다. |
| **감지증폭기(Sense Amplifier)와 로우 버퍼** | 셀 커패시터의 아주 약한 전하 차이를 감지해 또렷한 0/1로 증폭하고 한 행 전체를 임시로 붙잡아 둔다. 같은 행 안의 연속 접근이 빠른 이유가 바로 이 버퍼에 이미 데이터가 올라와 있기 때문이다. |
| **행/열 디코더 & 주소 로직** | 컨트롤러가 준 주소를 해석해 어느 행을 열고 어느 열을 읽을지 고른다. ACTIVATE로 행을 선택하고 READ/WRITE로 열을 지정하는 2단계 접근을 담당한다. |
| **I/O 인터페이스(PHY)와 DQ 데이터 핀** | 칩 안팎을 잇는 초고속 물리계층. 내부의 넓고 느린 데이터를 바깥의 좁고 빠른 핀 신호로 직렬화하고, GDDR6X의 PAM4·GDDR7의 PAM3 인코더/디코더, 온다이 종단(ODT), 데이터 클럭(WCK) 회로가 여기 모여 있다. |
| **명령·주소(CA) 버스와 데이터(DQ) 버스** | 명령/주소는 CA 선으로, 실제 데이터는 DQ 선으로 나뉘어 흐른다. 이 DQ 핀들이 여러 칩에 걸쳐 모여 128~512비트에 이르는 '넓은 메모리 버스'를 이루며, 이 버스 폭은 핀당 속도와 함께 대역폭을 결정하는 두 축 중 하나다. |
| **프리페치·직렬화 버퍼** | 느린 셀 어레이에서 한 번에 넓게 읽어온 데이터를 잠시 담았다가 핀 속도에 맞춰 순서대로 내보낸다. 코어 클럭과 인터페이스 클럭의 큰 속도 차이를 메우는 완충 장치다. |
| **리프레시 회로 & 클럭 생성(PLL/DLL)** | 커패시터 전하가 새기 전에 주기적으로 모든 행을 재충전하고, 초고속 데이터 전송의 타이밍을 맞추는 기준 클럭을 만들어 신호가 정확한 순간에 도착하도록 정렬한다. |
| **온다이 ECC & 데이터 무결성 로직** | GDDR6 이후 세대는 셀 미세화로 늘어난 비트 오류를 칩 내부에서 스스로 검출·정정하는 온다이 ECC를 갖는다. HBM은 여기에 더해 별도 신호선으로 시스템 단 ECC까지 지원해, 장시간 돌아가는 AI·데이터센터에서 데이터 신뢰성을 확보한다. |
| **BGA 패키지와 PCB 실장(GDDR의 경우)** | GDDR 칩은 GPU를 둘러싸고 기판(PCB)에 직접 납땜된다. DIMM 소켓 없이 짧은 배선으로 GPU에 붙는 이 구조 덕분에 신호 무결성이 좋아 높은 핀 속도를 견딘다. 기판 앞뒤 양면에 칩을 마주 붙이는 클램셸(clamshell) 실장으로 버스폭은 그대로 두고 용량만 2배로 늘리기도 한다. |
| **TSV(관통 실리콘 비아) — HBM** | HBM에서 여러 층으로 쌓인 DRAM 다이를 수직으로 꿰뚫어 전기적으로 잇는 미세 구멍. 층과 층을 옆이 아니라 위아래로 직결해, 아주 넓은 1024/2048비트 통로를 짧은 거리로 만들어 준다. |
| **베이스 로직 다이 & 마이크로범프 — HBM** | HBM 스택 맨 아래에서 스택 전체의 입출력을 총괄하는 논리 층. 그 위 DRAM 다이들과는 마이크로범프(초소형 접점)로 연결되며, 여기서 나온 넓은 신호가 인터포저로 전달된다. |
| **실리콘 인터포저 (2.5D 패키징) — HBM** | GPU 다이와 HBM 스택을 나란히 얹고 그 사이에 수천 가닥의 초미세 배선을 새긴 실리콘 받침판. 일반 PCB로는 불가능한 1024~2048비트급 초광폭 배선을 짧게 잇는 '고속도로 인터체인지' 역할을 한다. |
| **메모리 컨트롤러 (GPU 다이 내부, 논리적 구성)** | VRAM 칩 자체는 아니지만 짝을 이루는 필수 요소. 요청을 모으고 재정렬하며 명령을 발행하고 리프레시를 관리한다. 컨트롤러의 채널 수와 폭이 실제로 몇 개의 메모리 칩을 병렬로 부릴 수 있는지를 정한다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **VRAM (Video RAM, 비디오/그래픽 메모리)** | GPU 전용으로 붙는 작업 기억장치의 총칭. 물리적으로는 GDDR이나 HBM 같은 특수 DRAM으로 구현된다. |
| **GDDR (Graphics Double Data Rate, 그래픽용 이중 데이터율 메모리)** | 그래픽카드에 널리 쓰이는 DRAM 계열. 클럭 양쪽 에지에서 데이터를 보내는 DDR 방식에 더해 핀당 속도를 극한으로 끌어올린 것이 특징. 세대로 GDDR6 → GDDR6X → GDDR7이 있다. |
| **HBM (High Bandwidth Memory, 고대역폭 메모리)** | DRAM 다이를 여러 층 쌓아 GPU 옆에 붙이는 초광폭 메모리. 핀당 속도는 GDDR보다 낮지만 1024비트(차세대 HBM4는 2048비트)라는 넓은 폭과 짧은 배선으로 낮은 전력에 아주 큰 대역폭을 낸다. 데이터센터·AI 가속기에 주로 쓰인다. |
| **TSV (Through-Silicon Via, 관통 실리콘 비아)** | 칩을 수직으로 관통해 위아래 다이를 잇는 미세 배선. HBM의 3D 적층을 가능하게 하는 핵심 기술. |
| **실리콘 인터포저 / 2.5D 패키징 (Silicon Interposer)** | GPU와 HBM을 한 받침판 위에 나란히 올리고 그 안에 초미세 배선을 새겨 잇는 방식. 칩을 완전히 쌓는 3D와 평면 PCB의 중간이라 2.5D라 부른다. |
| **메모리 버스 폭 (Bus Width)** | 한 번에 동시에 오갈 수 있는 데이터 선(비트)의 수. 128·256·384·512비트처럼 넓을수록 대역폭이 커진다. 대역폭(바이트) = 핀당 속도 × 버스폭 ÷ 8. |
| **대역폭 (Bandwidth)** | 초당 옮길 수 있는 데이터의 총량(GB/s, TB/s). VRAM 성능의 핵심 지표로, 지연시간과는 다른 개념이다. |
| **PAM4 / PAM3 (Pulse Amplitude Modulation, 진폭 변조)** | 한 신호에 2개(PAM2/NRZ) 대신 여러 전압 레벨을 두어 한 번에 더 많은 비트를 싣는 기술. PAM4는 4레벨(2비트/심볼, GDDR6X), PAM3는 3레벨(약 1.5비트/심볼, GDDR7). GDDR7이 PAM4가 아닌 PAM3를 쓰는 것은 레벨 간 간격이 넓어 고속에서 잡음 여유가 더 크기 때문이다. |
| **프레임버퍼 / Z-버퍼 (Frame Buffer / Depth Buffer)** | 화면에 표시할 픽셀 색을 담는 메모리 영역이 프레임버퍼, 각 픽셀의 깊이(카메라와의 거리)를 담아 가림 판정을 하는 것이 Z(깊이)버퍼. 둘 다 VRAM에 상주한다. |
| **프리페치 (Prefetch)** | 느린 셀에서 한 번에 여러 비트를 미리 넓게 읽어내는 DRAM 내부 동작. 느린 코어와 빠른 인터페이스의 속도 차를 메운다(예: GDDR6는 채널당 16n). |
| **대역폭 압축 & 텍스처 압축 (DCC / Texture Compression)** | 델타 색상 압축(DCC)은 프레임버퍼를 무손실 압축해 오가는 데이터량을 줄여 '실효 대역폭'을 늘리고, BCn·ASTC 같은 텍스처 압축은 텍스처를 압축된 채로 VRAM에 두어 용량과 대역폭을 동시에 아낀다. 같은 하드웨어로 더 많은 일을 하게 하는 핵심 기법. |
| **온다이 ECC (On-die ECC)** | 셀 미세화로 늘어난 비트 오류를 칩 내부에서 스스로 검출·정정하는 기능. GDDR6부터 흔해졌고, HBM은 별도 신호선으로 시스템 단 ECC까지 지원해 장시간 AI 연산의 신뢰성을 높인다. |
| **클램셸 모드 (Clamshell)** | PCB 앞뒤 양면에 메모리 칩을 마주 붙여, 버스폭(대역폭)은 그대로 두고 용량만 2배로 늘리는 실장 방식. 프로/데이터센터 카드나 고용량 버전(예: 같은 칩으로 16GB↔32GB)에서 쓴다. |
| **지연 은닉 / 스레드 수준 병렬성 (Latency Hiding)** | 메모리를 기다리는 스레드를 재우고 다른 스레드를 실행해 대기 시간을 연산으로 덮는 GPU의 전략. VRAM이 지연보다 처리량을 우선할 수 있는 이유. |
| **리프레시 (Refresh)** | DRAM 커패시터의 새어나가는 전하를 주기적으로 다시 채워 데이터를 유지하는 동작. 이것이 필요해 DRAM을 '동적(Dynamic)' RAM이라 부른다. |
| **UMA / 통합 메모리 (Unified Memory Architecture)** | 내장 그래픽(iGPU)이나 일부 SoC가 별도 VRAM 없이 시스템 RAM 일부를 그래픽용으로 공유하는 구조. 대개 대역폭이 전용 VRAM보다 낮지만, 애플 실리콘처럼 아주 넓은 LPDDR 버스를 쓰는 SoC는 예외적으로 수백 GB/s급 고대역폭을 내기도 한다. |

## ⚠️ 흔한 오해

- **오해** — VRAM 용량이 크면 무조건 게임이 빨라진다.
  <br>**교정** — 용량은 필요한 만큼만 있으면 충분하고, 그 이상은 프레임에 큰 영향을 주지 않는다. 용량이 '부족할 때'는 데이터를 느린 시스템 RAM으로 넘겨 큰 병목이 생기지만, 넉넉한 상태에서 프레임을 좌우하는 것은 오히려 대역폭과 GPU 코어의 연산 성능이다.
- **오해** — VRAM은 그냥 더 빠른 일반 RAM일 뿐이다.
  <br>**교정** — GDDR/HBM은 지연시간이 아니라 처리량을 위해 설계된 특수 DRAM이다. 접근 하나하나의 지연(레이턴시)은 오히려 시스템 RAM보다 길 수 있으며, 대신 넓은 버스로 한 번에 훨씬 많은 데이터를 옮긴다.
- **오해** — HBM은 GDDR보다 모든 면에서 빠르다(핀 속도도 더 높다).
  <br>**교정** — HBM의 핀당 속도는 오히려 GDDR보다 낮다. HBM이 압도적인 총 대역폭을 내는 것은 1024비트(HBM4는 2048비트)라는 극단적으로 넓은 버스 덕분이며, 넓은 폭으로 낮은 핀 속도를 상쇄해 전력 효율까지 얻는 설계다.
- **오해** — 대역폭이 크니 VRAM은 지연시간도 짧을 것이다.
  <br>**교정** — 대역폭(초당 총량)과 지연시간(한 요청이 도착하기까지 걸리는 시간)은 별개다. GPU는 수만 개의 스레드를 번갈아 돌려 긴 지연을 숨기기 때문에, 큰 대역폭과 긴 지연이 동시에 성립할 수 있다.
- **오해** — 내장 그래픽(iGPU)에는 VRAM이 아예 없다.
  <br>**교정** — 전용 VRAM 칩이 없을 뿐, 시스템 RAM의 일부를 그래픽 메모리로 공유(UMA)해서 사용한다. 그래서 대개 대역폭이 전용 GDDR/HBM보다 낮고 이것이 성능 한계 중 하나다(단, 애플 실리콘처럼 넓은 LPDDR 버스를 쓰는 SoC는 예외적으로 높은 대역폭을 낸다).
- **오해** — VRAM에 저장된 화면·데이터는 전원을 꺼도 남는다.
  <br>**교정** — VRAM은 DRAM이라 전원이 끊기면 내용이 사라지는 휘발성 메모리다. 심지어 켜져 있는 동안에도 주기적 리프레시가 없으면 데이터가 사라진다.

## 💡 비유

시스템 RAM이 '한 번에 소량을 아주 빠르게 배달하는 오토바이 퀵서비스'라면, VRAM은 '차선이 수백 개인 화물 고속도로'다. 트럭 한 대(개별 접근)는 오토바이보다 느릴 수 있어도, 차선이 압도적으로 많아 한꺼번에 실어나르는 총 물동량(대역폭)은 비교가 안 된다. HBM은 여기에 더해, 여러 층짜리 물류창고를 초고속 화물 엘리베이터(TSV)로 수직 연결하고 그 창고를 공장(GPU) 바로 옆 담장(실리콘 인터포저)에 붙여 이동 거리를 극단적으로 줄인 구조라고 볼 수 있다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 부팅: 전원이 들어오면 GPU가 초기화되면서 VRAM을 켜고 리프레시를 시작한다. 부트 로고와 화면 이미지가 VRAM의 프레임버퍼에 올라가 디스플레이로 스캔아웃되면서 첫 화면이 뜬다.
- 게임 렌더링: 캐릭터·배경의 텍스처, 정점 데이터, 그리고 매 프레임의 색상 프레임버퍼와 Z(깊이)버퍼가 모두 VRAM에 상주한다. GPU가 초당 수백 GB로 이들을 읽고 쓰며 화면을 그려내, VRAM 대역폭이 곧 프레임 성능의 핵심 병목이 된다.
- 영상 스트리밍: 하드웨어 디코더가 풀어낸 영상 프레임이 VRAM의 프레임버퍼에 올라가고, 디스플레이가 이를 계속 읽어 화면으로 내보낸다. 4K 재생일수록 프레임 하나의 크기가 커져 VRAM 대역폭을 더 쓴다.
- AI 질문(LLM 추론): 언어모델의 수십억 개 가중치와 대화 문맥을 담은 KV 캐시가 VRAM에 통째로 상주한다. 토큰 하나를 만들 때마다 가중치 전체를 훑어 읽으므로, 답변이 나오는 속도는 대체로 VRAM 대역폭과 용량이 좌우한다.
- 인터넷 검색/일반 화면 갱신: 브라우저가 GPU 가속으로 웹페이지를 합성(compositing)할 때, 텍스트·이미지 레이어와 스크롤되는 화면이 VRAM의 프레임버퍼에서 갱신되어 매끄럽게 표시된다.
- 파일 열기(사진·큰 이미지 뷰어): 이미지 데이터가 VRAM으로 올라가 텍스처로 처리되면서 화면에 표시된다. 이미지가 VRAM 용량을 넘어서면 일부를 느린 시스템 RAM에 두게 되어 확대·스크롤이 버벅일 수 있다.
