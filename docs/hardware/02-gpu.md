# 그래픽처리장치 (GPU)
*Graphics Processing Unit (GPU)*

> 수천 개의 작은 코어로 같은 계산을 대규모 병렬로 수행해, 화면 픽셀을 그리는 그래픽 렌더링과 행렬 연산(AI·과학계산)을 초고속으로 처리하는 대량 병렬(throughput) 프로세서.

**분류**: 연산

---

## 🧭 한마디로, 무슨 일을 하나
GPU는 컴퓨터에서 '똑같은 연산을 엄청나게 많이 동시에' 해야 하는 일을 전담하는 처리량(throughput) 중심의 프로세서다. 원래는 3D 게임 화면처럼 수백만 개의 픽셀·정점을 병렬로 계산하는 그래픽 렌더링을 위해 만들어졌지만, 같은 대량 병렬 구조가 딥러닝의 행렬 곱셈, 과학 시뮬레이션, 영상 인코딩에도 이상적이라 오늘날 AI 연산의 핵심 장치가 되었다. CPU가 소수의 강력한 코어로 순차적·분기 많은 제어 흐름을 빠르게 처리한다면, GPU는 약한 코어 수천 개로 데이터를 쪼개어 동시에 갈아버린다. 컴퓨터 안에서 CPU의 '보조 연산 가속기'이자 화면을 실제로 그려 모니터로 내보내는 '출력 담당'이라는 두 역할을 함께 맡는다(단, 일부 데이터센터 GPU는 디스플레이 출력 없이 연산만 담당한다).

## ⚙️ 작동 방식

**1. CPU가 그릴 명령(드로우 콜)을 PCIe로 GPU에 전달한다**

게임·앱이 '이 삼각형들을 이 텍스처로 그려라' 같은 명령과 정점·텍스처 데이터를 준비하면, 이 데이터가 PCIe ×16 버스를 통해 VRAM으로 전송되고(자주 쓰는 데이터는 VRAM에 상주) 명령 스트림이 GPU의 커맨드 프로세서(호스트 인터페이스)에 쌓인다. CPU가 매번 화면을 직접 그리면 너무 느리기 때문에, 무엇을 그릴지만 지시하고 실제 계산은 GPU에 위임하는 것이다.

**2. 전역 스케줄러(예: NVIDIA GigaThread 엔진)가 작업을 여러 SM에 뿌린다**

GPU는 렌더링 작업이나 연산 커널을 잘게 나누어 칩 전체를 관리하는 전역 스케줄러가 놀고 있는 SM(스트리밍 멀티프로세서)들에 분배한다. '스레드 블록'이라는 계층은 주로 컴퓨트(CUDA/OpenCL) 프로그래밍 모델의 용어이고, 그래픽 렌더링에서는 정점·픽셀 작업을 워프 단위로 묶어 SM에 디스패치한다. 수십~수백 개의 SM을 항상 꽉 채워 돌려야 수천 개 코어가 놀지 않고 최대 처리량이 나오기 때문이다.

**3. 정점 셰이딩: 3D 좌표를 화면 좌표로 변환한다**

각 SM의 셰이더 코어들이 정점 셰이더를 실행해, 3D 공간에 있는 모델의 꼭짓점(정점)들을 카메라 시점에 맞춰 회전·이동·투영시켜 화면 좌표로 바꾼다. 눈에 보이는 대로 물체를 배치하려면 모든 정점의 위치를 먼저 계산해야 하기 때문이다. 정점 수가 수백만 개라도 각 정점 계산이 독립적이라 병렬로 한꺼번에 처리된다. (최신 파이프라인은 이 앞뒤 지오메트리 단계를 메시 셰이더로 대체·통합하기도 한다.)

**4. 프리미티브 조립·클리핑 후 래스터라이저가 삼각형을 픽셀 조각으로 쪼갠다**

변환된 정점들이 삼각형(프리미티브)으로 묶이고, 화면 밖 부분은 잘려나간다(클리핑). 그다음 고정 기능 하드웨어인 래스터라이저가 각 삼각형이 화면의 어느 픽셀들을 덮는지 판정해 수많은 '프래그먼트(픽셀 후보)'를 만든다. 벡터(수학적 도형)를 실제 화면의 격자 픽셀로 변환하는 이 단계가 있어야 색을 칠할 대상이 정해진다.

**5. 픽셀/프래그먼트 셰이더가 워프 단위(SIMT)로 색을 계산한다**

생성된 픽셀들은 보통 32개 스레드가 한 묶음인 '워프'로 그룹화되어(2×2 픽셀 쿼드 단위로 묶임), 하나의 명령이 32개 픽셀에 동시에 적용되는 SIMT 방식으로 셰이더 코어에서 실행된다. 이때 텍스처 유닛이 VRAM에서 이미지(텍스처)를 읽어 확대·축소에 맞게 보간(필터링)해주고, 조명·그림자 계산이 더해져 각 픽셀의 최종 색이 정해진다. 같은 셰이더 코드를 픽셀마다 반복하므로 SIMT가 매우 효율적이다.

**6. 워프 스케줄러가 메모리 대기 시간을 다른 워프 실행으로 숨긴다(지연 은닉)**

텍스처나 VRAM 접근은 수백 클럭이 걸려 느린데, 한 워프가 데이터를 기다리는 동안 워프 스케줄러가 즉시 준비된 다른 워프로 전환해 코어를 계속 돌린다. CPU처럼 큰 캐시로 지연을 줄이는 대신, GPU는 '항상 대기 중인 워프가 넘치게'(높은 점유율) 만들어 지연 자체를 감춘다. 이것이 GPU 고성능의 핵심 원리다.

**7. 깊이 테스트·블렌딩을 거쳐 ROP가 프레임버퍼에 기록한다**

성능을 위해 많은 GPU는 픽셀 셰이딩 전에 조기 깊이 테스트(Early-Z)를 수행해, 어차피 가려질 픽셀의 셰이딩을 미리 생략한다. 셰이딩이 끝난 픽셀은 ROP(래스터 연산 유닛)로 넘어가 깊이 값(Z) 비교로 앞 물체에 가려지는지 최종 판정하고, 반투명이면 뒤 색과 섞고(블렌딩), 안티에일리어싱을 적용한 뒤 VRAM 안의 프레임버퍼(완성 화면 이미지)에 최종 픽셀을 써넣는다. 겹치는 물체의 앞뒤 관계와 투명도를 올바르게 처리해야 화면이 정상적으로 보이기 때문이다.

**8. (특수 경로) RT 코어·텐서 코어가 광선 추적과 행렬 연산을 가속한다**

실사 같은 반사·그림자가 필요하면 RT 코어가 광선이 장면의 삼각형과 만나는지(BVH 순회·교차)를 하드웨어로 초고속 계산하고, AI 기반 화질 향상(DLSS 등)이나 LLM 추론이 필요하면 텐서 코어가 행렬 곱셈-누산을 한 번에 대량 수행한다. 이런 연산을 일반 셰이더 코어로 하면 너무 느려서 전용 하드웨어를 따로 둔 것이다.

**9. 디스플레이 엔진이 프레임버퍼를 스캔아웃해 모니터로 내보낸다**

완성된 프레임버퍼를 디스플레이 엔진이 초당 수십~수백 번 순서대로 읽어(스캔아웃), HDMI·DisplayPort 신호로 변환해 모니터로 전송한다. 화면 찢김을 막기 위해 모니터의 재생 주기에 맞춰(수직 동기·가변 주사율) 내보낸다. 이 단계가 있어야 계산된 이미지가 실제로 눈에 보인다. 한편 영상 재생 시에는 하드웨어 디코더(NVDEC 등)가 압축된 동영상을 셰이더 코어를 쓰지 않고 저전력으로 풀어 이 화면에 얹는다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **SM/CU (스트리밍 멀티프로세서 / 컴퓨트 유닛)** | GPU의 기본 연산 블록. 수십~수백 개가 모여 칩을 이루며, 각 SM 안에 셰이더 코어·워프 스케줄러·레지스터·공유 메모리·텐서/RT 코어·텍스처 유닛이 들어 있다. CPU의 '코어'에 해당하는 자족적 연산 단위다. |
| **셰이더 코어 (CUDA 코어 / 스트림 프로세서)** | 실제 산술을 담당하는 수천 개의 작은 ALU. 정점 변환, 픽셀 색 계산, 범용 연산의 덧셈·곱셈을 수행한다. 하나하나는 약하지만 수천 개가 동시에 돌아 막대한 처리량을 낸다. |
| **워프 스케줄러 & 디스패치 유닛** | SM 안에서 준비된 워프(32스레드 묶음)를 골라 매 클럭 셰이더 코어에 명령을 발행한다. 메모리 대기 중인 워프 대신 실행 가능한 워프로 즉시 전환해 코어를 놀리지 않게 하는 지연 은닉의 핵심. |
| **레지스터 파일** | 각 스레드가 계산 중인 값을 담아두는 초고속 저장소. GPU는 수천 스레드의 상태를 동시에 유지해야 해서 레지스터 파일이 CPU보다 훨씬 크다(SM당 수백 KB). 이 덕에 워프 전환이 즉각적이다. |
| **공유 메모리 / L1 캐시** | SM 내부의 작고 빠른 메모리. 같은 블록의 스레드들이 데이터를 나눠 쓰거나(공유 메모리), 자주 쓰는 데이터를 캐시해 느린 VRAM 접근을 줄인다. 최신 아키텍처는 L1과 공유 메모리를 하나의 통합 영역으로 구성한다. |
| **L2 캐시** | 모든 SM이 공유하는 칩 전체 캐시(수 MB~수십 MB). VRAM보다 훨씬 빠르게 데이터를 재사용하게 해 대역폭 부담과 지연을 줄인다. |
| **텐서 코어** | 작은 행렬(예: 4×4) 타일의 곱셈-누산을 한 번에 처리하는 전용 유닛. 딥러닝 학습·추론과 DLSS 같은 AI 화질 향상을 위해 FP16/BF16/FP8(신형은 FP4)·INT8 저정밀 연산을 셰이더 코어보다 수십 배 빠르게 수행한다. |
| **RT 코어 (레이 트레이싱 코어)** | 광선이 3D 장면의 물체(삼각형)와 어디서 만나는지 계산하는 전용 하드웨어. 가속 구조(BVH) 순회와 광선-삼각형 교차 판정을 담당해 사실적인 반사·그림자·전역 조명을 실시간으로 가능하게 한다. |
| **래스터라이저 (래스터 엔진)** | 삼각형(벡터 도형)을 화면 격자의 픽셀 조각(프래그먼트)으로 변환하는 고정 기능 하드웨어. 어떤 픽셀이 도형에 덮이는지 판정해 셰이딩할 대상을 만든다. |
| **텍스처 유닛 (TMU, 텍스처 매핑 유닛)** | VRAM에 저장된 이미지(텍스처)를 읽어 화면 픽셀에 입힌다. 확대·축소·기울기에 맞춰 여러 텍셀을 섞는 필터링(바이리니어·트라이리니어·이방성 등)으로 매끄러운 표면을 만든다. |
| **ROP (래스터 연산 유닛 / 렌더 출력 유닛)** | 셰이딩이 끝난 픽셀에 대해 깊이·스텐실 테스트, 색 블렌딩, 안티에일리어싱을 적용하고 최종 결과를 프레임버퍼에 기록한다. 물체 앞뒤 관계와 투명도를 올바르게 합성한다. |
| **메모리 컨트롤러** | VRAM(GDDR/HBM)과 GPU 코어 사이의 데이터 통로. 여러 개의 메모리 채널을 병렬로 관리해 초당 수백 GB~수 TB의 데이터를 코어에 공급한다. GPU 성능은 이 대역폭에 크게 좌우된다. |
| **VRAM (그래픽 메모리, GDDR6/6X/7 또는 HBM3/3e)** | 텍스처·정점·프레임버퍼·신경망 가중치 등 GPU가 다루는 대용량 데이터를 담는 전용 고속 메모리. 시스템 RAM보다 훨씬 넓은 대역폭에 최적화되어 있다. |
| **비디오 인코더/디코더 (NVENC / NVDEC 등)** | H.264·HEVC·AV1·VP9 같은 동영상 코덱을 하드웨어로 압축(인코딩)·복원(디코딩)하는 전용 블록. 셰이더 코어를 쓰지 않고 저전력으로 영상 스트리밍·녹화·화상회의를 처리한다. |
| **디스플레이 엔진** | 완성된 프레임버퍼를 읽어 모니터가 이해하는 신호(HDMI·DisplayPort)로 변환해 내보낸다. 재생 주파수, 다중 모니터, 가변 주사율, HDR 출력을 관리한다. |
| **PCIe ×16 인터페이스 (호스트 인터페이스)** | GPU 카드를 메인보드·CPU와 연결하는 통로. 16개 레인으로 명령과 데이터를 주고받는다. 게임 중에는 여유롭지만 대용량 데이터를 CPU↔GPU로 자주 옮기는 AI 작업에서는 병목이 되기도 한다. |
| **NVLink / 고속 인터커넥트** | 여러 GPU를 PCIe보다 훨씬 넓은 대역폭으로 직접 연결하는 데이터센터용 통로(예: NVLink, AMD Infinity Fabric). 거대한 AI 모델을 여러 GPU에 나눠 학습·추론할 때 GPU 간 데이터 공유 병목을 줄인다. |
| **전원부(VRM)·쿨러·팬** | 그래픽카드 기판에서 실제로 보이는 부분. VRM은 PCIe·보조 전원의 전기를 GPU가 쓰는 안정된 저전압·고전류로 변환하고, 방열판·히트파이프·팬은 수백 W의 발열을 식힌다. GPU 칩 자체가 아니라 '그래픽카드'를 구성하는 요소다. |
| **커맨드 프로세서 / 전역 스케줄러 (GigaThread 엔진·그리드 관리 유닛)** | PCIe로 들어온 명령 스트림(드로우 콜·컴퓨트 커널)을 해석하고, 렌더링·연산 작업을 워프·스레드 블록 단위로 잘게 나눠 유휴 SM들에 분배하는 칩 전면부(프론트엔드). 수백 개 SM을 항상 꽉 채워 돌리도록 작업을 조율하는 GPU의 '작업 지휘소'다. '작동 방식' 1~2단계에 등장하지만 주요 부품 표에는 빠져 있어, SM에 일감을 뿌리는 이 핵심 블록을 표에 명시할 필요가 있다. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **SIMT (Single Instruction, Multiple Threads / 단일 명령 다중 스레드)** | 하나의 명령을 여러 스레드(예: 32개)가 서로 다른 데이터에 동시에 적용하는 GPU의 실행 방식. CPU의 SIMD(단일 명령 다중 데이터)를 스레드 관점으로 확장한 개념으로, 수천 스레드를 효율적으로 굴리는 기반이다. |
| **워프(warp) / 웨이브프론트(wavefront)** | GPU가 한꺼번에 같은 명령으로 실행하는 스레드 묶음. NVIDIA는 32개를 '워프', AMD는 32 또는 64개를 '웨이브프론트'라 부른다(RDNA는 wave32/wave64 지원). 스케줄링·실행의 최소 단위다. |
| **스레드·블록·그리드** | GPU 컴퓨트 작업의 계층. 개별 계산 단위가 스레드, 스레드가 모인 것이 블록(하나의 SM에서 실행되며 공유 메모리로 협력), 블록이 모인 전체가 그리드다. 이 계층 덕에 문제를 잘게 나눠 병렬화한다. |
| **셰이더(shader)** | GPU에서 실행되는 작은 프로그램. 정점을 변환하는 정점 셰이더, 픽셀 색을 정하는 픽셀(프래그먼트) 셰이더, 범용 계산용 컴퓨트 셰이더, 지오메트리를 처리하는 메시 셰이더 등이 있다. 프로그래밍 가능한 코어에서 돌아간다. |
| **렌더링 파이프라인 (정점→래스터→픽셀)** | 3D 데이터가 화면 이미지로 바뀌는 정해진 처리 순서. 정점 처리 → 프리미티브 조립 → 래스터화 → 픽셀 셰이딩 → ROP 출력의 단계로 데이터가 흐른다. 최신 GPU는 앞단 지오메트리를 메시 셰이더로 대체하는 경로도 지원한다. |
| **래스터화(rasterization)** | 수학적 삼각형(벡터)을 화면의 픽셀 격자로 변환하는 과정. 어떤 픽셀이 도형에 덮이는지 판정해 색칠할 조각을 만든다. 현재 실시간 그래픽의 표준 방식이다. |
| **지연 은닉(latency hiding) / 처리량 지향** | 메모리 대기 시간을 다른 워프 실행으로 가려 코어를 쉬지 않게 하는 전략. CPU가 지연을 '줄이는'(큰 캐시·빠른 단일 스레드) 데 집중한다면 GPU는 지연을 '숨겨' 전체 처리량을 극대화한다. |
| **점유율(occupancy)** | SM이 동시에 유지하는 활성 워프 수가 하드웨어 최대치에 얼마나 가까운지를 나타내는 지표. 점유율이 높아야 지연 은닉이 성립한다. 스레드당 레지스터·공유 메모리 사용량이 많으면 상주 워프 수가 줄어 점유율이 떨어진다. |
| **메모리 병합 접근(coalescing)** | 한 워프의 스레드들이 서로 인접한 주소에 접근하면 GPU가 이를 소수의 큰 메모리 트랜잭션으로 묶어 처리하는 것. 접근이 흩어지면 트랜잭션이 늘어 실효 대역폭이 급락하므로, GPU 성능 최적화의 핵심 조건이다. |
| **텍스처 필터링** | 텍스처 이미지를 픽셀에 입힐 때 확대·축소·기울기에 맞춰 여러 텍셀을 섞어 매끄럽게 보이게 하는 기법. 바이리니어·트라이리니어·이방성 필터링 등이 있다. |
| **레이 트레이싱(ray tracing)** | 빛의 광선 경로를 추적해 반사·그림자·굴절을 물리적으로 계산하는 렌더링 방식. 사실감이 높지만 연산량이 커서 RT 코어의 하드웨어 가속으로 실시간화한다. |
| **VRAM & 메모리 대역폭** | VRAM은 GPU 전용 고속 메모리(용량, 예: 12~32GB)이고, 대역폭은 초당 옮길 수 있는 데이터량(예: 약 1TB/s)이다. 둘은 다른 지표이며, 그래픽·AI 성능은 대역폭에 특히 민감하다. |
| **프레임버퍼(framebuffer)** | 완성된 한 장의 화면 이미지를 담는 VRAM 영역. 디스플레이 엔진이 이곳을 읽어 모니터로 내보낸다. 화면 찢김을 막으려 보통 두 개 이상을 번갈아 쓴다(더블 버퍼링). |
| **드로우 콜(draw call)** | CPU가 GPU에게 '이 물체들을 이렇게 그려라'고 보내는 그리기 명령 한 건. 드로우 콜이 너무 많으면 CPU가 병목이 되므로 최적화에서 자주 언급된다. |
| **텐서 연산 / 행렬 곱-누산** | 행렬끼리 곱하고 더하는 연산으로, 딥러닝의 핵심 계산이다. 텐서 코어가 이를 저정밀도(FP16/FP8/FP4)로 대량 처리해 AI 추론·학습을 가속한다. |
| **GPGPU / 컴퓨트 API (CUDA·OpenCL·컴퓨트 셰이더)** | GPU를 그래픽이 아닌 범용 병렬 연산에 쓰는 것(GPGPU)과 이를 가능케 하는 프로그래밍 인터페이스. NVIDIA CUDA, 이식성 있는 OpenCL, 그래픽 API의 컴퓨트 셰이더 등이 있으며, 오늘날 AI·과학계산이 GPU에서 돌아가는 소프트웨어 토대다. |

| 텐서(AI) 연산 성능 | 저정밀(FP16/BF16/FP8/FP4) 소비자 수백 TFLOPS ~ 데이터센터 페타플롭급 | 희소성(sparsity) 가속 포함 시 수치가 더 커짐. Blackwell은 FP4 지원으로 추론 처리량이 크게 증가(B200 FP4 약 10~20 PFLOPS급). |

## ⚠️ 흔한 오해

- **오해** — GPU는 CPU보다 무조건 빠르다.
  <br>**교정** — GPU는 '같은 계산을 대량으로 병렬 처리'하는 처리량에서 압도적일 뿐이다. 분기·의존성이 많은 순차 로직이나 단일 작업의 반응 속도는 강력한 소수 코어를 가진 CPU가 더 빠르다. 둘은 역할이 다른 상호 보완 관계다.
- **오해** — 코어가 수천 개니 CPU 코어처럼 각자 독립적으로 다른 일을 한다.
  <br>**교정** — GPU 코어는 워프(예: 32개) 단위로 '같은 명령'을 함께 실행하는 SIMT 구조다. 한 워프 안 스레드들이 서로 다른 분기로 갈라지면(분기 발산) 각 경로를 순차 실행해 성능이 떨어진다. CPU 코어처럼 완전 독립적이지 않다.
- **오해** — VRAM 용량이 크면 무조건 빠르다.
  <br>**교정** — 용량(GB)은 '얼마나 담느냐', 대역폭(GB/s)은 '얼마나 빨리 옮기느냐'로 서로 다른 지표다. 대용량이라도 대역폭이 낮으면 느릴 수 있다. 실제 성능은 코어 수·대역폭·아키텍처가 함께 좌우한다.
- **오해** — 그래픽카드가 곧 GPU다.
  <br>**교정** — GPU는 연산을 수행하는 반도체 '칩'이고, 그래픽카드는 그 GPU에 VRAM·전원부(VRM)·쿨러·출력 포트·PCIe 기판을 붙인 '보드 전체'다. 노트북·스마트폰의 통합 GPU처럼 카드 없이 존재하기도 한다.
- **오해** — GPU는 게임·그래픽 전용 장치다.
  <br>**교정** — 같은 대량 병렬 구조가 딥러닝·과학계산·영상 처리에 이상적이라, 오늘날 GPU는 AI 학습/추론의 핵심 장치다. 일부 데이터센터 GPU는 아예 디스플레이 출력 포트가 없이 연산만 담당한다.
- **오해** — 클럭(GHz)이 높을수록 GPU 성능이 좋다.
  <br>**교정** — GPU 성능은 클럭보다 코어 수·메모리 대역폭·아키텍처 효율에 훨씬 크게 좌우된다. 그래서 CPU(수 GHz)보다 클럭이 낮아도 병렬 처리량은 수십 배 높을 수 있다.
- **오해** — 실시간 레이 트레이싱은 순수 소프트웨어 계산이다.
  <br>**교정** — 핵심인 광선-삼각형 교차 판정과 가속 구조(BVH) 순회를 RT 코어라는 전용 하드웨어가 처리한다. 이 하드웨어 가속이 있어야 사실적 반사·그림자가 실시간 프레임 안에 들어간다.

## 💡 비유

CPU가 복잡한 문제를 하나씩 깊게 푸는 소수의 박사라면, GPU는 단순 계산을 동시에 처리하는 수천 명의 학생 부대다. 화면의 수백만 픽셀을 각각 계산하는 일처럼 '똑같은 계산을 데이터만 바꿔 엄청나게 많이' 해야 할 때, 박사 몇 명보다 학생 수천 명이 압도적으로 빠르다. 또한 렌더링 파이프라인은 공장의 컨베이어 벨트에 비유할 수 있다. 원재료(정점)가 들어가 좌표 변환 → 삼각형 조립 → 잘게 쪼개기(래스터화) → 색칠(픽셀 셰이딩) → 검사·포장(ROP) 순서로 흘러가며 완성된 프레임이 나온다. 그리고 GPU의 '지연 은닉'은, 종업원이 한 테이블 주문을 주방에 넣고 음식이 나올 때까지 멍하니 기다리는 대신 그 사이 다른 테이블 주문을 받으러 가는 것과 같다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 게임 렌더링: GPU가 가장 주역으로 등장하는 장면. 정점 변환→래스터화→픽셀 셰이딩→ROP를 매 프레임 반복해 초당 수십~수백 장의 화면을 그리고, 필요하면 RT 코어로 반사·그림자를, 텐서 코어로 DLSS 화질 향상을 처리한다.
- 부팅: 전원을 켜면 GPU의 디스플레이 엔진이 프레임버퍼를 스캔아웃해 UEFI/BIOS 로고와 부팅 화면을 모니터로 내보낸다. OS가 뜬 뒤 데스크톱 화면 합성도 GPU가 담당한다.
- 영상 스트리밍: 유튜브·넷플릭스 재생 시 압축된 H.265/AV1 영상을 NVDEC(하드웨어 디코더)가 셰이더 코어를 거의 쓰지 않고 저전력으로 복원해 부드럽게 재생한다. 화상회의·게임 녹화 때는 NVENC로 인코딩한다.
- AI 질문(LLM 추론): 챗봇에게 질문하면 서버(또는 로컬) GPU의 텐서 코어가 거대한 신경망의 행렬 곱셈을 대량 병렬로 수행해 답을 생성한다. 이때 VRAM 용량·대역폭이 모델 크기와 속도를 좌우한다.
- 인터넷 검색·웹 브라우징: 브라우저가 페이지 합성·스크롤·애니메이션·동영상을 GPU 가속으로 처리해 매끄럽게 보여준다. CSS 애니메이션과 스크롤 렌더링이 GPU 합성 경로를 탄다.
- 파일 열기·데스크톱 UI: 창을 열고 아이콘·투명 효과·애니메이션을 그리는 화면 합성을 GPU가 담당한다. 대용량 이미지·영상 파일의 미리보기 렌더링도 GPU를 활용한다.
- Ctrl+S 저장: 저장 자체는 저장장치·CPU의 일이라 GPU 관여는 적지만, 저장 완료 알림·아이콘 변화 같은 화면 갱신은 여전히 GPU가 그려서 보여준다.
