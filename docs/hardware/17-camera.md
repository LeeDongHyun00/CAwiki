# 카메라·웹캠
*Camera / Webcam*

> 렌즈로 모은 빛을 CMOS 센서가 화소별 전하로 바꾸고, ISP가 이를 눈에 보이는 컬러 영상으로 가공한 뒤 압축·인코딩해 USB(UVC)로 컴퓨터에 흘려보내는 '빛→숫자' 변환 입력장치.

**분류**: 입출력

---

## 🧭 한마디로, 무슨 일을 하나
카메라·웹캠은 바깥세상의 빛(아날로그 광 신호)을 컴퓨터가 다룰 수 있는 디지털 픽셀 배열로 바꾸는 입력장치다. 키보드가 손가락의 움직임을, 마이크가 공기의 떨림을 디지털로 바꾸듯, 카메라는 장면에서 반사된 빛의 세기와 색을 초당 수십 장의 프레임으로 표본화한다. 특이한 점은 카메라 안에 이미 작은 컴퓨터(ISP·인코더)가 들어 있어, 센서가 뱉은 거친 원시 데이터를 스스로 보정하고 압축까지 마친 뒤 완성된 영상 스트림을 내보낸다는 것이다. 그래서 컴퓨터 본체는 대개 '가공·압축된 영상'을 받아, 호스트(CPU 또는 GPU의 하드웨어 디코더)가 압축을 풀어 앱에 넘긴다.

## ⚙️ 작동 방식

**1. ① 빛 모으기 — 렌즈·조리개·초점으로 상을 맺는다**

피사체에서 반사된 빛이 여러 장의 렌즈 요소를 통과하며 센서 평면에 또렷한 상으로 모인다. 조리개(f값)는 통과하는 빛의 양과 심도(초점이 맞는 깊이 범위)를 정하고, 초점은 렌즈-센서 거리를 맞춰 상을 선명하게 한다. 웹캠 대부분은 고정초점(주로 과초점 거리에 맞춤)이라 일정 거리 이상이 두루 선명하고, 자동초점(AF) 모델은 보이스코일 모터(VCM)가 렌즈를 미세하게 앞뒤로 밀어 대비가 최대가 되는 위치를 찾는다(대비검출 AF). 렌즈와 센서 사이의 적외선 차단 필터(IR-cut)가 실리콘이 민감한 근적외선을 걸러 사람 눈이 보는 색과 맞춘다.

**2. ② 광 → 전하 — 화소마다 빛을 전자로 바꿔 쌓는다(노출)**

화소마다 맨 위에 얹힌 마이크로렌즈가 빗겨 드는 빛까지 화소의 수광부로 모으고, 그 바로 아래의 베이어 컬러필터가 화소마다 빨강·초록·파랑 중 한 색만 통과시킨다(빛의 경로: 마이크로렌즈→컬러필터→포토다이오드). 실리콘 포토다이오드가 광자를 흡수하면 내부 광전효과로 전자-정공 쌍이 생겨, 노출시간(적분시간) 동안 화소의 전위 우물에 전하가 빛의 세기에 비례해 쌓인다. 너무 밝으면 우물이 넘쳐 포화(하이라이트 날림)되고, 넘친 전하가 옆 화소로 번지면 블루밍(번짐)이 나타난다.

**3. ③ 전하 → 전압 → 디지털 — 행 단위로 읽어 ADC로 수치화한다**

CMOS 센서는 화소마다 소형 회로(액티브 픽셀 센서)를 두고 행(row)을 한 줄씩 순차로 읽는다. 전송 트랜지스터가 쌓인 전하를 부동확산(FD) 노드로 옮기면 그곳에서 전하가 전압으로 바뀌고, 소스 팔로워가 그 전압을 버퍼링해 열 라인으로 내보낸다. 상관 이중 샘플링(CDS)이 리셋 직후 전압과 신호 전압의 차를 취해 리셋(kTC) 잡음과 화소별 오프셋을 없앤 뒤, 열마다 놓인 ADC가 아날로그 전압을 대략 10~12비트 디지털 값으로 변환한다. 결과는 아직 색이 섞이지 않은 원시 베이어(RAW) 데이터다. 행을 위에서 아래로 순차로 훑는 이 방식이 롤링셔터이며, 빠른 움직임을 기울어지게 만드는 원인이다.

**4. ④ RAW → 컬러 — ISP가 결함을 다듬고 디모자이킹한다**

센서가 MIPI CSI-2 같은 고속 직렬 링크로 내보낸 RAW를 이미지 신호처리기(ISP)가 받아, 먼저 검은색 기준 보정(블랙레벨), 렌즈 주변부 어두워짐 보정(렌즈 셰이딩), 죽은 화소 보정을 한다. 그다음 핵심 단계인 디모자이킹으로, 각 화소가 한 색만 가진 베이어 모자이크를 이웃 화소들로 보간해 모든 화소가 RGB 세 값을 다 갖도록 복원한다. 이 시점에 비로소 '한 장의 컬러 이미지'가 된다.

**5. ⑤ 색·밝기 다듬기 — 화이트밸런스·감마·노이즈 제거·HDR**

ISP가 화이트밸런스(AWB)로 조명 색온도에 따라 틀어진 색을 중립으로 되돌리고, 색보정행렬(CCM)로 센서 색을 표준 색공간(sRGB 등)에 맞춘다. 감마(또는 톤 커브) 보정으로 사람 눈의 밝기 인지와 디스플레이 특성에 맞게 계조를 재분배하고, 노이즈 제거·샤프닝으로 화질을 정리한다. HDR 모드에서는 노출을 달리한 정보(다중 노출 또는 화소 단위 노출차)를 합쳐 밝은 곳·어두운 곳을 함께 담아 명암 대비 범위를 넓힌다.

**6. ⑥ 3A 되먹임 — 자동노출·자동초점·자동화밸을 계속 조정한다**

ISP의 통계 엔진이 프레임의 밝기 히스토그램·대비·색 분포를 측정해, 다음 프레임을 위해 노출시간과 게인(자동노출 AE), 렌즈 초점 위치(자동초점 AF), 화이트밸런스 계수(AWB)를 되먹임(폐루프)으로 갱신한다. 방이 어두워지면 노출시간을 늘리고 아날로그·디지털 게인을 올리며(대신 노이즈 증가), 아주 어두우면 프레임레이트를 낮춰 노출을 더 확보하기도 한다. 피사체가 움직이면 초점을 다시 잡는 것이 이 폐루프의 일이다.

**7. ⑦ 색공간 변환 + 압축 — USB에 실을 수 있게 인코딩한다**

완성된 RGB 프레임을 밝기(Y)와 두 색차(U·V, =Cb·Cr)로 나눈 YUV(YCbCr) 4:2:0로 바꾼다. 색차를 가로·세로 각각 절반씩 솎아내(색 해상도는 원본의 1/4) 화소당 평균 데이터를 24비트에서 12비트로, 즉 전체를 약 절반으로 줄인다(사람 눈은 색 해상도보다 밝기에 민감해 잘 안 보인다). 비압축 1080p30은 이래도 약 93 MB/s(≈746 Mbps)라 USB 2.0(480 Mbps)에 담기지 않으므로 카메라 내부 인코더가 더 압축한다. MJPEG은 프레임마다 독립적으로 JPEG 압축(단순·저지연), H.264/H.265는 프레임 간 움직임까지 예측해 훨씬 작게 압축한다.

**8. ⑧ USB 전송 — UVC 규격으로 호스트에 흘려보낸다**

인코딩된 프레임을 USB 비디오 클래스(UVC) 규격의 패킷으로 쪼개 호스트로 보낸다. UVC는 지연이 일정한 아이소크로너스 전송과, 남는 대역을 몰아 쓰는 벌크(bulk) 전송을 모두 지원하며 웹캠은 둘 중 하나로 압축 스트림을 실어 보낸다. UVC 표준 덕분에 별도 드라이버 없이 OS가 인식한다. 호스트(CPU 또는 GPU 하드웨어 디코더)가 스트림을 받아 압축을 풀면 앱(화상회의·녹화·비전 AI)이 프레임을 얻는다. 이 전 과정이 프레임레이트의 박자로 반복되며, 30fps면 약 33ms마다 한 장씩 도착한다.

## 🧩 주요 부품

| 부품 | 하는 일 |
|---|---|
| **렌즈 경통(다중 렌즈 요소)** | 여러 장의 플라스틱·유리 렌즈를 겹쳐 빛을 센서 평면에 또렷이 모은다. 매수(3P·5P 등)와 재질이 선명도·왜곡·화각을 좌우한다. |
| **조리개(Aperture/Iris)** | 빛이 통과하는 구멍 크기(f값)로 들어오는 광량과 심도를 정한다. 웹캠은 대개 고정 조리개(f/2.0 안팎)라 조절 날개가 없고, 밝기는 노출시간·게인으로 제어한다. |
| **IR 컷 필터(적외선 차단 필터)** | 실리콘 센서가 민감한 근적외선을 걸러내, 사람 눈이 보는 색과 맞도록 정상화한다. (야간·얼굴인식용 IR 카메라는 반대로 이 필터 대신 IR 통과 필터를 쓴다.) |
| **초점 액추에이터(VCM 보이스코일 모터)** | 자동초점 모델에서 전류로 렌즈를 미세하게 앞뒤로 움직여 초점을 맞춘다. 고정초점 웹캠에는 없다. |
| **CMOS 이미지 센서 다이** | 수백만 개의 포토다이오드 화소가 격자로 박힌 반도체 칩. 빛을 전하로 바꾸는 심장부이며, 화소·증폭기·읽기회로·컬럼 ADC가 한 칩에 집적된다. |
| **마이크로렌즈 어레이** | 각 화소 맨 위에 얹힌 아주 작은 렌즈로, 빗겨 오는 빛까지 화소 중앙의 광 감지부로 모아 감도(집광 효율)를 높인다. |
| **베이어 컬러필터 어레이(CFA)** | 마이크로렌즈 바로 아래에서 화소마다 R·G·B 중 한 색만 통과시키는 색 필터. 초록을 빨강·파랑의 두 배로 배치(RGGB)해 사람 눈이 밝기에 예민한 초록 정보를 더 촘촘히 받는다. |
| **화소 읽기회로(액티브 픽셀 센서)** | 화소마다 놓인 전송·리셋 트랜지스터와 소스 팔로워가, 부동확산(FD) 노드에서 전하를 전압으로 바꿔 행 단위로 읽어낸다. 상관 이중 샘플링(CDS)으로 리셋 잡음을 줄인다. |
| **컬럼 ADC(아날로그-디지털 변환기)** | 센서 열마다 병렬로 놓여, 화소 전압을 대략 10~12비트 디지털 값으로 바꾼다. 열 병렬 구조가 빠른 프레임레이트를 가능케 한다. |
| **센서-ISP 인터페이스(MIPI CSI-2 등)** | 센서가 만든 RAW 픽셀 스트림을 ISP/브리지 칩으로 나르는 고속 직렬 링크. 여러 데이터 레인으로 초당 수 Gbps를 전송한다. |
| **ISP(이미지 신호처리기)** | RAW 데이터를 디모자이킹·노이즈 제거·화이트밸런스·감마·HDR로 가공하고, 자동노출·초점·화밸(3A)을 제어하는 카메라 속 전용 프로세서. 흔히 인코더·USB와 함께 한 SoC에 통합된다. |
| **하드웨어 영상 인코더** | 완성된 프레임을 MJPEG 또는 H.264/H.265로 압축해 USB 대역폭 안에 들어가게 만든다. 전용 회로라 실시간으로 처리하며, 보통 브리지 SoC 안에 통합돼 있다. |
| **USB 브리지 컨트롤러(MCU, UVC)** | 압축 스트림을 USB 비디오 클래스(UVC) 패킷으로 만들어 호스트로 전송하고, 노출·해상도 등 제어 명령을 받아 센서·ISP에 전달하는 지휘부. |
| **보조 요소(PCB·IR LED·마이크·상태 LED)** | 모든 칩을 얹은 기판, 얼굴인식·야간용 적외선 조명, 함께 내장된 마이크(오디오 ADC), 촬영 중임을 알리는 표시(테일리)등 등. |

## 📚 핵심 개념

| 용어 | 설명 |
|---|---|
| **CMOS 이미지 센서 (Complementary Metal-Oxide-Semiconductor)** | 화소마다 자체 증폭 회로를 둔 반도체 광센서. 저전력·고속·저가라 웹캠·스마트폰의 표준. 과거의 CCD 센서를 대체했다. |
| **포토다이오드 / 광전효과** | 빛(광자)을 흡수하면 전자-정공 쌍을 만들어 전하를 발생시키는 소자. 카메라가 빛의 세기를 전기로 바꾸는 근본 원리다. |
| **베이어 필터 / 컬러필터 어레이(CFA)** | 각 화소에 R·G·B 중 한 색만 씌우는 격자 패턴(보통 RGGB). 화소는 원래 색을 구분 못 하고 밝기만 재는데, 이 필터로 색을 나눠 담는다. |
| **디모자이킹(Demosaicing)** | 한 색만 가진 베이어 모자이크를 이웃 화소로 보간해, 모든 화소가 RGB 세 값을 다 갖도록 컬러 이미지를 복원하는 연산. |
| **롤링셔터 / 글로벌셔터** | 롤링셔터는 행을 순차로 노출·읽어 빠른 물체가 기울어져 보이는(젤로 현상) CMOS의 기본 방식. 글로벌셔터는 전 화소를 동시에 노출하지만 회로가 커져 비싸다. |
| **ISP(Image Signal Processor)** | 센서의 거친 RAW를 사람이 볼 만한 영상으로 바꾸는 전용 프로세서. 디모자이킹·노이즈 제거·색·감마·HDR·3A를 담당한다. |
| **MIPI CSI-2** | 이미지 센서를 프로세서/ISP에 잇는 표준 직렬 인터페이스. 여러 레인으로 RAW 픽셀을 고속 전송하는, 센서 쪽의 사실상 표준 배선 규격. |
| **ADC(Analog-to-Digital Converter)** | 화소가 만든 아날로그 전압을 디지털 숫자로 바꾸는 변환기. 비트 수(대략 10~12비트)가 밝기 계조의 세밀함을 정한다. |
| **게인 / ISO** | 어두울 때 신호를 전기적으로 증폭하는 정도. 아날로그 게인(읽기 전 증폭)과 디지털 게인(수치 곱)이 있으며, 올릴수록 밝아지지만 노이즈도 함께 커진다. |
| **3A (AE·AF·AWB)** | 자동노출(Auto Exposure)·자동초점(Auto Focus)·자동화이트밸런스(Auto White Balance). 환경 변화에 맞춰 밝기·초점·색을 실시간으로 잡아주는 되먹임 제어. |
| **화이트밸런스 / 색온도** | 백열등(붉음)·형광등·낮빛(푸름)처럼 조명 색이 달라도 흰색이 흰색으로 보이게 색을 되돌리는 보정. 색온도는 켈빈(K)으로 표기. |
| **감마 보정(Gamma)** | 빛의 선형 값을 사람 눈의 밝기 인지와 디스플레이 특성에 맞게 비선형으로 재분배하는 단계. 어두운 쪽 계조를 더 촘촘히 배분한다. |
| **다이내믹 레인지 / HDR** | 한 장면에서 가장 밝은 곳과 어두운 곳의 밝기 폭. HDR은 노출을 달리한 정보를 합쳐 역광에서도 밝음·어둠을 함께 담는 기법. |
| **UVC (USB Video Class)** | USB 카메라 표준 규격. 이 규격을 따르면 제조사 드라이버 없이 OS가 웹캠을 바로 인식한다. 전송은 아이소크로너스 또는 벌크 방식을 쓴다. |
| **MJPEG / H.264 / H.265** | 영상 압축 방식. MJPEG은 프레임마다 독립 JPEG(단순·저지연). H.264·H.265(HEVC)는 프레임 간 움직임까지 예측해 훨씬 작게 압축한다. |
| **YUV 4:2:0 / 크로마 서브샘플링** | 영상을 밝기(Y)와 두 색차(U·V=Cb·Cr)로 나누고, 색차를 가로·세로 각각 절반(전체적으로 1/4 해상도)으로 줄이는 방식. 4:4:4(24비트/화소) 대비 4:2:0은 12비트/화소로 데이터가 절반. 사람 눈이 색보다 밝기에 예민한 점을 이용한다. |
| **BSI (Back-Side Illumination, 후면조사)** | 배선층을 화소 뒤로 옮겨 빛을 가리지 않게 한 센서 구조. 집광 효율이 높아 저조도 성능이 좋아 요즘 소형 센서의 주류(고급은 배선·화소를 위아래로 쌓은 스택형 BSI). |
| **화소 비닝(Pixel Binning)** | 이웃한 여러 화소를 하나로 묶어 읽어 감도를 높이는 기법. 해상도를 낮추는 대신 저조도 노이즈를 줄인다. 4-in-1(쿼드베이어) 등이 흔하다. |
| **광학 포맷 / 센서 크기** | 센서 대각선 크기의 관례적 표기(예 1/2.8"). 클수록 화소당 빛을 많이 받아 저조도·계조에 유리하다. 화소 크기·화소 수와 함께 화질을 좌우한다. |
| **프레임레이트 / 노출시간** | 초당 프레임 수(fps). 한 프레임의 노출시간은 프레임 간격(≈1/fps)을 넘을 수 없어 프레임레이트↑는 밝기와 상충한다(어두우면 카메라가 fps를 낮춰 노출을 늘리기도 한다). |

## 📊 대표 사양·수치 감각

| 항목 | 값 | 비고 |

| 센서 광학 포맷 | 웹캠 대략 1/4"~1/2.8" (대각 약 4~6mm) | 작을수록 저렴·소형이나 저조도 불리 — 화소 크기·감도와 직결 |
| 화소 크기(픽셀 피치) | 대략 1.0~3.0 µm | 클수록 화소당 받는 빛이 많아 저조도 노이즈에 유리 |
| 조리개(f값) | 웹캠 일반 f/2.0~f/2.8 (고정) | f값이 작을수록 밝은 렌즈. 조절 날개 없는 고정식이 대부분 |
| ADC 해상도 | 화소당 대략 10~12비트 | 최종 출력은 보통 채널당 8비트(24비트 RGB)로 정리 |

| 최대 노출시간 | 30fps에서 최대 약 33ms(1/30초) | 프레임 간격을 넘길 수 없음 — 어두우면 게인으로 보완하거나 fps를 낮춤 |
| 화각(FOV) | 웹캠 대략 대각 60~90° | 넓을수록 배경이 많이 담기고 주변부 왜곡↑ |

| 양자효율(QE) 피크 | BSI 센서 대략 60~90% | 흡수한 광자를 전자로 바꾸는 비율 — 높을수록 저조도 유리 |
| 엔드투엔드 지연 | 캡처~인코딩~전송 대략 수십~100+ ms | 화상통화 입 모양-소리 어긋남(립싱크) 체감의 원인 |

## ⚠️ 흔한 오해

- **오해** — 화소 수(메가픽셀)가 많을수록 무조건 화질이 좋다.
  <br>**교정** — 화질은 화소 수만이 아니라 센서 크기·화소 크기·렌즈 품질·ISP가 함께 정한다. 작은 센서에 화소만 욱여넣으면 화소당 빛이 줄어 오히려 노이즈가 늘고 저조도가 나빠진다.
- **오해** — 카메라의 각 화소가 색(RGB)을 직접 다 잡아낸다.
  <br>**교정** — 베이어 방식 화소 자체는 색을 구분 못 하고 밝기만 잰다. 베이어 필터로 화소마다 한 색만 받은 뒤, 디모자이킹으로 나머지 두 색을 이웃에서 추정해 복원한다.
- **오해** — 웹캠은 촬영한 원본(RAW) 영상을 그대로 컴퓨터로 보낸다.
  <br>**교정** — 비압축 원본은 USB 2.0 대역을 훌쩍 넘어, 대개 카메라 안에서 ISP 가공 + MJPEG/H.264 압축을 마친 스트림을 보낸다. USB 3.x 웹캠은 무압축 YUV를 보내기도 하지만 그것도 이미 ISP가 가공한 영상이지 디모자이킹 전 RAW 베이어가 아니다. 컴퓨터가 센서 RAW를 직접 받는 일은 웹캠에선 거의 없다.
- **오해** — 영상이 기울거나 흔들려 보이는 롤링셔터는 소프트웨어 버그다.
  <br>**교정** — CMOS 센서가 화소를 행 단위로 순차 노출·읽기 때문에 생기는 물리적 현상이다. 프레임 안에서도 위·아래 줄의 촬영 시각이 달라, 빠른 움직임이 기울어져 찍힌다.
- **오해** — 카메라 안에서 물리 셔터가 찰칵 열리고 닫힌다.
  <br>**교정** — 웹캠과 대부분의 CMOS는 물리 셔터가 없다. 노출은 화소의 전하 적분 시간을 회로로 제어하는 전자셔터로 이뤄진다. (렌즈 앞 슬라이드 커버는 사생활용 물리 가리개일 뿐이다.)
- **오해** — 프레임레이트만 높이면 언제나 영상이 좋아진다.
  <br>**교정** — fps를 올리면 프레임당 노출시간이 짧아져 어두워진다. 어두운 환경에선 게인을 올려 노이즈가 늘거나 밝기가 떨어지므로 조명·해상도와 균형이 필요하다.
- **오해** — 웹캠 소프트웨어의 '줌'은 광학 줌처럼 화질 손실이 없다.
  <br>**교정** — 웹캠 줌은 대개 디지털 줌으로, 화면 일부를 잘라 확대(업스케일)하는 것이라 화질이 떨어진다. 렌즈가 실제로 배율을 바꾸는 광학 줌과 다르다.
- **오해** — Windows Hello 같은 얼굴인식은 그냥 웹캠에서 IR 차단 필터만 뺀 것이다.
  <br>**교정** — 보통은 전용 IR 센서에 IR 조명(플러드/구조광)을 더한 별도 모듈을 쓴다. 단순히 IR-cut을 뺀 컬러 카메라가 아니라, 근적외선에 최적화한 카메라로 위조 방지·저조도 인증을 한다.

## 💡 비유

사람의 눈에 그대로 대응한다. 렌즈=수정체, 조리개=홍채(밝으면 좁아지고 어두우면 넓어짐 — 단 웹캠은 조리개가 고정이라 홍채 대신 노출시간·게인으로 밝기를 맞춘다), CMOS 센서=망막, 그리고 ISP는 망막 신호를 '이게 무슨 색·밝기다'로 해석하는 뇌의 시각피질에 해당한다. // 베이어 필터와 디모자이킹은 이렇게 볼 수 있다 — 관객 넷 중 하나는 빨강, 둘은 초록, 하나는 파랑 셀로판을 낀 채 각자 한 색만 보고, 끝나고 서로 본 것을 나눠 전체 색을 재구성하는 것. // 롤링셔터는 위에서 아래로 커튼을 훑으며 찍는 스캐너와 같아서, 그 훑는 사이에 빠르게 지나간 물체는 비스듬히 늘어져 기록된다.

## 🔗 CAwiki 시나리오에서 만나는 곳

- 화상통화(시나리오 №10): 웹캠 렌즈→CMOS 센서→ISP→인코더(H.264/MJPEG)→UVC USB 전송으로 내 얼굴이 디지털 프레임이 되고, NIC를 통해 상대에게 전송된다. 카메라가 이 시나리오의 출발점 하드웨어다.
- 부팅·로그인(시나리오 №01): Windows Hello 같은 얼굴 인식 로그인에서 전용 적외선(IR) 카메라가 IR 조명으로 얼굴을 비춰 패턴(과 일부 기종은 깊이)을 캡처해 인증에 쓴다. 컬러 웹캠과 별개의 IR 카메라가 등장하는 장면.
- AI에게 질문할 때(시나리오 №14): 사진·실시간 영상을 비전 AI에 입력할 때, 카메라가 만든 압축 프레임을 CPU가 풀어 GPU·NPU의 신경망에 먹인다. 멀티모달 입력의 첫 관문.
- 영상 스트리밍(시나리오 №09): 방송·라이브 스트리머 쪽에서 웹캠이 캡처·인코딩한 영상이 송출 파이프라인으로 들어간다(수신자 관점의 디코딩과 짝을 이루는 촬영 측).
- Ctrl+S 저장(시나리오 №07): 캡처한 사진·녹화 영상을 파일로 저장할 때, 카메라가 이미 압축해 만든 스트림이 RAM 버퍼를 거쳐 SSD의 NAND에 기록된다.
- 화면 녹화·화상 캡처: QR코드·바코드 스캔, 문서 스캔 앱처럼 카메라 프레임을 실시간 분석하는 장면에서도 이 하드웨어가 입력원으로 등장한다.
