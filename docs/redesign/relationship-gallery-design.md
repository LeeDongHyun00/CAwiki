# 하나의 방으로 이어지는 관계지도

2026-10-08 · 디자인 및 인터랙션 시안

[공개 시안](https://leedonghyun00.github.io/CAwiki/relationship-room-study.html) · [참고 사이트](https://cactusdigitale.com/?ref=siteinspire)

이 시안은 기존 관계지도와 별도 주소에서 동작한다. 실제 하드웨어 모델 23개, 기존 6개 주제, 기존 부품 설명과 124개 관계 데이터를 사용한다. 이번에 운영 사이트에 적용하는 변경은 필름과 목록 이미지의 일치이며, 관계지도는 공간·배치·전환을 검토할 수 있도록 별도 제작했다.

## 공간

Cactus 레퍼런스의 정면·좌우 벽을 함께 바라보는 방 구조를 따른다. 이전 분석과 실제 화면 캡처는 `reference-audit.md`, `references/room-reference-home.png`, `references/room-reference-pointer.png`에 있다.

- 정면 벽 3열 × 3행에 9개, 좌우 벽에 각각 7개, 총 23개를 전시한다
- 정렬은 격자를 따르지만 격자선, 카드 테두리, 배경 연결선은 그리지 않는다
- 부품은 벽에서 조금 떠 있으며 실제 원근 투영과 금속 반사로 깊이를 드러낸다
- 좌우 벽의 가까운 부품이 커지는 원근 효과를 고려해 크기를 조정한다
- 정면 벽 아래에는 `관계지도` 또는 선택한 주제명만 놓는다
- 전시 화면에는 하드웨어 이름과 제목만 표시한다
- 아이보리 벽, 짙은 회색 글자, 선택 상태의 절제된 올리브색을 사용한다

처음부터 주제별로 군집을 만들지 않는다. 실루엣과 높이, 간격으로 균형을 잡고, 주제를 선택했을 때 관계에 따른 새로운 배치가 드러나게 한다.

## 하단의 순환 메뉴

`명령과 메모리 · 화면과 그래픽 · 저장과 실행 · 입력과 출력 · 네트워크 · 전원과 냉각` 여섯 제목이 가로로 이어진다. 가운데는 선명하고 양옆은 조금 작아지며 아래로 내려가는 얕은 호를 만든다. 마지막 다음에는 첫 제목이 다시 나타난다.

드래그는 제목을 탐색하는 동작이고 클릭은 관계를 선택하는 동작이다. 드래그를 놓는 것만으로 부품 구성을 바꾸지 않는다. 약 7px 이상 움직이면 클릭으로 처리하지 않으며 손을 놓으면 가장 가까운 제목 위치로 부드럽게 정렬한다. 제목 DOM은 여섯 개만 유지해 키보드와 보조기기에 중복 항목을 노출하지 않는다.

현재 선택한 제목을 다시 누르거나 Escape를 누르면 전체 방으로 돌아온다. 별도의 `전체보기` 버튼을 늘리지 않는다.

## 전환 흐름

| 조작 | 공간의 변화 | 유지하는 것 |
| --- | --- | --- |
| 제목 드래그 | 메뉴가 연속 순환 | 현재 전시와 선택 상태 |
| 주제 선택 | 관련 없는 부품은 먼저 흐려지고 사라짐, 관련 부품은 중앙으로 이동 | 같은 모델, 재질, 회전 방향 |
| 다른 주제 선택 | 두 주제에 공통으로 있는 부품은 현재 위치에서 새 위치로 연결 | 중간 프레임과 공간 연속성 |
| 부품 호버·포커스 | 부품이 시선 방향으로 조금 가까워짐 | 기본 배치와 카메라 |
| 부품 클릭 | 선택한 모델이 확대되어 설명 화면의 왼쪽에 도착 | 같은 모델 인스턴스 |
| X / Escape | 설명을 닫고 선택한 주제의 배치로 복귀 | 주제, 메뉴 위치, 부품 포커스 |
| 선택 주제 다시 클릭 | 23개가 각자의 원래 벽 위치로 돌아감 | 최초 공간의 기억 |

모델의 위치·크기는 약 1.1초 동안 5차 easing으로 연결한다. 비선택 모델의 사라짐은 이동 초반 약 440ms 안에 끝낸다. 설명은 모델 이동 후 약 450ms에 걸쳐 나타난다. 회전 쇼나 불필요한 분해 장면은 넣지 않는다. 빠르게 연속 선택해도 현재 프레임에서 새 목적지로 이어진다.

반투명 메시에 의한 내부 부품 노출을 피하기 위해 모델을 먼저 불투명하게 렌더한 뒤 렌더 결과의 투명도를 합성한다. 호버와 화면 전환은 별도 상태로 관리해 X를 누른 뒤 이전 호버 크기가 남지 않게 한다. 움직임이 끝나면 렌더 루프를 멈춘다.

## 중앙 배치와 연결 관계

선택한 주제의 중심 부품은 약간 크게, 나머지 4~6개는 주변에 서로 겹치지 않게 모인다. 긴 설명이나 방 전체를 가로지르는 선 없이도 ‘함께 작동하는 부품’의 범위를 읽을 수 있게 한다.

정확한 관계는 부품을 열어 `역할 / 내부 구성 / 연결 관계`에서 확인한다. 기존 노드·양방향 관계 설명을 사용하며, 연결 관계의 다른 부품을 선택하면 해당 부품 설명으로 이어진다. 내부 구성은 기능 설명 목록이며 실제 물리 배치라고 표현하지 않는다. 운영 통합 시에는 기존 `#map/node/:id?from=:group` 경로와 관계 상세 링크를 유지한다. 시안에서는 동일한 데이터로 설명 전환까지 확인할 수 있다.

## 작은 화면과 접근성

좁은 화면에서 23개를 한꺼번에 작게 압축하지 않는다. 전시 공간의 크기를 유지하고 좌우 벽을 읽기 쉬운 세 개의 전시 구획으로 펼친다. 좌우 드래그로 각 구획을 이동해 본다. 원근이 깊은 벽을 그대로 좁은 화면에 압축해 서로 겹치게 하지 않는다. 키보드로 화면 밖 부품에 포커스하면 해당 벽으로 카메라가 이동한다. 주제를 선택하면 5~7개가 화면 안의 세로 배치로 모인다. 설명 화면에서는 모델을 위쪽, 내용을 아래쪽에 놓는다.

메뉴는 좌우 방향키로 이동하고 Enter로 선택한다. 숨겨진 부품은 클릭·Tab 대상에서 제외한다. 설명을 닫으면 원래 부품에 포커스가 돌아간다. `prefers-reduced-motion`에서는 이동을 생략하고 상태를 바로 표시한다. WebGL을 사용할 수 없으면 같은 모델 이미지와 부품 설명을 제공한다.

## 필름 → 목록 이미지 일치

`hardware-portraits.js`가 목록의 3D 도착 자세와 정지 이미지의 모델·카메라·조명·프레이밍을 함께 정의한다. CPU/GPU뿐 아니라 필름에 등장하는 12개 부품은 실제 필름 모델에서 렌더한다. 특히 예전에 다른 모델을 사용했던 메인보드와 쿨러를 필름 모델로 교체했다. 나머지 11개도 같은 촬영 설정으로 렌더했다.

분해 중에 목록으로 나가도 복제 모델의 내부 그룹이 원래 조립 자세로 연결된다. 필름 원본은 수정하지 않는다. 도착한 모델 아래에 동일한 이미지를 먼저 놓은 다음 캔버스를 걷어내어 두 반투명 레이어 때문에 중간 밝기가 흐려지는 현상도 방지한다.
