# 관계지도 — 목록에서 이어지는 다섯 면의 방

2026-10-08 · 수정 디자인 및 인터랙션 시안

[목록부터 시작하는 공개 시안](https://leedonghyun00.github.io/CAwiki/relationship-room-study.html#wiki) · [방 바로 보기](https://leedonghyun00.github.io/CAwiki/relationship-room-study.html#all) · [참고 사이트](https://cactusdigitale.com/?ref=siteinspire)

메인 사이트의 `index.html#map`에 이 관계지도를 적용한다. 독립 시안 주소도 같은 구현을 공유한다. 하드웨어 목록의 23개 이미지와 실제 3D 모델, 16개 시나리오 표지, 6개 관계 주제, 기존 부품 설명 및 124개 관계 데이터를 사용한다. 기존 `#map/group/...`, `#map/node/...` 주소는 새 공간과 상세 설명으로 연결하며 관계 시나리오 경로는 유지한다.

## 레퍼런스 재확인

Cactus의 홈을 1440×960 Chromium에서 열고 포인터를 중앙·왼쪽·오른쪽·위·아래로 이동하며 확인했다. HTTPS 인증서 검증을 유지했고 소프트웨어 WebGL을 사용했다. 실제 휴대전화 성능을 측정한 결과는 아니다.

캡처: `references/room-v2-reference-right.png`, `room-v2-reference-ceiling.png`, `room-v2-reference-floor.png`

공개 브라우저 코드의 `BackgroundScene`에서도 다음 구조를 확인했다.

- 원근 카메라의 화각은 70°, 기준 Z 위치는 13.5
- 정면·왼쪽·오른쪽·천장·바닥의 다섯 전시 면
- 좌우 면은 Y축 ±90°, 천장과 바닥은 X축 ±90°를 기준으로 꺾임
- 포인터에 카메라의 X/Y 회전이 반응하고, 가까운 면의 콘텐츠는 가장자리에서 크게 잘려 보임
- 개별 전시물의 크기와 빈 공간이 달라 일정한 카드 목록으로 읽히지 않음
- 흰색 가장자리 페이드, 면을 따라 달라지는 콘텐츠 방향이 깊이를 만듦

이를 바탕으로 시안의 카메라·벽 방향·분포를 바꿨다. 참고 사이트의 이미지나 스크립트 자체를 서비스 자산으로 사용하지 않는다.

## 목록에서 오른쪽 공간으로

시안 첫 화면은 실제 Wiki와 같은 하드웨어 목록이다. 시나리오 탭에서도 진입을 확인할 수 있다.

1. 관계지도를 누르면 현재 목록이 하드웨어이면 그대로 유지한다
2. 시나리오 탭이라면 하드웨어 탭을 먼저 표시한다
3. 각 이미지의 현재 화면 좌표에서 같은 3D 모델이 이어받는다
4. 부품이 오른쪽으로 이동하고, 카메라도 오른쪽 공간으로 이동하며 화각이 넓어진다
5. 모델이 벽의 지정 위치에 도착한 뒤 방 제목과 원형 메뉴가 나타난다

약 2.2초 동안 카메라 X가 -46에서 0으로 이동한다. 출발할 때는 멀리 있는 좁은 화각으로 목록 이미지를 이어받고, 끝에서는 70°의 실내 원근으로 바뀐다. 부품의 위치 변화가 먼저 시작되고 카메라가 약간 뒤따른다. 원래 목록의 스크롤 위치도 출발 좌표에 반영한다.

모델의 셰이더와 텍스처는 목록을 보는 동안 준비해 최초 업로드가 진입 애니메이션을 끊지 않게 한다. 중간에 Tab·크기 변경·모션 감소가 발생하면 완성된 방으로 정리하고, Escape는 목록으로 돌아간다. 방의 X로 나가면 약 2.3초 동안 반대 방향으로 이어진다. 현재 카메라의 방향과 부품 위치·투명도에서 시작해 왼쪽의 목록으로 돌아온다. 주제를 선택했거나 시점을 돌렸어도 벽의 기본 배치로 순간 이동하지 않는다. 숨겨진 부품도 이동 중 다시 나타난다. 부품은 출발할 때 저장한 스크롤 위치에 있는 각 썸네일 자리로 도착한 후 이미지와 짧게 겹쳐 전환된다. 목록 제목과 메뉴도 함께 드러난다.

복귀 중에는 실수로 부품이나 메뉴를 누르지 않도록 입력을 잠근다. Escape·Tab·화면 크기 변경·모션 감소·WebGL 컨텍스트 손실이 발생하면 목록으로 전환을 완료하고 입력과 포커스를 복구한다. 모바일의 진입 카메라 종점도 실제 방의 화각과 위치에 맞춰 마지막 프레임의 시점 변화를 없앴다.

## 실제 전시 공간

- 다섯 면에 고정된 원래 위치를 둔다: 정면 9개, 좌우 각각 4개, 천장과 바닥 각각 3개
- 각 모델의 크기·높이·간격·기울기를 달리한다
- 좌우 벽의 모델은 벽 방향에 맞춰 돌고, 천장과 바닥의 모델은 그 면에 놓인 상태로 보인다
- 가까운 부품은 크게, 뒤쪽 부품은 작게 보인다. 주변부의 부분 크롭을 허용한다
- 포인터와 터치 드래그로 시점을 바꿀 수 있다
- 부드러운 접지 그림자와 면의 미세한 명암만 사용하며 격자선은 그리지 않는다
- 방 안에는 부품 이름과 관계 제목만 표시한다

부품의 실제 크기 비례가 아닌 탐색용 전시 배율이다. SRAM, 버스, 데이터센터 같은 항목의 실제 포함 범위와 개념은 부품 설명에서 구분한다.

## 명확한 원형 메뉴

`전체보기 · 명령과 메모리 · 화면과 그래픽 · 저장과 실행 · 입력과 출력 · 네트워크 · 전원과 냉각` 일곱 항목이 하나의 타원 궤도를 돈다.

텍스트는 X축으로 반복되는 목록이 아니다. 원의 각도에 따라 가로 위치는 sin, 높이와 앞뒤 깊이는 cos로 바뀐다. 앞쪽의 글자는 크고 선명하며 뒤쪽에서는 작아지고 높아진다. 기울기와 옅은 타원 궤적으로 회전을 알아볼 수 있게 한다. DOM 버튼은 7개만 유지한다.

드래그는 회전 탐색만 수행한다. 클릭·Enter로 주제를 선택하면 해당 제목이 앞쪽으로 회전한다. 좌우 방향키로 다음 항목을, Home/End로 처음과 끝 항목을 선택할 수 있다. `전체보기`는 항상 명시적인 메뉴 항목이다.

모바일 터치에서는 버튼의 암묵적 포인터 캡처가 메뉴로 전달될 때 버블링하는 `lostpointercapture`를 드래그 종료로 취급하지 않는다. 메뉴 자신이 캡처를 잃거나 실제 손을 떼거나 취소한 경우만 종료한다. 드래그 뒤의 클릭 억제는 방 드래그와 별도로 관리한다. 이동하지 않은 탭과 키보드 선택은 정상 동작한다.

메뉴 버튼은 모두 부모의 3D 평면 앞에 두며, 빈 제목 컨테이너는 터치 대상에서 제외한다. 뒤쪽 항목이 보이는데 부모가 탭을 받던 문제를 막는다. 메뉴 전용 터치 영역은 브라우저의 스크롤 제스처와 경쟁하지 않는다. 원형 메뉴의 관성 보간은 별도 프레임 루프로 처리해 글자만 회전할 때 23개 3D 모델을 다시 그리지 않는다.

## 선택과 복귀의 순서

| 상태 | 먼저 | 다음 |
| --- | --- | --- |
| 주제 선택 | 약 400ms 동안 관련 없는 모델만 사라짐 | 선택 모델이 약 1초 동안 중앙으로 모임 |
| 다른 주제 선택 | 이전 주제에서 빠지는 모델이 사라짐 | 공통 모델과 새 모델이 새 중심 배치로 이동 |
| 전체보기 | 모여 있던 모델이 각자의 원래 벽 위치로 복귀 | 복귀 후 숨겨진 모델들이 다시 나타남 |
| 부품 설명 닫기 | 선택한 부품의 확대 상태가 해제됨 | 원래 주제 배치와 키보드 포커스로 복귀 |

전체보기 복귀는 약 1.55초다. 앞부분 70%에서 기존 모델이 돌아가고, 72% 이후에 다른 모델을 드러낸다. 원래 위치는 무작위로 재생성하지 않는다. 빠른 재선택은 현재 화면의 위치와 투명도에서 새 목적지로 이어진다.

같은 투명도의 부품은 한 번의 불투명 3D 렌더로 묶은 뒤 결과를 합성한다. 이를 통해 페이드 중 내부 면이 비치지 않으며, 부품마다 별도 렌더를 반복하는 비용도 줄인다.

## 역할·내부 구성·연결 관계

역할은 핵심 문장과 펼쳐 읽는 상세 설명으로 구성한다.

내부 구성은 한 번에 4개의 항목과 선택한 항목의 설명을 표시한다. 이전/다음 및 전체 구성 선택으로 모든 내용을 읽을 수 있다. 긴 구성 전체를 세로로 나열하지 않는다. 설명 영역의 스크롤바는 숨기되 작은 화면에서 휠·터치·키보드로 넘치는 본문을 읽을 수 있다.

연결 관계에서 다른 하드웨어를 누르면 **기준 부품을 유지하고 관계(edge)만 선택한다**. 두 모델을 나란히 놓고 연결선을 그리며 양쪽 관점의 설명을 표시한다. 예를 들어 CPU에서 RAM을 누르면 제목과 경로의 기준은 CPU이고, 화면은 CPU ↔ RAM이다. RAM 단독 설명으로 이동하지 않는다.

관계 유형은 기존 지도와 동일하게 구분한다.

- 데이터·제어: 짧은 신호가 지나가는 선. 문자 그대로의 케이블이나 검증된 전송 경로라고 설명하지 않는다
- 전원: 차분한 황금색 선
- 냉각: 넓고 옅은 열 전달 선
- 장착·구성: 점선과 포함·장착 범위 설명
- 활용·비교: 직접 배선과 구분되는 점 형태의 연결

`다른 연결 보기`로 기준 부품의 연결 목록으로 돌아간다. X는 처음 선택한 주제와 부품 포커스로 복귀한다. 이전 관계지도의 124개 관계와 방향별 설명을 그대로 사용한다.

## 모바일과 대체 동작

모바일도 입체 방을 유지한다. 공간을 압축한 평면 목록으로 바꾸지 않고 좌우·상하 드래그로 벽과 천장·바닥을 바라본다. 화면 밖 부품으로 키보드 포커스가 이동하면 카메라가 해당 부품을 바라본다. 주제 선택 후에는 관련 부품을 화면 안의 세로 배치로 모은다. 두 부품의 관계는 위쪽에 모델 쌍, 아래쪽에 설명을 둔다.

모션 감소에서는 진입과 위치 이동을 생략한다. WebGL 대체 화면에서도 23개 전시물, 7개 메뉴, 두 부품의 관계 설명과 모든 내부 구성에 접근할 수 있다.

- `CAWIKI_ROOM_URL=http://127.0.0.1:4174/relationship-room-study.html python3 tests/relationship-room-study.py`: 독립 배포 파일의 실제 동작 확인
- 증거: `artifacts/relationship-room-study/`의 목록·진입 및 복귀 중간 프레임·전체 방·주제·관계 쌍·모바일 화면
- Chromium의 실제 터치 입력 경로(CDP `Input.dispatchTouchEvent`)로 7개 메뉴 탭 후 중앙 회전, 양방향 드래그, 취소 후 재선택을 검증한다
- 복귀 중 카메라 방향·부품 위치의 연속성, 썸네일 좌표 도착, 기존 스크롤 복원, 중단 후 입력 복구를 검증한다

운영 사이트 목록의 23개 썸네일은 이전 변경의 공용 `hardware-portraits.js` 설정을 유지한다. 이번 시안 수정으로 필름 및 목록의 모델 일치 설정을 바꾸지 않는다.

## 메인 사이트 연결

`relationship-room-host.js`가 같은 출처의 공간 화면을 메인 페이지 안에 표시한다. 필름의 카메라·스타일과 공간 전시를 분리하되 브라우저 주소는 `index.html#map`을 유지한다. 부모와 공간 화면은 출처와 전송 창을 확인한 메시지만 처리한다. 실제 Wiki 목록의 스크롤을 전달해 진입하고, 복귀 애니메이션이 끝난 뒤 원래 Wiki 목록과 포커스를 복원한다. 부품·관계 선택은 메인 주소에 반영되며 다른 경로로 이동하면 공간 화면을 해제한다. 배포 빌더는 공간 코드의 해시를 URL에 넣어 이전 파일 캐시를 피한다.

`python3 tests/relationship-main-route.py`는 독립 시안이 아닌 공개용 메인 HTML에서 관계지도 진입·상세 주소·관계 설명·역방향 복귀·스크롤 복원·모바일 터치와 기존 하드웨어/시나리오/필름 이동을 검사한다.

최신 main의 `lib/inside/` 분리 모듈·지연 준비·렌더링 최적화는 유지한다. 운영 라우팅은 `lib/inside/site.js`, 공간 연결은 `lib/inside/room-host.js`에 적용한다. Pages 빌더도 이 구조가 있으면 단일 미리보기 HTML로 덮지 않고 최적화된 메인과 버전된 모듈/자산을 함께 배포한다.
