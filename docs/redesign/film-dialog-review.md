## 이번 작업의 범위

운영 사이트에서는 시나리오 원리 팝업의 `관계지도에서 보기` 링크와 링크를 갱신하던 코드만 제거한다. CPU 카메라, 팝업 레이아웃, 링크의 목적지였던 기존 `#map/scenario/...` 페이지는 변경하지 않는다. 사용자의 마지막 범위 지정인 “구현은 관계페이지에서 보기 버튼 제거밖에 없어”를 따른다.

새 팝업은 별도의 HTML 시안이다. 메인 사이트에서 불러오지 않으며 시안 주소에서만 볼 수 있다. Creative Production의 스타일 검토 지침을 참고했다. 해당 보드 도구는 이 세션에 제공되지 않아 기존 저장소의 실제 부품 이미지를 사용하는 독립 HTML로 검토할 수 있게 했다.

## CPU 크기가 바뀌는 원인

- 시작 이미지는 실제 첫 프레임을 1440×900, 390×844 두 크기로 촬영한 파일이다
- `#cpu-intro`는 창 전체에 `object-fit: contain`으로 들어가고 760px에서 이미지가 교체된다
- 실제 필름 `compose()`는 현재 화면비와 부품 경계를 이용해 카메라 **거리**를 매번 계산한다
- 고정 이미지의 확대 비율과 3D의 카메라 이동은 서로 다른 투영이다. 카메라 거리가 달라지면 원근도 바뀌므로 CSS 크기 조정만으로 모든 화면의 픽셀을 맞출 수 없다

기존 카메라 코드는 바꾸지 않고 테스트 응답에만 첫 프레임 캡처 함수를 추가해 확인했다. 배경과 밝기 차이가 25/255를 넘는 CPU 영역의 가로 폭을 비교한 근삿값이다. 실제 단말 GPU의 픽셀 동일성을 측정한 결과가 아니다.

## 권장 설계: 같은 투영으로 시작하기

첫 CPU 구간의 **카메라 위치·방향·모델·조명을 고정**하고, 창 크기에 따라 카메라의 보이는 범위를 조절한다. 준비 이미지도 같은 기준 화면을 같은 배율로 표시한다. 창 비율 때문에 카메라를 앞뒤로 움직이지 않으므로 준비 이미지와 첫 3D의 원근이 일치할 수 있다.

시안은 현재 데스크톱 첫 프레임을 기준으로 한다. 가로로는 화면의 75% 이내, 세로로는 현재 데스크톱에서 CPU가 차지하는 약 59% 이내에 놓는다. 작은 화면의 CPU가 너무 작아지는 것을 막고, 낮은 창에서도 잘리지 않도록 양쪽 제한을 함께 사용한다. 수치는 디자인 제안이며 구현 후 조정할 값이다.

기준 화면 `W₀=1440`, `H₀=900`, 기준 CPU 경계 `Bᵥ=855`, `Bₕ=528`, 기준 세로 화각 `θ₀=31°`일 때:

```
s = min(0.75 × viewportWidth / Bᵥ, viewportHeight / H₀)
준비 이미지 표시 크기 = (W₀ × s, H₀ × s)
세로 화각 θ = 2 × atan(viewportHeight / (s × H₀) × tan(θ₀ / 2))
카메라 aspect = viewportWidth / viewportHeight
```

이미지와 카메라 모두 같은 중심·시선 오프셋을 사용한다. 화면 가장자리에서 잘리는 것은 이미지의 빈 배경이며 CPU 자체가 아니다. 카메라의 위치를 유지한 채 화각만 위와 같이 바꾸면 같은 기준 투영을 균일하게 확대·축소할 수 있다. 조명·톤매핑·색 공간·DPR은 별도로 일치시켜야 한다.

향후 구현 시 지켜야 할 인계 순서:

1. 처음부터 실제 표시 영역을 측정해 준비 이미지를 배치한다
2. 같은 설정으로 CPU만 우선 준비하고 첫 3D 프레임을 그린다
3. 모델 위치·크기는 고정한 채 불투명도만 120–180ms 겹쳐 인계한다
4. 드래그 시작 후 동일한 스크롤 진행값으로 다음 카메라·분해 구간에 연속 보간한다
5. 창 크기 변경·화면 회전·브라우저 확대에도 두 표시가 같은 측정값을 사용한다
6. 준비 중 입력은 보관하고 첫 프레임과의 인계 이후 적용한다. 현재 진행률을 0으로 초기화하지 않는다

한 카메라의 이미지를 CSS로 확대해서 **기존의 거리 가변 카메라에** 억지로 맞추는 방안, 더 많은 화면비별 이미지 추가, 검정 페이드로 차이를 감추는 방안은 근본 해결로 권하지 않는다. 지금의 실시간 카메라 원근을 모든 화면에서 그대로 유지해야 한다면 정적 이미지를 건너뛰고 최소 CPU 장면부터 렌더하는 별도 접근이 필요하며 최초 표시 시간과 함께 비교해야 한다.

이 문서는 설계이며 위 카메라 계산은 운영 코드에 추가하지 않았다. 시안의 슬라이더는 정적 이미지의 제안 구도만 보여준다. 실제 2D→3D 일치 검증으로 제시하지 않는다.

## 원리 팝업 디자인

- 밝은 위키 화면과 구별되는 시나리오의 흑연색 배경·회녹색 포인트를 유지한다
- 1040px 이내의 넓은 설명판에 부품 영역과 읽기 영역을 나눈다. 화면 안쪽 여백과 얇은 경계만 사용한다
- 장면 번호 → 한국어 제목 → 핵심 한 줄 → 실제 상세 설명 → 부품 흐름 → 짧은 개념 표현 안내 순서다
- 부품 이미지는 기존 사이트와 같은 모델 이미지다. 관련 부품 3개는 흐름을 읽는 보조 표현이며 이동 버튼이 아니다
- 전원 시안은 PSU 공급 → VRM 변환 → CPU 공급, 저장 시안은 메모리 → SSD 전송 → NAND 기록이다. SSD와 HDD를 직렬 연결로 표현하지 않는다
- 영문 소제목과 관계지도 이동 버튼은 두지 않는다. 참고 자료는 있는 시나리오에서만 보인다
- 작은 화면에서는 부품을 위로 올리고 본문을 아래에 둔다. 긴 내용은 세로로 읽을 수 있고 가로로 잘리지 않는다
- 열기는 약 550ms의 감속 이동·페이드, 닫기는 240ms 페이드다. 설명 중 시나리오 진행은 정지하고 닫을 때 원래 진행값·포커스로 돌아가는 기존 동작을 유지하는 설계다
- 모션 감소에서는 이동을 생략한다. X, Escape, 키보드 포커스와 브라우저 기본 dialog 처리를 유지한다

## 확인

- 변경된 운영 페이지의 부팅·저장 시나리오에서 원리 팝업 열기, X·Escape 닫기와 본문 표시, 버튼 부재, 페이지 오류 없음 확인
- 시안의 전원·저장 내용 전환, 데스크톱·모바일·좁은 부모 화면, 팝업 다시 열기·닫기, 가로 넘침 없음 확인
- 실제 필름 카메라 `lib/inside/study.js`, CPU 준비 이미지, 시나리오 CSS·렌더러는 변경하지 않음
- 시안의 스크린샷과 측정값은 `docs/redesign/film-dialog-review/`에 보관
