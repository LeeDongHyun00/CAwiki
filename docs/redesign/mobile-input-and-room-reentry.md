# 모바일 시나리오 입력과 관계지도 재진입

## 시나리오 드래그

드래그와 브라우저 관성은 문서 스크롤을 그대로 따릅니다. 제스처마다 한 장면에서 멈추던 상한 대신, 화면에 그려지는 시나리오가 **초당 최대 2장면** 속도로 따라갑니다. 손을 떼고 관성이 끝나면 장면 하나에 멈춥니다.

- 드래그 중에는 목표가 스크롤 위치와 같습니다. 세게 넘겨도 장면이 경계에서 멈추지 않고, 정해진 속도로 이어서 지나갑니다
- 새 터치는 장면이 따라가던 목표에서 이어 갑니다. 터치할 때마다 장면이 멈추지 않습니다
- 반대 방향으로 움직이면 아직 따라가지 못한 거리를 버리고 지금 보이는 위치에서 바로 되돌아갑니다
- 관성이 끝난 뒤(스크롤 입력 없이 100ms) 장면 하나에 멈춥니다. 스크롤한 거리가 장면의 15% 미만이면 가장 가까운 장면으로, 그 이상이면 진행 방향에서 보이는 위치보다 뒤로 가지 않는 가장 가까운 장면으로 갑니다. 시나리오는 그 장면까지 같은 속도로 움직입니다
- 문서 위치는 터치나 관성 중에는 건드리지 않고, 멈출 때 한 번 목표에 맞춥니다. 시나리오 화면은 고정되어 있고 문서는 스크롤 길이만 제공하므로 이 정렬은 보이지 않습니다
- 휠·마우스 입력, 데스크톱, 동작 줄이기 설정에서는 속도 제한과 장면 정착을 적용하지 않습니다. 메인 필름의 기존 속도 설정은 그대로입니다

## 검증

- `tools/test_scenario_scroll.mjs`: 96가지 장면 간격·방향·프레임 속도 조합에서 목표가 스크롤을 그대로 따르는지, 그려지는 속도가 초당 2장면 이하인지, 즉시 역방향, 멈출 장면 선택
- `tools/test_scenario_continuous_drag.py`: 터치 유지 중 목표 추종, 즉시 역방향, 장면 정착, 실제 Chromium 터치, 터치 후 휠·마우스, 단계 표시줄 터치
- `tools/test_scenario_release.py`: 손을 뗀 뒤 관성 입력 반영, 즉시 역방향, 새 터치에서 목표 유지
- `tools/test_scenario_gestures.py`: 전체 시나리오의 큰 관성 입력에서 프레임당 0.1장면 이하, 역방향 없음, 터치 중 스크롤 쓰기 없음
- `tools/test_scroll_pacing.mjs`: 공용 메인 필름 설정 회귀 검사

모바일 검증은 Chromium 에뮬레이션이며 실제 Safari 기기 성능 측정은 아닙니다.

## 관계지도 재진입

관계지도는 진입할 때마다 별도 iframe을 만든다. 전환 시작은 iframe의 `performance.now()`로 기록하고 재생 시간은 RAF 콜백 인수로 계산하고 있었다. 같은 출처의 창이 부모 기준 RAF 시간을 공유하는 환경에서는 새 iframe의 시간 원점과 차이가 생긴다. 부모가 오래 실행된 두 번째 진입부터 첫 프레임이 이미 전환 종료 시각을 지난 것으로 판단할 수 있다.

Chromium의 일반 반복 진입에서는 생략되지 않았다. 부모 기준 RAF 타임스탬프를 주입해 해당 조건을 재현했을 때 기존 두 번째 진입은 **1프레임**으로 끝났다. 전환 시작과 매 프레임 계산을 동일한 iframe 로컬 시간으로 통일했다. 원형 메뉴도 같은 시간 기준을 사용한다.

크기가 같아도 모든 `resize` 알림이 진행 중인 진입·복귀를 즉시 완료하던 분기도 제거했다. 동일한 크기의 알림은 무시하고 실제 크기가 바뀌면 목록의 출발·도착 위치만 다시 계산하여 같은 진행 시각에서 계속한다.
