# 모바일 시나리오 입력과 관계지도 재진입

2026-10-09

## 시나리오 드래그

기존 입력 처리는 브라우저의 관성 스크롤을 읽으면서 제한값을 넘을 때마다 `scrollTo()`로 문서 위치를 되돌렸다. 제한 범위도 제스처 시작 위치가 아니라 매 프레임 움직이는 모델의 위치를 기준으로 갱신됐다. 모바일 주소창의 높이 변화는 `seek()`를 실행해 아직 재생 중인 목표값을 바꾸고 스크롤 위치를 다시 썼다.

추가로 이벤트에서 기록한 `performance.now()`보다 해당 프레임의 RAF 타임스탬프가 앞서면 음수 경과 시간이 들어갈 수 있었다. 이 경우 보간과 속도 제한의 방향이 뒤집힌다. 경과 시간을 0 이상으로 제한하고 0이면 현재 값을 그대로 반환한다.

새 `ScenarioScrollPacer`는 다음 규칙을 사용한다.

- 한 번의 터치와 이어지는 관성을 합해, 제스처 시작 시 보이는 위치에서 최대 한 장면 분량만 이동한다
- 장면 경계 간 길이를 기준으로 계산하므로 6·7·8·9개 장면의 길이 차이에 관계없이 같은 제한이 적용된다
- 짧은 드래그에는 최소 이동이나 장면 단위 자동 점프를 적용하지 않는다
- 새 터치는 직전 목표가 아니라 현재 보이는 프레임에서 시작하며 바로 반대 방향으로 움직일 수 있다
- 입력 중에는 문서 위치를 쓰지 않는다. 관성이 끝난 후 한 번만 최종 목표와 문서 위치를 맞추고, 그때 발생하는 스크롤 이벤트는 입력으로 다시 처리하지 않는다
- 모바일 주소창 높이가 바뀌면 입력 기준만 다시 맞추며 제스처의 최초 최대 범위와 재생 중인 목표를 유지한다
- 세로 모바일뿐 아니라 가로 모드의 터치 기기도 제한한다. 단계 버튼·다시 보기·키보드·모션 감소 설정은 명시적인 탐색을 유지한다

메인 필름의 기존 속도 설정은 유지하며, 공용 계산기에 음수·0 시간에 대한 보호만 추가한다.

## 관계지도 재진입

관계지도는 진입할 때마다 별도 iframe을 만든다. 전환 시작은 iframe의 `performance.now()`로 기록하고 재생 시간은 RAF 콜백 인수로 계산하고 있었다. 같은 출처의 창이 부모 기준 RAF 시간을 공유하는 환경에서는 새 iframe의 시간 원점과 차이가 생긴다. 부모가 오래 실행된 두 번째 진입부터 첫 프레임이 이미 전환 종료 시각을 지난 것으로 판단할 수 있다.

Chromium의 일반 반복 진입에서는 생략되지 않았다. 부모 기준 RAF 타임스탬프를 주입해 해당 조건을 재현했을 때 기존 두 번째 진입은 **1프레임**으로 끝났다. 전환 시작과 매 프레임 계산을 동일한 iframe 로컬 시간으로 통일했다. 원형 메뉴도 같은 시간 기준을 사용한다.

크기가 같아도 모든 `resize` 알림이 진행 중인 진입·복귀를 즉시 완료하던 분기도 제거했다. 동일한 크기의 알림은 무시하고 실제 크기가 바뀌면 목록의 출발·도착 위치만 다시 계산하여 같은 진행 시각에서 계속한다.

## 검증

- `tools/test_scenario_scroll.mjs`: 서로 다른 장면 간격, 15/30/60/120Hz, 양방향 입력, 최소 이동 없음, 제스처 한도, 높이 변경, 즉시 역방향 입력, 음수 시간, 가로 터치 모드
- `tools/test_scenario_gestures.py`: 실제 Chrome 터치 스와이프와 큰 스크롤 입력, 16개 시나리오의 양방향 상한·역진행·입력 중 위치 쓰기 검사, 팝업·직접 단계 이동
- `tools/test_room_reentry.py`: HTTP 캐시를 유지한 데스크톱/모바일 왕복, 일반/부모 기준 RAF 시간, 동일 크기 알림·실제 높이 변화, 필터 사용 후 복귀를 포함한 12회 진입
- `tools/test_scroll_pacing.mjs`: 기존 메인 필름의 장면별 속도 설정 유지

결과 JSON은 `docs/performance/input-stability/`에 기록한다. 실제 기기의 OS 관성 스크롤이나 Safari 성능을 측정한 결과는 아니며, 모바일 입력은 Chromium 터치 에뮬레이션으로 확인한다.
