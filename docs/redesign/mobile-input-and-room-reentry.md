# 모바일 시나리오 입력과 관계지도 재진입

## 시나리오 드래그

한 번의 터치와 이어지는 브라우저 관성을 합쳐, 터치를 시작할 때 보이는 위치에서 최대 한 장면까지 이동한다. 이전의 손 떼기 목표 고정과 500ms 감속·입력 제한 상태는 제거했다. 손을 떼도 새로운 스크롤 변화량을 계속 받아 같은 장면 한도 안에서 자연스럽게 움직인다.

- 위·아래 방향에 동일한 한도를 적용하며, 장면 간격이 달라도 장면 단위로 계산한다
- 한도를 넘은 입력은 매번 소비해 차이를 쌓지 않는다. 한도 도달 후 반대 방향으로 조금 움직이면 즉시 현재 화면에서 역방향으로 진행한다
- 작은 드래그에는 최소 이동량이나 강제 장면 이동을 적용하지 않는다
- 새 터치는 대기 시간 없이 새 시작점과 한도를 가지며, 휠·마우스 입력도 즉시 받을 수 있다
- 터치나 관성 입력 중 문서 위치를 반복해서 되돌리지 않는다. 관성이 종료된 뒤 한 번만 최종 목표에 맞추고 제스처 상태를 해제한다
- 모바일 주소창 높이가 바뀌면 입력 좌표만 보정하고 시작점과 한도는 유지한다
- 음수 프레임 시간은 0으로 처리한다. 메인 필름의 기존 속도 설정은 유지한다

## 검증

- `tools/test_scenario_scroll.mjs`: 96가지 장면 간격·방향·프레임 속도 조합, 한 장면 한도, 초과 입력 후 즉시 역방향, 작은 입력, 주소창 변화, 손을 뗀 후 관성 입력
- `tools/test_scenario_continuous_drag.py`: 터치 유지 중 한도, 즉시 역방향, 실제 Chromium 터치, 터치 후 휠·마우스, 단계 표시줄 터치
- `tools/test_scenario_release.py`: 브라우저 이벤트 처리에서 손을 뗀 뒤 목표가 계속 갱신되는지, 관성을 합쳐 한 장면 이내인지, 다음 터치를 즉시 받는지 검사
- `tools/test_scroll_pacing.mjs`: 공용 메인 필름 설정 회귀 검사

현재 결과는 `continuous-drag.json`, `post-touch-inertia.json`에 기록한다. 기존 `release-500ms.json`은 이전 구현의 기록이며 현재 동작에 적용하지 않는다. 모바일 검증은 Chromium 에뮬레이션이며 실제 Safari 기기 성능 측정은 아니다.

## 관계지도 재진입

관계지도는 진입할 때마다 별도 iframe을 만든다. 전환 시작은 iframe의 `performance.now()`로 기록하고 재생 시간은 RAF 콜백 인수로 계산하고 있었다. 같은 출처의 창이 부모 기준 RAF 시간을 공유하는 환경에서는 새 iframe의 시간 원점과 차이가 생긴다. 부모가 오래 실행된 두 번째 진입부터 첫 프레임이 이미 전환 종료 시각을 지난 것으로 판단할 수 있다.

Chromium의 일반 반복 진입에서는 생략되지 않았다. 부모 기준 RAF 타임스탬프를 주입해 해당 조건을 재현했을 때 기존 두 번째 진입은 **1프레임**으로 끝났다. 전환 시작과 매 프레임 계산을 동일한 iframe 로컬 시간으로 통일했다. 원형 메뉴도 같은 시간 기준을 사용한다.

크기가 같아도 모든 `resize` 알림이 진행 중인 진입·복귀를 즉시 완료하던 분기도 제거했다. 동일한 크기의 알림은 무시하고 실제 크기가 바뀌면 목록의 출발·도착 위치만 다시 계산하여 같은 진행 시각에서 계속한다.
