# 시나리오 05–16 연출 설계

2026-10-08 · `redesign` · 설계 및 대표 동작 시안

[12편 스토리보드](../../artifacts/scenario-expansion-design.html) · [저장 3D 드래그 시안](../../artifacts/scenario-save-study.html) · [72개 장면 데이터](../../design/redesign/expansion/storyboards.json)

## 방향

부품은 조립된 상태로 유지하고 사용자의 동작이 처리와 결과로 이어지는 모습을 보여준다

1–4번의 큰 3D 모델, 낮은 채도의 재질, 어두운 공간, 여백, 연속 카메라와 최소 설명을 이어간다
추가 12편에서 분해는 기본 연출로 사용하지 않는다
CPU 덮개·SSD 라벨·GPU 방열판·스피커 외장이 열린 뒤 내부가 드러나는 장면 없이도 버퍼, 파형, 프레임, 전력 상태, 작업 교대가 원리를 설명한다

이번 산출물은 12편의 장면 설계와 07 저장의 대표 모션 시안이다
실제 서비스의 05–16 경로를 3D 필름으로 교체한 상태는 아니다

## 1–4번에서 확인한 기준

실제 페이지의 부팅·게임·검색·파일 열기를 각각 6단계로 이동해 총 24개 장면을 확인했다
게임에서는 직접 마우스 드래그와 상세 설명 팝업도 확인했다
[화면 비교](../../artifacts/scenario-expansion-design/existing-four.jpg)와 [장면 기록](../../artifacts/scenario-expansion-design/reference-audit.json)에 근거를 남겼다

| 기준 | 추가 시나리오에 이어갈 방식 |
|---|---|
| 조용한 공간 안의 큰 하드웨어 | 같은 재질·조명·모델을 재사용하고 시각 효과는 진행 중인 작업에 집중 |
| 한 진행값으로 카메라와 결과를 제어 | 모든 상태를 스크롤 진행값의 함수로 계산하고 역방향에서도 같은 위치를 복원 |
| 입력 → 내부 처리 → 화면 | 일상 동작으로 시작해 그 동작의 결과를 처음의 화면에서 확인 |
| 제목과 인과관계 한 문장 | 화면의 설명을 줄이고 조건·예외는 `원리 자세히`에 제공 |
| 여섯 단계와 얇은 하단 표시 | 단계 버튼·키보드 이동·재시작을 유지 |
| CPU·RAM·SSD·GPU의 위치 | 동일한 공간 기준을 유지하며 GPU는 메인보드 아래에 배치 |

기존 필름의 분해 동작은 추가 시나리오의 전제에서 제외한다
장면마다 부품을 교체하거나 다시 조립하는 대신 한 카메라가 같은 공간을 이동한다
기존 1–4번의 동작 수정은 이번 설계 범위에 포함하지 않는다

## 공통 연출

### 드래그의 시간

- 휠·터치·세로 마우스 드래그를 하나의 `progress: 0…1`에 연결
- 6개 시작점은 기본적으로 `0 / .18 / .36 / .55 / .74 / .92`
- 한 단계의 앞 40%는 원인이 발생하는 부품을 보여주고, 뒤 60%는 처리 흐름을 따라 다음 부품으로 이동
- 카메라 이동은 5차 보간으로 시작·끝 가속을 낮춤
- 입력 추종은 시간 기반 감쇠 `1 - exp(-8 × dt)`를 사용하되 멈추면 정확한 목표값으로 수렴
- 드래그를 놓으면 진행을 멈추며 타이머로 다음 단계가 자동 재생되지 않음
- 거꾸로 이동하면 데이터, 화면, 커서, 버퍼가 함께 되돌아감
- 실제 연산 시간과 설명 구간의 길이는 대응하지 않음

### 카메라와 구도

시나리오마다 하나의 공간 좌표를 유지한다
키보드·마우스는 입력 쪽, 메인보드는 중심, GPU는 아래, 모니터는 결과 쪽에 둔다
통화·AI만 상대방 또는 서버의 별도 공간으로 이동하며 공간 이름으로 경계를 분명히 한다

부품은 회전하거나 날아와서 자리 바꾸지 않는다
같은 신호나 데이터가 현재 화면에서 다음 화면의 연결 지점까지 보이게 한다
모바일은 가로 구도를 단순 축소하지 않고 모델을 상단, 캡션을 하단에 분리하며 카메라 거리를 별도로 정한다

실제 설치에서 쿨러가 가리는 CPU 등의 부품은 기존 교육용 전시 배치를 따른다
조립 상태 유지는 보여주는 모델의 레이어를 분리하지 않는다는 의미이며, 완성 PC의 케이스 내부를 물리적으로 그대로 복제한다는 뜻은 아니다

### 움직임의 어휘

| 의미 | 형태·변화 | 적용 |
|---|---|---|
| 입력·제어 명령 | 작고 빈 고리, 유한한 한 번의 이동 | 키 입력·실행·저장·USB 요청 |
| 이동하는 데이터 | 면적이 있는 작은 타일 또는 묶음 | RAM·SSD·네트워크 |
| 버퍼 | 들어오고 나가는 방향과 채워진 칸 | 저장·음악·스트리밍·녹화 |
| 압축·해제 | 같은 내용의 큰 프레임과 작은 묶음 사이 변형 | 음악·영상·통화·로딩·녹화 |
| 소리 | 이산 샘플 → 연속 파형 → 작은 진동 | 음악·통화 |
| 동시성 | 같은 시간 눈금 위의 두 줄과 교대 표시 | 멀티태스킹·영상/오디오 동기화 |
| 전력 상태 | 위치는 고정, 활동 조명과 유지 전원만 변화 | 절전 |
| 완료 | 결과 화면의 상태가 바뀌고 이동 표시 종료 | 전체 |

명령과 데이터는 색뿐 아니라 빈 고리와 채워진 면으로 구분한다
빛은 논리적인 전달을 뜻하며 실제 전자 하나의 궤적이나 물리 배선 지도로 설명하지 않는다
버퍼 칸·주소 공간·행렬은 부품 옆의 작은 개념 표현이다
실제 NAND 셀, 물리 DIMM의 칸막이, 별도의 운영체제 칩처럼 보이게 만들지 않는다

### 화면

주요 시야에는 모델, `01 / 06`, 제목, 설명 한 문장만 남긴다
작업 상태를 이해하는 데 필요한 작은 버퍼·파형은 해당 구간에서만 보여준다
상단 로고와 내비게이션, 우측 다음 장면 목록, 단계명 옆 영문 부제, 상세 팝업의 영문 제목을 추가하지 않는다

하단에 단계 이동과 `Computer Wiki →`를 두고 마지막에는 다시 보기를 제공한다
대표 시안의 하단 링크는 검토 동선을 위해 `설계 목록 →`로 연결한다
모달은 열린 순간 진행을 멈추고 닫으면 같은 위치로 돌아간다
터치·키보드·단계 버튼으로 드래그 없이도 전체 내용을 확인할 수 있어야 한다
모션 감소 설정에서는 카메라 비행을 생략하고 의미 있는 상태로 즉시 이동한다
자동 사운드는 사용하지 않는다

## 대표 시안: 저장

[저장 모션 시안](../../artifacts/scenario-save-study.html)은 기존 키보드·메인보드·CPU·RAM·SSD·GPU·모니터 모델을 사용한다
카메라가 이동해도 레이어는 조립된 상태를 유지한다
Ctrl과 S의 기존 키캡과 글자만 함께 내려갔다 돌아온다

작은 고리는 입력과 제어 요청, 타일은 데이터, 작은 상태 막대는 대기와 기록을 뜻한다
RAM에서 SSD로 이동하는 데이터가 CPU 내부를 통과하지 않는다
SSD 기록을 설명할 때 라벨을 떼어내지 않고 조립된 SSD 옆에 개념 타일을 둔다
모니터의 문서는 `수정됨 → 저장 중 → 저장됨`으로 이어진다
화면·카메라·키·고리·타일은 모두 같은 진행값에 묶여 역방향 이동도 가능하다

이 시안은 **버퍼를 거친 뒤 동기화 완료를 기다리는 저장 예시**다
모든 앱의 저장 표시가 같은 보존 수준을 뜻하는 것은 아니다
전원 차단 후에도 무조건 보존된다는 연출이나 문구는 사용하지 않는다
시안은 카메라와 원리 표현을 확인하는 용도이며 최종 제품 모델·조명·렌더링 성능의 합격 판정은 실제 배포 기기에서 이어서 검증한다

## 구현 구조

기존 `scenario-film.js`의 시나리오별 조건문을 12개 더 늘리기보다 공통 상태 계산과 연출 트랙을 분리한다
기존 네 편의 동작과 경로를 보존하면서 새 편부터 공통 트랙을 적용한다

```js
{
  id: 'save',
  stages: [{ at, title, copy, detail, camera }],
  layout: 'local-computer',
  tracks: [
    { kind: 'key-press', range, target },
    { kind: 'command', range, path },
    { kind: 'buffer', range, source, destination },
    { kind: 'transfer', range, path, payload },
    { kind: 'screen-state', range, before, after }
  ]
}
```

- **카메라**: 부품의 고정 좌표와 기기별 프레이밍
- **원리 상태**: `evaluate(progress)`가 현재 버퍼·프레임·전력·문서 상태 반환
- **모델 표현**: 기존 모델의 키·진동판 등 필요한 부분만 움직임
- **개념 표현**: 명령 고리, 데이터 타일, 버퍼, 시간 띠를 공유
- **화면 표현**: CanvasTexture로 문서·영상·통화 등 결과 생성, 변화할 때만 갱신
- **설명**: 현재 상태와 같은 장면 데이터를 캡션·상세 설명·대체 화면에 재사용

새 필름도 서비스의 기존 공용 렌더러를 사용한다
리뷰용 독립 페이지에서만 별도 렌더러를 사용한다
GPU·RAM·모니터를 편마다 복제해 메모리에 계속 남기지 않는다
정지·비활성 탭에서는 RAF를 멈추고, 모바일 DPR을 제한한다
네트워크·버퍼 효과를 위해 매 프레임 메시를 새로 만들지 않는다
서버와 상대방 모델은 필요 시 준비하고 종료 시 자원을 정리한다

## 구현 순서와 확인 기준

1. **입력과 저장** — 05 타이핑, 06 실행, 07 저장, 12 USB에서 명령·데이터·버퍼·문서 상태를 공통화
2. **미디어 처리** — 08 음악, 09 스트리밍, 15 로딩, 16 녹화에서 샘플·프레임·압축·컨테이너를 추가
3. **복합 흐름** — 10 통화, 11 멀티태스킹, 13 절전, 14 AI에서 두 공간·동시성·전력·서버 추론을 추가
4. **서비스 연결** — 기존 목록·썸네일·ID를 유지하며 영화형 페이지로 연결, 관계지도 설명으로 왕복

각 편마다 시작·중간·끝 정지 화면, 정방향·역방향 드래그, 마지막 결과를 확인한다
한 장면의 데이터가 다음 장면에서 이유 없이 다른 모양이나 위치로 끊기지 않는지 본다
작동 원리 설명과 보이는 이동 방향이 일치해야 한다
작은 화면에서 모델과 캡션이 겹치지 않고 주요 부품이 프레임에서 잘리지 않아야 한다
휠·마우스·터치·키보드·모션 감소·팝업 복귀·브라우저 뒤로 가기를 확인한다
실제 기기 성능은 프레임 시간과 메모리 회수로 확인하며 헤드리스 소프트웨어 WebGL 결과를 실제 GPU 성능으로 보고하지 않는다

## 기술 설명의 근거

기존 관계지도 16편의 설명과 원래 네 편의 흐름을 바탕으로 다음 1차 문서로 오해하기 쉬운 부분을 확인했다

- [Windows 파일 캐시](https://learn.microsoft.com/en-us/windows/win32/fileio/file-caching), [버퍼를 디스크로 동기화](https://learn.microsoft.com/en-us/windows/win32/fileio/flushing-system-buffered-i-o-data-to-disk)
- [USB 표준 디스크립터](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/standard-usb-descriptors), [Windows USB 열거 과정](https://techcommunity.microsoft.com/blog/microsoftusbblog/how-does-usb-stack-enumerate-a-device/270685/)
- [시스템 절전 상태](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/system-sleeping-states), [Modern Standby와 S3](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/modern-standby-vs-s3), [ACPI 절전·복귀](https://uefi.org/specs/ACPI/6.6/16_Waking_and_Sleeping.html)
- [NVDEC 설명](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/nvdec-application-note/index.html), [NVENC 프로그래밍 안내](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/nvenc-video-encoder-api-prog-guide/)

특정 운영체제·장치의 구현을 모든 컴퓨터의 유일한 경로로 설명하지 않는다
하드웨어 디코더·인코더 지원, DMA 경로, 전원 상태, 클라우드·로컬 실행의 차이는 해당 장면의 상세 설명에 둔다

## 이번 시안 검증

Chromium·Playwright의 소프트웨어 WebGL 환경에서 다음을 통과했다

- 12편·72개 장면의 제목·상세 설명·참고 모델 이미지와 선택 동작
- 저장 시안 6단계의 캡션과 진행값 일치
- 같은 진행 위치를 정방향·역방향으로 방문했을 때 캔버스 픽셀 차이 0
- 실제 마우스 드래그, 키보드 마지막 이동, 재시작
- 상세 설명을 연 동안 정지하고 닫은 뒤 같은 진행 위치로 복귀
- 1440×900·390×844 구도와 가로 넘침 없음
- 모션 감소에서 대표 상태와 완료 화면으로 즉시 이동
- 네트워크를 차단한 독립 HTML 초기화, 페이지 JavaScript 오류 0
- JavaScript 구문·Python 구문·문서 내부 링크 검사
