# 관계지도 공간 리디자인 설계

2026-10-08 · redesign · 2차 시안 반영 · 실제 구현 완료

[인터랙티브 시안](relationship-room-preview/index.html) · [기존 참고 조사](reference-audit.md)

## 결정

관계지도를 여섯 개의 밝은 전시 공간으로 만든다 각 방의 전면과 양옆 벽에 하드웨어를 보이지 않는 정렬 기준으로 배치한다 격자선은 시안과 최종 구현 모두 그리지 않는다 제목은 중앙 벽 하단에 고정한다 부품을 선택하면 같은 부품이 확대되면서 역할과 내부 구성을 읽는 페이지로 이어진다 관계는 선택한 두 부품 사이에서만 보여준다

시안은 명령과 메모리 방, CPU 설명, 내부 구성, CPU–DRAM 관계를 검토하기 위한 별도 HTML이다 실제 지도·라우터·배포에는 연결하지 않았다 기존 3D 모델을 투명 배경으로 새로 렌더링한 이미지로 배치와 전환을 보여주며, 최종 WebGL 모델·조명·카메라 품질을 구현한 결과물은 아니다 다른 네 부품은 역할 설명까지만 제공한다

## 2차 시안에 반영한 수정

- 첫 화면에 보이는 문자는 **하드웨어 이름 다섯 개와 관계지도 제목 하나**뿐이다
- 부품별 설명, 제목 위 분류명, 제목 아래 질문, 탐색 안내, 방 번호, 개수, 검토용 표시, 하단 장면 선택 메뉴를 모두 제거했다
- CPU 이름 옆 장식 화살표도 제거했다 클릭 기능은 그대로 유지하고 hover/focus 반응으로 선택 가능함을 드러낸다
- 전체 화면의 격자 SVG를 삭제했다 실제 구현에서 격자선이나 벽 윤곽선을 복원하지 않는다
- CPU를 중심에 크게 놓고 SRAM·DRAM은 전면 위쪽, NPU·보조 프로세서는 양옆에 배치했다 미세한 비대칭과 크기 차이로 공간 깊이를 만든다
- 모델은 기존 기하 구조로부터 다시 렌더링했다 PNG 자체가 투명하므로 이미지 사각형 경계가 없다
- 포인터에 3–5px만 반응하고 부품 선택 시 살짝 떠오른다 모바일·reduced motion에서는 포인터 효과를 적용하지 않는다
- 상세 화면의 장식 문구와 하단 검토 UI도 제거했다 역할·내부 구성의 실제 학습 내용은 선택 후 나타나는 설명 영역에 유지한다 복귀는 접근성 이름이 있는 닫기 아이콘 하나로 통일했다

## 1 공간 배치

- 배경 #F5F5F1, 전면은 따뜻한 백색에서 연한 회색으로 이어지는 명암, 본문 #292D2A, 강조 #536C51
- 데스크톱 전면 벽: 화면 가로 21–79%, 세로 10–78% 범위
- 제목: 전면 벽의 아래쪽 중앙, 가로 36–60px 가변 크기 부품 및 경로와 겹치지 않는 안전 영역 확보
- 보이지 않는 3열 정렬 기준으로 큰 중심 부품과 작은 부품을 교차 배치 슬롯은 제품의 실제 크기 비율이 아니라 탐색용 전시 비율
- 좌우 벽은 제품이 식별되는 20–32° 정도의 원근만 적용 장치 이름은 화면에 정면으로 보이게 유지
- 5–7개 부품을 첫 화면에 전부 표시한다 방 이동은 기존 관계지도 목록으로 나가서 선택한다 자동 회전이나 자동 순환은 없다
- 포인터 반응은 미세한 카메라 이동, hover/focus는 부품 1.03배·그림자 변화 키보드 포커스도 동일하게 강조
- **격자선·벽 테두리·바닥 줄눈은 구현하지 않는다** 공간의 깊이는 면의 명암, 흰색 페이드, 부품의 크기와 위치, 부드러운 그림자로만 표현한다
- 회색 이미지 박스를 제거했다 기존 모델을 투명 배경으로 새로 렌더링해 부품 형태만 공간에 보이게 배치했다 최종 구현에서도 회색 배경 평면을 추가하지 않는다

### 여섯 공간 배정

| 방 | 중심 | 전면의 관련 부품 | 옆면의 관련 부품 |
| --- | --- | --- | --- |
| 명령과 메모리 | CPU | SRAM, DRAM | NPU, 보조 프로세서 |
| 화면과 그래픽 | GPU | VRAM, 모니터 | CPU, 버스 |
| 저장과 실행 | SSD | HDD, DRAM | CPU, 버스, 보조 프로세서 |
| 입력과 출력 | 버스 | 키보드, 마우스, 카메라 | 오디오, 보조 프로세서, 메인보드 |
| 네트워크 | NIC | 네트워크 인프라, 데이터센터 | CPU, DRAM, 메인보드 |
| 전원과 냉각 | 메인보드 | PSU, 냉각 장치, VRM | CPU, SPI 플래시 |

현재 `RELATION_GROUPS`의 구성원을 유지한다 버스는 특정 형태의 단일 부품이 아니라 연결 체계이며 데이터센터도 단일 컴퓨터 부품이 아니다 해당 전시물에는 정확한 개념 이름과 설명을 제공한다 SRAM처럼 CPU 안에 포함될 수 있는 구성도 별도 독립 장치라고 오해되지 않게 내부 구성 관계를 명시한다

## 2 부품 설명 페이지

데스크톱은 왼쪽 50% 하드웨어, 오른쪽 약 32% 설명, 사이 충분한 여백을 둔다 작은 영어 장식 문구는 넣지 않는다 부품 이름·역할/내부 구성/연결 관계 세 항목과 닫기 아이콘만 제공한다 역할의 한 줄 핵심 설명은 본문에 둔다

### 역할

한 줄 핵심 역할 → 2–3문장 쉬운 설명 → 대표 동작 하나 순서다 예: CPU는 명령을 실행한다 필요한 정보는 캐시와 메모리에서 가져온다 장치와의 협업은 운영체제·드라이버·컨트롤러를 거칠 수 있다 모든 통신을 CPU가 직접 하나씩 중계하는 그림은 피한다

### 내부 구성

제품 외형에서 구성 개념도로 400–600ms 교차 전환한다 기본은 분해 연출 없이 코어·캐시·컨트롤러 같은 영역을 선택해 강조한다 선택 지점에 대응하는 이름과 짧은 역할만 오른쪽에 표시한다

- 실제 모델에 정확한 구성 요소가 있으면 해당 요소를 강조한다
- 모델에 없는 내부 구조를 실제 해부도처럼 꾸미지 않는다 별도의 검증된 기능 개념도를 사용한다
- CPU 시안의 6개 코어 배치는 예시이며 제품 사양이 아니다 개념도 표시를 유지한다
- 구성 요소 수를 임의로 6개로 제한하지 않는다 중요한 3–5개부터 보여주고 전체 구성 목록에서 나머지를 선택할 수 있게 한다
- 구성 요소의 포함 관계와 데이터 이동 관계를 구분한다

### 3D 감상 페이지와의 구분

`#object/:id`는 기존대로 3D 감상과 나가기만 유지한다 새 설명 화면은 `#map/node/:id`에 속한다 감상 페이지에 이전/다음·전체보기·관계보기 버튼을 다시 추가하지 않는다

## 3 연결망: 선택한 한 관계를 공간에 그린다

기본 방에서는 모든 연결선을 감춘다 부품 위에 마우스를 올리거나 키보드로 포커스하면 관련 부품의 이름 밑에 작은 점만 나타난다 실제 클릭은 부품 설명으로 이동한다 hover 없이도 동일 정보를 설명의 연결 관계에서 볼 수 있다

연결 관계 항목은 현재 부품의 상대 목록과 관계 유형을 제공한다 상대 하나를 선택하면 두 부품만 강조하고 경로는 벽면의 보이지 않는 정렬 기준을 따라 내려간 뒤 아래쪽 공간에서 연결한다 배경의 격자선을 표시하는 것은 아니다 경로가 제목이나 설명 뒤로 지나가지 않게 안전 영역을 둔다 모서리는 짧게 둥글리고 교차는 만들지 않는다

- 현재 데이터: 23개 노드, 124개 관계 CPU는 18개 관계를 가진다 첫 6개로 잘라서 끝내지 않는다
- 상대 목록은 검색과 유형 필터를 제공한다 현재 방 밖의 상대도 '다른 공간' 표시와 함께 접근 가능하다
- 선택하지 않은 17개 관계를 동시에 그리지 않는다 목록에서 선택을 바꿀 때 이전 경로를 지우고 새 경로를 만든다
- 본문은 양쪽 관점을 나란히 제공한다 기존 `ab` / `ba`를 보존한다
- CPU→DRAM 요청과 DRAM→CPU 응답은 순서를 나눠 보여준다 여러 기능을 한 방향으로 오해할 수 있는 영구 흐름 화살표는 쓰지 않는다
- 경로는 기능적 관계의 시각화다 실제 케이블 위치·전송 속도·물리적 직결을 의미하지 않는다는 설명을 제공한다

| 관계 | 표현 | 동작 |
| --- | --- | --- |
| 데이터·제어 | 회녹색 가는 실선 + 읽기/쓰기/요청 등의 이름 | 내용에 맞는 방향으로 짧은 신호 1회 이동 재생 버튼으로 반복 |
| 전력 | 절제된 황토색 선 + 공급 방향 | 공급원에서 대상 방향으로 한 번 밝아짐 |
| 열 | 옅은 주황색 면 + 열 이동 방향 | 열원에서 냉각부로 부드럽게 확산 |
| 포함·구조 | 얇은 괄호 또는 포함 영역 | 내부 영역이 드러남 이동 입자 없음 |
| 비교·맥락 | 점선과 관계 이름 | 정적 비교 이동 입자 없음 |

색만으로 분류하지 않는다 선 모양과 이름을 함께 사용한다 시안의 반복 경로는 위치 검토용 단순화이며 최종 구현에서는 요청/응답 상태와 재생 조작으로 교체한다

## 4 전환 설계

| 구간 | 시간 제안 | 화면 변화 |
| --- | --- | --- |
| hover / focus | 180–240ms | 미세 부양·조명 변화 텍스트 위치는 유지 |
| 클릭 후 선택 | 0–120ms | 선택 확정 나머지 부품 대비를 낮춤 |
| 공간 → 설명 | 120–800ms | 선택한 **그 부품**의 화면 위치·크기를 왼쪽 히어로 위치까지 이어서 보간 방의 원근은 점차 평평해짐 |
| 본문 진입 | 420–800ms | 10–16px 이동과 opacity 제목부터 등장 |
| 구성 선택 | 250–450ms | 기존 강조 해제 → 새 영역 강조 → 설명 교체 |
| 관계 선택 | 450–700ms | 상대 부품 등장 후 경로가 끝까지 이어짐 |
| 돌아가기 | 600–750ms | 동일 부품이 기존 슬롯으로 돌아가고 방 시점·선택·키보드 포커스 복구 |

기본 easing은 cubic-bezier(.22,1,.36,1) 스프링 튕김이나 큰 회전은 사용하지 않는다 트랜지션 도중 재클릭·뒤로가기는 마지막 의도대로 취소/전환한다 반복 입력을 긴 잠금으로 막지 않는다 읽는 화면에 스크롤 강제 이동을 적용하지 않는다

프리뷰는 CPU에 대한 연속 위치 전환과 나머지 부품의 설명 교체를 검토한다 모든 부품의 실제 출발 좌표 연속성, 카메라 보간, 중단 복구는 구현 단계에서 완성할 항목이다

## 5 모바일과 접근성

- 390px에서는 정면 위주 2열 배치 옆 벽을 억지로 기울이지 않는다 부품 겹침 없이 44px 이상 선택 영역을 확보한다
- 설명은 위쪽 모델, 아래쪽 본문으로 이어지는 자연스러운 세로 스크롤 화면이다 좁은 화면에 본문과 모델을 좌우로 압축하지 않는다
- 카메라 이동은 줄이고 부품의 위치 연속성과 짧은 fade를 유지한다
- 링크/버튼으로 모든 부품을 탐색할 수 있고 3D canvas의 클릭만으로 정보를 독점하지 않는다
- 페이지 전환 후 제목으로 포커스 이동 돌아오면 원래 부품 버튼 복구 브라우저 뒤로가기도 같은 상태를 복원한다
- reduced motion에서는 카메라 이동·신호 반복을 끄고 즉시 전환 또는 100ms 이내 fade 사용
- WebGL 실패 시 기존 이미지와 같은 DOM 설명·관계 목록을 제공한다
- 배경의 면 명암은 장식에만 사용하고 이름과 본문은 WCAG AA 대비를 확보한다

## 6 구현 구조와 단계

현재 관계 렌더러 `relationship-map.js`, 데이터 `relation-source.js`, 그룹 `relation-scenarios.js`를 기반으로 역할을 나눈다

1. `relationship-room-layout.js` — 그룹별 슬롯·벽·읽기 순서·카메라 기준 데이터
2. `relationship-room-stage.js` — 기존 WebGL 스테이지의 수명주기를 재사용하는 공간·조명·선택 부품 전환 새 canvas를 부품마다 만들지 않음
3. `relationship-detail.js` — DOM 기반 역할·구성·양쪽 관계 설명 접근성 제공
4. `relationship-room-motion.js` — room / entering / detail / returning 전환 상태와 중단 복구
5. `relationship-paths.js` — 기능 관계 유형별 경로 및 동작 어댑터

기존 `#map/group/:id`, `#map/node/:id?edge=...` 주소는 유지한다 예전 edge 딥링크는 해당 상대의 연결 관계를 바로 연다 `type`, `page`와 관계 시나리오 경로는 호환 처리한다 새 URL에서는 선택 탭과 출발 방을 저장할 수 있도록 `tab=parts&from=compute` 같은 선택 상태를 명시한다 이 파라미터는 구현 제안이다

CPU 방으로 공간→설명→복귀의 품질을 먼저 맞춘 뒤 6개 방과 23개 부품으로 확대한다 그룹 밖 관계를 포함한 124개 관계의 접근 가능성을 검증한다 기존 3D 모델의 불필요한 재생성을 막고 방의 5–7개만 활성화한다 DOM 설명은 canvas보다 위에 렌더링해 가려짐을 방지한다

### 구현 완료 기준

- 6개 방과 23개 설명, 124개 관계의 접근 경로가 유지됨
- 부품 클릭 시작점과 설명의 모델이 자연스럽게 이어짐 돌아가도 같은 위치
- 제목·부품·경로·본문의 겹침 없음 desktop / 390px / 320px 및 200% 확대 확인
- 마우스·터치·키보드·브라우저 뒤로가기·직접 링크·reduced motion 모두 확인
- 색과 동작이 실제 관계 유형에 맞음 특히 전원·열·구조 관계에 데이터 입자를 잘못 쓰지 않음
- 모바일 기기에서 프레임 시간 측정 후 DPR·그림자·동시 모델 수 조절 시안의 소프트웨어 브라우저 결과를 성능 보장으로 삼지 않음

## 이번 산출물 범위

공간/설명/내부 구성/관계/모바일 시각 시안을 바탕으로 실제 관계지도를 구현했다 아래 구현 및 검증 기록을 따른다

2차 시안 검토: 1440×900 / 390×844에서 이미지 로드와 배치 확인 첫 화면의 실제 표시 문자는 5개 부품명과 제목으로 확인 부품 클릭·복귀, 구성/관계 전환, reduced motion 정상 브라우저 JavaScript 오류 없음


## 구현 및 검증 — 2026-10-08

- 6개 방의 23개 실제 3D 모델을 공용 WebGL 렌더러 하나로 표시한다 방→상세→복귀에서 동일 모델의 위치와 크기를 760ms 보간한다 격자선과 전체 연결망은 제거했다
- 첫 화면에는 부품 이름과 중앙 벽 하단 제목만 남겼다 나가기는 문자 없는 닫기 아이콘 하나다 면 명암·모델 원근·작은 포인터 반응으로 공간감을 만든다
- 23개 부품의 역할과 전체 내부 구성 요소를 제공한다 내부 구성은 물리적 위치를 주장하지 않는 기능 개념도이며, 6개씩 표시하되 선택 메뉴로 모든 항목에 직접 접근할 수 있다
- 124개 관계를 검색·유형 필터로 선택할 수 있다 한 관계의 두 모델과 양쪽 설명을 동시에 보여준다 데이터 관계에만 짧은 신호가 지나가고 전원·열·장착·비교는 서로 다른 선과 면으로 표현한다 부품·이름을 가로지르지 않게 경로를 아래에 배치했다
- `#map/group/...`, `#map/node/...`, 기존 `edge`, `type`, `page` 주소를 유지한다 예전 group edge 주소는 선택한 부품의 관계 화면으로 연결한다 `from`으로 출발 공간과 선택 포커스를 복구한다
- 기존 16개 관계 시나리오의 64단계도 거미줄을 제거하고 모델·단계 설명·관련 부품 선택으로 정리했다 실제 필름과 원래 3D 감상 페이지의 단일 나가기 기능을 유지한다
- 움직임 감소, 이미지 대체 화면, 좁은 모바일, 전환 중 경로 변경, WebGL 컨텍스트 복구, 독립 HTML 오프라인 사용을 확인했다
