기본 `index.html`에 전체 사이트를 연결했다. 화면 전체를 모델에 할애하고 로고·상단 내비게이션·우측 예고 목록을 두지 않는다. 컬렉션은 필요할 때 전체 화면으로 연다.

## 포함된 하드웨어

| 영역 | 부품 |
|---|---|
| 연산 | CPU, GPU, NPU, 칩셋 |
| 메모리 | DDR5, SRAM, VRAM, SPI 플래시 |
| 저장 | SSD, HDD |
| 시스템 | 메인보드, 전원공급장치, 쿨링 팬, VRM, PCIe 슬롯 |
| 입출력 | 모니터, 키보드, 마우스, 스피커, 웹캠 |
| 네트워크 | 네트워크 카드, 라우터, 서버 랙 |

23종 모두 실제 메시, 재질, 분리 가능한 구성 요소가 있다. 각 모델을 회전·확대·분해할 수 있다. CPU·GPU의 표면과 형상을 보강했고, HDD의 플래터·헤드, PSU 회로, 팬 곡면, 광학 렌즈, 서버 베이 등은 장치별로 구성했다. 썸네일은 실제 새 모델을 렌더링했다.

## 화면과 동작

- **메인 필름**: CPU → GPU → DDR5 → M.2 SSD → SATA HDD → 타워형 CPU 쿨러 → PSU → VRM → 칩셋 → SPI 펌웨어 → PCIe 네트워크 카드 → 후면 I/O → 메인보드 전체 조립 → 모니터 밖으로, 총 14개 장면. GPU는 메인보드 아래, PSU·HDD는 옆에 전시해 다른 부품을 가리지 않는다. 독립적인 INPUT / OUTPUT 장면은 제거했다. 키보드와 마우스는 마지막 모니터 장면에만 등장한다. 마지막에는 메인보드 전체의 분해도에서 다시 결합한다. 역방향 스크롤도 같은 경로를 따른다.
- **건너뛰기**: GPU 구간부터 하단 중앙에 `건너뛰기 →`를 표시한다. 누르면 모니터 직전의 전체 메인보드 장면으로 바로 이동하고, 다음 스크롤로 모니터 연출을 이어간다.
- **메인보드**: LGA 소켓, DIMM 슬롯 4개, PCIe 슬롯, M.2, SATA, ATX 24핀, EPS, USB·팬·전면 헤더, CMOS 배터리, 후면 USB·LAN·오디오를 구성했다. PSU·SATA는 케이블로 연결한다. 칩셋·VRM·SPI의 분리는 납땜된 부품의 내부를 설명하기 위한 구조 단면이다.
- **모니터 엔딩**: 마지막 메인보드 장면을 WebGL 렌더 타깃에 직접 그려 모니터 화면에 사용한다. 정지된 장면은 캐시하고 카메라가 뒤로 이동하며 화면 안의 부품도 함께 축소한다. 세로 화면에도 같은 축소 방향을 적용한다. 화면을 채운 장면에서 실제 모니터·스탠드·키보드·마우스가 드러나는 줌아웃이다.
- **마우스**: 제공된 사진을 기준으로 앞끝이 낮은 무광 외장, 몸체와 곡면이 이어지는 좌우 버튼, 가는 이음새와 낮게 들어간 휠로 다시 모델링했다. 왼쪽 클릭은 버튼 뒤쪽을 축으로 앞끝만 약 0.5mm 내려간다. 바닥의 PTFE 피트·광학 센서와 내부 PCB·스위치·배터리, 여섯 레이어의 분해는 유지한다. 개별 보기·시나리오·모니터 엔딩에 같은 모델을 사용한다.
- **Computer Wiki**: 엔딩의 `Computer Wiki →` 버튼 또는 필름 우측 하단의 작은 링크로 `#wiki` 메인 페이지에 진입한다. 하드웨어 23종·시나리오 16편을 선택하고 필름을 다시 볼 수 있다.
- **관계지도**: 여섯 기능 묶음에서 하드웨어 23종과 관계 124개를 탐색한다. 부품 선택 시 양쪽 관점의 설명, 관계 유형 필터와 중심 이동을 제공한다. 원본 115개 관계를 보존하고 마우스·VRM을 보강했다. 원본의 보조 프로세서는 칩셋 모델과 구별한다.
- **작동 원리 목록**: 위키와 전체 화면 시나리오 목록의 카드 16개로 통합했다. 16편 모두 사용 상황의 동작 전·후를 보여주는 장면을 적용했다 USB는 실제 기기 사진을 참고한 3D 모델의 렌더를 사용한다. 관계지도 첫 화면의 별도 목록은 제거했다.
- **시나리오 내용**: 부팅·게임·검색·파일 열기 외에 타이핑·프로그램 실행·저장·음악·스트리밍·화상통화·멀티태스킹·USB·절전·AI·게임 로딩·화면 녹화까지 16개 주제, 64단계의 관계지도 설명을 제공한다. 기존 3D 필름 네 편과 바로 왕복할 수 있다. 모바일은 단계 설명을 지도 앞에 배치하고 선택한 관계의 설명으로 이동한다.
- **컬렉션**: 전체 23종, 한국어·영문 검색, 6개 분류. 부품 선택 상태를 보존하고 닫는다.
- **개별 부품**: 한 개의 큰 모델, 회전·확대, 구조 펼치기·재조립, 시점 초기화, 이전·다음. 브라우저 뒤로 가기 지원.
- **시나리오**: 승인된 클릭→화면 시안의 구도·카메라 이동을 게임·부팅·검색·파일 열기 네 편에 적용했다. 각각 6개 장면이며 휠·세로 드래그·터치로 카메라, 부품 내부 전개, 신호와 결과 화면을 함께 제어한다. 역방향도 같은 위치를 재현한다. 파일 열기는 SSD·HDD·메모리 캐시 경로를 비교할 수 있으며, 캐시 경로는 저장장치를 거치지 않는 4개 장면이다. 화면에는 제목과 한 문장만 남기고 상세 설명은 눌러서 연다. 단계 이동·다시 보기·원래 위치 복귀를 지원한다.
- **시나리오 표지**: 16편 모두 상황별 동작 장면을 보여준다. 기본은 동작 직전이며, 호버와 키보드 포커스에서 전원 켜기·게임 클릭·검색·파일 열기·타이핑·프로그램 실행·저장·음악·영상·통화·창 전환·USB 삽입·절전 복귀·AI 전송·게임 로딩·녹화를 한 번만 재생한다. 벗어나면 초기 상태로 돌아간다. 터치는 첫 탭으로 시나리오에 들어가며, 모션 감소 설정은 움직임 없이 결과를 보여준다. 위키와 시나리오 목록에 같은 이미지가 적용되며 외부 이미지 요청은 없다.
- **문구**: 제목·설명·상세 설명과 위키 제목에 붙인 마침표를 제거했다. 파일 확장자와 `M.2`, 버전 숫자 등의 표기는 유지한다.
- **모바일**: 부품은 터치 회전·핀치 확대, 시나리오는 세로 배치. 설명은 단계명과 한 문장만 남긴다.

EDOLUS의 연속적인 규모 변화와 카메라 동선을, Cactus Digitale의 큰 매체·여백·공간 이동을 적용했다. 원본의 로고·탐색 띠나 자산을 가져오지 않는다.

## 실행과 공유

```bash
python3 serve.py 4173
```

`http://localhost:4173/`

`#wiki`, `#collection`, `#object/hdd`, `#object/datacenter`, `#stories`, `#story/game/0`, `#map`, `#map/scenario/save/0`처럼 직접 진입할 수 있다.

```bash
python3 tools/build-redesign-preview.py
```

공유용 `artifacts/inside-site.html`에는 코드·모델·썸네일·대체 이미지가 포함된다. 외부 CDN·폰트·네트워크 자산에 의존하지 않는다.

## 코드

- `study.js`: 메인의 스크롤 연출, 모델별 투영 영역에 맞춘 카메라, 공용 WebGL 무대와 모니터 렌더 패스.
- `cinema-timeline.js`: 14개 장면의 구간·캡션·접근성 설명.
- `cinema-models.js`: ATX 메인보드, 설치 좌표, 타워 쿨러, 후면 I/O, 케이블, 모니터와 데스크 장면.
- `hero-models.js`: CPU·GPU 정밀 표현과 공유 재질.
- `collection-models.js`: 23종의 형상과 분해 구조, 자원 정리.
- `mouse-model.js`: 마우스의 곡면 패널, 외장·버튼·휠·기판·센서 모델.
- `experience.js`: 개별 모델의 회전·확대·분해와 자원 관리.
- `story-covers.js`, `story-actions.js`, `story-covers.css`: 16편의 상황 장면과 호버·포커스 동작
- `story-usb-preview.js`: USB 3D 렌더의 유한·역방향 재생
- `tools/usb-cover/scene.js`: USB 플러그와 허브의 3D 모델 제작 원본
- `scenario-data.js`: 네 시나리오의 카메라·부품·신호 경로·문장과 파일 열기 분기.
- `scenario-film.js`, `scenario-film.css`: 스크롤 연출, 모니터 결과, 모바일 구도, 상세 설명과 복귀 상태.
- `story-covers.js`, `story-covers.css`: 독립적인 SVG 장면과 호버·키보드 포커스 애니메이션.
- `relationship-map.js`, `relationship-map.css`: 기능 묶음·부품 관계·단계별 시나리오와 반응형 설명 배치
- `relation-scenarios.js`: 여섯 기능 묶음과 16개 작동 원리
- `relation-source.js`: `tools/build-relation-data.py`로 원본 관계에서 생성한 설명 데이터
- `site-data.js`, `site.js`: 전체 목록, 검색·분류·주소·공유 무대 관리.

페이지와 모델을 바꿔도 렌더러는 하나다. 개별 탐색 화면에서 사용을 마친 모델과 컨트롤은 해제하며, 정지·비활성 상태에서는 프레임을 계속 그리지 않는다. 필름의 움직이지 않는 세부 메시들은 레이어 안에서 합쳐 드로 콜을 줄이고, 프레임이 늦어진 환경에서도 경과 시간에 맞춰 스크롤을 따라간다. 컨텍스트가 손실되면 이미지로 전환하고 복구 후 선택한 모델을 다시 만든다.

제품별 내부 형상과 회로 패턴은 교육용 재구성이다. 제조사 CAD나 회로 배치의 정확한 복제는 아니다. 실제 GPU 기기 성능과 Safari 검증 범위는 [검증 기록](verification.md)을 따른다.
