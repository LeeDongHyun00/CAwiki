# 프레임의 출처가 보이는 시나리오

2026-10-08

## 연출 결정

통화의 눈·입·손 표현을 없애고 원형 머리와 어깨로 된 하나의 사람 픽토그램을 사용한다
상징 전체의 작은 기울기와 이동, 음성 레벨만 드래그 진행에 연결한다
카메라에서 나온 영상, 인코더에 들어간 프레임, 상대방 화면에 같은 형태를 사용한다

GPU 위의 색 네모는 어떤 내용인지 보여 주지 못했다
이미지 조각이 공유하는 하나의 원본 텍스처를 사용해 분리되어도 원본을 알아볼 수 있게 한다

| 구간 | 프레임의 출처와 변화 |
|---|---|
| 글자 입력 | 입력한 `가`의 획과 커서가 담긴 조각을 화면으로 조립 |
| 영상 스트리밍 | 마지막 모니터와 같은 풍경을 분리된 이미지에서 한 프레임으로 복원 |
| 화상 통화 | 같은 사람 픽토그램의 촬영 → 압축 → 상대방에서 복원 |
| 게임 로딩 | 풍경과 플레이어 이미지 자원을 VRAM에 준비하고 첫 장면으로 조립 |
| 화면 녹화 | 녹화할 재생 화면을 복제 → 압축 → 남은 화면 순서대로 처리 |
| 프레임 전달 경로 | 단색 패킷 대신 작은 원본 이미지가 이동 |
| AI 서버 | 영상 이미지 조립을 제거하고 가중치·연산 영역·토큰에 집중 |

압축 장면에는 작은 원본을 남기고 결과에 `압축 데이터` 포인트를 붙인다
프레임 아래의 연결선은 처리 위치를 GPU에 연결한다
이미지 조각은 이해를 위한 표현이며 실제 코덱의 블록 배치나 데이터 압축 방식을 그대로 재현한다는 의미가 아니다
논리적인 프레임 도식은 방열판에 가리지 않게 표시하고 상세 설명 팝업보다 아래에 둔다

## 절전 요청

작업 중인 문서 위에서 전원 메뉴를 열고 `절전` 행으로 포인터를 옮긴다
선택 행이 밝아진 뒤 화면이 꺼지고, 절전 구간에서는 검은 화면을 유지한다
복귀하면 같은 문서와 커서 위치가 다시 나타난다
`시스템 종료`와 `다시 시작`을 함께 표시해 선택한 동작을 구분할 수 있게 한다

## 구현 범위

- `scenario-screen.js`: 얼굴 없는 픽토그램, 공용 원본 프레임, 절전 메뉴와 작업 복귀
- `scenario-frames.js`: 한 텍스처의 서로 다른 영역을 사용하는 재사용 이미지 조각
- `scenario-signals.js`: 복원·압축·캡처·자원 업로드·프레임 전달의 실제 위치와 움직임
- 모든 변화는 기존 스크롤 진행값을 사용하며 정지 시 멈추고 되감기 시 같은 상태를 복원
