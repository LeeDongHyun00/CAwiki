# 부품 위에서 보이는 시나리오 연출

2026-10-08 · 05–16의 94개 장면 전체 점검

기존 구현을 동작 기준으로 분류하면 설명판만 변화 30개, 설명판과 전송선 위주 44개, 실제 입력·상태 변화 9개, 결과 화면 11개다

## 연출 원칙

[EDOLUS](https://edolus.com/)의 전체 공간→보드→칩 접근과 [Cactus Digitale](https://cactusdigitale.com/)의 대상 중심 여백·선택 강조·정보 오버레이를 기존 [실제 관찰 기록](reference-audit.md)과 저장 화면으로 다시 대조했다
원본 애셋이나 코드를 복사하지 않고 적용 원칙을 다음처럼 구체화한다

- 시선은 부품의 실제 위치에 연결한 원형 포인트에서 시작한다
- 명령은 옅은 금색, 데이터는 민트, 동시 작업은 제한된 보조색으로 구별한다
- CPU 다이·SSD NAND·GPU 다이/메모리는 필요한 장면에서 덮개만 열어 보여준다
- 부품에 붙은 사용 영역, 대기 조각, 실제 이동 경로를 통해 어디에서 무엇이 바뀌는지 보인다
- 복잡한 논리 개념의 작은 보조 도식은 남기되 3D 깊이와 분리해 항상 읽을 수 있게 한다
- 글자·창·영상·통화·파일·게임·응답·녹화 결과도 같은 드래그 진행값으로 이어진다
- 마지막 장면에도 자체 진행 구간을 주고, 되감으면 같은 상태를 복원한다
- 발광·파동은 사용자가 움직일 때만 진행하며 정지 화면에서 무한 반복하지 않는다

칩 위의 색·타일·작업 큐는 기능을 설명하는 개념 표현이다
CPU의 실제 코어 배치, 물리 메모리 할당, GPU 전용 코덱 위치를 특정 제품의 제조 도면처럼 단정하지 않는다
설명 팝업은 native dialog 최상위 계층에, 보조 도식은 WebGL 깊이 검사와 분리한 최종 순서에 둔다

보조 도식은 글자 조합·가상 주소·프로그램별 주소·토큰의 네 장면에만 남긴다
이 장면에도 실제 처리 위치의 포인트·영역·조각 움직임을 함께 둔다
화상통화의 지터 버퍼는 상대방 RAM에 배치하고, 복원할 데이터가 RAM에서 GPU로 향하도록 연결한다
저장 완료는 SSD가 CPU에 완료를 알리고 앱 화면이 바뀌는 의미로 구분한다
